### Answer Key

1. The client-server architecture solved the problem of running complex, monolithic applications on a single expensive machine. It provided a way to separate an application into multiple components that could run on different machines, effectively replacing the old mainframe model where everything ran in one place.
2. An "expensive" task is one that is resource-intensive. This includes workloads that consume a lot of RAM or CPU, or operations that have high latency, such as computation or reading data from a disk.
3. The text states that microservices "inherited or borrowed" from the client-server model. The concept of breaking a large, monolithic service into multiple smaller, independently communicating microservices is directly analogous to the original idea of breaking a single application into a client and a server.
4. The Remote Procedural Call (RPC) is the mechanism that was born from the client-server model to allow a program to make a call to a procedure on a remote machine. The concept has existed since the 1960s or 1970s.
5. A primary benefit is that the client no longer requires all the dependencies that the full application once did. For example, a database driver needed to communicate with a database can be installed only on the server, allowing the client to remain lightweight and free of such dependencies.
6. The architecture allows for better scaling because many clients running on cheap "commodity hardware" can make requests to a single, "beefy" server with good resources. This centralizes the heavy workload and allows the number of clients to grow because they are lighter and start faster.
7. The source describes the "three-tier architecture" as a "special case" of the client-server architecture. This applies specifically to situations that involve moving the server and database components into their own tiers.
8. The modern trend of "edge computing" is mentioned as an example of clients performing more work. In this model, clients like IoT devices can perform compute logic locally instead of sending every task to a remote server.
9. The critical problem was the lack of a standard for communication, which the source describes as the "wild, wild west." While it was possible to send data across the wire, there was no universal method, which meant different systems could not necessarily understand each other.
10. According to the text, gRPC (Google Remote Procedure Call) built upon the original RPC concept to create what is now effectively a "universal" communication standard. It facilitates communication between any two components.

### Glossary of Key Terms

|   |   |
|---|---|
|Term|Definition|
|**Client-Server Architecture**|The architectural model that separates an application into multiple components, typically a "client" and a "server," which can be located on different machines. In this model, clients call servers to perform expensive tasks.|
|**Commodity Hardware**|Inexpensive, standard hardware that can be used for client machines, as opposed to the more powerful and expensive "beefy" hardware used for servers.|
|**Edge Computing**|A modern trend where lightweight computational tasks are performed on client devices themselves (at the "edge" of the network), such as IoT devices, rather than being sent to a central server.|
|**Expensive Workload**|A task or computation that is resource-intensive. The text defines this as anything that "takes a lot of Ram or takes a lot of CPU or takes a lot of latency," such as reading from a disk.|
|**gRPC (Google Remote Procedure Call)**|A technology that built upon the concept of RPC to create a "universal" and standardized model for communication between any two software components.|
|**Mainframe**|A large, powerful computer on which an entire application runs in a single location. This model was superseded by the client-server architecture.|
|**Microservices**|An architectural approach where a large, monolithic application is broken down into multiple smaller, independent services that communicate with each other. The text presents this as an idea inherited from the client-server concept.|
|**Monolith**|A single, large application where all components and logic are contained within one service running on one machine.|
|**Remote Procedural Call (RPC)**|The mechanism born from the client-server model that allows a client to execute a procedure or function on a remote server. The concept dates back to the 1960s/70s and initially lacked a universal standard.|
|**Three-Tier Architecture**|Described in the text as a "special case" of the client-server architecture, typically involving the separation of the application into a client, a server (application logic), and a database.|
