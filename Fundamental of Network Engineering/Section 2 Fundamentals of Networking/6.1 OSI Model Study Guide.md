## Answer Key

1. A standardized communication model is crucial because it allows for the creation of "agnostic applications." This means a single version of an application can run over any network medium—such as Wi-Fi, Ethernet, or Fiber—without needing to know the specifics of the underlying network. This standard also allows for easier network equipment upgrades and enables innovation to occur within a single layer without affecting the others.
2. The Presentation Layer (Layer 6) is responsible for encoding and serialization. For example, it takes a data structure like a JSON object from an application and serializes it into a flat string of bytes that can be transmitted over the network. It handles the conversion of data into a format that the lower layers can handle and that the receiving system can understand.
3. The Session Layer (Layer 5) is responsible for establishing, managing, and terminating connections, essentially managing the "state" of a communication session. TCP is a stateful protocol that operates here because it stores state on both the client and server to manage the connection. This layer is where processes like the TLS (Transport Layer Security) handshake and connection establishment occur.
4. The Transport Layer (Layer 4) introduces the concept of **ports** (e.g., port 80, port 443), which are used to direct data to specific applications on a machine. The Network Layer (Layer 3) is only aware of IP addresses to get the data to the correct machine, but not which application on that machine should receive it.
5. The data units are called **frames** at Layer 2 (Data Link), **packets** at Layer 3 (Network), and **segments** at Layer 4 when using TCP. The lecture also mentions that UDP data units at Layer 4 are called datagrams.
6. The "Russian matryoshka doll" analogy describes how data from an upper layer is placed inside the data structure of a lower layer. The application data is put inside a TCP segment (Layer 4), which is then put inside an IP packet (Layer 3). Finally, the entire IP packet is put inside a data link frame (Layer 2) for transmission.
7. A switch is a Layer 2 device that makes forwarding decisions based on MAC addresses found in the data link frame; it only needs to process up to Layer 2. A router is a Layer 3 device that must process up to the Network Layer to read the source and destination IP addresses in the packet, which it uses to route the traffic between different networks.
8. A Layer 7 proxy must go "all the way up" because it needs to make decisions based on application-level data, such as a URL path (e.g., `/images`). Since this information is encrypted, the proxy must terminate the session, decrypt the data, inspect it, and then re-encrypt it to send it on. This process makes Layer 7 devices slower than Layer 4 devices, which only need to look at unencrypted port and IP address information.
9. A transparent proxy is a device, like one an ISP might use, that inspects traffic without needing to decrypt the application data. It can see public, unencrypted information like the source and destination IP addresses (Layer 3) and port numbers (Layer 4). Because of this, it can block traffic based on IP address or port.
10. The main criticisms of the OSI model are that it has too many layers, which can be hard to understand, and that the distinctions between some layers (like Presentation and Session) can be blurry or seem unnecessary. The TCP/IP model simplifies this by combining Layers 5, 6, and 7 into a single "Application" layer, making it less complex.

## Glossary of Key Terms

|   |   |
|---|---|
|Term|Definition|
|**Agnostic Application**|A software application designed so that it does not need any knowledge of the underlying network medium (e.g., Wi-Fi, Ethernet, Fiber). It can run on any of them without modification, thanks to standardized models.|
|**Application Layer (Layer 7)**|The highest layer of the OSI model. It is where application-specific protocols like HTTP operate and where the end-user application's data originates (e.g., a POST request with JSON data).|
|**Content Delivery Network (CDN)**|A type of Layer 7 reverse proxy. It inspects application content to perform tasks like caching data closer to users to improve performance.|
|**Data Link Layer (Layer 2)**|This layer deals with physical network addresses, known as MAC addresses. It packages data into units called **frames** for transmission over a local network segment.|
|**Encapsulation**|The process where data from a higher layer is wrapped inside the data structure of a lower layer. For example, an IP packet (Layer 3) is encapsulated within an Ethernet frame (Layer 2).|
|**Firewall**|A network security device that can block unwanted packets. To do its job, it needs to inspect traffic at least up to Layer 4 to see IP addresses and port numbers.|
|**Frame**|The unit of data at the Data Link Layer (Layer 2). It contains the Layer 3 packet and adds source and destination MAC addresses.|
|**IP Address**|A logical address used at the Network Layer (Layer 3) to route packets across different networks to the correct destination machine.|
|**Layer 2 Device**|A network device, such as a **switch**, that operates at the Data Link Layer. It forwards traffic based on MAC addresses.|
|**Layer 3 Device**|A network device, such as a **router**, that operates at the Network Layer. It forwards traffic between different networks based on IP addresses.|
|**Layer 4 Proxy**|A device that makes forwarding decisions based on information at the Transport Layer, specifically IP addresses and port numbers.|
|**Layer 7 Proxy**|A device, such as a **reverse proxy** or **load balancer**, that operates at the Application Layer. It must decrypt and inspect the actual application data (e.g., HTTP paths) to make intelligent routing or caching decisions.|
|**MAC Address**|A physical address unique to a network interface card (NIC). It is used by the Data Link Layer (Layer 2) to identify devices on a local network.|
|**Network Layer (Layer 3)**|This layer is responsible for routing and logical addressing using IP addresses. It packages data into units called **packets**.|
|**OSI Model**|The Open Systems Interconnection model. A conceptual framework that standardizes the functions of a telecommunication or computing system into seven abstract layers.|
|**Packet**|The unit of data at the Network Layer (Layer 3). It contains the Layer 4 segment and adds source and destination IP addresses.|
|**Physical Layer (Layer 1)**|The lowest layer of the OSI model. It is responsible for the actual transmission of raw bits (1s and 0s) over a physical medium, such as electrical signals on an Ethernet cable, radio waves for Wi-Fi, or light for fiber optics.|
|**Port**|An identifier used at the Transport Layer (Layer 4) to direct data to a specific process or application running on a host machine.|
|**Presentation Layer (Layer 6)**|This layer is responsible for data translation, encoding, and serialization. It converts application data into a standardized format for transmission (e.g., turning a JSON object into a string of bytes).|
|**Protocol Ossification**|A concept where network protocols become difficult to change or upgrade because intermediate devices (like routers) are built to expect a very specific format. If that format changes, these devices may "freak out" and fail to process the traffic.|
|**Reverse Proxy**|A server that sits in front of one or more back-end servers, acting as the single endpoint for clients. It receives client requests, forwards them to the appropriate back-end server, and returns the response, hiding the details of the back-end infrastructure.|
|**Segment**|The unit of data at the Transport Layer (Layer 4) when using TCP. It contains the application data and adds source and destination port numbers.|
|**Serialization**|The process of converting a complex data object (like a JSON object in JavaScript) into a format, such as a string of bytes, that can be easily stored or transmitted across a network. This occurs at the Presentation Layer (Layer 6).|
|**Session Layer (Layer 5)**|This layer is responsible for establishing, managing, and tearing down communication sessions. It handles the state of a connection, which is why stateful protocols like TCP are considered to operate here.|
|**TCP/IP Model**|A simpler, four-layer communication model that is more practical than the OSI model. It combines the OSI's Application, Presentation, and Session layers into a single "Application" layer.|
|**Transport Layer (Layer 4)**|This layer provides host-to-host communication services for applications, using protocols like TCP and UDP. It manages concepts like ports, flow control, and retransmission, and its data units are called **segments** (for TCP) or **datagrams** (for UDP).|
