### Rust Working with Numbers for Competitive Programming

In competitive programming, Rust provides robust support for numerical operations using integers and floating-point numbers, with features tailored for precision and performance. The standard library includes well-defined integer types, efficient modular arithmetic, and floating-point types suitable for problems requiring decimal precision. Below is a detailed explanation of working with numbers in Rust for competitive programming, covering integers, modular arithmetic, and floating-point numbers, structured to match the style of the previous response on input/output.

#### 1. Integers

The most commonly used integer type in competitive programming is `i32`, a 32-bit signed integer with a value range of $(-2^{31})$ to $(2^{31} - 1)$ (approximately $(-2 \cdot 10^9)$ to $(2 \cdot 10^9))$. For problems requiring larger numbers, the 64-bit `i64` type is used, with a range of $(-2^{63})$ to $(2^{63} - 1)$ (approximately $(-9 \cdot 10^{18})$ to $(9 \cdot 10^{18}))$.

Example of defining an `i64` variable:

```rust
use std::io::{self, Write};

fn main() {
    let x: i64 = 123_456_789_123_456_789;
    let mut stdout = io::stdout().lock();
    writeln!(stdout, "{}", x).expect("Failed to write");
}
```

```text
123456789123456789
```
- **Explanation**: The variable `x` is explicitly typed as `i64`. Rust allows underscores in numeric literals (e.g., `123_456_789`) for readability. The value is printed using `writeln!` to standard output.

A common mistake is performing calculations with smaller types, leading to overflow. Rust’s type system requires explicit casts to avoid this:

```rust
use std::io::{self, Write};

fn main() {
    let a: i32 = 123_456_789;
    let b: i64 = (a as i64) * (a as i64); // Cast to i64 to prevent overflow
    let mut stdout = io::stdout().lock();
    writeln!(stdout, "{}", b).expect("Failed to write");
}
```

```text
15241578750190521
```
- **Explanation**: Casting `a` to `i64` ensures the multiplication uses 64-bit arithmetic, producing the correct result. Alternatively, declare `a` as `i64` initially.

Most competitive programming problems are designed so `i64` is sufficient. Rust’s standard library does not include a 128-bit integer type, but for rare cases needing larger ranges (e.g., up to \(10^{38}\)), external crates like `num-bigint` can be used via `cargo`.

#### 2. Modular Arithmetic

Some problems require outputting a large result modulo \(m\), such as \(10^9 + 7\), to keep numbers manageable. Rust’s `i32` and `i64` types are ideal for this, as the modulo operation (`%`) can be applied after each arithmetic step to prevent overflow.

The modulo operation satisfies these properties for \(x \mod m\):

- \((a + b) \mod m = ((a \mod m) + (b \mod m)) \mod m\)
- \((a - b) \mod m = ((a \mod m) - (b \mod m)) \mod m\)
- \((a \cdot b) \mod m = ((a \mod m) \cdot (b \mod m)) \mod m\)

Example: Calculate \(n!\) (factorial of \(n\)) modulo \(m\):

```rust
use std::io::{self, BufRead, Write};

fn main() {
    let mut input = String::new();
    io::stdin()
        .lock()
        .read_line(&mut input)
        .expect("Failed to read line");
    let n: i64 = input.trim().parse().expect("Expected an integer");
    let m: i64 = 1_000_000_007; // Common modulus
    let mut x: i64 = 1;
    for i in 1..=n {
        x = (x * i) % m;
    }
    let mut stdout = io::stdout().lock();
    writeln!(stdout, "{}", x).expect("Failed to write");
}
```

- **Explanation**: Reads `n` from input, computes \(n!\) by multiplying `x` by each `i` and applying `% m` after each step to keep `x` small. Outputs the result.

Rust’s `%` operator may return a negative remainder for negative numbers (e.g., \(-5 \% 3 = -2\)). To ensure the remainder is in \(0 \ldots m-1\), adjust as follows:

```rust
use std::io::{self, Write};

fn main() {
    let mut x: i64 = -17;
    let m: i64 = 5;
    x = x % m;
    if x < 0 {
        x += m;
    }
    let mut stdout = io::stdout().lock();
    writeln!(stdout, "{}", x).expect("Failed to write"); // Outputs 3
}
```

- **Explanation**: After computing `x % m`, add `m` if `x` is negative to get the positive remainder. This is only needed for operations like subtraction that may yield negative results.

#### 3. Floating-Point Numbers

While integers are sufficient for most competitive programming problems, some require floating-point numbers. Rust’s primary floating-point types are:

- **`f64`**: A 64-bit double-precision floating-point type, suitable for most problems.
- **`f32`**: A 32-bit single-precision type, less common due to lower precision.

Example of outputting a floating-point number with specified precision:

```rust
use std::io::{self, Write};

fn main() {
    let x: f64 = 123.456;
    let mut stdout = io::stdout().lock();
    write!(stdout, "{:.9}", x).expect("Failed to write"); // Outputs 123.456000000
    writeln!(stdout).expect("Failed to write newline");
}
```

- **Explanation**: The `{:.9}` format specifier outputs `x` with 9 decimal places, as often required in problem statements. `writeln!` adds a newline.

Floating-point numbers can have rounding errors due to finite precision:

```rust
use std::io::{self, Write};

fn main() {
    let x: f64 = 0.3 * 3.0 + 0.1;
    let mut stdout = io::stdout().lock();
    write!(stdout, "{:.20}", x).expect("Failed to write"); // Outputs 0.99999999999999988898
    writeln!(stdout).expect("Failed to write newline");
}
```

- **Explanation**: The result is slightly less than 1 due to floating-point imprecision.

To compare floating-point numbers safely, avoid direct equality (`==`) and use a small epsilon (\(\epsilon\)):

```rust
use std::io::{self, Write};

fn main() {
    let a: f64 = 1.0;
    let b: f64 = 0.3 * 3.0 + 0.1;
    let epsilon = 1e-9;
    let mut stdout = io::stdout().lock();
    if (a - b).abs() < epsilon {
        writeln!(stdout, "a and b are equal").expect("Failed to write");
    } else {
        writeln!(stdout, "a and b are not equal").expect("Failed to write");
    }
}
```

- **Explanation**: If the absolute difference between `a` and `b` is less than \(\epsilon = 10^{-9}\), they are considered equal, mitigating precision errors.

Rust’s `f64` can accurately represent integers up to \(2^{53}\) (approximately \(9 \cdot 10^{15}\)) without loss of precision, useful for mixed integer and floating-point calculations.

#### 4. Additional Notes

- **Type Safety**: Rust requires explicit casts (e.g., `as i64`) to avoid overflow or type mismatches, ensuring reliable arithmetic.
- **Performance**: Integer and floating-point operations are optimized in release builds (`cargo build --release` or `rustc -O`). Modular arithmetic prevents large numbers, enhancing efficiency.
- **No 128-bit Integers**: For numbers beyond `i64`, use crates like `num-bigint`, though `i64` is typically sufficient.
- **Precision Control**: Use format specifiers like `{:.9}` to meet contest output requirements.

#### Example: Complete Numerical Problem Template

A template for a problem combining modular arithmetic and floating-point output:

```rust
use std::io::{self, BufRead, BufWriter, Write};

fn main() {
    let mut stdin = io::stdin().lock();
    let stdout = io::stdout();
    let mut stdout = BufWriter::new(stdout.lock());

    // Read input
    let mut line = String::new();
    stdin.read_line(&mut line).expect("Failed to read line");
    let mut iter = line.trim().split_whitespace();
    let n: i64 = iter.next().unwrap().parse().expect("Expected an integer");
    let x: f64 = iter.next().unwrap().parse().expect("Expected a float");

    // Compute factorial modulo 10^9 + 7
    let m: i64 = 1_000_000_007;
    let mut fact: i64 = 1;
    for i in 1..=n {
        fact = (fact * i) % m;
    }

    // Compute floating-point result
    let float_result = x * fact as f64;

    // Output results
    writeln!(stdout, "{}", fact).expect("Failed to write");
    writeln!(stdout, "{:.9}", float_result).expect("Failed to write");
}
```

- **Explanation**: Reads `n` and `x`, computes \(n!\) modulo \(10^9 + 7\), calculates \(x \cdot n!\) as a float, and outputs both with specified precision.

Format specifiers ensure precise output, making Rust effective for numerical problems in contests.
