### Rust Input and Output for Competitive Programming

In competitive programming, Rust uses standard streams for reading input and writing output, primarily through the `std::io` module. Input typically consists of numbers and strings separated by spaces or newlines, and output is formatted similarly. Rust provides efficient and safe methods for handling I/O, with tools to optimize performance, read whole lines, process unknown amounts of data, and support file-based I/O. Below is a detailed explanation of these techniques in Rust, tailored for competitive programming.

#### 1. Reading Input (Numbers and Strings)

Input in competitive programming often includes numbers and strings separated by spaces or newlines. Rust uses `std::io::stdin` for reading input, typically with `BufRead` for efficient buffered reading. Here’s how to read two integers and a string from a single line:

```rust
use std::io::{self, BufRead};

fn main() {
    let mut input = String::new();
    io::stdin()
        .lock()
        .read_line(&mut input)
        .expect("Failed to read line");
    let mut iter = input.trim().split_whitespace();
    let a: i32 = iter.next().unwrap().parse().expect("Expected an integer");
    let b: i32 = iter.next().unwrap().parse().expect("Expected an integer");
    let x: String = iter.next().unwrap().to_string();
    // Use a, b, x
}
```

- **Explanation**:
  - `io::stdin().lock()` provides a locked handle to standard input, reducing overhead for multiple reads.
  - `read_line(&mut input)` reads a line into a reusable `String` buffer, including the newline character.
  - `trim()` removes the trailing newline, and `split_whitespace()` splits the line into tokens (separated by spaces or tabs).
  - `iter.next().unwrap().parse()` converts each token to the desired type (`i32` for integers, `String` for strings).
  - This handles inputs like `123 456 monkey` or multi-line inputs with the same elements, as long as they’re on one line for this example.

For inputs spread across multiple lines (e.g., `123 456` on one line, `monkey` on the next), you can read multiple lines:

```rust
use std::io::{self, BufRead};

fn main() {
    let mut lines = io::stdin().lock().lines();
    let first_line = lines.next().unwrap().expect("Failed to read line");
    let mut iter = first_line.trim().split_whitespace();
    let a: i32 = iter.next().unwrap().parse().expect("Expected an integer");
    let b: i32 = iter.next().unwrap().parse().expect("Expected an integer");
    let second_line = lines.next().unwrap().expect("Failed to read line");
    let x: String = second_line.trim().to_string();
    // Use a, b, x
}
```

- `lines()` iterates over input lines, and each line can be processed similarly.

#### 2. Writing Output

Rust uses `std::io::stdout` for output, with macros like `println!` or `write!` for formatted printing. To output two integers and a string:

```rust
use std::io::{self, Write};

fn main() {
    let a = 123;
    let b = 456;
    let x = "monkey";
    let mut stdout = io::stdout().lock();
    writeln!(stdout, "{} {} {}", a, b, x).expect("Failed to write");
}
```

- **Explanation**:
  - `io::stdout().lock()` provides a locked handle for efficient output.
  - `writeln!(stdout, "{} {} {}", a, b, x)` formats the values with spaces between them and adds a newline, producing output like `123 456 monkey`.
  - `expect` handles potential I/O errors, though errors are rare in competitive programming due to controlled environments.

For finer control (e.g., no newline), use `write!`:

```rust
use std::io::{self, Write};

fn main() {
    let a = 123;
    let b = 456;
    let x = "monkey";
    let mut stdout = io::stdout().lock();
    write!(stdout, "{} {} {}", a, b, x).expect("Failed to write");
    writeln!(stdout).expect("Failed to write newline");
}
```

- `write!` omits the newline, allowing manual control with `writeln!`.

#### 3. Optimizing Input and Output

I/O can be a bottleneck in competitive programming. Rust’s I/O is efficient by default, but you can optimize further:

- **Buffered I/O**: Use `stdin().lock()` for input and `stdout().lock()` for output to minimize system calls by holding the lock across multiple operations.
- **Reusable Buffers**: Reuse a single `String` buffer for input to reduce memory allocations.
- **Manual Flushing**: Use `stdout.flush()` only when needed (e.g., in interactive problems) to avoid unnecessary flushes, unlike some languages’ output methods that flush automatically.

Example of optimized I/O:

```rust
use std::io::{self, BufRead, BufWriter, Write};

fn main() {
    let mut stdin = io::stdin().lock();
    let stdout = io::stdout();
    let mut stdout = BufWriter::new(stdout.lock());
    let mut input = String::new();
    stdin.read_line(&mut input).expect("Failed to read line");
    let numbers: Vec<i32> = input
        .trim()
        .split_whitespace()
        .map(|s| s.parse().expect("Expected an integer"))
        .collect();
    for num in numbers {
        write!(stdout, "{} ", num).expect("Failed to write");
    }
    writeln!(stdout).expect("Failed to write newline");
}
```

- `BufWriter` buffers output, reducing system calls.
- The `input` buffer is reused to minimize allocations.

#### 4. Reading Whole Lines (Including Spaces)

To read a line that may contain spaces (e.g., `"hello world"`), use `read_line`:

```rust
use std::io::{self, BufRead};

fn main() {
    let mut s = String::new();
    io::stdin()
        .lock()
        .read_line(&mut s)
        .expect("Failed to read line");
    let s = s.trim(); // Remove trailing newline
    // Use s
}
```

- `read_line` captures the entire line, including spaces, into `s`.
- `trim()` removes the trailing newline for clean processing.

#### 5. Reading Unknown Amounts of Data

For problems with an unknown number of input elements, iterate over input until it’s exhausted:

```rust
use std::io::{self, BufRead};

fn main() {
    let stdin = io::stdin().lock();
    for line in stdin.lines() {
        let line = line.expect("Failed to read line");
        for x in line.trim().split_whitespace() {
            let num: i32 = x.parse().expect("Expected an integer");
            // Process num
        }
    }
}
```

- `lines()` reads until EOF (e.g., Ctrl+D or Ctrl+Z).
- `split_whitespace()` processes each token within a line.
- This is ideal for inputs with varying sizes.

For token-based reading across lines:

```rust
use std::io::{self, BufRead};

fn main() {
    let stdin = io::stdin().lock();
    let mut tokens = stdin
        .lines()
        .flat_map(|line| line.unwrap().split_whitespace().map(String::from).collect::<Vec<_>>())
        .collect::<Vec<_>>()
        .into_iter();
    while let Some(x) = tokens.next() {
        let num: i32 = x.parse().expect("Expected an integer");
        // Process num
    }
}
```

- `flat_map` creates a single iterator over all tokens, regardless of line boundaries.

#### 6. File-Based Input and Output

Some contest systems use files for input and output. Rust supports this with `std::fs::File` and buffered I/O:

```rust
use std::fs::File;
use std::io::{self, BufRead, BufReader, BufWriter, Write};

fn main() {
    // Read from input.txt
    let input_file = File::open("input.txt").expect("Failed to open input.txt");
    let mut input = BufReader::new(input_file);

    // Write to output.txt
    let output_file = File::create("output.txt").expect("Failed to create output.txt");
    let mut output = BufWriter::new(output_file);

    // Example: Read and write
    let mut line = String::new();
    input.read_line(&mut line).expect("Failed to read line");
    let numbers: Vec<i32> = line
        .trim()
        .split_whitespace()
        .map(|s| s.parse().expect("Expected an integer"))
        .collect();
    for num in numbers {
        write!(output, "{} ", num).expect("Failed to write");
    }
    writeln!(output).expect("Failed to write newline");
}
```

- `BufReader` and `BufWriter` ensure efficient file I/O.
- `File::open` and `File::create` redirect input from `input.txt` and output to `output.txt`.

#### 7. Additional Notes

- **Error Handling**: Competitive programming often assumes valid input, so `unwrap` and `expect` are used for simplicity. In production, you’d use `Result` for robust error handling.
- **Performance**: For very large inputs, libraries like `byteorder` or `fast_io` (via `cargo`) can further optimize parsing, but `std::io` is usually sufficient.
- **Newline Control**: `writeln!` adds newlines efficiently; use `write!` and `flush()` for interactive problems requiring immediate output.

#### Example: Complete Template for a Problem

A template for a problem with multiple test cases:

```rust
use std::io::{self, BufRead, BufWriter, StdoutLock, Write};

fn solve_case(stdin: &mut impl BufRead, stdout: &mut BufWriter<StdoutLock>) {
    let mut line = String::new();
    stdin.read_line(&mut line).expect("Failed to read line");
    let numbers: Vec<i32> = line
        .trim()
        .split_whitespace()
        .map(|s| s.parse().expect("Expected an integer"))
        .collect();
    let result = numbers.iter().sum::<i32>(); // Example: sum numbers
    writeln!(stdout, "{}", result).expect("Failed to write");
}

fn main() {
    let mut stdin = io::stdin().lock();
    let stdout = io::stdout();
    let mut stdout = BufWriter::new(stdout.lock());
    let mut line = String::new();
    stdin.read_line(&mut line).expect("Failed to read line");
    let t: i32 = line.trim().parse().expect("Expected an integer");
    for _ in 0..t {
        solve_case(&mut stdin, &mut stdout);
    }
}
```

- Reads the number of test cases (`t`), then processes each case with optimized I/O.
- Uses `BufWriter` for output efficiency and reuses `line` for input.

Rust’s I/O for competitive programming is efficient and safe, using `std::io` with `BufRead` and `Write` for standard streams, `read_line` for whole lines, and `BufReader`/`BufWriter` for file I/O. Buffered I/O and reusable buffers optimize performance, while explicit parsing ensures correctness. This approach handles all common competitive programming I/O patterns, from fixed inputs to dynamic data and file-based systems.
