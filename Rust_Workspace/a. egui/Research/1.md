To master `egui`, you need to move from "placing buttons" to "understanding the immediate mode loop." Here is a structured roadmap designed to take you from a beginner to a proficient developer.

### 🗺️ Phase 1: The Foundation (Days 1-3)

**Goal:** Get a window open and understand how to display data.

1. **Setup the "Official" Way:**
    
    - Don't start from scratch. Clone the [eframe_template](https://github.com/emilk/eframe_template).
        
    - Run it (`cargo run`) and try to change the text in the window.
        
    - **Why?** `eframe` handles all the hard stuff (opening windows, handling OS events) so you can focus on the UI code.
        
2. **Learn the "Big Three" Widgets:**
    
    - **Label:** Display text.
        
    - **Button:** distinct interaction (`if ui.button("Click me").clicked() {... }`).
        
    - **TextEdit:** modifying a string (`ui.text_edit_singleline(&mut self.name)`).
        
3. **Understand State:**
    
    - Create a struct `MyApp` with a simple integer field (e.g., `count: i32`).
        
    - Make a button that adds +1 to `count`.
        
    - **Crucial Lesson:** Notice you don't need to tell the label to update. You just change the variable, and the UI updates automatically next frame.
        

**✅ Checkpoint Project:** **Counter App** (A standard counter with + and - buttons).

---

### 🗺️ Phase 2: The Architect (Days 4-7)

**Goal:** Stop putting everything in one long vertical list. Learn to organize space.

1. **Master Panels:**
    
    - Learn the difference between `CentralPanel` (the main workspace), `SidePanel` (toolbars), and `TopBottomPanel` (menus).
        
    - **Rule:** Always add `CentralPanel` last. It takes up whatever space is left.
        
2. **Containers and Layouts:**
    
    - **`ui.horizontal(|ui| {... })`:** Put buttons side-by-side.
        
    - **`ui.group(|ui| {... })`:** Visually group related items with a border.
        
    - **`Grid`:** Create a simple form (Label on left, Textbox on right) using `egui::Grid`.
        
3. **Windows:**
    
    - Use `egui::Window::new("Settings").show(ctx,...)` to create floating, draggable windows inside your app.
        

**✅ Checkpoint Project:** **Unit Converter.** A window with two text boxes and a dropdown. Typing in one box instantly updates the other (e.g., Meters to Feet).

---

### 🗺️ Phase 3: The Artist (Week 2)

**Goal:** Make it look good and create things that standard widgets can't do.

1. **Styling (The Easy Way):**
    
    - Use `ctx.set_visuals(Visuals::dark())` or `Visuals::light()`.
        
    - Try modifying `ctx.style_mut()` to change spacing or button rounding.
        
2. **The Painter (Custom Drawing):**
    
    - Don't just use widgets. Access `ui.painter()`.
        
    - Draw a red circle (`painter.circle_filled(...)`).
        
    - Draw a line connecting two widgets.
        
    - **Concept:** Learning that widgets and drawings share the same space.
        
3. **Interactivity without Widgets:**
    
    - Use `ui.allocate_response` to reserve empty space, then check if that empty space was clicked.
        
    - Draw a shape in that space that changes color when hovered. This is how you build **Custom Widgets**.
        

**✅ Checkpoint Project:** **Paint App.** A canvas where you can click and drag to draw lines or place rectangles.

---

### 🗺️ Phase 4: The Engineer (Week 3)

**Goal:** Handle complex data and slow tasks without freezing the UI.

1. **Memory & Persistence:**
    
    - Enable the `persistence` feature in `eframe`.
        
    - Make your app remember the user's input even after they close and reopen it.
        
2. **The Blocking Problem:**
    
    - Add a button that "Sleeps" for 2 seconds. Notice how the **entire window freezes**.
        
    - **The Fix:** Learn to use `std::thread` or channels (`std::sync::mpsc`).
        
    - Spawn a thread to do the work, and have the UI check for the result every frame.
        
3. **IDs:**
    
    - Create a loop that generates 10 buttons.
        
    - Use `ui.push_id` to ensure they don't conflict.
        

**✅ Checkpoint Project:** **File Downloader.** A button that starts a "fake download" (a sleep timer in a background thread) and a progress bar that updates smoothly while the download happens.

---

### 🗺️ Phase 5: The Integrator (Expert Level)

**Goal:** Put `egui` where it usually doesn't belong.

1. **Game Engine Integration:**
    
    - Try `bevy_egui`. Put a UI window on top of a 3D game scene.
        
2. **WGPU / Glow:**
    
    - Try to render a raw 3D triangle inside an `egui` image area. This is how tools like CAD software are built.

2. **Read code here:** [egui_demo_lib](https://github.com/emilk/egui/tree/master/crates/egui_demo_lib). This is the "Bible" of examples. If you want to know how to do a specific widget, find it in the demo and read the code.
    
3. **Watch this:** There are several YouTube tutorials on "Rust egui eframe" that walk through setting up a To-Do list.
    
4. **Reference:** Keep the [docs.rs/egui](https://docs.rs/egui) page open. Specifically, look at `egui::Ui` (where all the widget functions are).
