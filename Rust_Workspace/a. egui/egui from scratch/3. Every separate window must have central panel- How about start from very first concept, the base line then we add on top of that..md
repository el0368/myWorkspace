Yes, let's strip everything away. Forget buttons, forget fonts. Let's look at the **Skeleton** of the application.

To answer your question: **Yes, the main window MUST have a `CentralPanel` (or purely custom painting), otherwise the screen is effectively invisible.**

Here is the "Base Line" concept, layer by layer.

### Layer 1: The Void (The OS Window)

When you run your Rust code, `eframe` (the framework) opens a generic window on your operating system (Windows/Mac/Linux).

- **Keyword:** `eframe::App`
    
- **What it is:** The physical container.
    
- **Status:** It is empty.
    

### Layer 2: The "Space Eaters" (The Panels)

This is the most important concept in `egui` layout. You must imagine the window as a delicious cake. Every time you add a Panel, you **cut a slice** off the cake.

**The Order Matters:**

1. **`SidePanel` / `TopBottomPanel`**: These are the greedy ones. They take their slice _first_.
    
2. **`CentralPanel`**: This is the "Leftover" manager. It takes **whatever is left**.
    

**If you do not add a `CentralPanel`**, the "leftover" space is never drawn. It remains transparent or glitchy.

### Layer 3: The Code Structure

Here is the **exact** base line code. This is the template you should start every project with.

Read the comments carefully—they explain the "Space Eating" logic.

Rust

```
impl eframe::App for MyApp {
    fn update(&mut self, ctx: &egui::Context, _frame: &mut eframe::Frame) {
        
        // --- STEP 1: The Side Panel (The Menu) ---
        // We add this FIRST. 
        // It "eats" a slice of the screen on the LEFT.
        egui::SidePanel::left("my_left_panel").show(ctx, |ui| {
            ui.label("I took the left side!");
        });

        // --- STEP 2: The Top Panel (The Header) ---
        // We add this SECOND.
        // It looks at what space is remaining, and "eats" a slice off the TOP.
        egui::TopBottomPanel::top("my_top_panel").show(ctx, |ui| {
            ui.label("I took the top!");
        });

        // --- STEP 3: The Central Panel (The Canvas) ---
        // We add this LAST.
        // It takes EVERYTHING that is left over.
        // This is where your charts and main data go.
        egui::CentralPanel::default().show(ctx, |ui| {
            ui.label("I am the rest of the screen.");
        });
        
    }
}
```

### The "Floating Window" Exception

You asked: _"Every separate window must have central panel?"_

There is a difference between the **OS Window** and a **Floating Window**.

1. **The OS Window (The App):** YES. It needs the `CentralPanel` to define the background.
    
2. **A Floating Window (`egui::Window`):** NO.
    
    - **Keyword:** `egui::Window`
        
    - **Concept:** This is a popup (like a "Settings" box) that floats _above_ the other panels. It does not "eat" space. It floats on top of the cake.
        

### Summary of Keywords for the "Base Line"

|**Keyword**|**Philosophy**|**The Rule**|
|---|---|---|
|**`Context` (`ctx`)**|The Brain|Passed to every panel so they know where to draw.|
|**`SidePanel`**|The Space Eater|Reduces the available area for the rest of the app.|
|**`CentralPanel`**|The Background|**Must be called last.** Fills the remaining void.|
|**`Window`**|The Overlay|Floats on top. Does not affect the layout of panels.|

### Your Mental Check

When you read the code or the docs, ask yourself:

"Am I carving out a slice of the screen (Panel), or am I filling the hole that is left (CentralPanel)?"
