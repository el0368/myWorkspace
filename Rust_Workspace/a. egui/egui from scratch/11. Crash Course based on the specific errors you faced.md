### 1. The "Silent Killer" (Committing the `target` Folder)

- **The Symptom:** GitHub rejects your push with `File size limit exceeded (134 MB)`.
    
- **The Cause:** You committed the compiled binary files (`target/`) because your `.gitignore` was missing or broken.
    
- **The Fix:** You must tell Git to **stop tracking** the folder, but **keep the files** on your disk.
    

**Emergency Command Sequence:**

Bash

```
# 1. Create the shield (Use Git Bash to avoid encoding errors)
echo "target/" > .gitignore

# 2. Remove the heavy folder from Git's brain (Safe! Does not delete files)
git rm -r --cached target

# 3. Save the cleanup
git add .
git commit -m "Fix: Stop tracking target folder"
git push
```

### 2. The "Inception" (Nested Git Repositories)

- **The Symptom:** `fatal: 'apps/main_terminal/' does not have a commit checked out`.
    
- **The Cause:** You ran `cargo new main_terminal` inside a folder that was _already_ a Git repo. Rust automatically created a second hidden `.git` folder inside the sub-project, confusing Git.
    
- **The Fix:** You must destroy the inner `.git` folders so the root Git controls everything.
    

**Emergency Command Sequence:**

Bash

```
# 1. Delete the hidden .git folder in the sub-project
rm -rf apps/main_terminal/.git

# 2. Tell Git to forget the "Submodule" reference
git rm --cached apps/main_terminal

# 3. Add the files normally
git add .
```

### 3. The "Ghost Address" (Repository Not Found)

- **The Symptom:** `remote: Repository not found.`
    
- **The Cause:**
    
    1. You didn't actually create the repo on the GitHub website yet.
        
    2. **OR:** You created a **Private** repo, and your computer isn't logged in, so GitHub pretends it doesn't exist (security feature).
        
- **The Fix:** Create the repo online first. Then force a login.
    

**Emergency Command Sequence:**

Bash

```
# 1. Check where you are pushing
git remote -v

# 2. If wrong, fix it
git remote set-url origin https://github.com/YOUR_NAME/REPO_NAME.git

# 3. Push (This triggers the Login Popup on Windows)
git push -u origin main
```

### 4. The "Zombie Lock" (OS Error 32)

- **The Symptom:** `error: process cannot access the file ... because it is being used by another process.`
    
- **The Cause:** You tried to compile the code (`cargo check`) while the app was arguably still running in another window, or VS Code was locking the file.
    
- **The Fix:** Kill the process.
    

**Emergency Command Sequence:**

Bash

```
# 1. Close the window running your app.

# 2. If it still fails, NUKE the build folder (Forces a fresh start)
cargo clean

# 3. Rebuild
cargo run -p main_terminal
```

### 5. The "Identity Theft" (Duplicate Package Names)

- **The Symptom:** `error: two packages named 'main_terminal' in this workspace`.
    
- **The Cause:** You copy-pasted `Cargo.toml` from the Main App into a Library (`stock_scanner`) but forgot to change the `name = "..."` line.
    
- **The Fix:** Every `Cargo.toml` must have a unique name.
    

The Fix:

Open libs/stock_scanner/Cargo.toml and ensure:

Ini, TOML

```
[package]
name = "stock_scanner" # <--- CHECK THIS LINE
```
