The short answer is **YES, but it is not automatic.**

`egui_tiles` does not have a "magic switch" to do this. You have to build the mechanism yourself using **`egui::Viewport`**.

Here is the breakdown of the engineering reality behind what you are asking.

### 1. The Technology: Viewports vs. Tiles

You need to understand the difference between the "Layout" and the "Window".

- **`egui_tiles` (The Furniture):** It organizes things inside _one room_. It knows how to split a rectangle into smaller rectangles.
    
- **`egui::Viewport` (The House):** This creates a new native OS window (the thing you can drag to a second monitor).
    

To achieve your goal (VS Code style detachment):

You must write code that says: "When I drag this Tab out, DELETE it from Tree A (Main Window) and CREATE a new Tree B inside a new Viewport (Floating Window)."

### 2. Can you have two detached windows side-by-side?

Yes.

Once you detach a tab into a Viewport, it becomes a regular Windows/Mac/Linux window. The OS manages it. You can snap it, maximize it, or put two of them side-by-side on your second monitor. egui handles the rendering for all of them.

### 3. The "State" Problem (The Hard Part)

This is why I warned you about complexity.

- **Scenario:** You have a Scanner running in the Main Window.
    
- **Action:** You detach it to a Floating Window.
    
- **The Code Challenge:** You cannot just "move" the pixel graphics. You have to move the **Data Ownership**.
    
    - If your `ScannerState` is owned by the `MainWindow` struct, the new window cannot access it.
        
    - **Solution:** You must use Shared State (`Arc<Mutex<AppState>>`). Both the Main Window and the Floating Window must point to the same data in memory.
