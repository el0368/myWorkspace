### Architecture-Dependent Integers: `usize` and `isize` 🖥️

Unlike fixed-size integers (`i32`, `u64`, etc.), **`usize`** and **`isize`** are special integer types whose size in memory depends on the architecture of the computer compiling the code.

- **`usize`**: An **unsigned** integer type (can only be 0 or positive).1
    
- **`isize`**: A **signed** integer type (can be negative, 0, or positive).2
    

---

### How They Work: An Alias System

These types are not fundamentally new; they are **aliases** (or nicknames) for an existing fixed-size integer type. The specific type they alias to is chosen to match the system's native pointer size, which is the most efficient size for memory-related operations.

- On a **32-bit** system:
    
    - `usize` is an alias for `u32`.
        
    - `isize` is an alias for `i32`.
        
- On a **64-bit** system (most modern computers):
    
    - `usize` is an alias for `u64`.
        
    - `isize` is an alias for `i64`.
        

This system allows you to write portable code that is automatically optimized for the target machine's memory architecture.

---

### Practical Use Case and Example

The primary use for `usize` is for indexing into collections like arrays and vectors.3 The number of items you can have in a collection is limited by the amount of memory your computer can address, which is exactly what `usize` is designed to represent.

Rust

```Rust
fn main() {
    // On a 64-bit machine, `item_count` is effectively a u64.
    // On a 32-bit machine, it would be a u32.
    let item_count: usize = 500;

    // `offset` can be positive or negative, so isize is appropriate.
    // On a 64-bit machine, this is effectively an i64.
    let offset: isize = -10;

    println!("There are {} items.", item_count);
    println!("The offset is {}.", offset);
}
```
