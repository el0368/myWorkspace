## Rust Control Flow: The `match` Statement (Exhaustive Pattern Matching)

This study guide introduces the `match` statement in Rust, a powerful control flow construct for handling multiple possible variants of a value. It's Rust's primary mechanism for exhaustive pattern matching and a more robust alternative to chained `if-else if` statements for specific scenarios.

### I. Understanding the `match` Statement

What is the match statement?

The match statement is Rust's equivalent of switch or switch-case statements found in other programming languages. It allows you to:

1. Take a value.
    
2. Compare that value against **multiple possible patterns (variants)**.
    
3. Execute a specific block of code (or produce a value) for the _first_ pattern that matches the given value.
    

**What is the purpose of `match`?**

- **Handle Multiple Variants:** It enables reacting to all possible forms a value can take.
    
- **Consolidate Conditionals:** It provides a cleaner, more concise syntactic structure for handling many `if-else if` statements, especially when dealing with a single value that has several distinct possibilities.
    
- **Exhaustive Checking:** This is its most powerful feature. The Rust compiler _guarantees_ that you have covered **every possible variant** (all possibilities) of the value you are matching against. If you miss a case, the code will not compile.
    

**Syntax of a `match` statement:**

Rust

```Rust
match value_to_match {
    pattern1 => {
        // Code to run if value_to_match matches pattern1
    },
    pattern2 => {
        // Code to run if value_to_match matches pattern2
    },
    // ... more patterns ...
    _ => { // The 'catch-all' pattern (explained later)
        // Code to run if value_to_match doesn't match any previous pattern
    },
}
```

- `match`: The keyword to start the match statement.
    
- `value_to_match`: The expression or variable whose value you want to compare against various patterns. This can be almost any type (Boolean, integer, character, enum, tuple, etc.).
    
- `{}`: Curly braces that define the body of the `match` statement, containing its "arms."
    
- **Patterns / Arms:** Each `pattern => { block_of_code }` (or `pattern => value`) is called an "arm" or a "match arm."
    
    - `pattern`: A specific value or structure to compare `value_to_match` against.
        
    - `=>`: The "rocket" or "fat arrow" syntax, separating the pattern from its associated code.
        
    - `{ block_of_code }`: The code block to execute if the `value_to_match` successfully matches the `pattern`. (Can be omitted if the arm just returns a single value).

### II. Exhaustiveness and Compiler Guarantees

What does "exhaustive check" mean for match?

Rust's compiler performs an exhaustive check to ensure that every possible value or variant that the value_to_match could take is covered by at least one pattern (arm) in your match statement.

What happens if I don't cover all possibilities?

The code will fail to compile. Rust will issue a compiler error (e.g., "missing match arm: false not covered" for a Boolean). This is a strong safety guarantee that forces you to handle all potential scenarios, preventing unexpected runtime behavior.

**Example: `match` with a Boolean**

A `bool` is a great starting example because it has a finite and small set of possibilities: `true` or `false`.

Rust

```Rust
fn main() {
    let evaluation = true; // Dynamically calculated boolean in a real scenario

    match evaluation {
        true => { // Pattern for when evaluation is true
            println!("The value is true.");
        },
        false => { // Pattern for when evaluation is false
            println!("The value is false.");
        },
        // If 'false' arm was omitted, compiler error: "missing match arm: `false` not covered"
    }

    // Output if evaluation is true: The value is true.
    // Output if evaluation is false: The value is false.
}
```

Comparison to if-else if:

While an if-else if chain can achieve similar logic, it does not force exhaustiveness. You, the developer, must remember to add all else ifs and the final else. match provides this guarantee automatically, reducing potential bugs.

### III. `match` as an Expression (Returning Values)

Can match statements return a value?

Yes! Like if-else expressions, an entire match statement can evaluate to a single value, which can then be assigned to a variable.

**How does `match` return a value?**

- Each arm (`pattern => ...`) within the `match` statement must end with an **expression (without a semicolon)** if that arm is intended to return a value.
    
- **Crucial Rule:** All arms of a `match` expression **must return a value of the same type**. The compiler will enforce this for type safety.
    
- If an arm's body is a simple expression, you can often omit the curly braces for that arm.
    

**Example: Mapping Boolean to Integer Value**

Rust

```Rust
fn main() {
    let evaluation = false; // Try changing to `true`

    let mapped_value = match evaluation { // The entire match block evaluates to a value
        true => 20,  // Maps 'true' to 20. No curly braces needed for single expression.
        false => 40, // Maps 'false' to 40.
    }; // Semicolon needed here because it's part of a `let` statement

    println!("The mapped value is: {}", mapped_value); // Output: The mapped value is: 40 (if evaluation is false)
                                                       // Output: The mapped value is: 20 (if evaluation is true)
}
```

**Important Note on Commas:**

- When match arms are structured with blocks (`pattern => { block }`), commas between arms are _not_ required (but sometimes used for consistency).
    
- When match arms directly return single values/expressions without blocks (`pattern => value`), **commas between arms ARE required** to separate them.
    
    Rust
    
    ```Rust
    match evaluation {
        true => 20, // Comma required
        false => 40,
    };
    ```

### IV. Key Takeaways

- **`match` Statement:** Rust's powerful construct for reacting to multiple possible variants of a value. Similar to `switch-case`.
    
- **Exhaustiveness:** The compiler guarantees that all possible variants of the matched value are covered by an arm. This prevents unhandled cases and runtime errors.
    
- **Patterns/Arms:** Each `pattern => code/value` pair within the `match` block.
    
- **Value Matching:** `match` looks for the first arm whose pattern matches the value being evaluated.
    
- **`match` as Expression:** The entire `match` statement can return a value, which can be assigned to a variable.
    
- **Type Consistency:** All arms of a `match` expression must return the same type.
    
- **No Ternary Operator:** Rust uses `if-else` as an expression (which can be concise on one line) or `match` for conditional assignments, replacing the ternary operator of other languages.
    
- **Versatility:** `match` can work with many data types (Booleans, integers, characters) and is especially powerful with enums (which will be covered later).
