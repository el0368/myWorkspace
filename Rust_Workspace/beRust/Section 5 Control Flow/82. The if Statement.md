## Rust Control Flow: Introduction to `if` Statements

### 1. What is Control Flow?

- **Definition:** Control flow refers to the **order in which a program's instructions are executed**. It dictates the path that the program's logic will take.
    
- **Default Execution:** So far, our Rust programs have executed **line by line, from top to bottom**, resulting in consistent, predictable output every time.
    
- **Purpose of Control Flow Constructs:** The power of programming lies in the ability to **alter or control this default execution path**. We use specific constructs (like `if` statements) to introduce **conditional logic**, allowing programs to have different "branches" or "pathways" of execution based on whether certain criteria are met.
    

Analogy:

Imagine a GPS.

- **Default Flow:** "Go straight for 5 miles, then turn left." (Always the same path).
    
- **Control Flow:** "If there's heavy traffic on Highway 1, then take the scenic route; otherwise, stay on Highway 1." (The path changes based on a condition).
    

### 2. Conditional Code: The "If" Logic

- **Definition:** Conditional code is code that will **execute only if a specific condition is met** (if something "holds true" or a "criteria is satisfied").
    
- **Real-world Example (from transcript): The Pause Button**
    
    - **Logic:** "Start playing the video. **If** the user presses the Pause button, **then** pause the video."
        
    - The act of pausing is _conditional_; it only happens if the "user presses Pause" condition is true. The video doesn't pause automatically.
        

### 3. The `if` Statement

The `if` statement is the most fundamental control flow construct, allowing you to execute a block of code conditionally.

- **Syntax:**
    
    Rust
    
    ```Rust
    if boolean_condition {
        // Code to execute if the boolean_condition is true
    }
    ```
    
    - `if`: The keyword that begins the conditional statement.
        
    - `boolean_condition`: A value or an expression that **must evaluate to a `bool`** (`true` or `false`).
        
    - `{}`: A code **block** containing the instructions that will be executed _only if_ the `boolean_condition` is `true`.
        
- **No Parentheses Needed:** Unlike many other programming languages (e.g., C, Java, JavaScript), **Rust does NOT require or recommend wrapping the boolean condition in parentheses**. The compiler will actually warn you if you include them, as it considers them redundant.
    
    Rust
    
    ```Rust
    // Correct Rust syntax:
    if true {
        // ...
    }
    
    // Incorrect (but common in other languages), will cause a warning in Rust:
    // if (true) {
    //     // ...
    // }
    ```
    
- **Indentation:** When you enter an `if` block (or any nested block), it is standard Rust practice to **indent the code one level further** (typically 4 spaces) for readability. This visually indicates that the code belongs to that specific block.
    

**Example 1: Basic `if` Statements (Hard-coded Booleans)**

Rust

```Rust
fn main() {
    println!("Program start.");

    // This block WILL execute because the condition is true
    if true {
        println!("This line is from the first 'if' block.");
        println!("It will always be output because the condition is hard-coded true.");
    }

    // This block will NOT execute because the condition is false
    if false {
        println!("This line is from the second 'if' block.");
        println!("You will never see this line.");
    }

    println!("Program end.");
}
```

**Output:**

```Rust
Program start.
This line is from the first 'if' block.
It will always be output because the condition is hard-coded true.
Program end.
```

### 4. Dynamic Conditions (Variables and Expressions)

While using hard-coded `true` or `false` demonstrates the concept, in real-world programs, the `boolean_condition` is almost always **dynamic** (unpredictable in advance) and can vary each time the program runs.

- The condition can be:
    
    - A `bool` variable.
        
    - Any expression that **evaluates to a `bool`**. This includes:
        
        - Comparison operations (e.g., `x > y`, `age <= 18`).
            
        - Equality/Inequality checks (e.g., `name == "Alice"`, `status != "inactive"`).
            
        - Logical operations (e.g., `is_admin && has_permission`, `is_guest || has_invitation`).
            
        - Function calls that return a `bool`.
            

**Example 2: Dynamic `if` Condition with a Variable**

Rust

```Rust
fn main() {
    let user_is_premium = true; // This value could come from a database, user input, etc.
    let current_balance = 500;
    let required_balance = 100;

    println!("Checking user access...");

    // Using a boolean variable as the condition
    if user_is_premium {
        println!("Welcome, premium user! Access granted to exclusive content.");
    }

    // Using a comparison expression as the condition
    if current_balance >= required_balance {
        println!("You have sufficient funds for the transaction.");
    }

    let is_weekday = true;
    let hour = 9;

    // Combining multiple conditions with logical operators
    if is_weekday && hour >= 9 && hour <= 17 {
        println!("It's working hours!");
    }
}
```

### 5. Strict Boolean Requirement (No "Truthiness")

- **Rust is Strict:** A very important characteristic of Rust's `if` statements is their **strict requirement that the condition _must_ be a `bool` type**.
    
- **No "Truthiness":** Unlike some other programming languages (e.g., Python, JavaScript, Ruby, C/C++ often treat non-zero integers as `true` and zero as `false`), Rust has **no concept of "truthiness" or "falsiness."**
    
- **Compile-time Error:** If you try to use any non-boolean value (like an integer, string, or float) directly as an `if` condition, your program will **fail to compile** with a "mismatched types" error.
    

**Example of What NOT to Do (and why it fails in Rust):**

Rust

```Rust
fn main() {
    // let number = 5;
    // if number { // ERROR: expected `bool`, found integer
    //     println!("This would be 'truthy' in some languages.");
    // }

    // let text = "hello";
    // if text { // ERROR: expected `bool`, found `&str`
    //     println!("This would be 'truthy' in some languages.");
    // }
}
```

### 6. Key Takeaways

- **Control Flow:** Dictates the execution order of a program.
    
- **Conditional Code:** Executes only when a specific condition is `true`.
    
- **`if` Statement:** The core construct for conditional execution.
    
    - Syntax: `if condition { /* ... */ }`
        
    - Condition **must be a `bool`**.
        
    - **No parentheses** around the condition.
        
    - Code inside the block executes only if the condition is `true`.
        
- **Dynamic Conditions:** In real programs, `if` conditions usually come from variables or expressions that evaluate to a `bool`.
    
- **Strictness:** Rust does not have "truthiness"; `if` conditions _must_ be `true` or `false`.
