### **Building Projects with Cargo**

While `rustc` compiles a single file, **`cargo build`** is the command used to compile an entire Rust project, including all its source files and external library crates (dependencies). The executable's name is taken from the `name` field in the `Cargo.toml` file.

A shortcut for `cargo build` is **`cargo b`**. Cargo is efficient and will not recompile the project if no code has changed since the last build.

---

### **Build Modes: Debug vs. Release 🧑‍💻**

Cargo can build a project in one of two modes:

- **Debug Mode (Default)**
    
    - **Purpose:** Used during development for finding and fixing errors ("debugging").
        
    - **Speed:** Compilation is **fast**.
        
    - **Optimization:** The code is **unoptimized** for runtime performance.
        
    - **Features:** It includes extra **debugging metadata** in the executable, which helps developers find bugs but results in a larger file size.
        
- **Release Mode 🚀**
    
    - **Purpose:** Used for creating the final, production-ready application to be distributed to users.
        
    - **Speed:** Compilation takes **longer**.
        
    - **Optimization:** The code is **highly optimized** for runtime performance.
        
    - **Features:** It strips out all debugging metadata, resulting in a much smaller and faster executable.
        

---

### **Commands and Output Locations**

The compiled executables are placed inside the **`target/`** directory.

- **Debug Build**
    
    - **Command:** `cargo build` (or `cargo b`)
        
    - **Output Location:** The executable is placed in the `target/debug/` directory.
        
- **Release Build**
    
    - **Command:** `cargo build --release`
        
    - **Details:** The **`--release`** flag tells Cargo to perform an optimized release build.
        
    - **Output Location:** The executable is placed in the `target/release/` directory.
        
- **Cleaning the Build 🧹**
    
    - **Command:** `cargo clean`
        
    - **Action:** This command deletes the entire `target/` directory, removing all previously compiled executables. This is useful for guaranteeing a fresh compilation from scratch.
        

---

### **Running the Executable**

You can run the compiled program directly from your terminal by specifying its path.

- **On macOS/Linux:**
    
    Bash
    
    ```
    # Run the debug build
    ./target/debug/hello_world
    
    # Run the release build
    ./target/release/hello_world
    ```
    
- **On Windows:**
    
    PowerShell
    
    ```
    # Run the debug build
    .\target\debug\hello_world.exe
    
    # Run the release build
    .\target\release\hello_world.exe
    ```
