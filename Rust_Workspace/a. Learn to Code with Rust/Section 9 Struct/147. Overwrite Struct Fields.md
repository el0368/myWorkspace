### In-Depth Study Guide: Overwriting Struct Fields

This guide explains the rules and syntax for modifying the values of fields within a struct instance, and the ownership implications of doing so.

---

### 1. The Core Rule: Mutability is "All or Nothing"

In Rust, mutability is a property of the **binding** (the variable), not of the individual fields within a struct. This leads to a simple but strict "all or nothing" rule:

> To change the value of _any_ field in a struct instance, the entire instance must be declared as **mutable** using `let mut`.

You cannot make some fields of an instance mutable while others are immutable. The mutability applies to the entire instance as a whole.

It's also important to distinguish between the struct _definition_ and an _instance_:

- **Definition (`struct Coffee { ... }`):** This is the blueprint. It has no concept of mutability.
    
- **Instance (`let beverage = ...`):** This is the concrete value created from the blueprint. It is at this point that you decide if the instance is mutable (`let mut`) or immutable (`let`).
    

---

### 2. The Syntax for Overwriting Fields

Once an instance is declared as mutable, you can overwrite the value of any of its fields using dot notation and the standard assignment operator (`=`).

- **Syntax:** `instance_name.field_name = new_value;`
    

#### Example from the Transcript

Rust

```Rust
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    // 1. The instance MUST be declared with `let mut`.
    let mut beverage = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: false,
    };

    println!(
        "Original: A {} that costs ${} (hot? {}).",
        beverage.name, beverage.price, beverage.is_hot
    );

    // 2. Overwrite field values using dot notation and assignment.
    beverage.name = String::from("Caramel Macchiato");
    beverage.price = 6.99;
    beverage.is_hot = true;

    println!(
        "Updated: A {} that costs ${} (hot? {}).",
        beverage.name, beverage.price, beverage.is_hot
    );
}
```

### 3. Ownership and Dropping (In-depth Detail)

When you overwrite a field, Rust's ownership system ensures memory is handled safely. The behavior differs slightly depending on whether the field's type is `Copy`.

- **Overwriting `Copy` Types (e.g., `price: f64`, `is_hot: bool`):** These values live entirely on the stack. When you assign a new value, the old bits in memory are simply replaced by the new ones. This is a very fast and simple operation.
    
- **Overwriting Non-`Copy` Types (e.g., `name: String`):** This is a more involved process. A `String` owns data on the heap. When you overwrite the `name` field:
    
    1. A new `String` (e.g., "Caramel Macchiato") is created, allocating new memory on the heap.
        
    2. The `name` field of the `beverage` struct takes ownership of this new `String`.
        
    3. The _original_ `String` data ("Mocha") that the `name` field previously owned is now unowned.
        
    4. Rust immediately **drops** the old "Mocha" `String`, automatically deallocating its memory from the heap.
        

This process guarantees that there are no memory leaks. The old data is cleaned up safely the moment the field takes ownership of the new data.

---

### Key Takeaways

- To modify any field of a struct, the entire instance must be declared with `let mut`.
    
- You cannot have partially mutable struct instances.
    
- Use dot notation and the assignment operator (`=`) to change a field's value.
    
- When a field that owns heap data (like a `String`) is overwritten, Rust automatically drops the old value, preventing memory leaks.
