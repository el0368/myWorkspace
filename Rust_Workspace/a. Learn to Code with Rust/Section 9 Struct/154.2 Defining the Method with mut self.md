### Part 2: Defining the Method with `mut self`

This study guide explains the syntax and purpose of defining a method that takes **mutable ownership** of a struct instance, which is necessary for a method to modify its fields.

#### 1. The Syntax of `mut self`

When a method needs to modify the struct instance it is called on, its `self` parameter must be declared as mutable.

- **Syntax:** The `mut` keyword is placed directly before `self` in the method signature.
    
    Rust
    
    ```
    fn method_name(mut self) { ... }
    ```
    
- **Breakdown:**
    
    - `mut`: The keyword that grants permission to **mutate** the struct's fields.
        
    - `self`: The parameter name that represents the struct instance itself.
        
- **Type Annotation:** As with other `self` options, you can use explicit type annotations, but they are not required. `mut self` is a shorthand for `mut self: Self`, where `Self` is the type alias for the struct.
    

#### 2. Behavior and Permissions

A method with a `mut self` parameter has two key behaviors:

- **Ownership Transfer:** The method takes **full ownership** of the struct instance. Ownership is **moved** from the variable used in the method call to the `self` parameter. This means the original variable becomes invalid.
    
- **Mutation Permission:** The `mut` keyword gives the method body explicit permission to **modify** or overwrite the struct's fields. This allows for operations like `self.field = new_value;` which are not possible with an immutable `self`.
    

#### 3. Code Example: `double_length` Method

Rust

```Rust
// The struct blueprint
#[derive(Debug)]
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

impl TaylorSwiftSong {
    // This `mut self` signature takes MUTABLE OWNERSHIP.
    // It is a valid definition for a method that needs to modify a field.
    fn double_length(mut self) {
        // The `self` parameter is now mutable, so we can modify its fields.
        self.duration_secs = self.duration_secs * 2;
        
        // We can print the updated struct to verify the change.
        // `self` is the owner, so we can print the whole struct.
        println!("\nUpdated struct from within method: {:#?}", self);
        
        // This method does not return `self`, so the struct is consumed.
    }
}

fn main() {
    let song = TaylorSwiftSong {
        title: String::from("Blank Space"),
        release_year: 2014,
        duration_secs: 231,
    };

    println!("Original song from main: {:#?}", song);
    
    // Invoking the method on `song`.
    // Ownership of `song` is MOVED to the `mut self` parameter.
    // The `song` variable in `main` becomes invalid after this call.
    song.double_length();
    
    // The following line would result in a compile-time error:
    // println!("Original song after call: {:#?}", song);
}
```

**Output of the `double_length` method call:**

```Rust
Original song from main: TaylorSwiftSong {
    title: "Blank Space",
    release_year: 2014,
    duration_secs: 231,
}

Updated struct from within method: TaylorSwiftSong {
    title: "Blank Space",
    release_year: 2014,
    duration_secs: 462,
}
```
