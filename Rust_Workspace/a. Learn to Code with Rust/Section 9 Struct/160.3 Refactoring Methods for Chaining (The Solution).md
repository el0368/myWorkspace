
### Part 3: Refactoring Methods for Chaining (The Solution)

This study guide explains the core refactoring required to enable the **Builder Pattern** in Rust: modifying methods to return a mutable reference to `self`.

#### 1. The Goal: Enabling Method Chaining

The reason our methods in the previous lesson were not chainable is that they returned nothing (`()`). To enable chaining, each method must return a value that can be used to call the next method in the sequence.

- **The Solution:** For methods that modify a struct in place, the idiomatic and efficient solution is to have them **return a mutable reference to the instance itself**. This is the key that enables the Builder Pattern in Rust.
    
- **Why `&mut self`?** Returning a mutable reference (`&mut self`) allows the next method to be called on the _same instance_ and still have permission to modify it. This avoids the inconvenience of taking and returning ownership and is very memory-efficient.
    

#### 2. The Refactoring Process

Refactoring a method to be chainable involves two simple steps:

1. **Update the Return Type:** Add `-> &mut Self` (or `-> &mut Computer`) to the method's function signature.
    
2. **Add a Return Value:** Add `self` as the last expression in the method's body, without a semicolon. This implicitly returns the mutable reference to the instance.
    

#### Code Example (The Refactored `impl` Block)

This refactored implementation block is the key component of the Builder Pattern. The `main` function will be able to chain these methods together because of these changes.


```Rust
#[derive(Debug)]
struct Computer {
    cpu: String,
    memory: u32,
    hard_drive_capacity: u32,
}

impl Computer {
    fn new(cpu: String, memory: u32, hard_drive_capacity: u32) -> Self {
        Self { cpu, memory, hard_drive_capacity }
    }
    
    // REFACTORED METHOD: Now returns a mutable reference to itself (`&mut Self`).
    fn upgrade_cpu(&mut self, new_cpu: String) -> &mut Self {
        self.cpu = new_cpu; // Modifies the instance in place.
        self // The mutable reference is returned, without a semicolon.
    }
    
    // REFACTORED METHOD: Returns a mutable reference for chaining.
    fn upgrade_memory(&mut self, new_memory: u32) -> &mut Self {
        self.memory = new_memory;
        self // The mutable reference is returned.
    }
    
    // REFACTORED METHOD: Returns a mutable reference for chaining.
    fn upgrade_hard_drive_capacity(&mut self, new_capacity: u32) -> &mut Self {
        self.hard_drive_capacity = new_capacity;
        self // The mutable reference is returned.
    }
}

// The `main` function (to be shown in Part 4) can now use these methods in a chain.
```
