## **Key Concepts:**

**1. Return Ownership**

```rust
fn create_point() -> Point {
    Point { x: 10, y: 20 }  // Ownership moves to caller
}
```

No, **"caller"** means the **code that called the function**, not the struct itself.

```rust
fn create_point() -> Point {
    Point { x: 10, y: 20 }  // Ownership moves to caller
}

fn main() {
    let my_point = create_point(); // <- main() is the CALLER
    //  ^^^^^^^^
    //  Ownership moves HERE (to the caller)
}
```

**Ownership flow:**

1. `create_point()` creates the struct
2. Struct ownership moves to **`main()`** (the caller)
3. `main()` stores it in variable `my_point`

**"Caller"** = whoever called the function, **not** the struct.

**2. Local Creation**

```rust
fn process() {
    let local_struct = Point { x: 1, y: 2 };
    // local_struct dropped when function ends
}
```

**3. Constructor Pattern**

```rust
fn new_person(name: String) -> Person {
    Person { name, age: 0 }  // Common pattern for struct creation
}
```

**4. Ownership Flow**

- Struct created **inside function** → owned by function
- Struct **returned** from function → ownership **moves to caller**
- Local structs **automatically dropped** when function ends

**5. With Heap Data**

- `String` parameters get **moved into** the struct
- Function creates struct, **transfers ownership** to caller
- No memory leaks - clear ownership chain

Functions are perfect for **constructor-like patterns** and **factory methods**!

```rust
#[derive(Debug)]
struct Point {
    x: i32,
    y: i32,
}

#[derive(Debug)]
struct Person {
    name: String,
    age: u32,
}

// 1. Function RETURNS a struct (moves ownership to caller)
fn create_point(x: i32, y: i32) -> Point {
    Point { x, y }  // Create and return - ownership moves to caller
}

// 2. Function creates struct with heap data
fn create_person(name: String, age: u32) -> Person {
    Person { name, age }  // Moves ownership of String to struct, then to caller
}

// 3. Function creates and processes struct locally
fn process_local_struct() {
    let local_point = Point { x: 10, y: 20 };
    println!("Local struct: {:?}", local_point);
    // local_point is dropped when function ends
}

// 4. Function takes parameters and creates struct
fn make_origin() -> Point {
    Point { x: 0, y: 0 }  // Create struct with literal values
}

fn main() {
    // Calling functions that create structs
    
    // Function returns struct - ownership transfers to caller
    let my_point = create_point(5, 15);
    println!("Created point: {:?}", my_point);
    
    // Function with heap-allocated data
    let my_person = create_person(String::from("Alice"), 25);
    println!("Created person: {:?}", my_person);
    
    // Local struct creation and destruction
    process_local_struct();
    
    // Simple constructor-like function
    let origin = make_origin();
    println!("Origin: {:?}", origin);
    
    // Multiple struct creation
    let points = vec![
        create_point(1, 2),
        create_point(3, 4),
        make_origin(),
    ];
    println!("Points: {:?}", points);
}
```

## **Struct in Function Rules:**

**1. Creation & Ownership**

- Functions can create structs locally
- Returning a struct **moves ownership** to caller
- Local structs are **dropped** when function ends

**2. Constructor Pattern**

```rust
fn make_struct(params) -> StructType {
    StructType { fields }  // Create and return
}
```

**3. Scope Rules**

- Struct **definition** must be in scope (global or imported)
- Functions can access struct definitions from outer scopes

**4. Ownership Flow**

- Parameters → Function → Struct → Caller
- Clear ownership chain, no dangling references

**5. Memory Management**

- **Returned structs**: Caller owns, caller drops
- **Local structs**: Function drops automatically
- **Heap data** (like String): Moves with the struct

**6. Common Patterns**

- **Factory functions**: Create structs with logic
- **Constructors**: Simple struct creation
- **Processors**: Create, use, and drop locally

**Bottom line**: Functions are **struct factories** - they create, own briefly, then transfer ownership to whoever needs it.
