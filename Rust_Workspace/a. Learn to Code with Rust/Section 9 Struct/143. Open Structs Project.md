### Topics Covered in this Section

- **Defining a Struct**:
    
    - **What is a Struct?**: A container for related data used to model complex, real-world types.
        
    - **Named-Field Structs**: The most common type, with fields assigned a name and a type.
        
    - **Tuple Structs**: Fields are accessed by their position/index, not by name.
        
    - **Unit-Like Structs**: Structs that have no fields and represent a type without associated data.
        
    - Using the `struct` keyword and PascalCase for naming.
        
- **Instantiating a Struct**:
    
    - Creating a concrete instance from the struct's blueprint.
        
    - **Field Init Shorthand**: A shortcut to simplify `field: value` syntax when the variable name matches the field name.
        
    - **Struct Update Syntax (`..`)**: A shortcut to copy fields from another struct instance, noting that ownership rules apply.
        
- **Struct Behavior and Traits**:
    
    - **Deriving the `Debug` Trait**: Using the `#[derive(Debug)]` attribute to automatically implement the `Debug` trait for printing the struct's contents.
        
    - Understanding that structs do not implement the `Copy` trait by default.
        
- **Working with Structs**:
    
    - **The `impl` Block**: A block of code used to define methods and associated functions for a struct.
        
    - **Methods**:
        
        - A function that belongs to a struct instance.
            
        - The `self` keyword as the first parameter, representing the instance.
            
        - **Four Variations on `self`**:
            
            1. **Owned (`self`)**: Takes ownership of the struct.
                
            2. **Mutable Owned (`mut self`)**: Takes ownership and allows mutation.
                
            3. **Immutable Reference (`&self`)**: Borrows the struct without taking ownership, allowing read-only access.
                
            4. **Mutable Reference (`&mut self`)**: Borrows the struct mutably, allowing for modifications without taking ownership.
                
    - **Associated Functions**:
        
        - Functions within the `impl` block that don't take `self` as a parameter.
            
        - Accessed using the double-colon syntax (`StructName::function_name`).
            
        - **Constructor Functions**: A common use case for associated functions, often named `new`.
            
- **The Builder Pattern**: A pattern used to construct structs with many optional fields, often leveraging associated functions.
