## Rust Structs & Functions: Passing Structs by Value and by Reference

This study guide explores the four primary ways you can pass a `struct` instance to a function in Rust, clarifying how each method affects ownership, mutability, and the validity of the original variable.

### I. The Four Ways to Pass a Struct as a Function Parameter

A struct is a composite value that contains multiple pieces of data. When you pass it to a function, you are essentially determining how that function should handle this bundle of data and who should be responsible for it.

The four options are:

1. **Immutable Ownership:** Pass by value, immutably.
    
2. **Mutable Ownership:** Pass by value, mutably.
    
3. **Immutable Reference:** Pass by reference, immutably.
    
4. **Mutable Reference:** Pass by reference, mutably.
    

Each of these is a distinct parameter type, with different rules and use cases.

### 1. Immutable Ownership (Pass by Value)

- **Parameter Type:** `struct_name` (e.g., `Coffee`)
    
- **Behavior:** The function takes **full ownership** of the struct instance.
    
- **Ownership Flow:** Ownership is **moved** from the argument variable to the parameter.
    
- **Original Variable:** The original variable in the calling function becomes **invalid** and cannot be used after the function call.
    
- **Mutability:** The parameter is immutable by default, so you **cannot modify** the struct within the function body.
    
- **Use Case:** For functions that need to **consume** the struct and do not need to modify it.
    
    Rust
    
    ```Rust
    struct Coffee { name: String, price: f64 }
    fn drink_coffee(coffee: Coffee) { // Takes ownership (move)
        println!("Drinking my delicious {}", coffee.name);
        // The `coffee` parameter goes out of scope here, and the struct is deallocated.
    }
    fn main() {
        let mocha = Coffee { name: String::from("Mocha"), price: 4.99 }; // `mocha` is the owner
        drink_coffee(mocha); // Ownership of `mocha` MOVES to `coffee`. `mocha` is now invalid.
        // println!("Price: {}", mocha.price); // ERROR: borrow of moved value: `mocha`
    }
    ```
    

### 2. Mutable Ownership (Pass by Value)

- **Parameter Type:** `mut struct_name` (e.g., `mut Coffee`)
    
- **Behavior:** The function takes **full ownership** of the struct instance and is allowed to **modify** it.
    
- **Ownership Flow:** Ownership is **moved** from the argument variable to the parameter.
    
- **Original Variable:** The original variable in the calling function becomes **invalid**.
    
- **Mutability:** The `mut` keyword on the parameter gives permission to modify the struct's fields within the function body.
    
- **Use Case:** For functions that need to **consume** and **modify** the struct. If you want to use the modified struct afterwards, the function **must return** it. This can lead to the "return value bloat" problem.
    
    Rust
    
    ```Rust
    struct Coffee { name: String, price: f64 }
    fn brew_and_modify(mut coffee: Coffee) -> Coffee { // Takes ownership, returns ownership
        coffee.price = 5.99; // Mutation is allowed
        coffee.name.push_str(" (Strong)"); // Mutation is allowed
        coffee // Ownership is returned
    }
    fn main() {
        let mut mocha = Coffee { name: String::from("Mocha"), price: 4.99 }; // `mocha` must be `mut` for re-assignment
        mocha = brew_and_modify(mocha); // Ownership moves in, then returns back out.
        println!("New price: {}", mocha.price); // `mocha` is still valid.
    }
    ```
    

### 3. Immutable Reference (Pass by Immutable Reference)

- **Parameter Type:** `&struct_name` (e.g., `&Coffee`)
    
- **Behavior:** The function receives a **read-only reference** to the struct. This is a temporary **borrow**.
    
- **Ownership Flow:** **No ownership transfer occurs.** The original variable remains the owner.
    
- **Original Variable:** The original variable **remains valid** and fully usable after the function call.
    
- **Mutability:** The reference is immutable by default, so you **cannot modify** the struct within the function body.
    
- **Use Case:** This is the most common and idiomatic way to pass a struct for **read-only access**. It avoids moves and is highly efficient.
    
- **Implicit Dereferencing:** You can access the fields using dot notation (`.`) as if it were the struct instance itself; Rust automatically dereferences the reference behind the scenes for convenience.
    
    Rust
    
    ```Rust
    struct Coffee { name: String, price: f64 }
    fn print_coffee_details(coffee: &Coffee) { // Takes an immutable reference (borrow)
        // No ownership move, so `mocha` is not invalidated.
        println!("This coffee is {}, costing {}", coffee.name, coffee.price);
        // coffee.price = 10.99; // ERROR: cannot assign to a field of an immutable reference
    }
    fn main() {
        let mocha = Coffee { name: String::from("Mocha"), price: 4.99 };
        print_coffee_details(&mocha); // Pass a reference.
        println!("Mocha is still valid: {}", mocha.name); // `mocha` is still valid.
    }
    ```
    

### 4. Mutable Reference (Pass by Mutable Reference)

- **Parameter Type:** `&mut struct_name` (e.g., `&mut Coffee`)
    
- **Behavior:** The function receives an **exclusive, mutable reference** to the struct. This is a temporary **mutable borrow**.
    
- **Ownership Flow:** **No ownership transfer occurs.** The original variable remains the owner.
    
- **Original Variable:** The original variable **remains valid** but **must be declared `mut`** to allow a mutable reference to be created from it. The owner cannot be used directly while the mutable borrow is active.
    
- **Mutability:** The `&mut` keyword gives permission to **modify** the struct's fields within the function body.
    
- **Use Case:** This is the most common and idiomatic way to pass a struct for **read-write access**. It allows a function to modify a struct in place without taking ownership.
    
    Rust
    
    ```Rust
    struct Coffee { name: String, price: f64 }
    fn update_price(coffee: &mut Coffee, new_price: f64) { // Takes a mutable reference
        coffee.price = new_price; // Mutation is allowed
        println!("New price is: {}", coffee.price);
    }
    fn main() {
        let mut mocha = Coffee { name: String::from("Mocha"), price: 4.99 }; // The owner must be mutable
        update_price(&mut mocha, 10.99); // Pass a mutable reference.
        println!("Mocha is still valid, and price is updated: {}", mocha.price); // Output: 10.99
    }
    ```
    

### Summary of Parameter Options

|Option|Parameter Type|Ownership Flow|Original Variable State|Mutability in Function|Use Case|
|---|---|---|---|---|---|
|**1. Immutable Owner**|`Coffee`|**Move**|Becomes **invalid**|**No** (read-only)|Consume the value|
|**2. Mutable Owner**|`mut Coffee`|**Move**|Becomes **invalid**|**Yes** (read-write)|Consume & modify the value|
|**3. Immutable Ref**|`&Coffee`|**Borrow**|**Remains valid**|**No** (read-only)|Read-only access (most common)|
|**4. Mutable Ref**|`&mut Coffee`|**Borrow**|**Remains valid** (`mut` req)|**Yes** (read-write)|Read-write access (most common)|

Choosing the correct parameter type is crucial for writing safe, idiomatic, and efficient Rust code that respects ownership and minimizes unnecessary data transfers.
