### Part 3: The `self` Parameter with References

This study guide focuses on the `self` parameter in a method definition when it receives a **reference** to the struct. This is the most common and idiomatic approach for methods that do not need to consume their struct.

#### 1. The Core Concept: Borrowing, Not Moving

When a method signature defines its first parameter as `&self` or `&mut self`, it means the method receives a **reference (a borrow)** to the struct instance, not the actual value.

- **No Ownership Transfer:** This is the key distinction from the ownership-based `self` options. The method **does not take ownership** of the struct. The original variable that was used to call the method **remains the owner** and stays valid after the method call.
    
- **Cleanup:** The `self` parameter (the reference) still goes out of scope at the end of the method, but it is only responsible for cleaning up its own small, stack-allocated reference value. It does **not** deallocate the underlying struct's memory.
    
- **Benefit:** This completely avoids the inconvenience of ownership moves, the need to `return` the struct from the function, and the invalidation of the original variable.
    

#### 2. Option 3: Immutable Reference (`&self`)

This is the most common method signature, used for methods that only need to read a struct's data.

- **Syntax:** `fn method_name(&self) { ... }`
    
- **Behavior:** The method gets an immutable reference. It can **read** the struct's fields, but it **cannot mutate or modify** them.
    
- **Consequence:** The original variable remains valid and can be used after the method call.
    
- **Implicit Dereferencing:** When you access a field using dot notation (`self.field_name`), Rust automatically **dereferences** the reference behind the scenes to access the value. This makes the code look identical to accessing a field on an owned instance, which is a great convenience.
    

#### 3. Option 4: Mutable Reference (`&mut self`)

This option is used for methods that need to modify a struct without taking ownership.

- **Syntax:** `fn method_name(&mut self) { ... }`
    
- **Behavior:** The method gets a mutable reference. It can **read** the struct's fields and **mutate** them.
    
- **Consequence:** The original variable **remains valid** but **must be mutable** (`let mut...`) to allow a mutable reference to be created from it. The changes made in the method are reflected in the original struct instance.
    

#### 4. Summary and Key Implications

- **Borrowing:** Both `&self` and `&mut self` represent a borrow, not a move.
    
- **Original Variable:** The original owner of the struct keeps its ownership and remains valid.
    
- **The "Loan":** `&self` is a shared, read-only loan. `&mut self` is an exclusive, read-write loan.
    
- **Flexibility:** Using references is the standard way to write methods, as it allows for clean, reusable code without the complexities of constantly managing ownership moves.
    

#### Example: `TaylorSwiftSong` Methods with References

Rust

```Rust
// The struct blueprint.
#[derive(Debug)]
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

impl TaylorSwiftSong {
    // Option 3: Immutable Reference (`&self`) - For reading only.
    fn display_song_info(&self) {
        println!("Title: {}", self.title);
        println!("Release Year: {}", self.release_year);
        println!("Duration: {} seconds", self.duration_secs);
        // self.title = String::from("New Title"); // ERROR: cannot modify a borrowed value
    }

    // Option 4: Mutable Reference (`&mut self`) - For reading and writing.
    fn change_duration(&mut self, new_duration: u32) {
        self.duration_secs = new_duration; // This is a valid mutation.
    }
}

fn main() {
    let mut song = TaylorSwiftSong {
        title: String::from("Blank Space"),
        release_year: 2014,
        duration_secs: 231,
    };

    // Calling `display_song_info`.
    // We pass an immutable reference (`&song`). Ownership of `song` is NOT moved.
    song.display_song_info();
    
    // `song` is still a valid owner and can be used afterward.
    println!("\nOriginal song is still here: {:#?}", song);
    
    // Calling `change_duration`.
    // We pass a mutable reference (`&mut song`). Ownership of `song` is NOT moved.
    song.change_duration(250);

    // `song` is still valid and its field has been modified.
    println!("\nSong after duration change: {:#?}", song);
}
```
