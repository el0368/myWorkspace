The three kinds of structs in Rust are:Here's a detailed breakdown of each type:

## 1. **Named-Field Struct** (Classic Struct)

```rust
struct Point { x: i32, y: i32 }
```

- **Most common and intuitive**
- Fields have both names and types
- Access fields with dot notation: `point.x`
- Best for complex data with meaningful field names
- Similar to structs/classes in other languages

## 2. **Tuple Struct**

```rust
struct Color(i32, i32, i32);
```

- **Hybrid between struct and tuple**
- Fields have types but no names
- Access fields by index: `color.0`, `color.1`, `color.2`
- Useful for:
    - **Simple data containers**: `Point3D(x, y, z)`
    - **"Newtype" pattern**: `UserId(u32)` to wrap primitives with type safety
    - **When field order is more important than names**

## 3. **Unit Struct**

```rust
struct Unit;
```

- **No fields at all**
- Zero-sized type (takes no memory)
- Useful for:
    - **Marker types**: Representing states or permissions
    - **Implementing traits without data**: Like error types or tokens
    - **Type-level programming**: Using types for compile-time logic

## When to Use Each Type?

**Named-Field Struct:**

- Complex data with meaningful field names
- When code readability is important
- Most general-purpose use cases

**Tuple Struct:**

- Simple data where position matters more than names
- Wrapping existing types for type safety
- Mathematical concepts (coordinates, colors, etc.)

**Unit Struct:**

- Markers or tokens
- Implementing traits without needing data
- Representing states in state machines
- Zero-cost abstractions

The named-field struct is indeed the most commonly used because it provides the best balance of clarity and functionality for most use cases!

```rust
#[derive(Debug)]
// 1. NAMED-FIELD STRUCT (Classic struct)
// Fields have names and types
struct Point {
    x: i32,
    y: i32,
}

#[derive(Debug)]
// 2. TUPLE STRUCT
// Fields have types but no names, accessed by position
struct Color(i32, i32, i32); // RGB values
struct Point3D(f64, f64, f64); // x, y, z coordinates

// 3. UNIT STRUCT
// No fields at all
struct Unit;
struct Marker;

fn main() {
    // 1. Named-field struct usage
    let point = Point { x: 10, y: 20 };
    println!("Named-field struct: {:?}", point);
    println!("Accessing fields: x={}, y={}", point.x, point.y);
    
    // 2. Tuple struct usage
    let red = Color(255, 0, 0);
    let origin = Point3D(0.0, 0.0, 0.0);
    println!("Tuple structs: {:?}, {:?}", red, origin);
    // Access fields by index (like tuples)
    println!("Red value: {}, Green value: {}, Blue value: {}", red.0, red.1, red.2);
    
    // 3. Unit struct usage
    let unit = Unit;
    let marker = Marker;
    println!("Unit structs: {:?}, {:?}", unit, marker);
    
    // Demonstrating different use cases:
    
    // Named-field: Best when field meaning is important
    let player = Player {
        name: String::from("Alice"),
        health: 100,
        level: 5,
    };
    
    // Tuple struct: Good for wrapping values or simple data
    let coordinates = Coordinates(10.5, 20.3);
    let user_id = UserId(12345); // "newtype" pattern
    
    // Unit struct: Used for markers, tokens, or zero-sized types
    let _file_marker = FileMarker; // Might represent file system permissions
    let _admin_token = AdminToken; // Might represent admin privileges
}

#[derive(Debug)]
struct Player {
    name: String,
    health: u32,
    level: u32,
}

#[derive(Debug)]
struct Coordinates(f64, f64);

#[derive(Debug)]
struct UserId(u32); // "Newtype" pattern - wraps a primitive type

#[derive(Debug)]
struct FileMarker;

#[derive(Debug)]
struct AdminToken;
```
