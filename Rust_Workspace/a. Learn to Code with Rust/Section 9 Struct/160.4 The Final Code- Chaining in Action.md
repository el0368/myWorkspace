
### Part 4: The Final Code: Chaining in Action

This study guide presents the final, refactored code for our `Computer` struct. With the methods now designed to return a mutable reference to `self`, we can implement the elegant, chainable syntax of the Builder Pattern.

#### 1. The Power of Method Chaining

The Builder Pattern's primary goal is to allow for **method chaining**. Because each `upgrade_...` method now returns a mutable reference to the `Computer` instance, you can immediately call the next method in a single expression.

- **Dereferencing:** Rust's dot operator (`.`) automatically **dereferences** the reference for you, allowing you to treat `&mut Computer` just like a `Computer` instance when calling its methods.
    
- **Original Variable:** The original `computer` variable remains the owner and is modified in place, so no ownership is moved, and no values are lost.
    

#### 2. The Final `main` Function Code

The `impl Computer` block from Part 3 (which contains the refactored, chainable methods) is required for this code to work.

Rust

```Rust
// The `impl` block with refactored methods from Part 3 is assumed to be defined.
// ...

fn main() {
    // We create the initial computer instance. It must be mutable to allow changes.
    let mut computer = Computer::new(String::from("M3 Max"), 64, 2);

    // This is the elegant, chainable syntax of the Builder Pattern.
    // Each method returns `&mut self`, allowing the next `.method()` call.
    computer.upgrade_cpu(String::from("M4 Max"))
            .upgrade_memory(128)
            .upgrade_hard_drive_capacity(4);

    // After the entire chain has run, we can verify the results.
    println!("Final computer stats: {:#?}", computer);
    // The pretty-print Debug formatter gives us a clean, readable output.
}
```

#### 3. Verification and Final Output

The `println!` statement at the end of the `main` function demonstrates that all three methods in the chain were executed successfully on the single `computer` instance. The final output shows that the fields have been updated with the new values provided as arguments to the chained methods.

**Output:**

```Rust
Final computer stats: Computer {
    cpu: "M4 Max",
    memory: 128,
    hard_drive_capacity: 4,
}
```

This output confirms that:

- The `upgrade_cpu` method changed the CPU from "M3 Max" to "M4 Max".
    
- The `upgrade_memory` method changed the memory from `64` to `128`.
    
- The `upgrade_hard_drive_capacity` method changed the hard drive capacity from `2` to `4`.
    

The Builder Pattern is a design choice that makes a sequence of modifications to a single instance both readable and concise. It's a hallmark of a fluent and well-designed API.
