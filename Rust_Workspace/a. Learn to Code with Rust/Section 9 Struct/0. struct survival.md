### Rust `struct` Survival Guide

In Rust, a `struct` (short for structure) is a fundamental data type that allows you to create custom types by grouping together related data. Unlike a class in an object-oriented language, a `struct` in Rust is primarily a data container. Behavior is attached to it separately.

To survive with Rust `structs`, you need to master these key concepts.

#### 1. Defining a `struct`

A `struct` is a blueprint for creating an object. It defines the names and types of all the fields it will contain.

- **Syntax:**
    
    Rust
    
    ```Rust
    struct User {
        username: String,
        email: String,
        sign_in_count: u64,
        active: bool,
    }
    ```
    
    - Fields can have different data types.
        
    - This is the most common type, known as a "classic" or "C-like" struct.
        

#### 2. Creating a `struct` Instance

To use a `struct`, you must create an instance of it.

- **Standard Instantiation:**
    
    Rust
    
    ```Rust
    let user1 = User {
        email: String::from("alice@example.com"),
        username: String::from("Alice"),
        active: true,
        sign_in_count: 1,
    };
    ```
    
    - The order of the fields doesn't matter, but you must provide a value for every field.
        
- **Shorthand Initialization:**
    
    Rust
    
    ```Rust
    let username = String::from("Bob");
    let email = String::from("bob@example.com");
    
    let user2 = User {
        email, // Shorthand for email: email,
        username, // Shorthand for username: username,
        active: false,
        sign_in_count: 5,
    };
    ```
    
    - This is a common shortcut when a variable name is the same as the struct field name.
        
- **Using the `..` Shorthand:**
    
    Rust
    
    ```Rust
    // Create a new user with most of the same data as user1
    let user3 = User {
        email: String::from("charlie@example.com"),
        username: String::from("Charlie"),
        ..user1 // Fills the remaining fields from user1
    };
    ```
    
    - This is a handy way to create new instances that are mostly copies of an existing one.
        

#### 3. Accessing and Mutating Data

- **Accessing a Field:** Use dot notation (`.`).
    
    Rust
    
    ```Rust
    let username = user1.username;
    println!("{}", username);
    ```
    
- **Mutating a Field:** The entire `struct` instance must be declared as `mut`.
    
    Rust
    
    ```Rust
    let mut user1 = User { /* ... */ };
    user1.active = false;
    ```
    
    - You cannot make individual fields mutable; the mutability is on the `struct` instance itself.
        

#### 4. Methods and Associated Functions (`impl`)

This is where you attach behavior to a `struct`. An `impl` block defines methods that operate on a `struct` and associated functions that are related to it but don't require an instance.

- **Syntax:**
    
    Rust
    
    ```Rust
    impl User {
        // This is a method. It takes a reference to `self`.
        fn get_email(&self) -> &str {
            &self.email
        }
    
        // This is an associated function. It doesn't take `self`.
        // It's often used as a constructor.
        fn build_user(email: String, username: String) -> User {
            User {
                email,
                username,
                active: true,
                sign_in_count: 1,
            }
        }
    }
    ```
    
- **Calling a Method:** Use dot notation on an instance.
    
    Rust
    
    ```Rust
    let email = user1.get_email();
    ```
    
- **Calling an Associated Function:** Use the double colon (`::`) on the `struct` name.
    
    Rust
    
    ```Rust
    let user4 = User::build_user(String::from("dave@example.com"), String::from("Dave"));
    ```
    

#### 5. Lifetimes and Ownership

This is a critical survival topic for `structs`. If a `struct` holds a reference to data owned elsewhere, you must specify its lifetime.

- **The Problem:** The Rust compiler needs to ensure that the data a `struct` is referencing doesn't get dropped before the `struct` itself.
    
- **The Solution:** You add a lifetime parameter (e.g., `'a`) to the `struct` definition.
    
    Rust
    
    ```Rust
    struct Article<'a> {
        title: &'a str,
        body: &'a str,
    }
    
    // Now, the compiler knows that the references inside Article
    // must live for at least as long as the Article instance.
    let title = String::from("My Title");
    let body = String::from("My Body");
    
    let my_article = Article {
        title: &title,
        body: &body,
    };
    ```
    
    - If you're holding owned data (e.g., `String`), you don't need a lifetime. This is the more common and often preferred approach.
        

#### 6. Other Types of `structs`

- **Tuple Structs:** Structs without named fields. They are useful for creating distinct types from tuples.
    
    Rust
    
    ```Rust
    struct Color(i32, i32, i32);
    let black = Color(0, 0, 0);
    ```
    
- **Unit-like Structs:** Structs with no fields. They are useful when you need to implement a trait on a type but don't need to store any data.
    
    Rust
    
    ```Rust
    struct AlwaysEqual;
    ```
    

#### 7. The `derive` Macro

The `derive` macro is a powerful tool for automatically implementing common traits on your `structs`, saving you from writing boilerplate code.

- **Common Traits:**
    
    - `Debug`: To print an instance for debugging purposes (`{:?}` or `{:#?}`).
        
    - `PartialEq`, `Eq`: For comparing two instances for equality (`==`).
        
    - `Clone`, `Copy`: For duplicating an instance.
        
    - `Default`: To create a default instance easily.
        
- **Syntax:**
    
    Rust
    
    ```Rust
    #[derive(Debug, PartialEq, Clone)]
    struct Article {
        title: String,
        body: String,
    }
    
    // Now we can print our struct easily
    let article1 = Article { /* ... */ };
    println!("{:#?}", article1);
    
    // And compare it
    let article2 = article1.clone();
    assert_eq!(article1, article2);
    ```
    

By internalizing these concepts, you'll be able to effectively model your data and attach logical behavior to it, which is the foundation of writing robust and idiomatic Rust code.
