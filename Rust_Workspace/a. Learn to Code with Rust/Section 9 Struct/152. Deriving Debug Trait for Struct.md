## Rust Structs: Deriving the `Debug` Trait

This study guide explains the concept of **deriving** traits in Rust, focusing on how to automatically implement the `Debug` trait for your custom `struct`s to enable convenient printing and debugging.

### I. Review: Traits, `Display`, and `Debug`

- **Traits as Contracts:** A trait is a formal contract that a type can agree to uphold. By implementing a trait, a type promises to provide a specific set of behaviors or methods.
    
- **`Display` Trait:** This trait's contract is to provide a **human-friendly, readable string representation** of a type. It is relied upon by `println!`'s standard curly braces (`{}`).
    
- **`Debug` Trait:** This trait's contract is to provide a **programmer-friendly, technical string representation** of a type for debugging purposes. It is relied upon by the `println!`'s `{:?}` and `{:#?}` format specifiers.
    
- **Default Status of Structs:** By default, a custom `struct` that you define **does not implement either the `Display` or the `Debug` trait**. Attempting to print a struct with `println!("{}")` or `println!("{:?}")` will result in a compile-time error.
    

### II. The `derive` Attribute: A Compiler Directive

What is the derive attribute?

The derive attribute is a compiler directive or compiler command that you add above a type definition (like a struct or enum). It's a form of metadata for the compiler, instructing it to automatically generate code for a specific trait implementation.

- **Syntax:** `#` followed by square brackets `[derive(...)]`.
    
- **Purpose:** It's a shortcut to get a standard, default implementation for a trait without having to manually write the implementation code yourself. The compiler "derives" or "infers" the correct implementation for you.
    

### III. Automatically Implementing `Debug` with `#[derive(Debug)]`

To make a struct printable for debugging, you use the `derive` attribute to automatically implement the `Debug` trait.

- **Syntax:** `#[derive(Debug)]` is placed on the line immediately above your `struct` definition.
    
- **Functionality:** This tells the compiler, "Please generate a default `Debug` trait implementation for this struct."
    
- **Default Implementation:** The default `Debug` string representation for a struct will include:
    
    - The struct's name.
        
    - Curly braces `{}`.
        
    - A list of all its fields, with each field name followed by its value.
        

**Example: Deriving `Debug` for a `Coffee` Struct**

Rust

```Rust
// Our struct blueprint. Note the `derive` attribute on the line above it.
#[derive(Debug)]
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // The following line will now compile because we have a Debug implementation:
    println!("Standard Debug: {:?}", mocha);
    // Output: Standard Debug: Coffee { name: "Mocha", price: 4.99, is_hot: true }

    // This line also works and provides a more readable output:
    println!("\nPretty-Printed Debug:\n{:#?}", mocha);
    // Output:
    // Pretty-Printed Debug:
    // Coffee {
    //     name: "Mocha",
    //     price: 4.99,
    //     is_hot: true,
    // }

    // This line still fails because we do not have a Display implementation:
    // println!("Display format: {}", mocha); // ERROR: the trait `Display` is not implemented for `Coffee`
}
```

### IV. Format Specifiers for `Debug`

To utilize the `Debug` trait for printing, you use a specific format specifier within the `println!` macro's curly braces.

- **Standard Debug:** `{:?}` (a colon `:` followed by a question mark `?`).
    
- **Pretty-Print Debug:** `{:#?}` (a colon `:` followed by a hash `#` and a question mark `?`). This is identical to the standard format but adds newlines and indentation for a more aesthetically pleasing output, which is especially useful for inspecting complex or nested structs.
    

### V. `Debug` as a Developer Tool

- The primary purpose of the `Debug` trait is for **debugging**. It gives developers a quick and easy way to inspect the state of a struct at a particular point in the program.
    
- The default derived implementation is perfect for this because it automatically shows you all the fields and their values without any extra code.
    
- The `dbg!` macro (covered earlier) also relies on the `Debug` trait to print its output.
    

### VI. `Copy` Trait and Structs

- It is important to note that **structs do not automatically implement the `Copy` trait** by default.
    
- This means that standard ownership rules apply: when a struct is assigned to another variable (`let new_struct = old_struct;`), ownership is **moved**, and the original variable becomes invalid. This is true even if the struct contains only `Copy` types.
    
- You can manually implement or `derive` the `Copy` trait for your struct, but only if all of its fields also implement `Copy`.
    
    Rust
    
    ```Rust
    // This struct can be derived as `Copy` because all its fields are `Copy`.
    #[derive(Debug, Copy, Clone)] // You derive `Copy` and `Clone` together.
    struct Point {
        x: i32,
        y: i32,
    }
    ```
    

### VII. Key Takeaways

- **Default Behavior:** Your custom structs do not implement `Display` or `Debug` by default, so they are not printable.
    
- **`#[derive(Debug)]`:** The simple, standard way to get a default `Debug` trait implementation so you can print your struct for debugging.
    
- **Debug Formatters:** Use `{:?}` or `{:#?}` with `println!` to print a `Debug`-derived struct.
    
- **`derive` Attribute:** A compiler directive (`#[]`) that automatically generates trait implementations for you.
    
- **`Debug` vs. `Display`:** `Debug` is for programmers; `Display` is for end-users. You typically implement `Debug` with `derive` and manually implement `Display` for custom, user-facing output.
    
- **Future Customization:** While the derived `Debug` is great, Rust allows you to define your own custom implementations of traits for more control.
