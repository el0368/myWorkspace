# Rust Generics - In-Depth Study Guide

## Core Concept: What Are Generics?

### Definition and Purpose

A generic is fundamentally a **type argument** - a placeholder that stands in for an actual type that will be determined later. Think of it as creating a template where specific types can be "filled in" when the code is actually used.

### The Parameter-Argument Analogy

Just as function parameters are placeholders for actual values that get passed in later:

```rust
fn add(x: i32, y: i32) -> i32 {  // x and y are parameter placeholders
    x + y
}
// Later called with: add(5, 3)  // 5 and 3 are the actual arguments
```

Generics work the same way but for types:

```rust
fn process<T>(value: T) -> T {    // T is a type parameter placeholder
    value
}
// Later called with: process(42)     // i32 substitutes for T
// Or called with: process("hello")   // &str substitutes for T
```

### Why Generics Enable Reusability

Without generics, you'd need separate functions for each type:

```rust
fn process_int(value: i32) -> i32 { value }
fn process_string(value: String) -> String { value }
fn process_bool(value: bool) -> bool { value }
// ... and so on for every type you want to support
```

With generics, one definition works for all types:

```rust
fn process<T>(value: T) -> T { value }
// Works with any type automatically
```

## Generic Syntax and Declaration

### Basic Syntax Structure

Generics are declared using angle brackets `<>` containing type parameter names:

```rust
<T>           // Single generic type
<T, U>        // Multiple generic types
<T, U, V>     // Even more generic types
```

### Naming Conventions

- **Single generic**: Use `T` (short for "Type")
- **Multiple generics**: Use short, descriptive names
    - `T`, `U`, `V` for arbitrary types
    - `K`, `V` for key-value pairs
    - More descriptive names like `Item`, `Error` when context helps

### Important Multiple Generic Behavior

Multiple generics **enable** different types but **don't require** them:

```rust
fn example<T, U>(first: T, second: U) {
    // T and U CAN be different types
    // But they CAN ALSO be the same type
}

// Valid calls:
example(42, "hello");        // T=i32, U=&str (different types)
example(42, 99);             // T=i32, U=i32 (same types)
example("hi", "bye");        // T=&str, U=&str (same types)
```

## Generic Usage in Different Contexts

### Function Definitions

**Basic Function with Generic Parameter:**

```rust
fn hold_value<T>(item: T) -> T {
    item  // Return the same value
}
```

**Multiple Parameters with Same Generic:**

```rust
fn compare_same<T>(first: T, second: T) -> T {
    // Compiler enforces both parameters are the same type
    // Return type must also be that same type
    first
}
```

**Mixed Generic and Concrete Types:**

```rust
fn process_with_count<T>(item: T, count: i32) -> (T, i32) {
    (item, count)  // T can vary, count is always i32
}
```

### Struct Definitions

**Single Field Generic Struct:**

```rust
struct Container<T> {
    value: T,
}

// Usage:
let int_container = Container { value: 42 };           // T = i32
let string_container = Container { value: "hello" };   // T = &str
```

**Multiple Fields with Same Generic:**

```rust
struct Pair<T> {
    first: T,
    second: T,  // Both fields must be the same type T
}

let numbers = Pair { first: 1, second: 2 };           // T = i32
let words = Pair { first: "hi", second: "bye" };      // T = &str
```

**Multiple Different Generics:**

```rust
struct KeyValue<K, V> {
    key: K,
    value: V,   // K and V can be different types
}

let entry = KeyValue { key: "name", value: 42 };      // K = &str, V = i32
```

### Enum Definitions

**Simple Generic Enum:**

```rust
enum Choice<T> {
    Left(T),
    Right(T),   // Both variants use the same generic type
}

let int_choice = Choice::Left(42);        // T = i32
let str_choice = Choice::Right("hello");  // T = &str
```

**Multiple Generics in Enum:**

```rust
enum Either<L, R> {
    Left(L),
    Right(R),   // Each variant can have different types
}

let mixed = Either::Left("text");         // L = &str
let other = Either::Right(42);            // R = i32
```

## Implementing Methods for Generic Types

### The Fundamental Challenge

When a struct uses generics, the generic becomes part of the struct's **type identity**. The compiler sees `Container<i32>` and `Container<String>` as completely different types.

### Two Approaches to Implementation

#### Approach 1: Methods for Specific Concrete Types

```rust
struct Container<T> {
    value: T,
}

impl Container<i32> {  // Methods ONLY for Container<i32>
    fn double_value(&self) -> i32 {
        self.value * 2  // Only works because we know T = i32
    }
}

// This method is NOT available for Container<String> or other types
```

#### Approach 2: Methods for Any Generic Type

```rust
struct Container<T> {
    value: T,
}

impl<T> Container<T> {  // Methods for Container<any_type>
    fn get_value(&self) -> &T {
        &self.value  // Works for any type T
    }
    
    fn replace_value(&mut self, new_value: T) {
        self.value = new_value;  // Works for any type T
    }
}
```

### The Critical Syntax Explanation

**Why we need `impl<T> Container<T>`:**

**Wrong approach (won't compile):**

```rust
impl Container<T> {  // ERROR: What is T?
    // Rust doesn't know what T means here
}
```

**Correct approach:**

```rust
impl<T> Container<T> {  // First <T> declares T as a generic
    // Now Rust knows T is a type parameter, not a concrete type name
}
```

### The Compiler's Perspective

When Rust sees `Container<T>` without the initial `<T>` declaration:

1. It looks for a concrete type named `T` in your program
2. It expects `T` to be the name of an actual struct, enum, or type alias
3. It doesn't recognize `T` as a generic placeholder

When Rust sees `impl<T> Container<T>`:

1. The first `<T>` says "I'm declaring a generic type parameter named T"
2. The second `T` in `Container<T>` refers back to that declared parameter
3. Now it understands this is a generic implementation

### Practical Method Examples

**Methods that work with any type:**

```rust
impl<T> Container<T> {
    fn new(value: T) -> Container<T> {
        Container { value }
    }
    
    fn is_empty(&self) -> bool {
        // This is conceptual - we can't actually check if T is "empty"
        // without additional trait bounds
        false
    }
}
```

**Methods with additional generic parameters:**

```rust
impl<T> Container<T> {
    fn map<U>(self, f: fn(T) -> U) -> Container<U> {
        Container { value: f(self.value) }
    }
}

// Usage:
let int_container = Container::new(42);
let string_container = int_container.map(|x| x.to_string());
// T = i32 becomes U = String
```

## Type Substitution and Compiler Validation

### How the Compiler Works with Generics

When you use a generic type, the compiler performs **monomorphization** - it creates separate copies of the code for each concrete type used:

```rust
fn print_twice<T: std::fmt::Display>(value: T) {
    println!("{}", value);
    println!("{}", value);
}

// When you call:
print_twice(42);      // Compiler generates print_twice_i32
print_twice("hello"); // Compiler generates print_twice_str
```

### Type Consistency Enforcement

Generics allow the compiler to enforce type relationships:

```rust
fn swap<T>(x: T, y: T) -> (T, T) {
    (y, x)  // Both parameters and both return values must be same type
}

// Valid:
let (a, b) = swap(1, 2);           // T = i32
let (c, d) = swap("hi", "bye");    // T = &str

// Invalid:
// let (e, f) = swap(1, "hello");  // ERROR: T can't be both i32 and &str
```

### Flexibility vs. Constraints

Generics provide a balance:

- **Flexibility**: Work with many different types
- **Constraints**: Maintain type safety and relationships
- **Reusability**: Write code once, use with multiple types

## Advanced Generic Patterns

### Generic Type Aliases

```rust
type Result<T> = std::result::Result<T, String>;  // Custom Result type
type Vector<T> = Vec<T>;                          // Simpler name for Vec
```

### Nested Generics

```rust
struct Wrapper<T> {
    items: Vec<T>,  // Vec itself is generic, containing T
}

let numbers: Wrapper<i32> = Wrapper { items: vec![1, 2, 3] };
// T = i32, so items is Vec<i32>
```

### Generic Bounds (Preview)

While not covered in detail in this section, generics often have constraints:

```rust
fn process<T: Clone>(value: T) -> T {  // T must implement Clone
    value.clone()
}
```

## Key Principles and Mental Models

### The "Template" Mental Model

Think of generics as creating templates:

- You write the template once
- The compiler fills in the blanks with actual types
- Each filled-in version is type-safe and optimized

### Generic vs. Concrete Thinking

- **Concrete thinking**: "This function works with integers"
- **Generic thinking**: "This function works with any type that has these properties"

### Reusability Through Abstraction

Generics let you abstract over types while maintaining all of Rust's safety guarantees. You get the benefits of code reuse without sacrificing performance or type safety.

### The Power of Constraints

Even though this section focuses on basic generics, remember that generic types can have bounds and constraints that make them even more powerful and safe to use.
