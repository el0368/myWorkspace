## Rust Structs: Methods with Multiple Parameters

This study guide explains how to define and use struct methods that accept additional parameters beyond the mandatory `self` parameter. It clarifies the syntax for declaring these parameters and for passing the corresponding arguments during invocation.

### I. Methods with Parameters: The `self` and Beyond

- **Mandatory `self`:** A method must always accept some form of `self` (`self`, `&self`, `&mut self`) as its **first parameter**. This parameter gives the method access to the instance on which it was called.
    
- **Additional Parameters:** Methods can define any number of additional parameters after `self`, just like a regular function. These parameters represent custom inputs needed for the method's logic.
    
- **Order of Parameters:** The `self` parameter always comes first in the method signature, followed by any other parameters you define.
    

**Syntax of a Method with Multiple Parameters:**

Rust

```Rust
impl StructName {
    fn method_with_params(&self, param1: Type1, param2: Type2) -> ReturnType {
        // ... method body using self, param1, and param2 ...
    }
}
```

### II. Example: The `is_longer_than` Method

Let's define a method on the `TaylorSwiftSong` struct that compares the duration of one song to another.

Rust

```Rust
#[derive(Debug)]
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

impl TaylorSwiftSong {
    // This method takes an immutable reference `&self` as its first parameter.
    // It also takes a second parameter `other`, which is an immutable reference
    // to another `TaylorSwiftSong` instance.
    fn is_longer_than(&self, other: &TaylorSwiftSong) -> bool {
        // We compare the `duration_secs` field of the song we are on (`self`)
        // with the `duration_secs` field of the song being passed in (`other`).
        self.duration_secs > other.duration_secs
    }
}
```

**Key Points from this Example:**

- **`self` Parameter (`&self`):** Represents the song on which the method is called. It's an immutable reference because the method only reads its duration and does not modify it.
    
- **Additional Parameter (`other: &TaylorSwiftSong`):** This is the input for the second song. It's also an immutable reference to avoid moving ownership of the second song.
    
- **Return Value:** The method returns a `bool` based on the comparison of the two durations.
    

### III. Invoking Methods with Additional Arguments

When you invoke a method that has additional parameters, you must provide the corresponding arguments in the correct order.

- **No `self` Argument:** You **do not** provide an argument for the `self` parameter. Rust automatically handles passing the correct instance or reference.
    
- **Custom Arguments:** You **must provide arguments** for every other parameter that is defined in the method signature.
    
- **Type Matching:** The arguments must match the type of the parameters defined in the method signature. For a parameter that expects a reference (e.g., `&TaylorSwiftSong`), you must pass a reference (e.g., `&another_song`) as the argument.
    

**Example Invocation:**

Rust

```Rust
fn main() {
    let blank_space = TaylorSwiftSong {
        title: String::from("Blank Space"),
        release_year: 2014,
        duration_secs: 231,
    };

    let all_too_well = TaylorSwiftSong {
        title: String::from("All Too Well"),
        release_year: 2012,
        duration_secs: 327,
    };

    // We invoke `is_longer_than` on the `blank_space` instance.
    // `blank_space` is passed automatically as `self`.
    // We provide `&all_too_well` as the argument for the `other` parameter.
    if blank_space.is_longer_than(&all_too_well) {
        println!("{} is longer than {}", blank_space.title, all_too_well.title);
    } else {
        println!("{} is shorter than or equal to {}", blank_space.title, all_too_well.title);
    }
}
```

**Execution Flow of the Example:**

1. `blank_space.is_longer_than(&all_too_well)` is called.
    
2. Rust automatically passes `&blank_space` as the `self` parameter.
    
3. The argument `&all_too_well` is passed as the `other` parameter.
    
4. Inside the method, `self.duration_secs` (231) is compared to `other.duration_secs` (327).
    
5. `231 > 327` evaluates to `false`.
    
6. The `if` statement's condition is false, so the `else` block is executed.
    
7. The output is: `Blank Space is shorter than or equal to All Too Well`.
    

### IV. Key Takeaways

- **Method Parameters:** Methods can accept additional parameters just like regular functions, but they must always come **after** the `self` parameter.
    
- **`self` is Implicit:** Rust automatically passes the instance as the `self` argument. You only provide arguments for the custom parameters.
    
- **Flexibility with References:** Using references for additional parameters (e.g., `&TaylorSwiftSong`) is the standard practice. It avoids the complexities of ownership moves and allows the original argument variables to remain valid and usable.
    
- **Accessing Data:** The dot notation (`.`) works on `self` and any other struct parameters to access their fields. The compiler automatically dereferences references for you.
    
- **Consistent Interface:** Defining methods with parameters creates a consistent, reusable blueprint for how all instances of that struct type can interact with other instances of the same type.
    
- **Type Aliases:** You can use a reference to `Self` (`&Self`) as a type annotation for a parameter to make the code more resilient to a change in the struct's name.
