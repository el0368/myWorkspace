### Part 1: The Enum Blueprint & `impl` Block Setup

This progressive example starts by defining an enum with three different variant types (unit, tuple, and struct variants). It then sets up an `impl` block, which is the container for methods that will be associated with this enum type.

- **Method Definition:** A method is a function that belongs to a type. The syntax to define methods for an enum is identical to that of a struct: using an `impl` block.
    
- **`self` Parameter:** The first parameter, `self`, represents the instance on which the method is called. For our `wash_laundry` method, we will use an immutable reference (`&self`) to avoid taking ownership of the enum instance.
    
- **The Code:** This part shows the enum and the `impl` block setup.

```Rust

#[derive(Debug)]
enum LaundryCycle {
    Cold,                          // Unit variant (no associated data)
    Hot { temperature: u32 },      // Struct variant (named data)
    Delicate(String),              // Tuple variant (positional data)
}

// The `impl` block for our `LaundryCycle` enum, where methods will be defined.

    // The method definition will go here.
    // It will take `&self` to borrow the enum instance.
}
```

### Part 2: Defining the Method and its `match` Logic

This part shows the core logic of the enum method. The method uses a `match self` expression to handle each variant. The syntax for the `match` arms correctly pattern matches the variants' associated data, which are provided as references.

- **`match self`:** The `match` expression operates on `self` (the instance) to determine which variant it is.
    
- **Reference to Associated Data:** Because the `self` parameter is a reference (`&self`), Rust automatically provides references to the associated data inside the `match` arms. For a `u32` (a `Copy` type), this is implicitly handled. For a `String`, the pattern must match an `&String`, but the `&String` can be implicitly "deref-coerced" to `&str`. The code will often show `String` in the pattern, but the compiler handles the details for you.
    
- **The Code:** This example shows the `impl` block with the `wash_laundry` method's complete logic.
    

Rust

```Rust
// Our enum from Part 1.
#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

impl LaundryCycle {
    // A method that borrows the enum instance immutably.
    fn wash_laundry(&self) {
        match self { // Match on the `self` parameter (the enum instance).
            LaundryCycle::Cold => {
                println!("Running the laundry with cold temperature.");
            },
            // The pattern `Hot { temperature }` binds the `temperature` field.
            // Rust implicitly handles the reference to the `u32`.
            LaundryCycle::Hot { temperature } => {
                println!("Running the laundry with a temperature of {}.", temperature);
            },
            // The pattern `Delicate(fabric_type)` binds the `String` data.
            // `fabric_type` here is a reference to the `String` (`&String` or `&str`).
            LaundryCycle::Delicate(fabric_type) => {
                println!("Running the laundry with a delicate cycle for {}.", fabric_type);
            },
        }
    }
}

fn main() {
    // The instantiation and invocation will be in the final part.
}
```

### Part 3: Invoking the Enum Method

This final part shows how to call the `wash_laundry` method on different instances of the `LaundryCycle` enum.

- **Dot Notation:** Methods are invoked using dot notation (`.`) on an instance of the enum.
    
- **Implicit `self`:** The enum instance (`cold_cycle`, `hot_cycle`, etc.) is automatically provided as the `self` argument.
    
- **Final Result:** The program will execute the logic of the method three times, with the `match` statement choosing a different arm for each variant and printing the corresponding message.
    

Rust

```Rust
// Our final enum and method definition from Part 2.
#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

impl LaundryCycle {
    fn wash_laundry(&self) {
        match self {
            LaundryCycle::Cold => {
                println!("Running the laundry with cold temperature.");
            },
            LaundryCycle::Hot { temperature } => {
                println!("Running the laundry with a temperature of {}.", temperature);
            },
            LaundryCycle::Delicate(fabric_type) => {
                println!("Running the laundry with a delicate cycle for {}.", fabric_type);
            },
        }
    }
}

fn main() {
    // 1. Create instances of each variant.
    let cold_cycle = LaundryCycle::Cold;
    let hot_cycle = LaundryCycle::Hot { temperature: 100 };
    let delicate_cycle = LaundryCycle::Delicate(String::from("silk"));

    // 2. Invoke the method on each instance using dot notation.
    println!("--- Running Laundry Cycles ---");
    
    // Calls `wash_laundry` on the `Cold` variant.
    cold_cycle.wash_laundry();

    // Calls `wash_laundry` on the `Hot` variant.
    hot_cycle.wash_laundry();

    // Calls `wash_laundry` on the `Delicate` variant.
    delicate_cycle.wash_laundry();
}
```
