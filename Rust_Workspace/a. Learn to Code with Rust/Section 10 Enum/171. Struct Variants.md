### Part 1: The Problem and the "Workaround"

This progressive example starts by showing the problem of tuple variants—their associated data lacks descriptive names. It then demonstrates a verbose but valid workaround by defining a separate struct and storing an instance of that struct inside the enum variant.

- **The Problem:** A tuple variant like `PayPal(String, String)` lacks clarity. A reader can't tell what the two `String`s represent just from the enum definition.
    
- **The Workaround:** A separate `Credentials` struct is used to provide names (`username`, `password`) to the data. This struct is then wrapped inside the `PayPal` enum variant.
    

Rust

```Rust
// The "workaround" struct to provide names for the data.
#[derive(Debug)]
struct Credentials {
    username: String,
    password: String,
}

// Enum using a tuple variant that stores the separate struct.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String),
    DebitCard(String),
    PayPal(Credentials), // Stores one value: a `Credentials` struct.
}

fn main() {
    // 1. Create the `Credentials` struct instance first.
    let paypal_credentials = Credentials {
        username: String::from("bob@gmail.com"),
        password: String::from("password"),
    };
    
    // 2. Pass the struct instance as the associated data for the enum variant.
    // This is still a tuple variant, so it uses parentheses `()`.
    let paypal = PaymentMethodType::PayPal(paypal_credentials);
    
    println!("PayPal variant with a separate struct: {:#?}", paypal);
}
```

### Part 2: The Direct Solution - Struct Variants

This part introduces the idiomatic Rust solution for the problem from Part 1. We refactor the enum definition to use the **struct variant** syntax, which embeds a named-field struct directly within the enum variant itself. This eliminates the need for the separate `Credentials` struct.

- **Struct Variant Syntax:** Instead of parentheses `()` for a tuple variant, you use curly braces `{}` and define named fields, just like a regular `struct`.
    
- **The Advantage:** The data is now self-documenting and intrinsically linked to the enum variant, making the code more concise and easier to understand.
    

Rust

```Rust
// The enum definition is refactored to use a struct variant for PayPal.
// Note the curly braces `{}`.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String), // Tuple variant
    DebitCard(String),  // Tuple variant
    PayPal {            // Struct variant
        username: String,
        password: String,
    },
}

fn main() {
    // The separate `Credentials` struct is no longer needed.
    // This is the clean, direct enum definition.
}
```

### Part 3: Instantiation and Use of a Struct Variant

This part demonstrates how to create an instance of a struct variant. The syntax for instantiation mirrors the definition, using curly braces and named fields.

- **Instantiation Syntax:** The syntax changes from parentheses `()` to curly braces `{}`. You provide the concrete values for each named field inside the braces.
    
- **The Code:** This example shows how to create an instance of the `PayPal` struct variant and print it.
    

Rust

```Rust
// The enum from Part 2.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String),
    DebitCard(String),
    PayPal {
        username: String,
        password: String,
    },
}

fn main() {
    // Instantiating a `CreditCard` (a tuple variant) still uses parentheses.
    let visa = PaymentMethodType::CreditCard(String::from("5678"));
    
    // Instantiating a `PayPal` (a struct variant) uses curly braces.
    let paypal = PaymentMethodType::PayPal {
        username: String::from("bob@gmail.com"),
        password: String::from("password"),
    };
    
    println!("Visa variant: {:?}", visa);
    println!("PayPal variant: {:#?}", paypal);
}
```

### Part 4: The Three Types of Enum Variants

This final part brings all the concepts together by showing the three different types of enum variants in a single, comprehensive enum definition, and how to instantiate each one. This demonstrates that enums can be very flexible and expressive.

- **The Three Types:**
    
    1. **Unit Variants:** Like a unit-like struct, they hold no data.
        
    2. **Tuple Variants:** Like a tuple-like struct, they hold positional data.
        
    3. **Struct Variants:** Like a named-field struct, they hold named data.
        

Rust

```Rust
// An enum with all three types of variants.
#[derive(Debug)]
enum PaymentMethodType {
    // 1. Unit variant (no associated data)
    Cash,
    
    // 2. Tuple variant (positional associated data)
    CreditCard(String),
    
    // 3. Struct variant (named associated data)
    PayPal {
        username: String,
        password: String,
    },
}

fn main() {
    // Instantiating a unit variant.
    let cash_payment = PaymentMethodType::Cash;

    // Instantiating a tuple variant.
    let visa_payment = PaymentMethodType::CreditCard(String::from("5678"));
    
    // Instantiating a struct variant.
    let paypal_payment = PaymentMethodType::PayPal {
        username: String::from("alice@gmail.com"),
        password: String::from("1234"),
    };
    
    println!("Unit variant: {:?}", cash_payment);
    println!("Tuple variant: {:?}", visa_payment);
    println!("Struct variant: {:#?}", paypal_payment);
}
```
