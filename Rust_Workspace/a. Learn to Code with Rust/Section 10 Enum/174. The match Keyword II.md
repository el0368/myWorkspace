### Part 1: `match` Arms with Direct Values (The "Before" State)

This progressive example starts with the base case for `match` statements: each arm returns a single, direct value. This sets the stage for introducing code blocks.

- **`match` as an Expression:** In its simplest form, a `match` statement acts as an expression, returning a single value based on the pattern it matches.
    
- **Consistent Type:** All arms must return a value of the same type. In this case, all arms return a `u32`.
    
- **The Code:** This part defines the `OperatingSystem` enum and a function where the `match` statement returns direct `u32` values.
    

Rust

```Rust
#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

// This function returns a `u32` value based on the `os` variant.
fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => 39, // Arm returns a direct u32 value
        OperatingSystem::MacOS   => 23, // Arm returns a direct u32 value
        OperatingSystem::Linux   => 34, // Arm returns a direct u32 value
    }
}

fn main() {
    let my_computer = OperatingSystem::Linux;
    let age = years_since_release(my_computer);
    
    println!("My computer's operating system is {} years old.", age);
    // Output: My computer's operating system is 34 years old.
    
    // The rest of this code is completed in the next parts.
}
```

### Part 2: `match` Arms with Code Blocks (The Challenge)

This part introduces the ability to use a code block (`{}`) within a `match` arm. It then highlights the compiler's strictness about a consistent return type, which can lead to a type mismatch error if a block doesn't explicitly return a value.

- **Code Blocks in Arms:** A `match` arm can contain a full code block with multiple lines of execution.
    
- **The Challenge:** The block itself becomes the expression for that arm. By default, a block with statements (lines ending in a semicolon) or no final expression returns the unit type `()`.
    
- **The Error:** This creates a type mismatch, as the other arms are returning a `u32`.
    

Rust

```Rust
#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => {
            // This arm now has a code block.
            // But it doesn't return a value, so it implicitly returns `()`.
            // This causes a compile-time error!
            println!("Quite an old operating system!");
            // The compiler expects a `u32` but gets `()`.
        },
        OperatingSystem::MacOS => 23,
        OperatingSystem::Linux => 34,
    }
}

fn main() {
    let my_computer = OperatingSystem::Linux;
    // This code would not compile due to the `match` arm error.
}
```

---

### Part 3: Implicit Return from a `match` Arm Block (The Solution)

This part provides the solution to the problem from Part 2. To make a code block return a value, its last line must be an expression without a semicolon.

- **Implicit Return from Blocks:** Just like in a function body, a code block in a `match` arm will implicitly return the value of its last expression, as long as that line does not end with a semicolon.
    
- **The Fix:** We add a `u32` value as the last expression in the `Windows` arm block.
    
- **The Result:** The block now correctly returns a `u32`, and all `match` arms have a consistent return type, which satisfies the compiler.
    

Rust

```Rust
#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => {
            println!("Quite an old operating system!"); // This line executes
            39 // The last expression, implicitly returned by the block (and the `match` arm)
        },
        OperatingSystem::MacOS => 23,
        OperatingSystem::Linux => 34,
    }
}

fn main() {
    let my_computer = OperatingSystem::Linux;
    // This code now compiles and is ready to be used.
}
```

### Part 4: The Final Progressive Example

This final part ties all the concepts together into a complete, working program. It demonstrates how a `match` statement can have a mix of direct-value arms and a code-block arm, all returning a consistent type.

- **Code Flow:** We create two different enum instances and pass them one by one to the `years_since_release` function.
    
- **Mixed Arms in Action:** The `MacOS` variant will match the direct-value arm, while the `Windows` variant will match the arm with the code block, executing the `println!` before returning its value.
    

Rust

```Rust
#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => {
            println!("Quite an old operating system!");
            39
        },
        OperatingSystem::MacOS => 23,
        OperatingSystem::Linux => 34,
    }
}

fn main() {
    let my_computer = OperatingSystem::Linux;
    let age = years_since_release(my_computer);
    println!("My computer's operating system is {} years old.", age);
    // Output: My computer's operating system is 34 years old.
    
    // Demonstrate the block arm
    let dads_computer = OperatingSystem::Windows;
    let dads_age = years_since_release(dads_computer);
    println!("My dad's computer is {} years old.", dads_age);
    // Output:
    // Quite an old operating system!
    // My dad's computer is 39 years old.
}
```
