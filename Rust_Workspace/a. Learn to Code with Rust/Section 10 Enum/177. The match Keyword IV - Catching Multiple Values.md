### Part 1: The Catch-All (`_`) Pattern

This progressive example starts by defining an enum and a method. It then shows the simplest way to match multiple variants in a `match` statement: by using a specific arm for a case you care about and a catch-all pattern (`_`) for all other cases.

- **Catch-all Pattern (`_`):** The underscore (`_`) is a wildcard that matches any variant that hasn't been matched by a preceding arm. It must be the last arm in the `match` statement.
    
- **The Code:** This part defines the `OnlineOrderStatus` enum and the `check` method, which uses the `_` pattern.
    

Rust

```Rust
// Our enum representing the stages of an online order.
#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn check(&self) {
        match self {
            // A specific arm for the `Delivered` variant.
            OnlineOrderStatus::Delivered => {
                println!("Your item has been delivered.");
            },
            // The catch-all pattern (`_`) matches all other variants.
            _ => {
                println!("Your item is not there yet.");
            },
        }
    }
}

fn main() {
    println!("--- Using the `_` catch-all pattern ---");
    
    // This will match the specific arm.
    let delivered_order = OnlineOrderStatus::Delivered;
    delivered_order.check(); // Output: Your item has been delivered.
    
    // This will be caught by the catch-all arm.
    let packed_order = OnlineOrderStatus::Packed;
    packed_order.check(); // Output: Your item is not there yet.
}
```

### Part 2: Matching Multiple Specific Variants with `|`

This part refactors the `match` statement to use the vertical pipe (`|`) operator. This allows us to group multiple specific variants into a single arm, making the logic more precise than a generic catch-all.

- **`|` Operator:** The pipe symbol (`|`) means "OR." It allows a single `match` arm's block to execute if the matched value is equal to `PatternA` OR `PatternB`.
    
- **The Code:** This example shows a `check` method that uses this syntax to group the `Ordered` and `Packed` variants.
    

Rust

```Rust
// Our enum from Part 1.
#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn check(&self) {
        match self {
            // This single arm now matches if the variant is either `Ordered` or `Packed`.
            OnlineOrderStatus::Ordered | OnlineOrderStatus::Packed => {
                println!("Your item is being prepped for shipment.");
            },
            // A specific arm for `Shipped`.
            OnlineOrderStatus::Shipped => {
                println!("Your item has left the building.");
            },
            OnlineOrderStatus::Delivered => {
                println!("Your item has been delivered.");
            },
        }
    }
}

fn main() {
    println!("\n--- Using the `|` operator ---");
    
    // This will match the `Ordered | Packed` arm.
    let order_status = OnlineOrderStatus::Ordered;
    order_status.check(); // Output: Your item is being prepped for shipment.
    
    // This will also match the `Ordered | Packed` arm.
    let packed_status = OnlineOrderStatus::Packed;
    packed_status.check(); // Output: Your item is being prepped for shipment.

    // This will match the separate `Shipped` arm.
    let shipped_status = OnlineOrderStatus::Shipped;
    shipped_status.check(); // Output: Your item has left the building.
}
```

### Part 3: The Named Catch-All Pattern

This part introduces the most flexible way to handle multiple variants: using a named variable as the catch-all pattern. This allows you to capture the specific variant that was matched and use its value in the arm's code block.

- **Named Catch-all:** A catch-all pattern that uses a variable name (`other_status`) instead of an underscore (`_`). The matched variant is bound to this variable.
    
- **The Code:** This example refactors the `check` method to use this named catch-all, and the `println!` call now interpolates the specific variant that was captured. The `#[derive(Debug)]` attribute is essential for printing the enum variant's name.
    

Rust

```Rust
// Our enum from Part 1. The `Debug` trait is necessary for printing the variant name.
#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn check(&self) {
        match self {
            // A specific arm for the `Delivered` variant.
            OnlineOrderStatus::Delivered => {
                println!("Your item has been delivered.");
            },
            // This named catch-all matches all other variants.
            // The `other_status` variable captures the variant.
            other_status => {
                // We can now interpolate the actual variant that was matched.
                println!("Your item status is: {:?}.", other_status);
            },
        }
    }
}

fn main() {
    println!("\n--- Using the named catch-all pattern ---");
    
    // The `Shipped` variant will be matched by `other_status`.
    let shipped_order = OnlineOrderStatus::Shipped;
    shipped_order.check(); // Output: Your item status is: Shipped.
    
    // The `Ordered` variant will also be matched by `other_status`.
    let ordered_order = OnlineOrderStatus::Ordered;
    ordered_order.check(); // Output: Your item status is: Ordered.
}
```
