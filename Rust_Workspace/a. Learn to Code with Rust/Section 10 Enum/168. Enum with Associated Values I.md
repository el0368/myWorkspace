### Part 1: Initial Enum Definition and the Need for Associated Data

This progressive example starts with a simple enum definition and demonstrates a roundabout way to associate data with its variants, setting the stage for why tuple variants are a better solution.

- **Enum Definition:** We define a basic `PaymentMethodType` enum with three simple variants.
    
- **The Problem:** We want to associate additional data (like an account number) with each variant. A clumsy way to do this is with a separate tuple.
    
- **The Code:** This example shows the initial `enum` definition and how a `CreditCard` variant and a `String` can be combined in a tuple.
    

Rust

```Rust
// Our initial enum definition with simple variants.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard,
    DebitCard,
    PayPal,
}

fn main() {
    // We want to associate an account number with the `CreditCard` variant.
    // A clumsy way is to use a separate tuple.
    let credit_card_number = String::from("0034-5678-9012-3456");
    let visa = (PaymentMethodType::CreditCard, credit_card_number);

    // This creates a tuple, but the data is not intrinsically linked to the variant.
    println!("Clumsy tuple: {:?}", visa);
    // The preferred solution is to integrate the data directly into the enum.
}
```

---

### Part 2: The Solution - Tuple Variants

This part introduces the direct and idiomatic Rust syntax for associating data with enum variants. We refactor the enum definition to use this new syntax.

- **Tuple Variant Syntax:** You add parentheses `()` after a variant name in the enum definition, and inside them, you specify the types of the data that the variant will hold.
    
- **Instantiation:** You create an instance of a tuple variant by calling it like a function, passing the concrete values for its data fields inside parentheses.
    

Rust

```Rust
// Refactored enum definition with tuple variants.
// Each variant now stores a `String` (representing an account number).
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String), // This variant holds one piece of data, a String.
    DebitCard(String),
    PayPal(String),
}

fn main() {
    // Instantiating a `CreditCard` variant with its associated String data.
    let visa = PaymentMethodType::CreditCard(String::from("5678"));

    // Instantiating a `DebitCard` variant.
    let mastercard = PaymentMethodType::DebitCard(String::from("2532-1298"));

    println!("Visa enum instance: {:?}", visa);
    println!("Mastercard enum instance: {:?}", mastercard);
}
```

### Part 3: Handling Multiple Pieces of Associated Data

This part shows that enum variants are not limited to a single piece of associated data. They can hold multiple data fields of different types, just like a regular tuple.

- **Multiple Data Fields:** You declare multiple types inside the parentheses, separated by commas.
    
- **Instantiation:** When creating the instance, you provide the concrete values in the same order as their types were declared.
    

Rust

```Rust
// Updated enum definition where `CreditCard` holds multiple pieces of data.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String, u32, u32), // Account number, expiration month, expiration year.
    DebitCard(String),
    PayPal(String),
}

fn main() {
    // Instantiating the `CreditCard` variant with all three pieces of data.
    let visa = PaymentMethodType::CreditCard(
        String::from("0034-5678-9012-3456"),
        12, // Month
        2028 // Year
    );

    let mastercard = PaymentMethodType::DebitCard(String::from("2532-1298"));
    
    println!("Visa with multiple data: {:?}", visa);
    println!("Mastercard: {:?}", mastercard);
}
```

### Part 4: Demonstrating Type Safety and Use

This final part extends the concept to show the main advantage of enum variants with associated data: they create unique, safe types that prevent logical errors.

- **Type Uniqueness:** The compiler treats `PaymentMethodType::DebitCard(...)` and `PaymentMethodType::CreditCard(...)` as distinct types, even if they hold the same underlying data type.
    
- **Functionality:** Enum variants can be passed as a single, consolidated value to functions, which can then use pattern matching to access their data.
    

Rust

```Rust
// The enum from Part 2.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String),
    DebitCard(String),
    PayPal(String),
}

// A function that expects a `PaymentMethodType` as a single argument.
// This is a much cleaner function signature than accepting a tuple.
fn get_payment_details(payment: &PaymentMethodType) {
    // Pattern matching can then be used to work with the data.
    // (This is covered in detail in a later lesson.)
    match payment {
        PaymentMethodType::CreditCard(account_num) => println!("Credit Card ending in {}", account_num),
        PaymentMethodType::DebitCard(account_num) => println!("Debit Card ending in {}", account_num),
        PaymentMethodType::PayPal(account_num) => println!("PayPal account: {}", account_num),
    }
}

fn main() {
    let visa = PaymentMethodType::CreditCard(String::from("5678"));
    let mastercard = PaymentMethodType::DebitCard(String::from("1298"));
    
    // We can now pass the full enum variant as a single value.
    get_payment_details(&visa);      // Output: Credit Card ending in 5678
    get_payment_details(&mastercard); // Output: Debit Card ending in 1298
}
```
