# Rust Strings: Complete Study Guide

## String Types in Rust

### Two Main String Types

**`str` (String Slice)**

- Lowercase spelling: `str`
- Always appears in borrowed form as `&str`
- Called a "string slice" or "ref str"
- Represents a reference to text stored elsewhere
- Cannot be mutated or changed
- More lightweight and efficient
- No ownership concerns due to borrowing

**`String` (Heap String)**

- Capital 'S' spelling: `String`
- Lives on the heap memory
- Can grow, shrink, and be mutated
- Owns its data
- More flexible but uses more resources
- Subject to ownership rules

### String Slice Origins

**From String Literals**

- Created using double quotes: `"hello world"`
- Hard-coded, unchanging content
- Embedded directly in the final executable
- Available at runtime as a reference to program memory
- Cannot be modified

**From Heap Strings**

- Can reference portions of `String` data
- Created through various operations on `String` types

## Type Coercion (Deref Coercion)

### Automatic Conversions

- `&String` → `&str`: Always possible
- Rust automatically converts String references to string slices when needed
- This works because string slices can represent borrowed text from any source

### Impossible Conversions

- `&str` → `&String`: Cannot be done automatically
- No guarantee that a string slice originated from a heap String
- Most string slices come from program literals, not heap allocations

### Function Parameter Best Practices

- Use `&str` parameters instead of `&String`
- More flexible - accepts both `&String` and `&str` arguments
- Follows Rust's principle of accepting the most general type possible

## String Concatenation

### `push_str` Method

- Appends a string slice to an existing String
- Syntax: `my_string.push_str("additional text")`
- Original String must be mutable
- Takes a `&str` parameter
- Modifies the original String in place

### `push` Method

- Appends a single character to a String
- Syntax: `my_string.push('c')`
- Uses single quotes for character literals
- Original String must be mutable
- More efficient than `push_str` for single characters

### Plus Operator (`+`)

- Calls the `add` method behind the scenes
- Syntax: `result = string1 + &string2`
- Takes ownership of the first String (moves it)
- Second operand must be a string slice (`&str`)
- Returns a new String with concatenated content
- Original first String becomes invalid after operation

```rust
let s1 = String::from("Hello");
let s2 = String::from(" World");
let result = s1 + &s2; // s1 is no longer valid here
```

## String Indexing and Slicing

### Why Direct Indexing is Prohibited

- Strings store data as UTF-8 bytes
- Visual characters don't always equal single bytes
- English letters: 1 byte each
- Emojis and special characters: multiple bytes each
- Accessing single byte positions could break multi-byte characters
- Rust prevents runtime panics by disallowing `string[index]`

### Range Slicing Syntax

- Use range syntax: `&string[start..end]`
- Creates a string slice of the specified byte range
- End position is exclusive (not included)
- Still not guaranteed to work - can panic if range splits multi-byte characters
- Examples:
    - `&text[0..5]` - first 5 bytes
    - `&text[2..8]` - bytes 2 through 7

### Safe Slicing Practices

- Ensure ranges align with character boundaries
- Test with various character types (ASCII, Unicode, emojis)
- Consider using character iteration methods for safer text processing

## The `format!` Macro

### Purpose and Functionality

- Similar to `println!` but returns a String instead of printing
- Creates new heap-allocated String with formatted content
- Useful for building strings dynamically

### Syntax Options

- Basic: `format!("Hello {}", name)`
- Positional arguments: `format!("{1} {0}", "world", "Hello")`
- Named arguments: `format!("{greeting} {name}", greeting="Hi", name="Alice")`
- All display formatting options from `println!` available

### Requirements

- Values must implement the `Display` trait
- Returns ownership of the newly created String
- More memory expensive than direct concatenation but more readable

## Common String Methods

### Whitespace Handling

**`trim()`**

- Removes whitespace from both beginning and end
- Returns a `&str` (string slice)
- Efficient - no new allocation needed
- Original string remains unchanged
- Demonstrates Rust's memory efficiency principles

**`trim_start()`**

- Removes whitespace only from the beginning
- Returns `&str`
- Preserves trailing whitespace

**`trim_end()`**

- Removes whitespace only from the end
- Returns `&str`
- Preserves leading whitespace

### Case Conversion

**`to_uppercase()`**

- Converts all characters to uppercase
- Returns a new `String` (not `&str`)
- Original string remains unchanged
- Memory allocation required for new String

**`to_lowercase()`**

- Converts all characters to lowercase
- Returns a new `String`
- Original string unchanged
- Creates new allocation

### Text Replacement

**`replace()`**

- Find and replace functionality
- Syntax: `string.replace("find", "replace")`
- Replaces ALL occurrences of the search pattern
- Returns a new `String`
- Original string remains unchanged
- Case-sensitive matching

### String Splitting

**`split()` Method**

- Divides string at specified delimiter
- Returns a `Split` struct (iterator)
- Think of it as cutting string with a knife at delimiter positions

**Converting Split Results**

- Use `collect()` method to gather results
- Must specify collection type: `Vec<&str>`
- Each piece becomes a string slice referencing original string
- Common pattern: `text.split(',').collect::<Vec<&str>>()`

## User Input Collection

### Required Components

**Import Statement**

- Need `use std::io;` to access input/output functionality
- Brings `io` submodule into scope

**Creating Input Buffer**

- Must create mutable String: `let mut input = String::new();`
- `read_line` requires mutable reference to write into
- String must be mutable to allow modification

### The `read_line` Method

**Setup and Usage**

- Create stdin handle: `io::stdin()`
- Call method: `stdin().read_line(&mut input)`
- Passes mutable reference to String buffer
- Method writes user input into the provided String

**Return Value - Result Enum**

- Returns `Result<usize, Error>`
- `Ok(usize)`: Success variant containing number of bytes read
- `Err(Error)`: Failure variant with error information
- Actual text content stored in the original String variable

### Error Handling Best Practices

**Using Match Statements**

- Validate operation success before proceeding
- Pattern match on Result variants:
    
    ```rust
    match stdin().read_line(&mut input) {    Ok(_) => {        // Process input string here    }    Err(error) => {        // Handle error case    }}
    ```
    

### Input Processing Considerations

**Newline Character Handling**

- Enter key adds `\n` (newline) to input
- Usually need to remove with `trim()`
- Example: `let clean_input = input.trim();`
- Essential for comparing user input to expected values

**Complete Input Processing Pattern**

```rust
let mut input = String::new();
match io::stdin().read_line(&mut input) {
    Ok(_) => {
        let processed = input.trim();
        // Use processed input here
    }
    Err(e) => println!("Error reading input: {}", e),
}
```

## Memory Efficiency Principles

### Rust's Approach to String Operations

- Prioritizes avoiding unnecessary data duplication
- Methods return string slices when possible (like `trim`)
- Creates new allocations only when transformation is required
- Contributes to Rust's performance advantages

### When New Allocations Occur

- Case conversion methods (`to_uppercase`, `to_lowercase`)
- `replace` method
- `format!` macro
- Concatenation with `+` operator

### When References Are Used

- `trim`, `trim_start`, `trim_end`
- String slicing operations
- Results from `split` method (individual pieces)

## Key Takeaways for Practical Usage

1. **Parameter Design**: Use `&str` for function parameters to accept both String types
2. **Concatenation Choice**: Use `push_str` for efficiency, `+` for readability, `format!` for complex formatting
3. **Indexing Safety**: Always use range slicing, never direct indexing
4. **Input Handling**: Always trim user input and handle Result types properly
5. **Memory Awareness**: Understand when operations create new allocations vs. return references
6. **Error Handling**: Use proper Result handling patterns for robust applications
