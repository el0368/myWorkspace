# Strings — deep, in-scope study guide (practical + examples)

---

## `&str` vs `String` — the essentials

- **`&str`** (string slice)
    
    - Immutable **borrow** (`&str`) to UTF-8 data.
        
    - Commonly from **string literals** embedded in the binary (`"hello"`).
        
    - Lightweight, no ownership, no allocation.
        
    - Example: `let s: &str = "hello";`
        
- **`String`** (owned)
    
    - Heap-allocated, growable, mutable.
        
    - Owns its buffer; operations that change size require a `String`.
        
    - Example: `let mut s = String::from("hello");`
        

**Memory note:** `&str` points to bytes somewhere (binary or heap). `String` stores bytes on the heap and provides ownership/ability to mutate.

---

## Creating & converting

```rust
// string literal -> &str
let literal: &str = "Hello";

// &str -> String
let a = String::from("Hello");
let b = "Hello".to_string();        // method on &str
let c: String = format!("{} {}", "Hello", "World"); // format! returns String

// String -> &str (borrowing / deref coercion)
let s = String::from("hello");
let s_slice: &str = &s;            // &String coerced to &str automatically
```

**Rule of thumb for APIs:** Accept `&str` for parameters when possible so callers may pass either `&str` or `&String`.

---

## Deref coercion (brief)

- Rust **automatically** converts `&String` → `&str` where required.
    
- It **does not** convert `&str` → `&String` (no reverse coercion).
    

---

## Concatenation: three idiomatic ways

### 1) `push_str(&str)` — append a slice to a `String`

```rust
let mut fullname = String::from("Sylvester");
let lastname = "Stallone";   // &str
fullname.push(' ');          // push single char
fullname.push_str(lastname); // append &str
println!("{}", fullname);    // "Sylvester Stallone"
```

- `push_str` borrows the argument (no ownership transfer).
    
- Use when you already have a mutable `String`.
    

### 2) `push(char)` — append one character

```rust
let mut s = String::from("Hi");
s.push('!');
```

- `char` uses single quotes `'a'`. Useful to add a single character or space.
    

### 3) `+` operator (syntactic sugar for `add`) — consumes left operand

```rust
let a = String::from("Sylvester");
let b = String::from("Stallone");
let full = a + " " + &b; // `a` is moved; &b coerces to &str
// println!("{}", a);    // ❌ a was moved
println!("{}", full);
```

- `a + &b` is `a.add(&b_as_str)` under the hood.
    
- The **left** `String` is moved (consumed) — store the result if you need it.
    
- To keep the left operand, `clone()` it first (costly).
    

**Preference:** `push_str` or `format!` are often clearer when you need to keep originals.

## `format!` — build a `String` with interpolation

- Like `println!` but **returns** a `String`.
    
- Arguments are **borrowed** (no move).
    
- Supports positional and named args, formatting, width, precision, debug, etc.
    

Examples:

```rust
let first = "Sylvester";
let last = "Stallone";
let s = format!("{} {}", first, last);               // "Sylvester Stallone"
let s2 = format!("{0} {1} - {0}", first, last);      // positional reuse
let named = format!("{first} {last}", first=first, last=last);

let pi = 3.14159;
let p = format!("{:.2}", pi);   // "3.14"  -> precision
let debug = format!("{:?}", vec![1,2]); // debug formatting
```

## Indexing, slicing, and Unicode (safety)

- **You CANNOT use `s[0]` to get the first character** — compiler error.  
    Strings are UTF-8; indexing by byte is unsafe for multi-byte characters.
    

### Byte length vs character count

```rust
let emoji = "😀";              // 1 visible glyph
println!("bytes: {}", emoji.len());          // 4 (bytes)
println!("chars: {}", emoji.chars().count()); // 1 (Unicode scalar values)
```

### Safe slicing with ranges (must align at UTF-8 boundaries)

```rust
let s = "Bloodhook";
let slice = &s[0..1]; // Ok, first byte forms a valid char 'B'
```

- If the range cuts a multi-byte character, slicing panics at runtime.
    

### Safer: `.get(range)` returns `Option<&str>`

```rust
let name = "éclair";             // 'é' is 2 bytes
assert!(name.get(0..1).is_none()); // prevents panic
if let Some(part) = name.get(0..2) { println!("{}", part); } // valid
```

### Iterating characters

```rust
let s = "héllo";
for ch in s.chars() {
    println!("{}", ch);
}
let first_char = s.chars().nth(0).unwrap(); // safe way to access first char
```

**Key rule:** Use `.chars()` for character semantics, `.bytes()` for raw bytes, and `.get(..)` to avoid slicing panics.

## Common string methods (what they return & behavior)

- `trim()` → `&str`
    
    - Removes leading/trailing whitespace. Does **not** allocate; returns a slice.
        
- `trim_start()` / `trim_end()` → `&str`
    
    - Remove starting or ending whitespace only.
        
- `to_uppercase()` / `to_lowercase()` → `String`
    
    - Return a **new** `String` (allocation), since content changes.
        
- `replace(from, to)` → `String`
    
    - Replaces _all_ occurrences of `from` substring; returns a new `String`.
        
- `split(pattern)` → `Split` iterator
    
    - Use `.collect::<Vec<&str>>()` to gather borrowed slices.
        
    - If you need owned pieces, map `to_string()` or collect into `Vec<String>`.
        

Examples:

```rust
let s = "  Rock, Metal  ";
let trimmed: &str = s.trim();                 // borrowed view
let up: String = trimmed.to_uppercase();      // allocate
let replaced = up.replace("METAL", "METAL!"); // allocate
let genres: Vec<&str> = trimmed.split(", ").collect(); // ["Rock","Metal"]
```

---

## `split` & `collect` patterns

- Splitting a `&str` and collecting into `Vec<&str>` **does not allocate per piece** (it borrows substrings).
    
- To own the pieces: `split(...).map(|s| s.to_string()).collect::<Vec<String>>()`.
    

---

## `.len()` vs `.chars().count()`

- `.len()` → number of **bytes**.
    
- `.chars().count()` → number of Unicode scalar values (closer to "characters" but not grapheme clusters).
    
- For user-visible characters (grapheme clusters), use the `unicode-segmentation` crate (outside transcript scope).

## Reading user input (`stdin().read_line(&mut s)`)

```rust
use std::io;

let mut input = String::new();
let res = io::stdin().read_line(&mut input);
match res {
    Ok(bytes) => println!("Read {} bytes: {:?}", bytes, input),
    Err(e) => eprintln!("read_line error: {}", e),
}
let trimmed = input.trim(); // usually remove trailing newline
```

- `read_line` expects a **mutable reference** to a `String` and **appends** into it.
    
- It returns `Result<usize, std::io::Error>` — `Ok(n)` where `n` = number of bytes read (not the text).
    
- **Important:** user pressing Enter adds `\n` (remove with `trim()`).
    

---

## Ownership & methods that return slices vs `String`

- Methods that only create a view (like `trim`, `split` slices) return `&str` and don’t allocate. Good for efficiency.
    
- Methods that produce modified content (`replace`, `to_uppercase`) return a **new `String`** because the original must be preserved.
    

---

## Error-prone patterns & safe alternatives

- ❌ `s[0]` — compile error.  
    ✅ Use `s.chars().nth(0)` or `s.get(0..1)` safely.
    
- ❌ `&s[0..3]` may panic for multi-byte chars.  
    ✅ Use `s.get(0..3)` and handle `None`.
    
- ❌ `a + b` moving left operand unexpectedly.  
    ✅ Use `format!` or `push_str` if you need to keep originals.
    
- ❌ Using `unwrap()` on `read_line` or `.get(..).unwrap()` unsafely.  
    ✅ Use `match`, `if let`, or `.expect("clear message")` if you truly expect success.
    

---

## Best practices & concise recommendations

- **Function parameters:** prefer `&str` (flexible for callers).
    
    ```rust
    fn greet(name: &str) { println!("Hi {}", name); }
    ```
    
- **Build strings:** use `format!` for many interpolations; `push_str`/`push` for incremental mutation.
    
- **Avoid unnecessary clones:** clone only when you need an owned duplicate.
    
- **Be Unicode aware:** `.len()` is bytes; use `.chars()` for characters. Use `.get()` to avoid slicing panics.
    
- **Trim user input** to remove trailing `\n` from `read_line`.
    
- **Collecting split results:** prefer `Vec<&str>` (borrows) if the original string outlives the vector; otherwise collect owned `String`s.

## Compact cheat-sheet examples

### Safe slice & char access

```rust
let s = "éclair";
assert!(s.get(0..1).is_none()); // prevents panic
if let Some(ch) = s.chars().next() { println!("first char: {}", ch); }
```

### Concatenate keeping original

```rust
let a = String::from("A");
let b = String::from("B");
let full = format!("{} {}", a, b);  // a and b still usable
```

### Split into borrowed slices (no allocation per piece)

```rust
let line = "a, b, c";
let parts: Vec<&str> = line.split(", ").collect();
```

### Read line and trim

```rust
use std::io;
let mut buf = String::new();
io::stdin().read_line(&mut buf).expect("read failed");
let input = buf.trim();
```
