# 📊 Rust String Operations – Comparison Table

|Operation|Input Types|Return Type|Ownership Rules|Efficiency Notes|
|---|---|---|---|---|
|`push_str`|`&mut String`, `&str`|`()` (no return)|Borrows `&str` (does not take ownership). Consumes `&mut String` since it mutates it.|Very efficient, appends slice directly onto heap allocation (may reallocate if capacity is exceeded).|
|`push`|`&mut String`, `char`|`()`|Borrows `char`. Requires `&mut String`.|Efficient for appending single Unicode scalar values.|
|`+` (concatenation)|`String` (LHS, ownership taken), `&str` (RHS)|`String`|Moves LHS `String` (invalidates it). Borrows RHS `&str`. Returns new `String`.|May involve reallocation. Less efficient than `push_str` if chaining many additions.|
|`format!`|Multiple inputs (anything implementing `Display`)|`String`|Takes inputs by reference (`&T`), **no ownership moves**. Returns new `String`.|Flexible but least efficient: always allocates a new heap String.|
|`replace`|`&str` (search), `&str` (replacement)|`String`|Works on `&String` or `&str` target. Returns a new `String`.|Allocates a new string, replaces all matches → potentially expensive.|
|`trim`|`&String` or `&str`|`&str` (slice)|Borrows only, never allocates. No ownership changes.|Extremely efficient — just returns slice indices into the same memory.|
|`to_uppercase` / `to_lowercase`|`&String` or `&str`|`String`|Borrow input, return a new `String`.|Requires new allocation for transformed characters.|
|`split` + `collect::<Vec<&str>>()`|`&String` or `&str`, delimiter `&str`|`Vec<&str>`|Borrow input, never take ownership. Returns slices of original.|Very efficient; no duplication of data (unless you later clone).|

---

⚡ **Key Takeaways**

- **Mutating ops** (`push_str`, `push`) → modify in place, require `mut String`.
    
- **Concatenation (`+`)** → moves the left-hand String, so use carefully.
    
- **Formatting ops** (`format!`, `replace`, case conversion) → always allocate new heap strings.
    
- **Borrowing ops** (`trim`, `split`) → return slices, zero-copy, very efficient.
