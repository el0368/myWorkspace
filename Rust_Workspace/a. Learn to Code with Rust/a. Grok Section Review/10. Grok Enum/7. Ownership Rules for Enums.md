### 7. Ownership Rules for Enums

**Explanation in the Scope of a Typical Rust Course Transcript:**

In Rust, **enums** follow the same ownership rules as other types, adhering to Rust’s memory safety model. An enum instance owns its data, including any associated data stored in its variants. By default, enums do not implement the `Copy` trait, so assigning an enum to a new variable or passing it to a function moves ownership, invalidating the original variable unless a copy or clone is explicitly made. If an enum’s variant contains a non-`Copy` type (e.g., `String`), moving the enum transfers ownership of that data, while `Copy` types (e.g., `i32`) are copied. This ensures that the enum’s data, whether simple or complex, is managed safely, preventing issues like dangling references or double freeing, as would be emphasized in a Rust course for clarity and safety.

**Rust Code Example:**

Below is a minimal code example demonstrating ownership rules for enums, styled to match the educational tone of the provided transcript.

    Text(String), // Non-Copy type
    Number(i32), // Copy type
}

    let data1 = Data::Text(String::from("Hello"));
    let data2 = data1; // Ownership moves to data2

    // Access data2
    match data2 {
        Data::Text(text) => println!("Text: {}", text),
        Data::Number(num) => println!("Number: {}", num),
    }
