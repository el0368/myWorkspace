### 2. Types of Structs

**Explanation in the Scope of the Transcript:**

The transcript outlines that Rust supports three types of structs, each serving distinct purposes for organizing data:
- **Named Field Struct**: The most common type, where each piece of data (field) is assigned a descriptive name, providing clarity and explicit association with values. This is ideal for modeling complex entities with labeled attributes.
- **Tuple-Like Struct**: Fields are identified by their position (index) rather than names, resembling a tuple but still defining a distinct type. This is useful when you want a lightweight struct with ordered data but need to distinguish it from other tuples or tuple structs.
- **Unit-Like Struct**: A struct with no fields, akin to an empty tuple, used in cases where a type is needed without storing data, often for attaching behavior (methods) to a type in complex scenarios.

These types allow flexibility in how data is structured, with named field structs being the most frequently used due to their clarity, while tuple-like and unit-like structs serve niche use cases.

**Rust Code Example:**

Below is a minimal code example demonstrating the three types of structs, aligning with the transcript’s description.
```rust
// Named field struct
struct Person {
    name: String,
    age: u32,
}

// Tuple-like struct
struct Point(i32, i32);

// Unit-like struct
struct Empty;

fn main() {
    // Named field struct instantiation
    let person = Person {
        name: String::from("Alice"),
        age: 30,
    };
    println!("Person: {} is {} years old", person.name, person.age);

    // Tuple-like struct instantiation
    let point = Point(3, 4);
    println!("Point: ({}, {})", point.0, point.1);

    // Unit-like struct instantiation
    let empty = Empty;
    println!("Empty struct: {:?}", empty);
}
```

**Code Explanation:**

1. **Named Field Struct (`Person`)**:
   - Defined with named fields `name` and `age`, as per the transcript’s note that this is the most common type.
   - Instantiated with curly braces `{}` and field names, providing clarity (e.g., `name: String::from("Alice")`).
   - Fields are accessed using dot notation (`person.name`, `person.age`), emphasizing the explicit naming described in the transcript.

2. **Tuple-Like Struct (`Point`)**:
   - Defined with parentheses `()` and positional fields (`i32, i32`), matching the transcript’s description of fields identified by order, not names.
   - Instantiated like a tuple (`Point(3, 4)`), and fields are accessed by index (`point.0`, `point.1`), as noted in the transcript.
   - Useful for lightweight, ordered data, distinct from other tuples or tuple structs.

3. **Unit-Like Struct (`Empty`)**:
   - Defined with no fields, resembling an empty tuple, as described in the transcript.
   - Instantiated without data (`Empty`), showing its use as a placeholder type, often for attaching methods in complex code (though methods are not shown here for brevity).
   - Printed with `{:?}` (requires `#[derive(Debug)]` in a full implementation, omitted here for minimalism).

**Key Takeaways**:
- **Named Field Structs** provide clarity with labeled fields, ideal for most real-world modeling.
- **Tuple-Like Structs** are lightweight, using positional fields for ordered data.
- **Unit-Like Structs** are field-less, used for type placeholders in advanced scenarios.
