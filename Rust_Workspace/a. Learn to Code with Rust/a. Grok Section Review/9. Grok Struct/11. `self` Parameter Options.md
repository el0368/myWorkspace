### 11. `self` Parameter Options

**Explanation in the Scope of the Transcript:**

The transcript details that methods on structs always include a `self` parameter as their first parameter, representing the struct instance. The `self` parameter can be specified in four ways, each affecting ownership and mutability:
- **Immutable Ownership (`self`)**: Takes full ownership of the struct, moving it to the method. The struct is deallocated when the method ends unless returned, making it unusable afterward.
- **Mutable Ownership (`mut self`)**: Takes ownership and allows modification of the struct’s fields, but the struct is still moved and deallocated unless returned.
- **Immutable Reference (`&self`)**: Borrows the struct immutably, allowing read-only access without taking ownership, preserving the struct’s usability.
- **Mutable Reference (`&mut self`)**: Borrows the struct mutably, allowing modification of fields without taking ownership, keeping the struct usable.

The transcript notes that these options can use shorthand (`self`, `mut self`, `&self`, `&mut self`) or explicit type annotations (e.g., `self: Self`, `self: &Self`). The `Self` keyword is an alias for the struct type, making code resilient to name changes. Immutable references are preferred to avoid ownership issues, and the choice depends on whether the method needs to modify the struct or transfer ownership.

**Rust Code Example:**

Below is a minimal code example demonstrating the `self` parameter options, aligned with the transcript’s description.
```rust
struct Book {
    title: String,
    pages: u32,
}

impl Book {
    // Immutable reference: read-only access
    fn get_title(&self) -> &String {
        &self.title
    }

    // Mutable reference: modify fields
    fn add_pages(&mut self, pages: u32) {
        self.pages += pages;
    }

    // Immutable ownership: takes ownership, moves struct
    fn consume(self) -> String {
        self.title
    }
}

fn main() {
    let mut book = Book {
        title: String::from("Rust Guide"),
        pages: 300,
    };

    // Immutable reference method
    println!("Title: {}", book.get_title());

    // Mutable reference method
    book.add_pages(50);
    println!("Pages: {}", book.pages);

    // Immutable ownership method: moves book
    let title = book.consume();
    println!("Consumed title: {}", title);
    // book is no longer valid here
}
```

**Code Explanation:**

1. **Struct Declaration**:
   - The `Book` struct is defined with `title: String` and `pages: u32`, providing a context for method definitions.

2. **Method Definitions with `self` Options**:
   - `get_title(&self)` uses an immutable reference, allowing read-only access to `title`, as per the transcript’s note on `&self` for non-destructive access.
   - `add_pages(&mut self, pages: u32)` uses a mutable reference, enabling modification of `pages`, aligning with the transcript’s description of `&mut self` for mutating fields.
   - `consume(self)` takes ownership, moving the struct and returning its `title`, demonstrating the transcript’s point that `self` moves the struct, making it unusable afterward.

3. **Method Invocation**:
   - Methods are called with dot notation (`book.get_title()`, `book.add_pages(50)`, `book.consume()`), showing how `self` is implicitly provided, as noted in the transcript.
   - After `consume`, `book` is invalid, reflecting ownership transfer.

4. **Minimal Usage**:
   - The example is minimal, showcasing three `self` options (omitting `mut self` for brevity) to demonstrate their impact on access and ownership.

**Key Takeaways**:
- The `self` parameter can be `self`, `mut self`, `&self`, or `&mut self`, controlling ownership and mutability.
- Immutable references (`&self`) are preferred for non-destructive access, while ownership (`self`) moves the struct, and mutable references (`&mut self`) allow changes.
