### Part 1: Initial Setup and the Problem of Ownership

This progressive example starts by setting up two vectors that will be used to demonstrate different ownership behaviors. It highlights the crucial distinction between types that implement `Copy` and those that do not, and the ownership transfer that occurs when data is moved into a vector.

- **`Copy` Types:** The `pizza_diameters` vector holds `i32` integers, which are `Copy` types.
    
- **Non-`Copy` Types:** The `pizza_toppings` vector holds `String`s, which are non-`Copy` types that manage heap data.
    
- **Ownership Transfer:** When the `pizza_toppings` vector is created, ownership of the `String`s from the `pepperoni`, `mushroom`, and `sausage` variables is **moved** into the vector. This makes the original variables invalid.
    

Rust

```Rust
fn main() {
    // A vector of `Copy` types (i32)
    let pizza_diameters = vec![8, 10, 12, 14];

    // Three `String`s (non-Copy types)
    let pepperoni = String::from("Pepperoni");
    let mushroom = String::from("Mushroom");
    let sausage = String::from("Sausage");

    // Ownership of the `String`s moves from the variables into the vector.
    let pizza_toppings = vec![pepperoni, mushroom, sausage];

    // The original `String` variables are now invalid.
    // println!("{}", pepperoni); // ERROR: borrow of moved value: `pepperoni`

    println!("Pizza Diameters: {:?}", pizza_diameters);
    println!("Pizza Toppings: {:?}", pizza_toppings);

    // The rest of this code is completed in the next parts.
}
```

### Part 2: Accessing Elements by Value and Reference

This part demonstrates the different behaviors of direct access (`[]`) depending on whether the element's type is `Copy` or non-`Copy`. It shows that direct access to a `Copy` type creates a copy, while attempting the same for a non-`Copy` type results in a compiler error. The solution for non-`Copy` types is to borrow a reference.

- **`Copy` Type Access:** Accessing a vector element whose type is `Copy` (like `i32`) creates a **full copy** of the value. The vector retains ownership.
    
- **Non-`Copy` Type Access:** Attempting to access a non-`Copy` type (like `String`) by value will result in a **compile-time error** because it would trigger a move, which Rust prohibits for elements within a vector.
    
- **Solution: Borrowing (`&`)**: The correct way to read a non-`Copy` element from a vector is to borrow a **reference (`&`)** to it. This allows you to use the element without moving ownership.
    

Rust

```Rust
fn main() {
    let pizza_diameters = vec![8, 10, 12, 14];
    let pizza_toppings = vec![
        String::from("Pepperoni"),
        String::from("Mushroom"),
        String::from("Sausage"),
    ];

    // --- Accessing a `Copy` type (i32) ---
    // The value `12` is copied out of the vector. The vector still owns its data.
    let value = pizza_diameters[2];
    println!("Copied value: {}", value); // Output: 12

    // --- Accessing a non-`Copy` type (String) ---
    // This line would cause a compile-time error because it attempts to move the String
    // out of the vector, which is a partial move.
    // let invalid_move = pizza_toppings[2]; // ERROR: cannot move out of index of `Vec`

    // --- The solution: Borrowing a reference (`&`) ---
    // This creates a reference (`&String`) to the element at index 2.
    // The `pizza_toppings` vector remains the owner of all its elements.
    let reference = &pizza_toppings[2];
    println!("Borrowed reference: {}", reference); // Output: Sausage
}
```

### Part 3: Slices and Out-of-Bounds Panics

This part demonstrates two final ways to access vector elements: by creating a slice, and by showing the danger of an out-of-bounds index, which is not caught by the compiler for vectors.

- **Slices:** A slice is a **reference to a contiguous portion of a collection**. It's created using the borrow operator (`&`) and a range syntax (`[start..end]`). This allows you to borrow multiple elements at once.
    
- **Out-of-Bounds Panics:** Unlike arrays, where the compiler can often catch an invalid index, the vector's dynamic size means that out-of-bounds access can only be detected at **runtime**. This will cause a **panic!**.
    

Rust

```Rust
fn main() {
    let pizza_diameters = vec![8, 10, 12, 14];
    let pizza_toppings = vec![
        String::from("Pepperoni"),
        String::from("Mushroom"),
        String::from("Sausage"),
    ];

    // --- Creating a slice from a vector ---
    // This creates a slice (a reference to a portion) from index 1 to 3 (exclusive).
    let pizza_slice = &pizza_diameters[1..3];
    println!("Pizza diameter slice: {:?}", pizza_slice); // Output: [10, 12]

    // You can also use shorthand to slice to the end.
    let toppings_slice = &pizza_toppings[1..];
    println!("Toppings slice: {:?}", toppings_slice); // Output: ["Mushroom", "Sausage"]

    // --- The risk of out-of-bounds indexing ---
    // The compiler does NOT catch this because the vector's length is not fixed.
    // pizza_diameters[100]; // This line would cause a runtime panic!

    // The same is true for borrowing a reference to an invalid index.
    // let invalid_ref = &pizza_toppings[50]; // This line would also panic!
}
```
