- **Custom Enum:** The `MyOption` enum is defined with two variants: `Some` (which holds an `i32`) and `None`.

### Part 2: Defining and Using the Risky `.unwrap()` Method

This part defines a custom `.unwrap()` method for `MyOption`. This method shows why `.unwrap()` is considered a risky, "optimistic" method: it will return the value from `Some` but will crash the program if the variant is `None`.

- **Method Signature:** The method `unwrap()` takes `self` (ownership of a copy) and returns an `i32`.
    
- **`match` Logic:** A `match` statement is used to handle both `Some` and `None` variants. The `Some(value)` arm returns the value, while the `None` arm uses the `panic!` macro to crash the program.
    
- **The Code:** This example shows the `unwrap()` method in the `impl` block and demonstrates its use in `main`.
    

Rust

```Rust
// The custom enum from Part 1.
#[derive(Debug, Copy, Clone)]
enum MyOption {
    Some(i32),
    None,
}

impl MyOption {
    fn unwrap(self) -> i32 {
        match self {
            // Success: `MyOption::Some` is matched, and its value is returned.
            MyOption::Some(value) => value,
            // Failure: `MyOption::None` is matched, causing a program crash.
            MyOption::None => panic!("Uh oh, we called unwrap() on a None value!"),
        }
    }
}

fn main() {
    // A variable with the `Some` variant.
    let some_option = MyOption::Some(100);
    // A variable with the `None` variant.
    let none_option = MyOption::None;
    
    // Successful call to `unwrap()` on a `Some` value.
    let result_from_some = some_option.unwrap();
    println!("Unwrapped value from Some: {}", result_from_some);
    
    // This line would cause the program to panic!
    // let result_from_none = none_option.unwrap(); // PANIC: Uh oh, we called unwrap() on a None value!
}
```

### Part 3: Defining and Using the Safe `.unwrap_or()` Method

This part introduces a custom `.unwrap_or()` method, which is a safer alternative to `.unwrap()`. It guarantees a non-panicking outcome by providing a fallback value.

- **Method Signature:** The method `unwrap_or()` takes `self` and an additional `fallback_value` parameter and returns an `i32`.
    
- **`match` Logic:** The `match` statement either returns the `Some` value or, if the variant is `None`, returns the `fallback_value` instead of panicking.
    
- **The Code:** This example shows the `unwrap_or()` method and demonstrates its use on both a `Some` and `None` variant, proving that it never panics.
    

Rust

```Rust
// The custom enum from Part 1.
#[derive(Debug, Copy, Clone)]
enum MyOption {
    Some(i32),
    None,
}

impl MyOption {
    fn unwrap_or(self, fallback_value: i32) -> i32 {
        match self {
            // Success: `MyOption::Some` is matched, and its value is returned.
            MyOption::Some(value) => value,
            // Failure: `MyOption::None` is matched, and the fallback value is returned instead of panicking.
            MyOption::None => fallback_value,
        }
    }
}

fn main() {
    let some_option = MyOption::Some(100);
    let none_option = MyOption::None;
    
    // Call `unwrap_or()` on a `Some` value. The value from `Some` is returned.
    let result_from_some = some_option.unwrap_or(13);
    println!("Unwrapped value from Some: {}", result_from_some);
    
    // Call `unwrap_or()` on a `None` value. The fallback value is returned.
    let result_from_none = none_option.unwrap_or(13);
    println!("Unwrapped value from None (fallback): {}", result_from_none);
}
```

### Part 4: The Final Progressive Example (Full Comparison)

This final part brings all the concepts together into a single, comprehensive program. It shows the `MyOption` enum and both `unwrap()` and `unwrap_or()` methods. The `main` function demonstrates a full comparison of the two, highlighting the risk of `unwrap()` versus the safety of `unwrap_or()`.

Rust

```Rust
// The complete custom enum with both methods
#[derive(Debug, Copy, Clone)]
enum MyOption {
    Some(i32),
    None,
}

impl MyOption {
    fn unwrap(self) -> i32 {
        match self {
            MyOption::Some(value) => value,
            MyOption::None => panic!("Uh oh, we called unwrap() on a None value!"),
        }
    }
    
    fn unwrap_or(self, fallback_value: i32) -> i32 {
        match self {
            MyOption::Some(value) => value,
            MyOption::None => fallback_value,
        }
    }
}

fn main() {
    let some_option = MyOption::Some(100);
    let none_option = MyOption::None;
    
    // --- Demonstrating `unwrap()` (The Risky Method) ---
    let unwrapped_value = some_option.unwrap();
    println!("Unwrapped successfully: {}", unwrapped_value);
    
    // This next line would cause a panic! We keep it commented out to show the rest of the code.
    // let panicking_value = none_option.unwrap();
    // println!("This line is not reached.");
    
    // --- Demonstrating `unwrap_or()` (The Safe Method) ---
    let result_from_some = some_option.unwrap_or(13);
    println!("Unwrap_or on Some: {}", result_from_some);
    
    let result_from_none = none_option.unwrap_or(13);
    println!("Unwrap_or on None: {}", result_from_none);
    
    // We can also see that the original `some_option` variable is still valid
    // because `MyOption` implements the `Copy` trait.
    println!("\nOriginal `some_option` is still valid: {:?}", some_option);
}
```
