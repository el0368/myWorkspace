### Part 1: The Problem - `Result` with Non-`Copy` Generics (`String`)

This progressive example starts with a function that returns a `Result` where both the success (`T`) and error (`E`) types are `String`. Since `String` is a non-`Copy` type, a move of ownership will occur when we try to extract it from the `Result` enum.

- **The Problem:** A `match` statement that extracts data from a `Result` performs a **move** if the associated data is a non-`Copy` type (like `String`). This move invalidates the original `Result` variable, preventing any subsequent use of it.
    
- **The Code:** This part shows the `operation` function returning `Result<String, String>`. The `main` function attempts to use a `match` statement to handle the result, and a commented-out line shows the resulting compiler error.
    

Rust

```Rust
// A function that returns a `Result` with non-Copy types (`String`, `String`).
fn operation(great_success: bool) -> Result<String, String> {
    if great_success {
        Ok("Success".to_string())
    } else {
        Err("Error".to_string())
    }
}

fn main() {
    let my_result = operation(true);
    
    // The `match` statement takes the `String` out of `my_result`.
    // The `message` variable now owns the String.
    let content = match my_result {
        Ok(message) => message,
        Err(message) => message,
    };
    
    // This line would cause a compile-time error!
    // The data inside the `Result` has been moved to `content`, so `my_result` is now partially moved.
```

### Part 2: The Subtle Problem - Mixed `Copy` and Non-`Copy` Generics

This part demonstrates a more subtle issue. Even if one of the `Result`'s generic types is a `Copy` type, the entire `Result` is still considered "partially moved" if the _other_ type is a non-`Copy` type.

- **Mixed Generics:** We modify the `operation` function to return `Result<String, &'static str>`, where `&'static str` is a `Copy` type.
    
- **The Problem:** A `match` arm that extracts the `String` from the `Ok` variant will still perform a **move**, which invalidates the `Result` and prevents subsequent use, even though the `Err` variant's data would have been copied.
    
- **The Code:** This part shows the refactored `operation` function and the commented-out line that would still cause a compiler error.
    

Rust

```Rust
// The `operation` function is now refactored to use a mixed generic type.
// The `Ok` variant still holds a `String` (non-Copy).
// The `Err` variant now holds a `&'static str` (Copy).
fn operation(great_success: bool) -> Result<String, &'static str> {
    if great_success {
        Ok("Success".to_string())
    } else {
        Err("Error")
    }
}

fn main() {
    let my_result = operation(true);
    
    let content = match my_result {
        Ok(message) => message,
        Err(message) => message.to_string(), // Convert `&str` to `String` for consistent return type
    };
    
    // This line would still cause a compile-time error. The `String` inside the `Ok` variant
    // was moved to `content`, so `my_result` is partially moved.
```

### Part 3: The Solution - `Result` with Only `Copy` Generics

This part presents the solution to the previous problems. When both generic types of the `Result` enum are **`Copy` types**, the data will be copied out of the enum, not moved. The original `Result` variable remains valid and can be used afterward.

- **All `Copy` Types:** We modify the `operation` function to return `Result<&'static str, &'static str>`. Now both `T` and `E` are `Copy` types.
    
- **The Solution:** A `match` arm that extracts data will now make a **copy** of the reference, not a move. This keeps the original `Result` variable completely valid.
    
- **The Code:** This is the complete, working code that demonstrates a `match` statement followed by a call to `.unwrap()`, which is only possible because the original `Result` variable was not moved.
    

Rust

```Rust
// The `operation` function is now refactored to use only `Copy` types.
// `&'static str` is a reference, which is a `Copy` type.
fn operation(great_success: bool) -> Result<&'static str, &'static str> {
    if great_success {
        Ok("Success")
    } else {
        Err("Error")
    }
}

fn main() {
    let my_result = operation(true);
    
    // The `match` statement extracts data.
    // Because `&'static str` is a `Copy` type, the data is copied out, NOT MOVED.
    let content = match my_result {
        Ok(message) => message,
        Err(message) => message,
    };
    
    // The `my_result` variable is still valid, so we can unwrap it.
    // This code now compiles and runs without any errors.
    println!("Content is: {}", content);
    println!("My result is still here: {:?}", my_result);
    // This line also works, because the data inside the `Result` was copied, not moved.
    println!("The unwrapped value is: {}", my_result.unwrap());
}
```
