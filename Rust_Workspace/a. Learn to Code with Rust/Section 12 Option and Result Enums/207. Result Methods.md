### Part 1: Risky Extraction with `.unwrap()` and `.expect()`

This progressive example starts by demonstrating the risky "optimistic" methods available on the `Result` enum. Like with `Option`, these methods are quick for extracting the value but can cause a program crash if the operation fails.

- **`.unwrap()`:** This method attempts to extract the successful value from the `Ok` variant. If the variant is `Err`, the program will **panic!** at runtime.
    
- **`.expect()`:** This method is identical to `.unwrap()` but allows you to provide a custom, descriptive error message that will be displayed if a panic occurs. This provides more context for debugging.
    
- **The Code:** This part shows a successful `.unwrap()` call and a commented-out line that would cause a panic. It then shows the `.expect()` method in action with a custom error message.
    

Rust

```Rust
fn divide(numerator: f64, denominator: f64) -> Result<f64, String> {
    if denominator == 0.0 {
        Err("Cannot divide by zero".to_string())
    } else {
        Ok(numerator / denominator)
    }
}

fn main() {
    let successful_result = divide(10.0, 2.0); // Returns `Ok(5.0)`
    
    // Successful extraction: `.unwrap()` retrieves the `f64` value.
    let number = successful_result.unwrap();
    println!("Unwrapped value: {}", number); // Output: Unwrapped value: 5
```

### Part 2: Safe Extraction with `.unwrap_or()`

This part demonstrates the `unwrap_or()` method, which is a safer alternative for handling a `Result` enum that might fail. Instead of panicking, it returns a fallback value.

- **`.unwrap_or()`:** This method attempts to extract the `Ok` value. If it's an `Err` variant, it returns a default or fallback value that you provide as an argument.
    
- **Type Safety:** The type of the fallback value must match the type of the success value (`T`) in the `Result` enum.
    
- **The Code:** This example shows how `unwrap_or()` works for both a successful and a failed `Result`, highlighting its ability to prevent crashes.
    

Rust

```Rust
fn divide(numerator: f64, denominator: f64) -> Result<f64, String> {
    if denominator == 0.0 {
        Err("Cannot divide by zero".to_string())
    } else {
        Ok(numerator / denominator)
    }
}

fn main() {
    let successful_result = divide(10.0, 2.0); // Returns `Ok(5.0)`
    let failed_result = divide(10.0, 0.0);    // Returns `Err("...")`
    
    // For a successful result, `.unwrap_or()` returns the `Ok` value.
    let number1 = successful_result.unwrap_or(0.0);
    println!("Successful unwrap_or: {}", number1); // Output: Successful unwrap_or: 5

    // For a failed result, `.unwrap_or()` returns the fallback value.
    let number2 = failed_result.unwrap_or(0.0);
    println!("Failed unwrap_or returns fallback: {}", number2); // Output: Failed unwrap_or returns fallback: 0
```

### Part 3: Checking the Variant with `is_ok()` and `is_err()`

This final part introduces two boolean-returning methods, `is_ok()` and `is_err()`, which are useful for checking the specific variant of a `Result` enum. This allows for conditional logic without needing a full `match` statement.

- **`is_ok()`:** Returns `true` if the variant is `Ok`, and `false` otherwise.
    
- **`is_err()`:** Returns `true` if the variant is `Err`, and `false` otherwise.
    
- **The Code:** This example shows how to use these methods to check the variant of a successful and a failed `Result`.
    

Rust

```Rust
fn divide(numerator: f64, denominator: f64) -> Result<f64, String> {
    if denominator == 0.0 {
        Err("Cannot divide by zero".to_string())
    } else {
        Ok(numerator / denominator)
    }
}

fn main() {
    let successful_result = divide(10.0, 2.0); // `Ok(5.0)`
    let failed_result = divide(10.0, 0.0);    // `Err("...")`
    
    // --- Checking a successful Result ---
    println!("For a successful result:");
    println!("Is it Ok? {}", successful_result.is_ok());   // Output: Is it Ok? true
    println!("Is it Err? {}", successful_result.is_err()); // Output: Is it Err? false
    
    // --- Checking a failed Result ---
    println!("\nFor a failed result:");
    println!("Is it Ok? {}", failed_result.is_ok());     // Output: Is it Ok? false
    println!("Is it Err? {}", failed_result.is_err());   // Output: Is it Err? true
}
```
