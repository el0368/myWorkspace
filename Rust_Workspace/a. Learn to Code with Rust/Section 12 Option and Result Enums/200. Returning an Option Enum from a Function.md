### Part 1: The Function that Returns an `Option`

This progressive example starts by introducing a common and powerful Rust design pattern: using `Option<T>` as a function's return type. This allows the function to gracefully handle scenarios where a return value might or might not exist, avoiding the need for null values or panicking.

- **Design Pattern:** The `Option` enum is perfect for modeling situations where a function's result is not guaranteed. `Some` represents a successful outcome with a value, while `None` represents a failure or a missing value.
    
- **Function Signature:** The function signature must specify the `Option` enum and its generic type parameter `T`. The function body must return either a `Some` variant with a value of type `T`, or a `None` variant.
    
- **The Code:** This part defines the `is_item_in_stock` function, which returns an `Option<bool>` to handle the three scenarios mentioned in the transcript.
    

Rust

```Rust
// A function that returns an `Option<bool>`.
// `Option` allows us to return a boolean or nothing at all.
fn is_item_in_stock(item_is_in_system: bool, item_is_in_stock: bool) -> Option<bool> {
    // Scenario 1: Item exists and is in stock.
    if item_is_in_system && item_is_in_stock {
        return Some(true);
    }
    
    // Scenario 2: Item exists but is out of stock.
    else if item_is_in_system {
        return Some(false);
    }
    
    // Scenario 3: Item does not exist in the system at all.
    else {
        return None;
    }
}

}
```

### Part 2: Matching on `Some` and `None`

This part demonstrates the basic way to handle the `Option` returned by the `is_item_in_stock` function. A simple `match` statement with two arms (`Some(value)` and `None`) is used to handle both success and failure cases.

- **`match` on `Option`:** The `match` keyword is the most robust and idiomatic way to consume an `Option`. It forces us to handle both the `Some` and `None` variants.
    
- **Binding the Value:** The `Some(value)` arm pattern binds the associated `bool` to a new variable called `value`, which can then be used in the arm's code block.
    
- **The Code:** This example shows two function calls, one that returns `Some(false)` and one that returns `None`, and uses a simple `match` statement to process them.
    

Rust

```Rust
// The function from Part 1
// ...

fn main() {
    println!("--- Scenario 1: Item exists, but is out of stock ---");
    let availability = is_item_in_stock(true, false);
    
    // The `match` statement handles both `Some` and `None`
    match availability {
        Some(value) => {
            println!("Item is available: {}", value); // Output: Item is available: false
        },
        None => {
            println!("Your item doesn't exist in our system.");
        },
    }
    
    println!("\n--- Scenario 2: Item doesn't exist ---");
    let availability = is_item_in_stock(false, false);
    
    match availability {
        Some(value) => {
            println!("Item is available: {}", value);
        },
        None => {
            println!("Your item doesn't exist in our system."); // Output: Your item doesn't exist in our system.
        },
    }
}
```

### Part 3: Matching on a Specific `Some` Value

This part introduces a more advanced and precise way to handle the `Option` enum. We refactor the `match` statement to have separate arms for `Some(true)` and `Some(false)`, allowing for more granular logic.

- **Precise `match` Arms:** You can create patterns that match not just the enum variant, but also the specific value it holds. This allows you to differentiate between the `Some(true)` and `Some(false)` cases, which are both handled by the single `Some(value)` arm in the previous part.
    
- **The Code:** This example shows the final, most robust `match` statement, which handles all three possibilities with distinct logic for each.
    

Rust

```Rust
// The function from Part 1
// ...

fn main() {
    // --- Scenario 1: Item exists and is in stock ---
    println!("--- Scenario 1: Item exists and is in stock ---");
    let availability = is_item_in_stock(true, true);
    
    match availability {
        Some(true) => { // This arm matches only if the variant is `Some` AND the value is `true`.
            println!("Yes, the item is available!");
        },
        Some(false) => { // This arm matches only if the variant is `Some` AND the value is `false`.
            println!("No, the item is not in stock.");
        },
        None => {
            println!("Your item doesn't exist in our system.");
        },
    }
    // Output: Yes, the item is available!
    
    // --- Scenario 2: Item exists, but is out of stock ---
    println!("\n--- Scenario 2: Item exists, but is out of stock ---");
    let availability = is_item_in_stock(true, false);
    
    match availability {
        Some(true) => {
            println!("Yes, the item is available!");
        },
        Some(false) => { // This arm is now matched.
            println!("No, the item is not in stock.");
        },
        None => {
            println!("Your item doesn't exist in our system.");
        },
    }
    // Output: No, the item is not in stock.
    
    // --- Scenario 3: Item doesn't exist ---
    println!("\n--- Scenario 3: Item doesn't exist ---");
    let availability = is_item_in_stock(false, false);
    
    match availability {
        Some(true) => {
            println!("Yes, the item is available!");
        },
        Some(false) => {
            println!("No, the item is not in stock.");
        },
        None => { // This arm is now matched.
            println!("Your item doesn't exist in our system.");
        },
    }
    // Output: Your item doesn't exist in our system.
}
```
