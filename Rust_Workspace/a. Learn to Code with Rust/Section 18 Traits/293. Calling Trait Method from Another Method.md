### Calling Trait Methods Within Other Methods

When we implement a trait for a type, the methods that come from the trait become available on that type. This means we can call them **inside other methods** we write for that type, just like any other method.

For example, suppose we want to add a method to our `Hotel` struct called `summarize`. This method should combine two pieces of information:

1. The hotel’s `name` field.
    
2. The return value of the `get_description` method, which is required by the `Accommodation` trait.
    

---

### Where Do We Define It?

It’s important to remember that:

- The `impl Accommodation for Hotel` block is **only for trait methods**. Rust requires us to implement the methods declared in the trait (no more, no less). We can’t add unrelated methods in that block.
    
- To add _regular methods_ unique to `Hotel`, we use the **plain `impl Hotel` block**.
    

So `summarize` belongs in `impl Hotel`, not in the trait implementation block.

---

### Writing the `summarize` Method

Here’s what it looks like:

```rust
impl Hotel {
    fn summarize(&self) -> String {
        format!("{}: {}", self.name, self.get_description())
    }
}
```

A few details worth noting:

- `&self` means the method borrows the `Hotel` immutably.
    
- We use the `format!` macro to build a string.
    
- Inside, we interpolate two values: `self.name` and `self.get_description()`.
    
- Calling `self.get_description()` works because `Hotel` implements the `Accommodation` trait, which guarantees that method exists.
    

---

### What Happens When We Call It

If `Hotel` does **not** define its own `get_description`, Rust falls back to the **default implementation** provided in the trait. For example, with our current setup, calling `summarize` might return:

```
The Luxe: A wonderful place to stay
```

But if `Hotel` had its own custom `get_description` method, then `summarize` would use that instead.

---

### One Big Limitation: No Mixing Defaults with Overrides

Something Rust does _not_ allow is **partially extending** a trait’s default method.

In some languages, you can:

- Call the parent’s (default) method,
    
- Then add extra logic around it.
    

In Rust, this is not possible. You must **choose one**:

- Either rely entirely on the default from the trait,
    
- Or completely override it with your own implementation.
    

So if you want `Hotel` to customize `get_description`, you must fully reimplement it. There’s no way to “call the default first, then do more.”

---

### Key Takeaways

- Trait methods can be invoked inside other methods on the same type, just like any other method.
    
- Custom methods unrelated to the trait must go in a plain `impl` block, not inside the trait’s `impl`.
    
- Default trait methods give you flexibility, but in Rust you cannot “extend” them — you either use the default or replace it entirely.
