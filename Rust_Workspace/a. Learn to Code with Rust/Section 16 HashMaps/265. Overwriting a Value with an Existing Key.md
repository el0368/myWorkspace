# Handling Duplicate Keys in Rust HashMaps

This document explains how Rust HashMaps handle duplicate keys, based on the provided transcript.

## Key Uniqueness in HashMaps

- **Unique Keys**: Every key in a Rust HashMap must be unique, as keys serve as identifiers for their corresponding values. Duplicate keys would create ambiguity when retrieving values.

## Behavior with Duplicate Keys

- **Replacement on Insert**: If you attempt to insert a key-value pair with a key that already exists in the HashMap, Rust will **replace** the existing key-value pair with the new one.
- **No Error**: The insertion does not cause an error; instead, the new value overwrites the old one for the given key.

## Example: Overwriting a Key-Value Pair

Using the `coffee_pairings` HashMap from previous lessons:

- **Initial State**: The HashMap contains the key `"Latte"` with the value `"Oat Milk"`.
- **Inserting Duplicate Key**: Calling `coffee_pairings.insert("Latte", "Pistachio Milk")` replaces the existing pair (`"Latte", "Oat Milk"`) with the new pair (`"Latte", "Pistachio Milk"`).

**Example Code**:

```rust
let mut coffee_pairings: HashMap<&str, &str> = HashMap::new();
coffee_pairings.insert("Latte", "Oat Milk");
println!("Before: {:?}", coffee_pairings); // Outputs: {"Latte": "Oat Milk"}
coffee_pairings.insert("Latte", "Pistachio Milk");
println!("After: {:?}", coffee_pairings); // Outputs: {"Latte": "Pistachio Milk"}
```

## Key Takeaways

- **Overwrite Behavior**: The `insert` method either adds a new key-value pair or replaces the existing pair if the key already exists.
- **Careful Usage**: Be cautious when using `insert`, as it silently overwrites existing values, which may lead to unintended data loss if not anticipated.
- **No Duplicates**: Rust ensures keys remain unique by replacing old values rather than allowing multiple entries for the same key.

This behavior ensures predictable and safe handling of key-value pairs in Rust HashMaps.
