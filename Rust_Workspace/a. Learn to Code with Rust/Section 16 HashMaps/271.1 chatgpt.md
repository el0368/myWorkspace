# Hash map (Rust) — in-depth study guide

---

## What a `HashMap` is (quick points)

- A **hash map** stores **unordered** key → value associations (`K -> V`).
    
- Keys must be **unique**; values may repeat.
    
- Use a hash map when you care about **lookup by key**, not element order.
    
- Rust's hash map lives in `std::collections::HashMap`.
    

---

## Types & creation

```rust
use std::collections::HashMap;

// common: compiler infers types from inserted data
let mut map = HashMap::new();

// if you create an empty map and don't insert immediately, you must annotate:
let mut typed_map: HashMap<String, i32> = HashMap::new();

// alternative macro (pre-populated)
let map2: HashMap<&str, i32> = [("a", 1), ("b", 2)].iter().cloned().collect();
```

**Notes**

- `HashMap<K,V>` has two generics: `K` (key type) and `V` (value type). Both must be consistent for the whole map.
    
- Keys must implement `Eq` + `Hash` (the compiler enforces this). Values have no special trait requirement.
    

---

## Insert / Update semantics

```rust
use std::collections::HashMap;

let mut scores = HashMap::new();
scores.insert("Blue".to_string(), 10);     // key and value moved into the map
scores.insert("Yellow".to_string(), 50);

// insert returns Option<V>: Some(previous_value) if the key existed
let prev = scores.insert("Blue".to_string(), 25); // replaces value 10 -> 25
assert_eq!(prev, Some(10));
```

**Key points**

- `insert(k, v)` **moves** `k` and `v` into the map (no clone unless you call `.clone()`).
    
- If the key already exists, the previous value is returned as `Option<V>` and replaced.
    
- Because insert consumes the key, if you need the key later, either clone it before insert or use owned key reuse strategies.
    

---

## Entry API (conditional insert / modify)

The `entry` API is extremely useful for patterns like “insert if absent” or “modify if present”:

```rust
use std::collections::HashMap;

let mut counts: HashMap<String, i32> = HashMap::new();
let word = "hello".to_string();

// increment count: create entry if not present
*counts.entry(word.clone()).or_insert(0) += 1;

// or_insert returns &mut V — you can mutate the value in place
```

Variants:

- `map.entry(key).or_insert(default)` — inserts `default` if key absent, returns `&mut V`.
    
- `or_insert_with(|| expensive_default())` — computes default only if needed.
    
- `entry` also supports `and_modify(...)` to conditionally modify an existing entry.
    

Common use: frequency counters, grouping, default initialization.

## Removing items

```rust
let mut m = HashMap::new();
m.insert("k".to_string(), 42);

// remove returns Option<V>
let val = m.remove("k"); // val == Some(42)
let none = m.remove("missing"); // None
```

**Notes**

- `remove(&key)` returns the removed value in `Some` or `None` if absent.
    
- Because `remove` returns the owned `V`, it moves the value out of the map.
    

---

## Accessing values

### `get`

```rust
let mut m = HashMap::new();
m.insert("k".to_string(), 10);

// get returns Option<&V>
if let Some(v) = m.get("k") {
    println!("value = {}", v); // v is &i32
}
```

- `get(&key)` returns `Option<&V>` — a **reference** to the stored value, not the owned value.
    
- Borrowing prevents moving the value out of the map, letting the map keep ownership.
    

### Indexing (`[]`)

```rust
let m: HashMap<String, i32> = [("a".to_string(), 1)].iter().cloned().collect();
// println!("{}", m["b"]); // panic: key not found
println!("{}", m["a"]); // works
```

- `m[&key]` **panics** if the key is missing. Use only when you are certain the key exists.
    
- Prefer `get` + pattern match for robust code.
    

---

## Iteration

```rust
for (k, v) in &m {          // iterates over (&K, &V)
    println!("{}: {}", k, v);
}

for k in m.keys() {         // iterates over &K
    println!("key: {}", k);
}

for v in m.values() {       // iterates over &V
    println!("value: {}", v);
}

// consume the map, yielding (K, V)
for (k, v) in m.into_iter() {
    // k and v are owned
}
```

**Notes**

- `&m` iteration borrows the map; map remains usable. `into_iter()` consumes it.

## Ownership & borrowing specifics

- **Insertion**: `insert(k, v)` moves `k` and `v` into the map. After `insert`, original variables are no longer usable unless they implement `Copy` or were cloned.
    
- **get**: returns a `&V` borrowing the value inside the map; ownership stays with the map.
    
- **remove**: returns `Option<V>` — you get the owned value back (moved out of the map).
    
- **Keys as references**: you can use `HashMap<&str, V>`, but you must ensure the referenced data outlives the map. For most apps, `HashMap<String, V>` is safer — the map owns its keys.
    

Example: keep map owning keys (recommended)

```rust
m.insert("key".to_string(), 5);
```

If you must avoid allocating for keys (e.g., when keys are static literals), `&'static str` keys are possible:

```rust
let mut m: HashMap<&'static str, i32> = HashMap::new();
m.insert("const_key", 1);
```

## Type inference & empty map gotcha

- `HashMap::new()` needs type information if you don't insert immediately:
    
    ```rust
    let mut m = HashMap::new(); // compiler error unless next inserts clarify types
    // missing type info -> specify:
    let mut m: HashMap<String, i32> = HashMap::new();
    ```
    
- If your next `insert` provides concrete key/value types, inference works automatically.

## `len`, `is_empty`, and map size

```rust
m.len();      // number of key-value pairs
m.is_empty(); // true if len == 0
```

## Ordering and complexity

- **Unordered**: iteration order is arbitrary and can change; do not rely on it.
    
- **Performance**: average O(1) lookup/insert/remove; worst-case can be worse due to collisions (implementation detail). For ordered maps, consider `BTreeMap` (different tradeoffs).

## Practical patterns (examples)

### Frequency counter (word counts)

```rust
let text = "hello hello world";
let mut counts = HashMap::new();
for word in text.split_whitespace() {
    *counts.entry(word.to_string()).or_insert(0) += 1;
}
println!("{:?}", counts); // {"hello":2, "world":1}
```

### Insert only if absent (`or_insert`)

```rust
let mut map = HashMap::new();
map.entry("key".to_string()).or_insert(100); // inserts 100 if missing
map.entry("key".to_string()).or_insert(200); // has no effect because key exists
```

### Update existing value (if present)

```rust
if let Some(v) = map.get_mut(&"key".to_string()) {
    *v += 1; // mutate in place
}
```

- `get_mut` returns `Option<&mut V>` for in-place mutation.

## Common pitfalls & best practices

- **Don’t index with `[]` unless certain the key exists** — prefer `get` and handle `None`.
    
- **Be explicit with ownership**: inserting moves values; clone if you need the original afterwards.
    
- **Prefer `String` keys for dynamic data**, or use `&'static str` / references only when lifetimes are known and safe.
    
- **Use `entry` for common conditional patterns** (increment counters, default insertion).
    
- **Remember map is unordered** — if a stable order is required, sort keys or use a `BTreeMap`.
    
- **Avoid storing references to short-lived data** (e.g., temporaries) as keys or values — ensure referents outlive the map.

## Quick method reference (common)

|Operation|Method|Signature (conceptual)|
|---|--:|---|
|create|`HashMap::new()`|`HashMap<K, V>`|
|insert/replace|`insert(k, v)`|`fn insert(&mut self, K, V) -> Option<V>`|
|conditional insert|`entry(k).or_insert(v)`|`Entry<K,V>` API → `&mut V`|
|remove|`remove(&k)`|`fn remove(&mut self, &K) -> Option<V>`|
|read|`get(&k)`|`fn get(&self, &K) -> Option<&V>`|
|mutate in place|`get_mut(&k)`|`fn get_mut(&mut self, &K) -> Option<&mut V>`|
|iterate|`for (k, v) in &map`|yields `(&K, &V)`|
|check key|`contains_key(&k)`|`fn contains_key(&self, &K) -> bool`|
|length|`len()` / `is_empty()`|`usize` / bool|

## Minimal checklist when designing with `HashMap`

1. Decide types `K` and `V` and ensure `K: Eq + Hash`.
    
2. Choose whether map should **own** keys/values (`String`) or borrow them (`&str`) — prefer owning for general use.
    
3. Use `entry` for default/accumulator patterns.
    
4. Use `get/get_mut` instead of `[]` to avoid panics.
    
5. Keep map lifetimes clear when using references as keys/values.
