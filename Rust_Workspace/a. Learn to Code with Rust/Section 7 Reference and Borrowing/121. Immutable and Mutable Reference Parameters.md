### Step 0: The Initial Problem (The Starting Code) 🔑

We begin with code that works, but it's inefficient and verbose. The core issue is **ownership**.

**Starting Code:**

Rust

```Rust
fn main() {
    let mut current_meal: String = String::new();
    // `add_flour` takes ownership of `current_meal`...
    current_meal = add_flour(current_meal);
    // ...and we need to re-assign the returned value to get ownership back.
}

// `add_flour` takes ownership of the String.
fn add_flour(mut meal: String) -> String {
    meal.push_str("Add flour");
    // It must return the String to give ownership back.
    meal
}
```

**Analysis:**

- The `add_flour` function takes `meal` **by value**, which means it takes full ownership of the `String` passed into it.
    
- Because `main`'s `current_meal` variable is "moved" into the function, `add_flour` must return the `String` at the end to give ownership back to `main`.
    
- This creates a cumbersome pattern of passing a value in, only to have to catch it again on return.
    

---

### Step 1: Introducing Immutable Borrows with `show_my_meal` 📖

The first step is to create a function that only needs to _read_ data. This is the perfect use case for an **immutable reference** (also called an immutable borrow), which allows the function to look at the data without taking ownership.

**Action:** We create `show_my_meal` and then call it from `main`.

**Code Changes:**

1. **Define `show_my_meal` with a reference parameter:** The parameter type is changed from `meal: String` (take ownership) to `meal: &String` (borrow immutably).
    
2. **Call the function by passing a reference:** In `main`, we call it with `&current_meal`, creating a reference to pass in.
    

Rust

```Rust
// In main():
show_my_meal(&current_meal);

// New function definition:
fn show_my_meal(meal: &String) { // <-- Parameter is now a reference
    println!("Meal steps: {meal}");
}
```

**Explanation:**

- `meal: &String` means this function borrows the `String` but doesn't own it.
    
- It has read-only access. It cannot modify the `String`.
    
- When the function ends, only the reference (`meal`) is dropped. The original `current_meal` in `main` remains the owner and is completely unaffected.
    

---

### Step 2: Modifying `add_flour` to Use a Mutable Borrow ✍️

Now, we apply the same borrowing concept to `add_flour`. Since this function needs to _change_ the data, we use a **mutable reference**.

**Action:** Update the `add_flour` function signature and body.

**Code Changes:**

1. **Change the parameter type:** The parameter is changed from `mut meal: String` to `meal: &mut String`.
    
2. **Remove the return:** Since the function now modifies the original `String` directly, it no longer needs to return it.
    

Rust

```Rust
// The updated function signature and body:
fn add_flour(meal: &mut String) { // <-- Parameter is now a MUTABLE reference
    meal.push_str("Add flour");
    // No longer need to return `meal`
}
```

**Explanation:**

- `meal: &mut String` means the function borrows a **mutable** reference to a `String`.
    
- This gives the function permission to modify the original value at its memory address.
    
- Ownership of the `String` itself still remains with `current_meal` in `main`.
    

---

### Step 3: Updating the Call in `main` ✅

Finally, we update the `main` function to correctly call the new version of `add_flour`.

**Action:** Change how `add_flour` is called.

**Code Changes:**

1. **Pass a mutable reference:** The call is changed from `current_meal = add_flour(current_meal)` to `add_flour(&mut current_meal)`.
    
2. **Remove the reassignment:** Since `add_flour` no longer returns a value, we don't need to assign its result back to `current_meal`.
    

Rust

```Rust
// In main():
add_flour(&mut current_meal); // <-- Pass a mutable reference
```

**Explanation:**

- The `&mut current_meal` syntax creates a mutable borrow of `current_meal` and passes it to the function.
    
- The `add_flour` function modifies `current_meal` in place.
    

---

### Final Code and Summary

This is the final, idiomatic version of the code that uses borrowing effectively to avoid unnecessary moves.

Rust

```Rust
fn main() {
    let mut current_meal: String = String::new();

    // Pass a mutable reference to modify the String in place.
    add_flour(&mut current_meal);

    // Pass an immutable reference to read the String.
    show_my_meal(&current_meal);
}

// Borrows a mutable reference and modifies the original String.
fn add_flour(meal: &mut String) {
    meal.push_str("Add flour");
}

// Borrows an immutable reference and reads the original String.
fn show_my_meal(meal: &String) {
    println!("Meal steps: {meal}");
}
```

This final version is more efficient and clearly expresses the intent: `show_my_meal` only reads the data, while `add_flour` modifies it, all without transferring ownership.
