### Part 1: The Problem with Type-Specific Functions

This guide starts by demonstrating the problem that generics solve: code duplication for identical logic that operates on different types.

- **Hard-Coded Types:** By hard-coding a specific data type (like `i32` or `bool`) in a function's signature, you limit its use to only that type.
    
- **Code Duplication:** If you need the exact same functionality for a different type, you are forced to duplicate the function and simply change the type annotations.
    
- **The Code:** This example shows two functions with identical logic but different, hard-coded types.
    

Rust

```Rust
// A simple function that works only with i32s.
fn identity_i32(value: i32) -> i32 {
    value
}

// A duplicate function with the same logic, but for bools.
fn identity_bool(value: bool) -> bool {
    value
}

fn main() {
    let result_i32 = identity_i32(5);
    println!("i32 result: {}", result_i32);
    
    let result_bool = identity_bool(true);
    println!("bool result: {}", result_bool);
    
    // The rest of this code is completed in the next parts.
}
```

### Part 2: The Solution - Introducing Generics

This part introduces the generic syntax as the solution to the problem from Part 1. Generics allow you to write a single function that works for multiple types.

- **Generic Type Parameter:** A generic is a placeholder for a type. You declare it in angle brackets `< >` after the function name. `T` is the common convention for the name, as it stands for "Type."
    
- **Using the Generic:** Once a generic type (`T`) is declared, you can use it to annotate parameters and return values. This signals that they are related and must be of the same type, even though the specific type is unknown.
    
- **The Code:** This example shows the single `identity` function that replaces the two functions from Part 1.
    

Rust

```Rust
// The `<T>` declares a generic type parameter named `T`.
// `value: T` says the parameter can be of any type `T`.
// `-> T` says the return type must be the same type `T`.
fn identity<T>(value: T) -> T {
    // The logic inside the function is type-agnostic.
    value
}

// The rest of this code is completed in the next parts.
fn main() {
    // This part will be completed in the next parts.
}
```

### Part 3: Invoking a Generic Function

This part demonstrates the power and flexibility of the generic `identity` function. You can call it with different types of arguments, and the compiler will automatically deduce the concrete type for `T` in each case.

- **Type Deduction:** The compiler automatically determines the specific type for `T` at the point of invocation based on the argument you pass in.
    
- **The Code:** This example shows the same `identity` function being called with a variety of different types, all of which work perfectly.
    

```Rust
fn identity<T>(value: T) -> T {
    value
}

fn main() {
    // Rust deduces that `T` is `i32`.
    let num_result = identity(5);
    println!("i32 result: {}", num_result);
    
    // Rust deduces that `T` is `f64`.
    let float_result = identity(13.14);
    println!("f64 result: {}", float_result);
    
    // Rust deduces that `T` is `bool`.
    let bool_result = identity(true);
    println!("bool result: {}", bool_result);

    // This also works with more complex types like String and custom structs.
    let string_result = identity(String::from("Rust"));
    println!("String result: {}", string_result);
    
    // We can even use custom types with generics, as long as they meet any necessary requirements.
    #[derive(Debug)]
    struct DeliSandwich;
    let sandwich_result = identity(DeliSandwich);
    println!("Custom type result: {:?}", sandwich_result);
}
```

### Part 4: Monomorphization (The Compiler's Magic)

This final part reveals the "magic" behind generics in Rust: the compiler's **monomorphization** process, which ensures that generics have zero runtime cost.

- **Monomorphization:** This is a compile-time process where Rust replaces each generic function with a concrete version for every unique type it is used with. The generic code you write is a template, and the compiler fills in that template for each use case.
    
- **The Result:** The final compiled executable contains no generic code. Instead, it has multiple, highly optimized, type-specific functions. This gives you the convenience of writing one generic function with the performance of writing many specific ones.
    
- **The Code (Conceptual):** This example shows what the compiler's output would be for our generic `identity` function after monomorphization.
    

Rust

```Rust
// The generic `identity` function as you write it:
fn identity<T>(value: T) -> T {
    value
}

// After monomorphization, the compiler generates something like this for your executable:

// This function is created for the `i32` call:
fn identity_i32(value: i32) -> i32 {
    value
}

// This function is created for the `f64` call:
fn identity_f64(value: f64) -> f64 {
    value
}

// And this one for the `bool` call, and so on...
fn identity_bool(value: bool) -> bool {
    value
}

// The final executable contains these concrete, performant functions.
```
