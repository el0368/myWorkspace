Generics are placeholders for types that allow you to write reusable code that can work with different data types without duplication. Here are some code examples illustrating how to use generics in functions, structs, and enums, as well as with methods.

### Generics in Functions

Generics make functions more flexible by allowing them to operate on various types. The generic type `T` is defined in angle brackets `<T>` after the function name.

Rust

```Rust
// This function can find the largest item in a slice of any type T
// as long as T can be compared (implements the 'PartialOrd' trait) and copied.
fn largest<T: PartialOrd + Copy>(list: &[T]) -> T {
    let mut largest = list[0];

    for &item in list.iter() {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let number_list = vec![34, 50, 25, 100, 65];
    let result = largest(&number_list);
    println!("The largest number is {}", result); // The largest number is 100

    let char_list = vec!['y', 'm', 'a', 'q'];
    let result = largest(&char_list);
    println!("The largest char is {}", result); // The largest char is y
}
```

In this example, the `largest` function works for both a `Vec<i32>` and a `Vec<char>` because `i32` and `char` are types that can be compared and copied, which is a requirement defined by the **trait bounds** `PartialOrd` and `Copy`.

### Generics in Structs

Using generics in struct definitions allows a single struct to hold fields of different types.

Rust

```Rust
// A struct 'Point' that can hold two values of any type T.
struct Point<T> {
    x: T,
    y: T,
}

// A struct 'PointMixed' that can hold two values of potentially different types, T and U.
struct PointMixed<T, U> {
    x: T,
    y: U,
}

fn main() {
    // Both fields are of type i32
    let integer = Point { x: 5, y: 10 };
    // Both fields are of type f64
    let float = Point { x: 1.0, y: 4.0 };
    // This would result in a compile error because the types must be the same.
    // let wont_work = Point { x: 5, y: 4.0 };

    // Fields can have different types
    let mixed = PointMixed { x: 5, y: 4.0 };
    println!("The x value is {} and the y value is {}", mixed.x, mixed.y); // The x value is 5 and the y value is 4.0
}
```

### Generics in Enums

Generics are also common in enums, particularly for variants that hold associated data. A great example is the `Option<T>` enum, which is a built-in part of the Rust standard library.

Rust

```Rust
// The Option enum is a generic type.
// The T represents the type of data the Some variant can hold.
// enum Option<T> {
//    None,
//    Some(T),
// }

fn main() {
    // The Option is instantiated with an i32
    let some_integer = Some(5);
    // The Option is instantiated with a f64
    let some_float = Some(3.14);
    // The Option is instantiated with a String
    let some_string = Some("a string");
    // The Option is instantiated as None, without a type.
    let none: Option<i32> = None;

    // We can use a match statement to handle both Some and None variants.
    if let Some(x) = some_integer {
        println!("The value is: {}", x); // The value is: 5
    }
}
```

### Methods with Generics

Defining methods for generic structs requires you to declare the generic type in the `impl` block as well.

Rust

```Rust
struct Point<T> {
    x: T,
    y: T,
}

// This 'impl' block defines a method for any generic type T.
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

// This 'impl' block defines a method that only works when T is a specific type, f64.
impl Point<f64> {
    fn distance_from_origin(&self) -> f64 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}

fn main() {
    let p = Point { x: 5, y: 10 };
    println!("p.x = {}", p.x()); // p.x = 5

    let p2 = Point { x: 3.0, y: 4.0 };
    // This works because the impl block for 'distance_from_origin' is specific to f64.
    println!("Distance from origin: {}", p2.distance_from_origin()); // Distance from origin: 5
    
    // The following line would be a compile error because 'distance_from_origin'
    // is not defined for Point<i32>
    // p.distance_from_origin();
}
```

This example shows how to implement methods that apply to all generic types (`x()`) and methods that are specialized for a particular concrete type (`distance_from_origin()`).
