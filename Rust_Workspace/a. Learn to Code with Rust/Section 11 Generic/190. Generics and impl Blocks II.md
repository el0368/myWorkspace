### Part 1: The Generic `impl` Block Syntax (The Solution)

This progressive example introduces the correct syntax for defining methods on a generic struct that should be available for **any** type of generic parameter `T`.

- **The Problem:** The previous approach, `impl TreasureChest<String>`, was too restrictive. It only applied to structs with a `String` treasure. Simply writing `impl TreasureChest<T>` is also incorrect, as Rust would mistake `T` for a concrete type name.
    
- **The Solution:** The correct syntax is to declare the generic type parameter in angle brackets after the `impl` keyword. This tells the compiler that the `T` is a placeholder, not a concrete type.
    
- **The Code:** This part shows the `impl<T> TreasureChest<T>` syntax that allows for a universal method definition.
    

Rust

```Rust
// Our generic struct blueprint.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

// The new syntax: `<T>` is declared after `impl` to signal it's a generic.
// The `T` in `TreasureChest<T>` then refers to this generic.
impl<T> TreasureChest<T> {
    // Methods defined here will exist on ANY `TreasureChest` struct,
    // regardless of what concrete type `T` is.
    // The method's logic, however, can only use the non-generic fields
    // or generic fields in a type-agnostic way.

    fn capital_captain(&self) -> String {
        // `self.captain` is always a `String`, so this works for any `T`.
        self.captain.to_uppercase()
    }
}

fn main() {
    // This part will be completed in the next examples.
}
```

### Part 2: Defining a Method for All Generic Types

This part shows a concrete method, `capital_captain`, defined within the generic `impl` block. This method works for any type `T` because its logic only relies on the `captain` field, which is a hard-coded `String` and therefore always has a known type.

- **Method Logic:** The method takes an immutable reference (`&self`) as it only needs to read the `captain` field. It returns a new `String` with the captain's name in uppercase.
    
- **Compatibility:** This method will be universally compatible with all `TreasureChest` instances because it does not depend on the specific type of `self.treasure`.
    

Rust

```Rust
// The generic struct and `impl<T>` block from Part 1.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

impl<T> TreasureChest<T> {
    fn capital_captain(&self) -> String {
        self.captain.to_uppercase()
    }
}

fn main() {
    // We create three instances with different types for `T`.
    // Instance 1: T is a string literal (&str)
    let gold_chest = TreasureChest {
        captain: String::from("Firebeard"),
        treasure: "Gold",
    };

    // Instance 2: T is a `String`
    let silver_chest = TreasureChest {
        captain: String::from("Bloodsail"),
        treasure: String::from("Silver"),
    };
    
    // Instance 3: T is an array of string slices ([&str; 3])
    let special_chest = TreasureChest {
        captain: String::from("Bootyplunder"),
        treasure: ["Gold", "Silver", "Platinum"],
    };

    // This part will be completed in the next example.
}
```

### Part 3: Invoking the Method on All Generic Instances

This final part demonstrates the power of the generic `impl` block by calling the `capital_captain` method on each of the three different `TreasureChest` instances.

- **Universal Availability:** The `capital_captain` method is available on all three instances, regardless of whether `T` is an `&str`, a `String`, or an array.
    
- **The Code:** This example shows the complete, working program with the method calls and the final output.
    

Rust

```Rust
// The final generic struct and impl block.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

impl<T> TreasureChest<T> {
    fn capital_captain(&self) -> String {
        self.captain.to_uppercase()
    }
}

fn main() {
    let gold_chest = TreasureChest {
        captain: String::from("Firebeard"),
        treasure: "Gold",
    };
    
    let silver_chest = TreasureChest {
        captain: String::from("Bloodsail"),
        treasure: String::from("Silver"),
    };
    
    let special_chest = TreasureChest {
        captain: String::from("Bootyplunder"),
        treasure: ["Gold", "Silver", "Platinum"],
    };

    println!("Captain of gold chest: {}", gold_chest.capital_captain());
    // Output: Captain of gold chest: FIREBEARD
    
    println!("Captain of silver chest: {}", silver_chest.capital_captain());
    // Output: Captain of silver chest: BLOODSAIL
    
    println!("Captain of special chest: {}", special_chest.capital_captain());
    // Output: Captain of special chest: BOOTYPLUNDER
}

// For comparison, this method would NOT be available on all three structs:
// impl TreasureChest<String> {
//     fn clean_treasure(&mut self) { /* ... */ }
// }
// This method would only exist for the `silver_chest` instance, not the others.
```
