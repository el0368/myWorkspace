# Study Guide: Ownership (Rust)

---

## 1) Core Ownership Rules

1. **Each value has exactly one owner at a time.**
    
2. **Ownership can move** (a _move_ transfers ownership to a new owner).
    
3. **When the owner goes out of scope, the value is cleaned up** (memory is deallocated).
    

These rules allow Rust to manage memory without a garbage collector and prevent use-after-free, double-free, and data races at compile time.

---

## 2) Stack vs. Heap: Mental Model

- **Stack**
    
    - Fixed-size, known-at-compile-time data (e.g., `i32`, `f64`, `bool`).
        
    - Very fast push/pop (LIFO).
        
    - Values copied cheaply if they implement `Copy`.
        
- **Heap**
    
    - Dynamically sized data decided at runtime (e.g., `String`’s contents).
        
    - Allocated by a **memory allocator**; program receives an **address (reference)** to reach it.
        
    - Avoid duplicating heap data unless you truly need it (explicit `clone`).
        

---

## 3) Moves vs Copies vs Clones

### Copy (cheap duplication, stack data)

Types like integers/floats/bools usually implement `Copy`. Assigning or passing them duplicates the value.

```rust
let a: i32 = 10;
let b = a;           // a is still valid: i32 is Copy
println!("{a}, {b}"); // 10, 10
```

### Move (transfer of ownership, no duplication)

Types like `String` (heap-owning) **do not** implement `Copy`. Assigning or passing them **moves** ownership.

```rust
let s1 = String::from("hello");
let s2 = s1;             // move: s1 becomes invalid
// println!("{s1}");     // ❌ compile error: value moved
println!("{s2}");        // ✅ "hello"
```

### Clone (explicit deep duplication)

If you truly need another owned copy of heap data, **clone** it.

```rust
let s1 = String::from("hello");
let s2 = s1.clone();     // deep copy of heap data
println!("{s1}, {s2}");  // both valid
```

**Guideline:** Prefer moves & references to keep programs efficient. Use `clone` sparingly and intentionally.

---

## 4) Scope, Blocks, and Cleanup (`drop`)

- A **scope** is created by `{ ... }`. When a value’s owner leaves scope, Rust runs cleanup automatically.
    
- You can also end ownership early using `std::mem::drop`.
    

```rust
{
    let temp = String::from("temporary");
    // use temp...
    std::mem::drop(temp);   // explicitly free now
    // temp is invalid here
}
// scope ends, other owned values are dropped automatically
```

---

## 5) Strings and Ownership (why `String` moves)

Rust has two core “string” types:

- `&str` — **string slice** (borrowed reference), often from string literals in the executable; **does not own**.
    
- `String` — **owned, growable** heap string; **owns** its buffer on the heap.
    

Because `String` owns heap data, Rust avoids implicit duplication. Assignments and parameter passing move ownership unless you **borrow** or **clone**.

---

## 6) References & Borrowing

- A **reference** is an **address** to existing data; it **borrows** instead of owning.
    
- Create a reference with `&value` (“borrow operator”).
    
- **Borrowing lets you use data without taking ownership** and without duplicating it.
    

```rust
let s = String::from("hello");
let r: &String = &s;     // borrow, not move
println!("{r}");         // prints "hello"
```

- **Dereferencing** with `*` follows an address to the value:
    
    ```rust
    let x = 42;
    let rx = &x;
    assert_eq!(*rx, 42);   // dereference to use the value directly
    ```
    
- In many everyday operations (e.g., `println!`), Rust **auto-dereferences** so you can write `println!("{rx}")` and it prints the value, not the address.
    
- **Immutable references** can be freely copied: `let r2 = r;` is fine; they point to the same data.
    

> Note: The transcript emphasizes immutable references; (mutability and borrowing rules are explored more deeply later).

## 7) Function Parameters and Ownership

Function calls follow the same rules as assignment.

### Passing a non-Copy value moves it

```rust
fn takes_string(s: String) {
    println!("{s}");
}

fn main() {
    let name = String::from("Ada");
    takes_string(name);    // move into function
    // println!("{name}"); // ❌ moved
}
```

### Passing a Copy type duplicates it

```rust
fn takes_i32(n: i32) {
    println!("{n}");
}

fn main() {
    let n = 7;
    takes_i32(n);          // copy into function
    println!("{n}");       // ✅ still usable
}
```

### Borrow to avoid moves

Use references to _read_ without taking ownership:

```rust
fn len_of(s: &String) -> usize {
    s.len()                // uses borrowed value
}

fn main() {
    let title = String::from("Rust");
    let l = len_of(&title); // borrow instead of move
    println!("{title} has length {l}");
}
```

This pattern (pass `&T` instead of `T`) prevents ownership transfer and avoids the need to return the value.

---

## 8) Address vs. Value (seeing the difference)

A reference is an address; you can print the address with `:p`:

```rust
let s = String::from("hi");
let r = &s;
println!("addr of s: {:p}", r); // shows the pointer value
println!("value: {r}");         // auto-deref prints "hi"
```

This clarifies “reference (address) vs. value”.

## 9) Common Pitfalls (and Fixes)

1. **Using a moved value**
    
    ```rust
    let s1 = String::from("x");
    let s2 = s1;
    // println!("{s1}"); // ❌ moved
    ```
    
    **Fix:** Use `clone()` if you truly need two owned copies; or borrow instead.
    
2. **Forgetting that function parameters move by default**
    
    - Passing a `String` by value moves ownership.
        
    - **Fix:** Change the function to take `&String` (borrow) if it only needs to read.
        
3. **Unnecessary cloning**
    
    - `clone()` is convenient but can be costly on big data.
        
    - **Fix:** Prefer borrowing `&T` where possible.

## 10) Progressive Examples

### A) Move, then Fix with Clone

```rust
// ❌ move error
let original = String::from("data");
let moved = original;
// println!("{original}"); // error

// ✅ explicit clone when two owners are required
let a = String::from("data");
let b = a.clone();
println!("{a} | {b}");
```

### B) Pass by Value vs Borrow

```rust
fn shout(s: String) -> String {
    s.to_uppercase()
}

fn shout_ref(s: &String) -> String {
    s.to_uppercase()
}

fn main() {
    let name = String::from("Ada");

    // Moves:
    let upper = shout(name);
    // println!("{name}"); // ❌ moved

    let name2 = String::from("Grace");
    // Borrows (no move):
    let upper2 = shout_ref(&name2);
    println!("{name2} -> {upper2}");
}
```

### C) Scope and Cleanup Timing

```rust
fn main() {
    let outside = String::from("outside");
    {
        let inside = String::from("inside");
        println!("{inside}");
        // `inside` dropped here automatically
    }
    println!("{outside}");
    std::mem::drop(outside); // explicitly drop early
    // println!("{outside}"); // ❌ already dropped
}
```

## 11) Quick Reference (no pun intended)

- **One owner at a time.**
    
- Ownership **moves** on assignment and argument passing for non-Copy types.
    
- **Copy** types (e.g., integers) are duplicated on assignment and argument passing.
    
- Use **`clone()`** to make an explicit deep copy of heap-owning data.
    
- **Scope** end ⇒ owner drops ⇒ memory freed.
    
- **References (`&T`)** let you **borrow** without owning or duplicating.
    
- **Dereference (`*`)** follows a reference to the value; many places auto-deref for you.
    
- For functions, pass **`&T`** when you only need to read; pass **`T`** if you need to take ownership or mutate (discussed further in later sections).
