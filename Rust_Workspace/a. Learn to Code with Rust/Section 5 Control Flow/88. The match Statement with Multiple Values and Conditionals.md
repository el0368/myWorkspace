## Rust Control Flow: Advanced `match` Patterns

This study guide explores more sophisticated ways to use the `match` statement in Rust, allowing for more flexible pattern matching beyond simple direct value comparisons.

### I. Matching Against Multiple Values in a Single Arm (The `|` Operator)

How can I make one match arm handle several specific values?

You can use the pipe symbol (|) as an OR operator within a pattern to specify that an arm should match if the value corresponds to any of the listed options.

- **Syntax:** `value1 | value2 | value3 => { ... }`
    
- **Purpose:** This is useful when several distinct input values should lead to the exact same logic or produce the same output. It's concise and readable compared to repeating the same code for multiple single-value arms.
    
- **Behavior:** The `match` statement will check if the `value_to_match` is equal to `value1` OR `value2` OR `value3`. If any match is found, that arm is executed.
    

**Example: Even/Odd with Explicit Value Lists**

Rust

```Rust
fn main() {
    let number = 8; // Change this to 2, 4, 6, 8, 1, 3, 5, or 100 to test

    match number {
        // This arm matches if 'number' is 2, OR 4, OR 6, OR 8
        2 | 4 | 6 | 8 => {
            println!("{} is a small, even number.", number);
        },
        // This arm matches if 'number' is 1, OR 3, OR 5
        1 | 3 | 5 => {
            println!("{} is a small, odd number.", number);
        },
        // The catch-all pattern to handle all other integers
        _ => {
            println!("{} is not a small number (or an unlisted one).", number);
        },
    }
}
```

**Tracing `number = 8`:**

1. Rust checks `number` against the first pattern: `2 | 4 | 6 | 8`.
    
2. `8` matches `8`.
    
3. The first arm's block is executed: `println!("8 is a small, even number.");`.
    
4. No other arms are checked or executed.

### II. Conditional Matching with `if` Guards in Patterns

How can I add an extra condition to a match arm that isn't just a direct value comparison?

You can use an if guard directly after a pattern within a match arm. This allows you to introduce an additional Boolean condition that must be true for that pattern to be considered a match.

- **Syntax:** `pattern if boolean_condition => { ... }`
    
- **Purpose:** This is incredibly powerful for complex logic where a simple value match isn't enough, but you still want the exhaustiveness guarantees of `match`.
    
- **Variable Binding:** You can often **bind the matched value to a temporary variable** within the pattern itself (e.g., `value` in `value if ...`). This variable can then be used in the `if` guard and within the arm's code block.
    
    - This bound variable is specific to that match arm's scope.
        
- **Evaluation Order:** Rust first checks if the value matches the _pattern_. If it does, then it evaluates the _`if` guard_. Both must be true for the arm to be chosen.
    

**Example: Even/Odd using `if` Guards**

Rust

```Rust
fn main() {
    let number = 5; // Change this to 8, 5, 0, or any other integer

    match number {
        // 'val' is a temporary variable that holds the 'number' for this arm.
        // This arm matches ANY integer 'val' IF 'val' is even.
        val if val % 2 == 0 => {
            println!("{} is an even number.", val);
        },
        // This arm matches ANY integer 'val' IF 'val' is odd.
        val if val % 2 != 0 => { // Alternatively: `val if val % 2 == 1` or just `val` with an `else` at the end
            println!("{} is an odd number.", val);
        },
        // Note: For integers, the compiler isn't "smart enough" to know that
        // (val % 2 == 0) and (val % 2 != 0) cover all possibilities.
        // Therefore, the catch-all `_` is still required to satisfy exhaustiveness.
        _ => {
            unreachable!(); // This arm should logically never be reached for an i32
        },
    }
}
```

**Tracing `number = 5`:**

1. Rust starts matching `number` (which is `5`).
    
2. It checks the first arm: `val if val % 2 == 0`.
    
    - Does `5` match `val`? Yes, `val` is temporarily `5`.
        
    - Is `5 % 2 == 0`? No, `5 % 2` is `1`, which is not `0`. The `if` guard is `false`. **Arm fails to match.**
        
3. Rust moves to the second arm: `val if val % 2 != 0`.
    
    - Does `5` match `val`? Yes, `val` is temporarily `5`.
        
    - Is `5 % 2 != 0`? Yes, `5 % 2` is `1`, which is not equal to `0`. The `if` guard is `true`. **Arm matches!**
        
4. The second arm's block is executed: `println!("5 is an odd number.");`.
    
5. No other arms are checked.

### III. The `unreachable!` Macro

What is the unreachable! macro?

The unreachable! macro is a special debugging and development tool in Rust.

- **Syntax:** `unreachable!();` (like all macros, ends with `!`, and invoked with `()`).
    
- **Purpose:** It's used in `match` arms (or other code paths) that you, as the programmer, are **certain will logically never be reached** at runtime.
    
- **Compiler Satisfaction:** Its primary role is to **satisfy Rust's exhaustiveness checker** for `match` statements when the compiler isn't smart enough to deduce that all cases are covered by your `if` guards or complex logic.
    
- **Runtime Behavior:** If, contrary to your belief, the `unreachable!` macro _is_ actually executed at runtime (due to a logical error in your code), it will cause the program to **panic!** (crash). This provides a strong signal during testing that your assumptions about code paths were incorrect.
    
- **Benefit for Readers:** It clearly communicates to anyone reading the code that this particular branch should theoretically never be taken.
    

**Example of `unreachable!` (as shown above in Even/Odd `if` guard example):**

Rust

```Rust
// ... (inside the match statement)
_ => { // This arm should logically never be reached for an i32 number
    unreachable!("A number is always either even or odd if modulo 2 works.");
    // An optional message can be added inside the parentheses for more context on panic.
},
```

In the even/odd example, since `number % 2 == 0` or `number % 2 != 0` _must_ be true for any integer, the `_` (catch-all) arm should never be reached. Using `unreachable!()` tells the compiler this and acts as a runtime assertion.

### IV. Key Takeaways

- **Multiple Value Matching (`|`):** Use `|` within a single `match` arm to apply the same logic to several distinct literal values.
    
- **`if` Guards:** Add an `if condition` after a pattern (`pattern if condition => ...`) to introduce additional Boolean logic to an arm. This allows for more complex conditional matching.
    
    - You can bind the matched value to a temporary variable within the pattern (e.g., `val if ...`) and use it in the guard and arm body.
        
- **`unreachable!` Macro:** A macro used to satisfy the compiler's exhaustiveness checks for `match` statements when you are logically certain a particular arm will never be reached. If it _is_ reached, the program will panic.
    
- **Order of Arms:** Still crucial. Patterns are evaluated top-down. The `_` (catch-all) pattern and arms with broad `if` guards should generally come last to avoid making earlier, more specific patterns unreachable.
    

These advanced `match` features significantly enhance Rust's pattern matching capabilities, making it a powerful and safe tool for handling complex control flow.
