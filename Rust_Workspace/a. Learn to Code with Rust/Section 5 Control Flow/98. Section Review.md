## Rust Control Flow: Section Review Study Guide

This section focused on **Control Flow**, which dictates **how a program will execute** by altering the sequential flow of its logic based on conditions or for repetition.

### I. Conditional Execution: `if`, `else if`, `else`, and `match`

Conditional constructs allow code to execute selectively, providing multiple pathways based on dynamic data.

1. **`if` Statement:**
    
    - **Purpose:** Executes an associated code block only if its condition evaluates to `true`. Introduces conditional logic.
        
    - **Syntax:** `if condition { /* ... */ }`
        
    - **Requirement:** The `condition` must strictly evaluate to a `bool` (`true` or `false`). Rust does not have "truthiness."
        
    - **No Parentheses:** Do not wrap the condition in parentheses.
        
    
    Rust
    
    ```Rust
    let is_raining = true;
    if is_raining {
        println!("Take an umbrella!");
    }
    ```
    
2. **`else if` Statement:**
    
    - **Purpose:** Provides an alternative conditional pathway. Its block executes if its condition is `true` AND all preceding `if` or `else if` conditions in the chain were `false`.
        
    - **Chain Behavior:** Rust checks conditions sequentially from top to bottom and **executes only the block of the _first_ condition that evaluates to `true`**. All subsequent conditions in the chain are skipped.
        
    - **Dependency:** Must follow an `if` statement.
        
    
    Rust
    
    ```Rust
    let score = 85;
    if score >= 90 {
        println!("Grade: A");
    } else if score >= 80 { // Only checked if score < 90
        println!("Grade: B");
    } // ... more else if's
    ```
    
3. **`else` Keyword:**
    
    - **Purpose:** Serves as a **fallback option**. Its block executes if **all preceding `if` and `else if` conditions in the chain have evaluated to `false`**.
        
    - **No Condition:** The `else` keyword itself does not have an associated condition.
        
    - **Guarantee:** Guarantees that **exactly one block** in the entire `if-else if-else` chain will always execute.
        
    - **Dependency:** Must come at the very end of an `if` or `if-else if` chain.
        
    
    Rust
    
    ```Rust
    let temperature = 28;
    if temperature > 30 {
        println!("It's scorching hot!");
    } else if temperature > 20 {
        println!("It's pleasantly warm.");
    } else { // Catches all temperatures <= 20
        println!("It's quite cool.");
    }
    ```
    
4. **`if-else` as an Expression:**
    
    - **Purpose:** These conditional blocks can produce a value, allowing their result to be assigned to a variable. This is Rust's equivalent of the ternary operator found in other languages.
        
    - **Mechanism:** The last line of each branch (`if`, `else if`, `else`) must be an **expression (without a semicolon)**. All branches must return a value of the **same type**.
        
    
    Rust
    
    ```Rust
    let is_adult = true;
    let status_message = if is_adult {
        "You are an adult." // No semicolon here
    } else {
        "You are a minor." // No semicolon here
    }; // Semicolon needed here to end the `let` statement
    println!("{}", status_message);
    ```
    
5. **`match` Statement:**
    
    - **Purpose:** A powerful construct for comparing a value against **multiple possible patterns (variants)** and executing specific logic (or returning a value) for the first matching pattern. Often more concise and robust than long `if-else if` chains for a single value.
        
    - **Syntax:**
        
        Rust
        
        ```Rust
        match value_to_match {
            pattern1 => { /* ... */ },
            pattern2 => value_to_return, // Can return value directly (needs comma separator)
            _ => { /* catch-all */ },
        }
        ```
        
    - **Exhaustive Checking:** A key feature: the Rust compiler **guarantees** that you have covered **every possible variant** of the `value_to_match`. If you miss a case, the code will not compile. This makes `match` inherently safer.
        
    - **Patterns/Arms:** Each `pattern => { block }` or `pattern => value` is a "match arm." Evaluation proceeds top-down, stopping at the first match.
        
    - **`_` (Underscore) Catch-all / Wildcard Pattern:** Matches _any_ value not explicitly covered by preceding patterns. It's the `match` equivalent of an `else` clause and _must_ be the last arm to satisfy exhaustiveness for types with many (or infinite) variants (like `i32` or `String`).
        
    
    Rust
    
    ```Rust
    let month_num = 7;
    let season = match month_num {
        1 | 2 | 12 => "Winter", // Match multiple values with `|`
        3 | 4 | 5 => "Spring",
        6 | 7 | 8 => "Summer",
        9 | 10 | 11 => "Autumn",
        _ => "Unknown", // Catch-all for any other i32 value
    };
    println!("Month {} is in the {} season.", month_num, season);
    ```
    
    - **`if` Guards in `match` arms:** You can add an `if` condition to a pattern to refine the match: `pattern if condition => { ... }`.
        
    - **`unreachable!` Macro:** Used in arms that are logically impossible to reach (but the compiler needs assurance for exhaustiveness), causing a panic if hit.
        

### II. Iteration (Looping): `loop`, `break`, `continue`, `while`

Iteration involves repeating a block of code multiple times.

1. **`loop` Keyword:**
    
    - **Purpose:** Declares a block of code to be executed **repeatedly and indefinitely** (an infinite loop) by default.
        
    - **Termination:** Requires manual termination using the `break` keyword.
        
    
    Rust
    
    ```Rust
    let mut counter = 0;
    loop {
        println!("Looping...");
        counter += 1;
        if counter == 3 {
            break; // Force termination after 3 loops
        }
    }
    ```
    
2. **`break` Keyword:**
    
    - **Purpose:** Immediately **terminates the innermost loop** it's contained within. Execution jumps to the code following the loop.
        
    - **Common Use:** Typically paired with an `if` statement to conditionally stop a `loop` or `while` loop.
        
3. **`continue` Keyword:**
    
    - **Purpose:** Stops the **current iteration** of a loop and immediately proceeds to the **beginning of the next iteration**. Any code remaining in the current loop's body after `continue` is skipped.
        
    - **Common Use:** Used with an `if` statement to conditionally skip parts of a loop's processing for specific iterations.
        
    
    Rust
    
    ```Rust
    let mut num = 0;
    loop {
        num += 1;
        if num % 2 != 0 { // If num is odd
            continue; // Skip the rest of this iteration
        }
        println!("Even number: {}", num); // Only prints even numbers
        if num >= 6 {
            break;
        }
    } // Output: Even number: 2, Even number: 4, Even number: 6
    ```
    
4. **`while` Loop:**
    
    - **Purpose:** Executes a block of code **as long as its specified condition remains `true`**. It's a more elegant alternative to `loop` when the termination condition is clear at the start of each cycle.
        
    - **Automatic Termination:** Automatically stops when its condition evaluates to `false`. Does not require `break` for basic termination (though `break` and `continue` can still be used).
        
    - **State Mutation:** The code inside the `while` block **must** modify some state that will eventually cause the `while` condition to become `false`, otherwise, it will lead to an infinite loop.
        
    
    Rust
    
    ```Rust
    let mut countdown = 3;
    while countdown > 0 { // Loop as long as `countdown` is positive
        println!("Countdown: {}", countdown);
        countdown -= 1; // Mutate state to eventually terminate loop
    }
    println!("Liftoff!");
    ```
    

### III. Recursion

What is Recursion?

Recursion is a programming technique where a function calls itself from within its own body. It solves problems by breaking them into smaller, self-similar sub-problems.

- **Recursive Call:** The function invoking itself. Each call creates a new, independent execution layer on the call stack.
    
- **Infinite Recursion:** Occurs if a recursive function never stops calling itself, leading to a stack overflow error (program crash).
    
- **Base Case:** The **crucial terminating condition** that stops the recursion. It's an `if` statement (or similar logic) that, when met, prevents further recursive calls and allows the nested function calls to unwind and return their results.
    

Rust

```Rust
// Recursive function to calculate factorial (n!)
fn factorial(n: u32) -> u32 {
    // Base Case: Factorial of 0 is 1. No more recursion here.
    if n == 0 {
        return 1;
    }
    // Recursive Step: n * factorial(n-1)
    else {
        n * factorial(n - 1) // Function calls itself
    }
}

fn main() {
    let num = 4;
    println!("Factorial of {} is {}", num, factorial(num)); // Output: Factorial of 4 is 24
}
```
