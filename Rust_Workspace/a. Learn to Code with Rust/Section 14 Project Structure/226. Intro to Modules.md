### Part 1: Modules as Organizational Containers

This progressive example introduces the concept of a **module** in Rust as an organizational container for related code. It demonstrates how to declare a module and populate it with various Rust constructs.

- **Module (`mod`):** A module is a way to group related code, such as functions, structs, and enums, into a logical unit. It acts as a namespace for its contents, preventing naming conflicts and improving code organization.
    
- **Declaration Syntax:** A module is declared with the `mod` keyword, followed by a name in `snake_case`, and a code block in curly braces.
    
- **Contents:** A module can contain any valid Rust constructs, including constants, enums, structs, and functions.
    

Rust

```Rust
// The main function, which is the entry point of our program.
fn main() {
    // We'll see how to use the module in a later part.
}

// A module named `inventory` that contains all the inventory-related code.
mod inventory {
    // Constants are declared with `const`.
    const FLOOR_SPACE: i32 = 10000;
    const MANAGER: &str = "Ivan Inventory";

    // An enum to represent a product's category.
    #[derive(Debug)]
    enum ProductCategory {
        Ladders,
        Hammers,
    }

    // A struct to represent an item in the warehouse.
    #[derive(Debug)]
    struct Item {
        name: String,
        category: ProductCategory, // The field uses our custom enum type.
        quantity: u32,
    }

    // A function that belongs to this module.
    fn talk_to_manager() {
        // This function can access other items within the same module's scope.
        println!("Hey {MANAGER}, how's your coffee?");
    }
}
```

### Part 2: Module Visibility (The Problem)

This part of the study guide introduces a core principle of modules: by default, all items within a module are **private** to that module. This is a key feature for encapsulation and preventing unintended use of internal components.

- **Privacy by Default:** Rust's default behavior is to make all items (`const`, `enum`, `struct`, `fn`, etc.) private to their containing module.
    
- **The Problem:** Because all the constructs in the `inventory` module are private, they cannot be accessed or used from outside the module (e.g., from the `main` function). The compiler will throw an error if we try to do so.
    
- **The Code:** This example shows the code from Part 1, but with a commented-out section in `main` that would cause a compile-time error.
    

Rust

```Rust
fn main() {
    // This line would cause a compile-time error!
    // The `inventory` module is private by default.
    // inventory::talk_to_manager();

    // This line would also cause an error because `Item` is private.
    // let my_item = inventory::Item {
    //     name: String::from("Ladder"),
    //     category: inventory::ProductCategory::Ladders,
    //     quantity: 10,
    // };
}

// ... the `inventory` module from Part 1 ...
mod inventory {
    // ...
}
```

### Part 3: The `pub` Keyword (The Solution)

This part introduces the **`pub` keyword**, which is the solution to the problem from Part 2. The `pub` keyword makes an item public, allowing it to be accessed from outside its module.

- **`pub` Keyword:** The `pub` keyword makes a module's contents public. It's a key tool for creating a public API for your code while keeping internal implementation details private.
    
- **Public Hierarchy:** To access a nested item (e.g., a field within a public struct), the entire path to that item must also be public. For example, if a `struct` is public, its fields are still private by default and must be made public to be accessed.
    
- **The Code:** This example shows how to use the `pub` keyword to make the `inventory` module and its contents publicly accessible, allowing them to be used in the `main` function.
    

Rust

```Rust
fn main() {
    // Now that `inventory` is public, this line works.
    inventory::talk_to_manager();
    // Output: Hey Ivan Inventory, how's your coffee?

    // Now that `Item` and its fields are public, this works.
    let my_item = inventory::Item {
        name: String::from("Ladder"),
        category: inventory::ProductCategory::Ladders, // `ProductCategory` is also public.
        quantity: 10,
    };
    
    // We can also print our new item.
    println!("My new item is: {:?}", my_item);
    // Output: My new item is: Item { name: "Ladder", category: Ladders, quantity: 10 }
}

// The module is now declared as public.
pub mod inventory {
    pub const FLOOR_SPACE: i32 = 10000;
    pub const MANAGER: &str = "Ivan Inventory";

    #[derive(Debug)]
    pub enum ProductCategory { // The enum is public.
        Ladders,
        Hammers,
    }

    #[derive(Debug)]
    pub struct Item { // The struct is public.
        pub name: String, // The fields are also explicitly made public.
        pub category: ProductCategory,
        pub quantity: u32,
    }

    pub fn talk_to_manager() { // The function is public.
        println!("Hey {MANAGER}, how's your coffee?");
    }
}
```
