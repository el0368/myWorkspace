### Part 1: The Three Ways to Define a Module

This progressive example starts by outlining the three valid ways to define a module in Rust. These methods are mutually exclusive, and using more than one for a single module will lead to a compiler error.

- **Module Declaration:** The `mod <name>;` statement tells the compiler that a module named `<name>` exists.
    
- **Module Definition:** The compiler then looks for the module's contents in one of three places:
    
    1. **Inline:** In a code block (`{}`) immediately following the `mod` declaration.
        
    2. **File-Based:** In a file named `<name>.rs` in the same directory.
        
    3. **Folder-Based:** In a file named `mod.rs` inside a directory named `<name>`.
        
- **The Code:** This part shows a `main.rs` file that declares two modules, and the contents of those modules are defined in separate files, which is a valid setup.
    

Rust

```Rust
// File: src/main.rs
mod inventory;
mod orders;

fn main() {
    println!("Inventory manager: {}", inventory::MANAGER);
    println!("Orders manager: {}", orders::MANAGER);
}

// File: src/inventory.rs
pub const MANAGER: &str = "Ivan Inventory";

// File: src/orders/mod.rs
pub const MANAGER: &str = "Oliver Orderson";
```

### Part 2: The Problem - Module Definition Ambiguity

This part demonstrates a common compiler error that occurs when a module is defined in more than one way. The compiler doesn't know which definition to use and signals a fatal ambiguity.

- **Ambiguity:** Rust's compiler expects a single, unambiguous definition for a module. It will not try to merge definitions from multiple locations.
    
- **The Error:** If the compiler finds a module's contents in both a file (e.g., `src/orders.rs`) and a folder (e.g., `src/orders/mod.rs`), it will produce a fatal error and refuse to compile.
    
- **The Code:** This example shows the file structure that would cause the error and the resulting compiler message.
    

```Rust
// File structure that causes an error:
// src/
// ├── main.rs
// ├── inventory.rs
// ├── orders.rs         // First definition for the `orders` module
// └── orders/
//     └── mod.rs        // Second definition for the `orders` module
```

- **Expected Error Message:**
    
    Plaintext
    
    ```
    error[E0583]: file for module `orders` found at both "src/orders.rs" and "src/orders/mod.rs"
    delete or rename one of them to remove the ambiguity
    ```
    

---

### Part 3: The Solution - The One-Definition Rule

This final part brings all the concepts together and reinforces the core rule: **a module can only have one definition**. The solution is to choose one of the three methods and stick with it.

- **One Definition:** To prevent compilation errors, you must ensure that for any given module, its contents are defined in only one location, using one of the three methods.
    
- **Example Scenarios:**
    
    - If a module's code is in `src/my_module.rs`, you must not have an `src/my_module/mod.rs` file.
        
    - If a module is defined inline with `{...}`, there must not be a corresponding `.rs` file or directory.
        
- **The Code:** This is the final, complete code from Part 1, which represents a valid project structure.
    

Rust

```Rust
// File: src/main.rs
// This declaration will only look for one definition.
mod inventory;
mod orders;

fn main() {
    println!("Inventory manager: {}", inventory::MANAGER);
    println!("Orders manager: {}", orders::MANAGER);
}

// File: src/inventory.rs (Valid, single definition)
pub const MANAGER: &str = "Ivan Inventory";

// File: src/orders/mod.rs (Valid, single definition)
pub const MANAGER: &str = "Oliver Orderson";
```
