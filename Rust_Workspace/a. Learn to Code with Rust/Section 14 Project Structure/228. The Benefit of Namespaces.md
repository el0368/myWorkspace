### Part 1: The Problem with Naming Conflicts

This progressive example starts by highlighting a common problem in larger projects: the potential for **naming conflicts**. It introduces the idea of using modules as a solution to this problem, as they create separate namespaces.

- **The Problem:** In a large program, you might need to use the same name for different items in different parts of your code. If these items exist in the same top-level scope, the compiler won't know which one you're referring to, leading to a naming conflict.
    
- **The Solution:** Modules create separate namespaces, which are like logical containers or directories for your code. The full name of an item becomes its module path, which allows for duplicate names as long as they reside in different modules.
    
- **The Code:** This part sets up two modules, `inventory` and `orders`, both of which have a private `MANAGER` constant. The code in `main` would fail to compile if both constants were at the top level, but placing them in separate modules makes this setup valid.
    

Rust

```Rust
pub mod inventory {
    pub const MANAGER: &str = "Ivan Inventory";
}

pub mod orders {
    pub const MANAGER: &str = "Oliver Orderson";
}

fn main() {
    // This part will be completed in the next section.
}
```

### Part 2: Accessing Items from Different Namespaces

This part demonstrates how to access items with the same name from different modules using the **scope resolution operator (`::`)**.

- **Scope Resolution Operator (`::`):** The double-colon syntax is used to navigate through a module's namespace and access a specific, publicly available item within it. The path for an item is unique even if the item's name is not.
    
- **The Code:** This example shows how to access both `MANAGER` constants by prefixing them with their respective module names, which disambiguates them for the compiler.
    

Rust

```Rust
pub mod inventory {
    pub const MANAGER: &str = "Ivan Inventory";
}

pub mod orders {
    pub const MANAGER: &str = "Oliver Orderson";
}

fn main() {
    println!("The manager of our inventory is {}", inventory::MANAGER);
    // Output: The manager of our inventory is Ivan Inventory

    println!("The manager of our orders is {}", orders::MANAGER);
    // Output: The manager of our orders is Oliver Orderson
}
```

### Part 3: The Final Progressive Example (The Power of Namespaces)

This final part brings all the concepts together and serves as a comprehensive example of how namespaces work in Rust. It shows that multiple items can have the same name, as long as they exist in separate modules.

- **The Rule:** An item's name is unique only within its own namespace.
    
- **The Code:** This is the final, complete code that demonstrates the power of modules in preventing naming conflicts.
    

Rust

```Rust
// Our first module with a public `MANAGER` constant.
pub mod inventory {
    pub const MANAGER: &str = "Ivan Inventory";
}

// Our second module with a public `MANAGER` constant.
pub mod orders {
    pub const MANAGER: &str = "Oliver Orderson";
}

fn main() {
    println!("The manager of our inventory is {}", inventory::MANAGER);
    println!("The manager of our orders is {}", orders::MANAGER);
}
```
