In this lesson, you will learn how to organize a Rust project by breaking up a single file into multiple files, which is essential for building larger, more scalable applications.

---

### 1. The Crate Root

- A **crate root** is the starting point of the Rust compiler. For a binary crate (an executable), the crate root is the **`src/main.rs`** file.
    
- The code in the crate root file belongs to an implicit, top-level, unnamed module. All other modules and functions you declare will be nested within this root module.
    

### 2. Declaring a Module

- You declare a module with the **`mod` keyword**, followed by the module's name (in `snake_case`).
    
- The module name serves as a **namespace** for all the items (functions, structs, etc.) contained within it, preventing naming conflicts.
    
- By default, all items within a module are **private** and can only be accessed from within the module itself.
    

### 3. Three Ways to Define a Module

There are three ways to define a module's contents, all of which are valid and can be mixed within a single project.

#### a. Inline Module

- **Syntax:** You declare the module and its contents directly within the same file using curly braces.
    
- **Example:**
    
    Rust
    
    ```Rust
    mod my_module {
        // All module items go here
        pub fn greet() {
            println!("Hello!");
        }
    }
    ```
    

#### b. File-Based Module

- **Syntax:** You declare the module with `mod <name>;` (note the semicolon) in a parent file. This tells Rust to look for the module's code in a separate file.
    
- **File Naming:** The module's contents must be in a file named **`<name>.rs`** in the same directory as the parent file.
    
- **Example:**
    
    Rust
    
    ```Rust
    // File: src/main.rs
    mod inventory; // This tells Rust to look for `src/inventory.rs`
    
    fn main() {
        inventory::talk_to_manager();
    }
    ```
    
    Rust
    
    ```Rust
    // File: src/inventory.rs
    // This file contains the contents of the `inventory` module.
    pub fn talk_to_manager() {
        // ...
    }
    ```
    

#### c. Folder-Based Module

- **Syntax:** You declare the module with `mod <name>;` in a parent file.
    
- **Folder Naming:** The module's contents must be in a folder named **`<name>/`** in the same directory as the parent file. The main file inside this folder is called **`mod.rs`**.
    
- **Example:**
    
    Rust
    
    ```Rust
    // File: src/main.rs
    mod orders; // This tells Rust to look for `src/orders/`
    ```
    
    Rust
    
    ```Rust
    // File: src/orders/mod.rs
    // This file contains the contents of the `orders` module.
    pub fn create_order() {
        // ...
    }
    ```
    

### 4. Code Example: Refactoring an Inline Module to a File-Based Module

This example shows how to refactor an inline module into a separate file to keep the crate root (`main.rs`) clean and concise.

Rust

```Rust
// Original code (all in one file):
/*
mod inventory {
    pub const MANAGER: &str = "Ivan Inventory";
    pub fn talk_to_manager() {
        println!("The manager is: {}", MANAGER);
    }
}
fn main() {
    inventory::talk_to_manager();
}
*/

// Refactored code (split into two files):
// File: src/main.rs
mod inventory;

fn main() {
    inventory::talk_to_manager();
}

// File: src/inventory.rs
// This file contains the contents of the `inventory` module.
pub const MANAGER: &str = "Ivan Inventory";
pub fn talk_to_manager() {
    println!("The manager is: {}", MANAGER);
}
```
