# 🦀 Module Ambiguity in Rust (New Style)

## 1. **What it is**

Module ambiguity happens when Rust **cannot tell which function, struct, or module you mean** because multiple paths could lead to the same name.

- Usually happens with **nested modules** or when using **relative (`self::`, `super::`) vs absolute (`crate::`) paths**.
    
- Can also happen if you `use` multiple modules that define the same item.
    

---

## 2. **Project Structure (New Style)**

```
src/
 ├── main.rs
 ├── math.rs          <-- root of math module
 └── math/            <-- folder for submodules
     └── add.rs
```

---

## 3. **Code Example**

### `math.rs` (module root)

```rust
pub fn sum(a: i32, b: i32) -> i32 {
    a + b
}

pub mod add; // declares submodule
```

### `math/add.rs` (submodule)

```rust
pub fn sum(a: i32, b: i32) -> i32 {
    a + b + 1
}

// Trying to call math::sum directly
pub fn double_sum(a: i32, b: i32) -> i32 {
    // sum(a,b) ❌ ambiguous: which sum?
    crate::math::sum(a,b) * 2   // ✅ use absolute path from crate root
}
```

### `main.rs`

```rust
mod math;

fn main() {
    println!("{}", math::sum(2,3));         // math::sum
    println!("{}", math::add::sum(2,3));    // math::add::sum
    println!("{}", math::add::double_sum(2,3)); // uses math::sum via crate::
}
```

---

## 4. **Why the Ambiguity Happens**

Inside `math/add.rs`:

```rust
pub fn double_sum(a: i32, b: i32) -> i32 {
    sum(a,b) * 2
}
```

Rust sees **two possible `sum` functions**:

1. `math::sum` (parent module)
    
2. `math::add::sum` (itself, partially defined)
    

- Rust cannot guess which one you mean → **module ambiguity**.
    
- Fix: **use absolute paths (`crate::`) or relative paths (`super::`)**.
    

---

## 5. **Alternative Relative Path**

You can use `super::` to go **one module up**:

```rust
pub fn double_sum(a: i32, b: i32) -> i32 {
    super::sum(a,b) * 2   // go to parent module math::sum
}
```

- `super::` = parent module
    
- `self::` = current module
    
- `crate::` = crate root
    

---

## 6. **Ambiguity with `use`**

```rust
mod math {
    pub mod add {
        pub fn sum(a: i32, b: i32) -> i32 { a + b }
    }
}

mod physics {
    pub fn sum(a: f64, b: f64) -> f64 { a + b }
}

use math::add::*;
use physics::*;

fn main() {
    println!("{}", sum(2,3)); // ❌ Error: which sum?
}
```

✅ Fix with **explicit absolute paths**:

```rust
println!("{}", math::add::sum(2,3));
println!("{}", physics::sum(2.0,3.0));
```

---

## 7. **Summary (New Style)**

- Module ambiguity = Rust cannot resolve which item you mean.
    
- Causes:
    
    1. Same names in different modules
        
    2. Confusing relative vs absolute paths
        
    3. `use` bringing multiple conflicting names into scope
        
- Fix:
    
    - Use **`crate::`** for absolute paths
        
    - Use **`super::`** for relative paths to parent modules
        
    - Fully qualify names when necessary
        

---

⚡ Analogy (New Style):

- `crate::` = “start from the main entrance of my project”
    
- `super::` = “go up one room”
    
- `self::` = “stay in this room”
