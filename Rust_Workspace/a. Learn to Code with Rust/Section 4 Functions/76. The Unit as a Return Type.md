### Study Guide: The Unit Type (`()`) in Rust 텅

The **unit type** is a special type in Rust that represents the absence of a value. It is essentially an **empty tuple**.

Both the **type** and its only **value** are written as a pair of empty parentheses: `()`.

Think of it as the programming equivalent of "nothing" or "void" from other languages, but with a concrete type that the compiler can reason about.

---

### The Unit Type as a Default Return Value

Every function in Rust must return a value. If you do not specify a return type in a function's signature, Rust assumes the function returns the unit type `()`.

This means the following two function definitions are syntactically equivalent:



```Rust
// This function implicitly returns the unit type.
fn do_nothing() {
    // ...
}

// This is the explicit version of the same function.
// You almost never need to write this, as it's the default.
fn do_nothing_explicit() -> () {
    // ...
    () // Explicitly return the unit value
}
```

---

### Statements, Expressions, and the Unit Type

The reason for this default behavior is that Rust is an expression-based language. Even statements have a value.

A line of code that ends with a semicolon (`;`) is a **statement**. All statements in Rust evaluate to the unit type `()`.

This is why a function that only contains `println!` calls and other statements implicitly returns `()`. The last statement in the function evaluates to `()`, which becomes the function's implicit return value.

Rust

```Rust
fn main() {
    fn returns_a_value() -> i32 {
        5 // This is an EXPRESSION, so the function returns an i32
    }

    fn returns_nothing() { // Implicitly returns ()
        let _x = 5; // This is a STATEMENT, so it evaluates to ()
    }
}
```

### Practical Examples

#### Example from the Transcript

This function contains a `println!` statement. Since that statement ends with a semicolon, it evaluates to `()`, which becomes the function's return value.

Rust

```Rust
fn mystery() {
    println!("Hello there");
}

fn main() {
    // The `result` variable will have the type ()
    let result = mystery();
    // dbg!(result); // This would print `result = ()`
}
```

#### My Example: Chaining Methods

Some methods don't produce a new value but modify something in place. These methods often return `()` to indicate they've completed their action but have no value to give back.

Rust

```Rust
fn main() {
    let mut my_vector = vec![1, 2, 3];

    // The .push() method adds an item to the vector but returns ().
    let result = my_vector.push(4);

    println!("Vector after push: {:?}", my_vector);
    println!("Return value of .push(): {:?}", result); // Prints "()"
}
```

### Key Takeaways

- The unit type `()` represents an empty value.
    
- Both the type and its single value are written as `()`.
    
- Functions that do not specify a return type implicitly return `()`.
    
- Statements (lines ending in `;`) evaluate to the unit type `()`.
