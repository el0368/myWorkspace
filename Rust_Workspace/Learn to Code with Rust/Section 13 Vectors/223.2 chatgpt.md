# 📘 Study Guide: Vectors in Rust

---

## 1. What a Vector Is

- A **vector (`Vec<T>`)** is a collection type in Rust that holds multiple values of the **same data type** (homogeneous elements).
    
- Elements are stored **in order** and each has an **index**, starting from `0`.
    
- Unlike arrays (which are fixed in size), vectors are **dynamic** — they can **grow** and **shrink**.
    
- Vectors are stored on the **heap**, since the heap provides the flexibility to reallocate and shift memory as elements are added or removed.
    

---

## 2. The `Vec` Type and Generics

- The official vector type is `Vec<T>`.
    
    - `Vec` is the container type.
        
    - `T` is a **generic parameter** that specifies the type of the elements stored inside.
        
- Benefit of generics:
    
    - You can reuse the same container type (`Vec`) for many different element types — integers, booleans, strings, structs, etc.
        
- Rule: a single vector can only store **one data type at a time**.
    

---

## 3. Creating Vectors

### 3.1 `Vec::new`

- Syntax:
    
    ```rust
    let v: Vec<i32> = Vec::new();
    ```
    
- Creates an empty vector.
    
- Requires a **type annotation** because the compiler doesn’t know the element type for an empty collection.
    
- If you add elements later (e.g., with `push`), the compiler can **infer** the type.
    

### 3.2 `vec![]` Macro

- Shortcut to create and optionally populate a vector.
    
- Syntax:
    
    ```rust
    let v = vec![1, 2, 3, 4];
    ```
    
- Uses square brackets `[]` (not parentheses).
    
- Elements separated by commas.
    
- Type is inferred from the values provided.
    

---

## 4. Adding and Removing Elements

### 4.1 `push`

- Appends an element to the **end** of the vector.
    
    ```rust
    v.push(10);
    ```
    

### 4.2 `insert`

- Inserts an element at a **specific index**.
    
    - Example:
        
        ```rust
        v.insert(0, 99); // prepends at the beginning
        v.insert(2, 77); // inserts in the middle
        ```
        
- Shifts subsequent elements to the right.
    

### 4.3 `pop`

- Removes the **last element**.
    
- Returns an `Option<T>`:
    
    - `Some(value)` if an element was removed.
        
    - `None` if the vector was empty.
        
- Reason for `Option`: removal is not guaranteed.
    

### 4.4 `remove`

- Removes an element at a **specific index**.
    
- Returns the element directly.
    
- **Panics** if the index is invalid.
    
    ```rust
    let removed = v.remove(1);
    ```
    

---

## 5. Reading Elements

### 5.1 Indexing (`[]`)

- Retrieve an element at a given index:
    
    ```rust
    let x = v[0];
    ```
    
- **Ownership rules apply**:
    
    - If element type implements `Copy` (e.g., integers), the value is copied.
        
    - If not (`String`, custom structs), ownership may move — which Rust typically disallows directly.
        
    - Solution: use borrowing (`&`) to avoid moving ownership.
        

### 5.2 `get` Method

- Safer alternative:
    
    ```rust
    match v.get(2) {
        Some(val) => println!("Got: {}", val),
        None => println!("No element at this index"),
    }
    ```
    
- Returns an `Option<&T>`:
    
    - `Some(&value)` if the index is valid.
        
    - `None` if out of range.
        
- Prevents runtime panic.
    

### 5.3 Borrowing Slices

- You can borrow a **range of elements** as a slice (`&[T]`):
    
    ```rust
    let slice = &v[1..3];
    ```
    
- The upper bound is **exclusive**.
    
- Slice is a reference, not an owned copy.
    

---

## 6. Writing / Replacing Elements

- Use indexing syntax with `=`:
    
    ```rust
    v[0] = 100; // overwrite element at index 0
    ```
    
- Must have **mutable access** to the vector.
    

---

## 7. Ownership and Borrowing Rules with Vectors

### 7.1 Copy vs. Move

- For `Copy` types: values are duplicated when accessed.
    
- For non-`Copy` types: direct indexing may attempt to move ownership out of the vector.
    
    - Typically avoided using **borrows** (`&`).
        

### 7.2 Mutable References

- At most **one mutable reference** to a vector at a time.
    
- Prevents situations where two references could modify the vector simultaneously.
    
- When a mutable reference is active, no other (mutable or immutable) references can exist.
    

### 7.3 Immutable References

- Any number of immutable references allowed at the same time.
    
- Safe since they cannot modify the data.
    

---

## 8. Options and Panics in Vector Methods

- `pop` → returns `Option<T>` (safe, no panic).
    
- `get` → returns `Option<&T>` (safe, no panic).
    
- `remove` and indexing (`[]`) → **panic at runtime** if index is invalid.
    

---

## 9. Core Takeaways

1. **Vectors = dynamic arrays** stored on the heap.
    
2. `Vec<T>` uses generics, allowing any element type (but only one per vector).
    
3. Creation: `Vec::new` (empty, type annotation needed) or `vec![]` macro (with values).
    
4. Mutation methods: `push`, `insert`, `pop`, `remove`.
    
5. Reading: indexing (`[]`), `get`, slices.
    
6. Ownership rules matter: borrow with `&` for non-`Copy` types.
    
7. Mutability rules: one mutable reference at a time; many immutable references allowed.
    
8. Safe methods return `Option`; unsafe methods panic on errors.
