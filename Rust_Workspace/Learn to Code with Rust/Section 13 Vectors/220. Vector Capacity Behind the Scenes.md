### Part 1: Initializing a Vector with a Specific Capacity

This progressive example starts by demonstrating how to create a vector and explicitly set its initial capacity. This is a crucial step for understanding the internal mechanics of a vector, as its capacity is what determines when a heap reallocation will occur.

- **`.with_capacity(size)`:** This is a constructor function for vectors that creates a new, empty vector but with a pre-allocated capacity for a specified number of elements.
    
- **Length vs. Capacity:** This part clarifies the distinction between a vector's **length** (the number of elements it currently contains) and its **capacity** (the maximum number of elements it can hold before a new allocation is required).
    
- **The Code:** This example shows a vector created with a capacity of 4, and the output confirms its initial state: a length of 0 and a capacity of 4.
    

Rust

```Rust
fn main() {
    // Create an empty vector with an initial capacity of 4.
    let mut seasons: Vec<&str> = Vec::with_capacity(4);

    // Initial state:
    println!("Initial State:");
    println!("Length: {}", seasons.len()); // Output: 0
    println!("Capacity: {}", seasons.capacity()); // Output: 4
    
    // The rest of this code is completed in the next parts.
}
```

### Part 2: Filling the Vector to its Maximum Capacity

This part demonstrates what happens when a vector is populated with elements but does not exceed its initial capacity. Rust is able to add the elements without any performance overhead, as the memory was already pre-allocated.

- **`push(value)`:** We use the `push` method to add four elements, which is the exact number of spots that were initially allocated.
    
- **No Reallocation:** The length of the vector increases, but its capacity remains the same because there is no need for a larger memory block. The `push` operation is very efficient in this scenario.
    
- **The Code:** This example shows the `seasons` vector being populated and then its length and capacity being checked again to show that capacity was not exceeded.
    

Rust

```Rust
fn main() {
    let mut seasons: Vec<&str> = Vec::with_capacity(4);
    
    // Push four elements into the vector.
    seasons.push("Summer");
    seasons.push("Fall");
    seasons.push("Winter");
    seasons.push("Spring");
    
    println!("\nState after filling capacity:");
    println!("Vector: {:?}", seasons);
    // Output: Vector: ["Summer", "Fall", "Winter", "Spring"]
    
    println!("Length: {}", seasons.len()); // Output: 4
    println!("Capacity: {}", seasons.capacity()); // Output: 4
    
    // The rest of this code is completed in the next parts.
}
```

### Part 3: Exceeding Capacity and Heap Reallocation

This part is the core of the lesson. It demonstrates what happens behind the scenes when a vector's capacity is exceeded and how this action ties into Rust's borrowing rules.

- **Heap Reallocation:** When we try to add a fifth element to a vector with a capacity of 4, Rust must perform a complex operation. It finds a new, larger location on the heap (e.g., with double the capacity), copies all the old elements over, and then adds the new element.
    
- **The Danger:** This reallocation is the reason Rust must be so strict about mutable references. If a reference were pointing to an element in the old memory location, it would become a "dangling reference" after the reallocation, pointing to deallocated memory.
    
- **The Code:** This example shows a fifth element being pushed into the vector and the resulting increase in capacity.
    

Rust

```Rust
fn main() {
    let mut seasons: Vec<&str> = Vec::with_capacity(4);
    seasons.push("Summer");
    seasons.push("Fall");
    seasons.push("Winter");
    seasons.push("Spring");
    
    println!("\nState before exceeding capacity:");
    println!("Length: {}", seasons.len()); // Output: 4
    println!("Capacity: {}", seasons.capacity()); // Output: 4
    
    // We now push a fifth element, which exceeds the current capacity.
    // This triggers a heap reallocation behind the scenes.
    seasons.push("Summer");
    
    println!("\nState after exceeding capacity:");
    println!("Vector: {:?}", seasons);
    // Output: Vector: ["Summer", "Fall", "Winter", "Spring", "Summer"]
    
    // The capacity is now larger (e.g., 8).
    println!("Length: {}", seasons.len()); // Output: 5
    println!("Capacity: {}", seasons.capacity()); // Output: 8
    
    // The rest of this code is completed in the final part.
}
```

### Part 4: Final Summary and the Link to Borrowing Rules

This final part brings all the concepts together and explains the direct link between vector capacity management and Rust's borrowing rules.

- **The Rule:** You cannot have a mutable reference (`&mut`) and any other reference (`&`) to a value at the same time.
    
- **The Reason:** A mutable operation on a vector (like `push` or `insert`) can trigger a heap reallocation, which invalidates any existing references to the old memory location. By prohibiting multiple references at the same time as a mutable one, Rust's compiler guarantees that all references are always valid, even if the vector moves in memory.
    
- **The Code:** This example shows a commented-out line that would cause a compile-time error due to this borrowing conflict, which is a direct consequence of the heap reallocation.
    

Rust

```Rust
fn main() {
    let mut seasons: Vec<&str> = Vec::new();
    seasons.push("Summer");
    seasons.push("Fall");
    seasons.push("Winter");
    seasons.push("Spring");

    // We create an immutable borrow to the first element.
    let first_season_ref = &seasons[0];
    
    // This line would cause a compile-time error!
    // The `push` method requires a mutable borrow of the vector.
    // The compiler sees that `first_season_ref` (an immutable borrow)
    // is still active, so it prevents this mutation to avoid invalidating the reference.
    // seasons.push("New Season"); // ERROR: cannot borrow `seasons` as mutable because it is also borrowed as immutable
    
    // The immutable borrow is still valid.
    println!("The first season is: {}", first_season_ref);
    // Output: The first season is: Summer

    // This shows that Rust's borrowing rules directly protect against the dangers of heap reallocation.
}
```
