# Rust Vectors - Complete Study Guide

## What Are Vectors?

Vectors are dynamic, resizable collections that store elements of the same type in sequential order. Unlike arrays which have fixed sizes determined at compile time, vectors can grow and shrink during program execution. This flexibility comes from being stored on the heap, where memory can be reallocated as needed.

**Key Characteristics:**

- **Homogeneous**: All elements must be the same data type
- **Ordered**: Elements maintain their insertion order
- **Zero-indexed**: First element is at index 0, second at index 1, etc.
- **Dynamic sizing**: Can add or remove elements at runtime
- **Heap allocation**: Stored on heap for flexible memory management

## Vector Type and Generics

The official Rust vector type is `Vec<T>`, where `T` represents the generic type parameter for the stored elements. This design allows vectors to hold any type while maintaining type safety.

Examples of different vector types:

- `Vec<i32>` - vector of 32-bit integers
- `Vec<String>` - vector of String objects
- `Vec<bool>` - vector of boolean values
- `Vec<CustomStruct>` - vector of user-defined structs

## Creating Vectors

### Method 1: Using `Vec::new()`

```rust
let mut numbers: Vec<i32> = Vec::new();
// OR using turbofish operator
let mut numbers = Vec::<i32>::new();
```

**Important**: Empty vectors created with `Vec::new()` require explicit type annotation because the compiler cannot infer the type from an empty collection. However, if you immediately add elements, the compiler can infer the type from the first insertion.

### Method 2: Using the `vec!` Macro

```rust
let numbers = vec![1, 2, 3, 4, 5];
let names = vec!["Alice", "Bob", "Charlie"];
```

The `vec!` macro allows you to create and populate a vector in one step. Note the square brackets (not parentheses) and comma-separated values.

## Adding Elements (Mutation Operations)

### `push()` Method

Appends an element to the end of the vector:

```rust
let mut numbers = vec![1, 2, 3];
numbers.push(4); // numbers is now [1, 2, 3, 4]
```

### `insert()` Method

Inserts an element at a specific index position:

```rust
let mut numbers = vec![1, 3, 4];
numbers.insert(1, 2); // numbers is now [1, 2, 3, 4]
// insert(index, value)
```

This method can be used for:

- **Prepending**: `insert(0, value)` adds to the beginning
- **Middle insertion**: `insert(n, value)` adds at any valid position

## Removing Elements

### `pop()` Method

Attempts to remove and return the last element:

```rust
let mut numbers = vec![1, 2, 3];
let last = numbers.pop(); // Returns Some(3)
let empty_pop = Vec::<i32>::new().pop(); // Returns None
```

**Returns**: `Option<T>` where `T` is the element type

- `Some(value)` if element was removed successfully
- `None` if the vector was empty

### `remove()` Method

Removes an element at a specific index:

```rust
let mut numbers = vec![1, 2, 3, 4];
let removed = numbers.remove(1); // Returns 2, numbers is now [1, 3, 4]
```

**Important**: This method panics at runtime if the index is invalid (out of bounds). Unlike `pop()`, it returns the actual value, not an `Option`.

## Reading Vector Elements

### Index Access with Square Brackets

```rust
let numbers = vec![10, 20, 30];
let first = numbers[0]; // Gets 10
```

**Ownership Considerations:**

- **Copy types** (integers, booleans, chars): Value is copied, no ownership issues
- **Non-Copy types** (String, custom structs): Compiler prevents moving ownership out of vector

For non-Copy types, use borrowing:

```rust
let names = vec![String::from("Alice"), String::from("Bob")];
let first_name = &names[0]; // Borrow, don't move ownership
```

### `get()` Method (Safe Access)

```rust
let numbers = vec![10, 20, 30];
let maybe_first = numbers.get(0); // Returns Some(&10)
let maybe_invalid = numbers.get(10); // Returns None
```

**Returns**: `Option<&T>` - a reference wrapped in an Option

- `Some(&value)` for valid indices
- `None` for invalid indices

This method is safer than direct indexing because it won't panic on invalid indices.

## Slicing Vectors

Create references to portions of a vector using slice syntax:

```rust
let numbers = vec![1, 2, 3, 4, 5];
let slice = &numbers[1..4]; // References elements at indices 1, 2, 3 (not 4)
```

**Syntax**: `&vector[start..end]`

- `start`: inclusive lower bound
- `end`: exclusive upper bound
- Returns a slice (`&[T]`) referencing the specified range

## Writing/Modifying Vector Elements

### Direct Index Assignment

```rust
let mut numbers = vec![1, 2, 3];
numbers[1] = 20; // numbers is now [1, 20, 3]
```

Uses the same square bracket syntax as reading, but with assignment operator.

## Reference Rules and Borrowing

Rust's borrowing rules apply strictly to vectors to prevent data races and memory safety issues:

### Mutable References

- **Only one mutable reference allowed at a time**
- While a mutable reference exists, no other references (mutable or immutable) can coexist
- Once the mutable reference is no longer used, new references can be created
- Prevents simultaneous modification that could cause memory corruption

```rust
let mut numbers = vec![1, 2, 3];
let mutable_ref = &mut numbers;
// No other references allowed until mutable_ref is done being used
```

### Immutable References

- **Multiple immutable references allowed simultaneously**
- Safe because none can modify the data
- Cannot coexist with mutable references
- Ensures data consistency during read operations

```rust
let numbers = vec![1, 2, 3];
let ref1 = &numbers;
let ref2 = &numbers; // This is fine - both are immutable
```

### Why These Rules Matter

1. **Memory safety**: Prevents use-after-free and double-free errors
2. **Data race prevention**: Eliminates concurrent modification issues
3. **Collection integrity**: Ensures the vector maintains ownership of all its elements
4. **Predictable behavior**: Guarantees data won't change unexpectedly during operations

## Key Memory Management Concepts

### Heap Storage

Vectors are stored on the heap because:

- Heap provides flexible memory allocation
- Can grow and shrink as needed
- Stack has limited, fixed-size allocation
- Heap allows for runtime size determination

### Ownership in Collections

- Vectors maintain ownership of all their elements
- This ensures memory safety and prevents dangling pointers
- When a vector is dropped, all its elements are also properly cleaned up
- Borrowing allows temporary access without transferring ownership

## Best Practices

1. **Use `get()` for bounds-safe access** when index validity is uncertain
2. **Prefer borrowing over moving** for non-Copy types when accessing elements
3. **Be mindful of reference lifetimes** to avoid borrowing conflicts
4. **Use appropriate creation method**: `Vec::new()` for empty vectors that will grow, `vec!` macro for pre-populated vectors
5. **Consider capacity** for performance: vectors may reallocate when growing, so `Vec::with_capacity()` can be more efficient for known sizes
