### Variable Mutability in Rust

By default, variables in Rust are **immutable**, meaning once a value is assigned to a variable name, it cannot be changed. This is a core safety feature of the language that encourages you to write predictable code.

Attempting to change the value of an immutable variable will result in a compiler error.

Rust

```Rust
// `level` is immutable by default.
let level = 5;
println!("Current level: {level}");

// ERROR: This line will not compile.
// level = 6; // cannot assign twice to immutable variable
```

---

### Enabling Mutability with `mut` 🔄

To make a variable's value changeable, you must explicitly declare it as **mutable** by adding the `mut` keyword after `let` during its initial declaration.

Once a variable is marked as mutable, you can reassign a new value to it later in the program without using the `let` keyword again.

Rust

```Rust
// `level` is now declared as mutable.
let mut level = 5;
println!("Current level: {level}");

// This is now allowed.
level = 6;
println!("Leveled up to: {level}");
```

---

### A Key Restriction: Type Invariance

A critical rule to remember is that even a mutable variable **cannot change its data type**. If a variable is declared as an integer, you can change its numeric value, but you cannot reassign it to a different type like a string.

Rust

```Rust
let mut score = 100; // `score` is an integer.

score = 150; // This is valid.

// ERROR: This will not compile. You cannot change the variable's type.
// score = "Perfect!"; // expected integer, found `&str`
```
