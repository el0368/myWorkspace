### Variables

Variables are names for values in your program, acting as placeholders for data.

- Declaration with let and Type Inference:
    
    Rust can infer the type of a variable from its initial assignment.
    
    Rust
    
    ```Rust
    fn main() {
        // Rust infers 'name' as a String type (specifically &str initially, then String if mutable or moved)
        let name = "Alice";
        // Rust infers 'age' as an integer type (usually i32 by default)
        let age = 30;
        // Rust infers 'is_student' as a boolean type
        let is_student = false;
    
        println!("Name: {}, Age: {}, Student: {}", name, age, is_student);
    }
    ```
    
- Explicit Type Annotation:
    
    You can explicitly specify the data type after a colon :.
    
    Rust
    
    ```Rust
    fn main() {
        let temperature: f64 = 25.5; // f64 for double-precision floating-point
        let count: i32 = 100;       // i32 for 32-bit signed integer
        let character: char = 'R';  // char for a single Unicode character
        let is_active: bool = true; // bool for boolean values (true/false)
    
        println!("Temp: {}, Count: {}, Char: {}, Active: {}", temperature, count, character, is_active);
    }
    ```
    
- Interpolation (println! macro):
    
    Dynamically injecting variable values into strings using curly braces {}.
    
    Rust
    
    ```Rust
    fn main() {
        let city = "New York";
        let population = 8_000_000; // Using underscores for readability in large numbers
    
        // Method 1: Pass variables as arguments (most common)
        println!("The city of {} has a population of {}.", city, population);
    
        // Method 2: Referencing by numeric position (0-indexed)
        // Useful for reusing values without repeating arguments
        println!("The population of {0} is {1}. {0} is a big city!", city, population);
    
        // Method 3: Naming arguments (useful for clarity with many arguments)
        // Note: This isn't the primary way to *declare* variables but for `println!`
        let product = "Laptop";
        let price = 1200.50;
        println!("{item} costs ${value:.2}", item = product, value = price); // .2 for 2 decimal places
    }
    ```
    
- Immutability by Default:
    
    Once a variable is declared with let, its value cannot be changed.
    
    Rust
    
    ```Rust
    fn main() {
        let score = 100;
        // score = 150; // ERROR! Cannot assign twice to immutable variable `score`
        println!("Score: {}", score);
    }
    ```
    
- Mutability with mut:
    
    Use the mut keyword to allow a variable's value to be changed.
    
    Rust
    
    ```Rust
    fn main() {
        let mut age = 25;
        println!("Initial age: {}", age);
    
        age = 26; // This is allowed because 'age' is mutable
        println!("New age: {}", age);
    
        // age = "twenty-seven"; // ERROR! Mismatched types: expected `i32`, found `&str`
        // A mutable variable can change its value, but not its type.
    }
    ```
    

### Constants

Constants are immutable values known at compile time, declared with `const`.

- Declaration and Explicit Type:
    
    Constants must have an explicit type annotation and follow UPPER_SNAKE_CASE naming convention.
    
    Rust
    
    ```Rust
    // Declared at the file level, accessible from any function
    const MAX_POINTS: u32 = 100_000; // u32 for unsigned 32-bit integer
    const GRAVITY: f64 = 9.81;
    
    fn main() {
        println!("Max points allowed: {}", MAX_POINTS);
        println!("Gravitational constant: {}", GRAVITY);
    
        // Constants cannot be changed
        // MAX_POINTS = 50_000; // ERROR! Cannot assign to this expression
    }
    
    fn calculate_score(points: u32) -> u32 {
        // Constants can be used across multiple functions
        points * MAX_POINTS / 1000
    }
    ```
    

### Variable Shadowing

Redeclaring an existing variable with `let`, effectively creating a new variable that "overshadows" the old one.

- Changing Value and/or Type:
    
    Shadowing allows you to change both the value and the type of the variable.
    
    Rust
    
    ```Rust
    fn main() {
        let x = 5; // x is an i32
        println!("The value of x is: {}", x);
    
        let x = x + 1; // 'x' is shadowed, new 'x' is 6 (still i32)
        println!("The value of x is: {}", x);
    
        { // A new scope block
            let x = x * 2; // 'x' is shadowed *within this scope*, new 'x' is 12
            println!("The value of x in the inner scope is: {}", x);
        } // The inner 'x' goes out of scope here
    
        println!("The value of x after inner scope is: {}", x); // Original 'x' (value 6) is back
    
        // Common use case: type transformation
        let spaces = "   "; // 'spaces' is a string literal (&str)
        let spaces = spaces.len(); // 'spaces' is now a usize (number of bytes/characters)
        println!("Number of spaces: {}", spaces);
        // If not shadowing, you'd need `let num_spaces = spaces.len();`
    }
    ```
    

### Scopes and Blocks

Scopes define the visibility and lifetime of names (like variables). Blocks (defined by `{}`) create scopes.

- **Nested Scopes:**
    
    Rust
    
    ```Rust
    fn main() {
        let outer_variable = 10;
        println!("Outer variable at start: {}", outer_variable);
    
        { // This is a new block, creating a new scope
            let inner_variable = 20;
            println!("Inner variable inside block: {}", inner_variable);
            println!("Outer variable accessible inside block: {}", outer_variable); // outer_variable is accessible here
    
            // let outer_variable = 30; // This would shadow outer_variable ONLY within this block
            // println!("Shadowed outer variable inside block: {}", outer_variable);
        } // The inner_variable goes out of scope here, and the shadowed outer_variable (if any) is gone.
    
        // println!("Inner variable outside block: {}", inner_variable); // ERROR! Cannot find `inner_variable` in this scope
        println!("Outer variable after block: {}", outer_variable); // Still 10, as the shadowing was localized
    }
    ```
    

### Compiler Directives (`#[...]`)

Annotations that customize compiler behavior.

- #[allow(unused_variables)]:
    
    Suppresses warnings for variables that are declared but not used.
    
    Rust
    
    ```Rust
    // Apply to the entire file
    #![allow(unused_variables)]
    
    fn main() {
        let unused_val = 5; // No warning because of the file-level allow directive
    
        #[allow(dead_code)] // Specific to this function, though not strictly needed here
        fn some_unused_function() {
            println!("This function is declared but not called.");
        }
    
        // Apply to a specific line (less common for unused_variables, but shows syntax)
        #[allow(unused_assignments)] // For example, if you assign and then reassign without using the first value
        let mut x = 10;
        x = 20; // This specific assignment might be allowed if unused_assignments was relevant here
    }
    
    fn another_function() {
        let another_unused_val = 100; // No warning due to file-level directive
    }
    ```
    

### Other Tidbits

- Type Aliases (type keyword):
    
    Providing alternate names for existing types to improve readability and express intent.
    
    Rust
    
    ```Rust
    // Define a type alias for i32 when it represents meters
    type Meters = i32;
    // Define a type alias for f64 when it represents a temperature in Celsius
    type Celsius = f64;
    
    fn main() {
        let distance: Meters = 100;
        let current_temp: Celsius = 28.5;
    
        println!("Distance: {} meters", distance);
        println!("Temperature: {} Celsius", current_temp);
    
        // Rust still treats Meters and Celsius as their underlying types (i32 and f64)
        let sum_of_meters_and_int: i32 = distance + 50;
        println!("Sum: {}", sum_of_meters_and_int);
    }
    ```
    
- Rust Error Codes (e.g., E0384):
    
    When you encounter an error, Rust provides a specific error code.
    
    Rust
    
    ```Rust
    // Example that would cause E0384 (assigning to an immutable variable)
    /*
    fn main() {
        let immutable_var = 10;
        immutable_var = 20; // This line causes E0384
    }
    */
    // To get more info, you would run: `rustc --explain E0384` in your terminal.
    ```
    
- Unused Variable Warning (_ prefix):
    
    The most common way to silence unused_variables warnings is by prefixing the variable name with an underscore.
    
    Rust
    
    ```Rust
    fn main() {
        let _unused_variable = 10; // No warning, compiler knows it's intentionally unused
        let _another_unused_string = "hello"; // No warning
    
        let used_variable = 20;
        println!("Used variable: {}", used_variable);
    
        // If you were to remove the underscore:
        // let still_unused_variable = 30; // This would cause an `unused_variables` warning
    }
    ```
