### Part 1: The Problem with Privacy

This progressive example introduces the concept of module privacy in Rust. It shows that items declared inside a module are, by default, private and cannot be accessed from outside the module.

- **Privacy by Default:** All items within a module (constants, functions, structs, etc.) are private by default. This is a core feature for encapsulation, as it prevents external code from accessing internal implementation details.
    
- **The Problem:** Attempting to use a private item from outside its module's scope (e.g., from `main`) will result in a compile-time error, as the name is not considered valid in that scope.
    
- **The Code:** This part sets up the `inventory` module and shows a commented-out line in `main` that would fail to compile.
    

Rust

```Rust
mod inventory {
    const MANAGER: &str = "Ivan Inventory";

    pub fn talk_to_manager() {
        println!("Hey {MANAGER}, how's your coffee?");
    }
}

fn main() {
    // This line causes a compile-time error because `MANAGER` is private.
    // println!("The manager of our inventory is {}", inventory::MANAGER);
}
```

---

### Part 2: The Solution with the `pub` Keyword

This part introduces the **`pub` keyword**, which is the solution to the problem from Part 1. The `pub` keyword makes an item public, allowing it to be accessed from outside its module.

- **`pub` Keyword:** To make an item public, you must explicitly add the `pub` keyword before its declaration. This gives other parts of the program permission to access and use that item.
    
- **Item-by-Item Explicitness:** The `pub` keyword must be added to **each individual item** you want to expose. It does not make all items in a module public automatically.
    
- **The Code:** This example shows how to add `pub` to the `MANAGER` constant. The code in `main` now compiles and runs successfully.
    

Rust

```Rust
mod inventory {
    // The `pub` keyword makes this constant public.
    pub const MANAGER: &str = "Ivan Inventory";

    pub fn talk_to_manager() {
        println!("Hey {MANAGER}, how's your coffee?");
    }
}

fn main() {
    // Now that `MANAGER` is public, this line works.
    println!("The manager of our inventory is {}", inventory::MANAGER);
}
```

### Part 3: Accessing Public Items with the Scope Resolution Operator

This part demonstrates the correct syntax for accessing a public item that lives inside a module. The scope resolution operator (`::`) is used to navigate through the module's namespace.

- **Scope Resolution Operator (`::`):** This is the double-colon syntax used to access a named item inside a namespace (like a module or a type). It means "look inside this module for this item."
    
- **The Code:** This example shows how `inventory::MANAGER` is the full path to access the `MANAGER` constant. It also implicitly shows that `inventory` itself must be a public module for us to be able to access its contents.
    

Rust

```Rust
// The module must be declared public for its public items to be accessible.
pub mod inventory {
    pub const MANAGER: &str = "Ivan Inventory";

    pub fn talk_to_manager() {
        println!("Hey {MANAGER}, how's your coffee?");
    }
}

fn main() {
    // The full path `inventory::MANAGER` is used to access the public constant.
    println!("The manager of our inventory is {}", inventory::MANAGER);
    // Output: The manager of our inventory is Ivan Inventory
}
```
