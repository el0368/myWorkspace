### Packages, Crates, and Modules

- A **package** is a container for one or more **crates**. It's the top-level unit for organizing Rust code.
    
- A **crate** is the fundamental unit of compilation in Rust. It can be a **binary crate** (an executable program with a `main` function) or a **library crate** (reusable code without a `main` function).
    
- A **module** is a way to organize code within a crate into logical units. Modules can be nested and control the visibility of items.
    

### Visibility with `pub`

- The **`pub` keyword** makes an item (like a function, struct, or enum) public, allowing it to be accessed from outside its current module.
    
- By default, everything in Rust is private to its module.
    

### Submodules and File Organization

- Modules can be defined in different ways:
    
    - **Inline modules:** Declared directly within a file using `mod my_module { ... }`.
        
    - **File-based modules:** Declared with `mod my_module;` and defined in a separate `my_module.rs` file.
        
    - **Folder-based modules:** Declared with `mod my_folder;` and defined in `my_folder/mod.rs` or `my_folder.rs` and sub-files.
        

### Paths and the `use` Keyword

- Items are accessed using their full path, starting from the crate root (`crate::`).
    
- The **`use` keyword** brings an item into the current scope, allowing you to use it without its full path.
    
- `self` and `super` are used for relative paths:
    
    - **`self`** refers to the current module.
        
    - **`super`** refers to the parent module.
        
- The **`as` keyword** renames an item when imported with `use` to avoid naming conflicts.
    
- The **glob operator (`*`)** imports all public items from a module at once.
    

### Multiple Binary Crates and the Standard Library

- A single package can contain multiple binary crates, each with its own `main.rs` file in a sub-directory of `src/`.
    
- The standard library (`std`) is a vast collection of pre-written Rust code that you can use by importing it into your crates.
    

### Documentation Comments

- **Documentation comments** (`///`) are used to document your code. They are written in Markdown and are used by `cargo doc` to generate HTML documentation for your project.
