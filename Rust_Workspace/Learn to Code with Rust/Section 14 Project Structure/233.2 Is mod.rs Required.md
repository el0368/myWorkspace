# 🦀 Is `mod.rs` Required?

## 1. **Old Style (Pre-2018)**

- Before **Rust 2018 edition**, if you wanted to represent a module as a folder, you _had_ to use a `mod.rs` file inside that folder.
    
- Example (old style):
    
    ```
    src/
     ├── main.rs
     └── math/
         ├── mod.rs   <-- must exist
         ├── add.rs
         └── sub.rs
    ```
    
- `math/mod.rs` acted like the **root file** of the `math` module.
    

---

## 2. **New Style (Rust 2018 and later)**

- Now, `mod.rs` is **no longer required**.
    
- Instead, you can put the root file directly as `math.rs` in `src/`, and then have a folder `math/` with submodules.
    
- Example (new style, preferred):
    
    ```
    src/
     ├── main.rs
     ├── math.rs      <-- root of `math` module
     └── math/
         ├── add.rs
         └── sub.rs
    ```
    
- Inside `math.rs`:
    
    ```rust
    pub mod add;
    pub mod sub;
    ```
    

This achieves the same result but keeps things cleaner (no `mod.rs` clutter).

---

## 3. **So, what’s the rule?**

- **If you’re using Rust 2018+ (which is the default now):**
    
    - You can use **either style**, but `math.rs + math/` is recommended.
        
- **If you’re working on old Rust code (pre-2018):**
    
    - You might still see `mod.rs`, since that was required.
        

---

## ✅ Summary

- `mod.rs` was once **mandatory** for folder-modules.
    
- Since Rust 2018, it’s **optional** — you can use `math.rs` instead.
    
- Both styles still work, but modern Rust style prefers **`math.rs + math/`** because it avoids lots of `mod.rs` files everywhere.
    

---

⚡ Analogy:

- `mod.rs` = old-school "index file" in each folder.
    
- `math.rs + math/` = modern "entry file + folder" style, cleaner for big projects.
