So let's talk about the third way to declare a module in Rust, which uses a directory and a `mod.rs` file. This method is ideal for organizing larger projects and keeping your main files clean.

---

### 1. The Three Ways to Define a Module

Rust provides three ways to define a module's contents after you declare it with the `mod` keyword. All three are valid and can be mixed within a single project.

1. **Inline Module:** The module's contents are placed directly inside a code block (`{}`) in the same file.
    
2. **File-Based Module:** The module's contents are placed in a separate file with the same name, e.g., `mod orders;` in `main.rs` looks for `orders.rs`.
    
3. **Folder-Based Module:** This is the method we'll focus on. The module's contents are placed in a directory with the same name, and that directory contains a file named `mod.rs`.
    

### 2. The Folder-Based Module Structure

To create a folder-based module, you follow this structure:

- **Declaration:** In your parent file (e.g., `src/main.rs`), you declare the module with `mod <name>;`.
    
- **Directory:** You create a directory in the same location as the parent file, with the same name as the module (e.g., `src/orders/`).
    
- **Module Content:** All of the module's code is placed inside a file named **`mod.rs`** within that directory.
    

This structure automatically tells Rust that all the code inside `orders/mod.rs` belongs to the `orders` module.

### 3. Example: Refactoring `orders` to a Directory-Based Module

This example shows how to refactor an inline module into a folder-based one. This is a common practice for organizing complex projects.

#### Before (Inline Module)

`src/main.rs` contains all the code.

Rust

```Rust
mod orders {
    pub const MANAGER: &str = "Oliver Orderson";
}

fn main() {
    println!("The manager is {}", orders::MANAGER);
}
```

#### After (Folder-Based Module)

The `orders` module's content is moved to `src/orders/mod.rs`, and the declaration in `main.rs` is simplified.

**File: `src/main.rs`**

Rust

```Rust
mod inventory; // File-based module from a previous lesson
mod orders;   // Rust will now look for `src/orders/mod.rs`

fn main() {
    println!("The manager of our inventory is {}", inventory::MANAGER);
    println!("The manager of our orders is {}", orders::MANAGER);
}
```

**File: `src/inventory.rs`** (for context)

Rust

```Rust
pub const MANAGER: &str = "Ivan Inventory";

pub fn talk_to_manager() {
    println!("Hey {MANAGER}, how's your coffee?");
}
```

**File: `src/orders/mod.rs`**

Rust

```Rust
// The contents of the `orders` module now live here.
// The `mod orders {}` block is no longer needed.
pub const MANAGER: &str = "Oliver Orderson";
```

The `pub` keyword is still necessary to make the `MANAGER` constant public from the `orders` module.

By using a folder-based module, you keep your main file clean and organized, with all of the `orders`-related code neatly contained in its own directory.
