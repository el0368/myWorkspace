### Part 1: Initial Setup and the Problem of Private Fields

This progressive example starts by making all items in the `inventory` module public, which allows them to be accessed from `main.rs`. However, it then highlights a key difference in privacy rules for structs.

- **Module Privacy:** By default, all items within a module are private. The `pub` keyword makes them public.
    
- **Struct Privacy:** While marking a `struct` as `pub` makes the `struct` name public, its **fields remain private by default**.
    
- **The Problem:** We can access the `Item` struct's name, but we cannot create an instance of it using curly brace syntax because its fields are private. The compiler will throw an error for each private field.
    
- **The Code:** This part shows a `pub struct` with private fields, and the resulting compiler error in `main`.
    

Rust

```Rust
// File: src/inventory.rs
pub const MANAGER: &str = "Ivan Inventory";

#[derive(Debug)]
pub enum ProductCategory {
    Ladders,
    Hammers,
}

#[derive(Debug)]
pub struct Item { // The struct name is public
    name: String, // These fields are private by default
    category: ProductCategory,
    quantity: u32,
}

pub fn talk_to_manager() {
    println!("Hey {MANAGER}, how's your coffee?");
}

// File: src/main.rs
mod inventory;

fn main() {
    // This code causes a compile-time error!
    // The `Item` struct is public, but its fields are private.
    // let tall_ladder = inventory::Item {
    //     name: String::from("Ladder-o-matic 2000"), // ERROR: field `name` is private
    //     category: inventory::ProductCategory::Ladders, // ERROR: field `category` is private
    //     quantity: 100, // ERROR: field `quantity` is private
    // };
}
```

### Part 2: The Solution - Public Fields and Instantiation

This part provides the solution to the problem from Part 1. To make a struct fully instantiable using the direct curly brace syntax, all of its fields must be explicitly marked as public with the `pub` keyword.

- **`pub` on Fields:** You must add `pub` to each individual field of a `struct` that you want to be public.
    
- **Full Instantiation:** A struct can only be instantiated directly with curly brace syntax from outside its module if all of its fields are public.
    
- **The Code:** This example shows the `inventory` module with all of its fields marked as public, and a working `main` function that successfully creates and prints an `Item` instance.
    

Rust

```Rust
// File: src/inventory.rs
pub const MANAGER: &str = "Ivan Inventory";

#[derive(Debug)]
pub enum ProductCategory {
    Ladders,
    Hammers,
}

#[derive(Debug)]
pub struct Item {
    pub name: String, // Explicitly make the field public
    pub category: ProductCategory, // Explicitly make the field public
    pub quantity: u32, // Explicitly make the field public
}

pub fn talk_to_manager() {
    println!("Hey {MANAGER}, how's your coffee?");
}

// File: src/main.rs
mod inventory;

fn main() {
    // This code now compiles successfully.
    let tall_ladder = inventory::Item {
        name: String::from("Ladder-o-matic 2000"),
        category: inventory::ProductCategory::Ladders,
        quantity: 100,
    };
    
    // We can now print our new item.
    println!("{:#?}", tall_ladder);
    // Output:
    // Item {
    //     name: "Ladder-o-matic 2000",
    //     category: Ladders,
    //     quantity: 100,
    // }
}
```

### Part 3: The Design Rationale and Other Scenarios

This final part brings all the concepts together and explains the design philosophy behind Rust's granular privacy rules. It highlights that privacy is an intentional decision to give developers more control over their API.

- **Privacy as a Design Tool:** The ability to have a public struct with private fields allows for more complex design patterns. You can hide implementation details and only expose the parts of the struct that other code needs to see.
    
- **Constructor Functions:** If a struct has private fields, you must provide a public associated function (a constructor) that lives within the same module to create an instance. This is the only way for external code to create the struct.
    
- **Method Privacy:** Methods within an `impl` block also have their own visibility. The `impl` block itself is not marked `pub`, but each method inside it can be `pub` or private.
    

Rust

```Rust
// File: src/inventory.rs
pub const MANAGER: &str = "Ivan Inventory";

#[derive(Debug)]
pub enum ProductCategory {
    Ladders,
    Hammers,
}

#[derive(Debug)]
pub struct Item {
    pub name: String,
    category: ProductCategory, // This field is now private again.
    pub quantity: u32,
}

impl Item {
    // This is a public associated function that can construct an instance.
    // It is required because the `category` field is private.
    pub fn new(name: String, quantity: u32) -> Self {
        // This function has access to the private `category` field
        // because it is in the same module.
        Item {
            name,
            category: ProductCategory::Ladders, // Hard-code a default private value.
            quantity,
        }
    }
}

// File: src/main.rs
mod inventory;

fn main() {
    // We can now call the public constructor to create the Item.
    // We do not have access to the private `category` field from here.
    let my_ladder = inventory::Item::new(String::from("Simple Ladder"), 10);
    
    println!("{:#?}", my_ladder);
    // Output:
    // Item {
    //     name: "Simple Ladder",
    //     category: Ladders,
    //     quantity: 10,
    // }
}
```
