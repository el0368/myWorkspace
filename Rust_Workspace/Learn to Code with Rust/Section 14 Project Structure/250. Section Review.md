### 1. What's the difference between a **package**, a **project**, and a **crate**?

- **Project / Package:** These terms are often used interchangeably. A **package** is the top-level unit of a Rust project, defined as a directory that contains a **`Cargo.toml`** file. The `Cargo.toml` file holds metadata like the project's name, version, and dependencies.
    
- **Crate:** A **crate** is the fundamental unit of code that the Rust compiler (`rustc`) compiles. A package must contain at least one crate. Crates are the building blocks of a Rust project.
    

**Analogy:** A **package** is like a complete recipe book (the directory with `Cargo.toml`). A **crate** is a single recipe inside that book (the collection of Rust source files).

### 2. What are the two types of crates and how does Rust know which is which?

There are two types of crates:

- **Binary Crate:** This is a program that compiles to an executable that you can run. Rust identifies a binary crate by looking for a **`src/main.rs`** file.
    
- **Library Crate:** This is a collection of reusable code (functions, structs, etc.) that does not have a `main()` function. Its purpose is to be used by other crates. Rust identifies a library crate by looking for a **`src/lib.rs`** file.
    

A single package can have a binary crate, a library crate, or both, but it must have at least one of these two files to be a valid package. Both crates will have the same name, which is determined by the `name` field in `Cargo.toml`.

### 3. What is a **module** and why are they used?

A **module** is an organizational container used to group related Rust code (constants, functions, structs, enums, etc.) into a logical unit. Modules create a **namespace**, which is like a directory for your code.

- **Advantage:** Modules help prevent naming conflicts. You can have two different modules that both have an item named `get_item`, and Rust can distinguish between them by their module path (e.g., `inventory::get_item` vs. `products::get_item`).
    
- **Encapsulation:** Modules also control the visibility of their items, allowing you to expose only the public parts of your API while keeping the internal implementation details private.
    

### 4. How do I make items in a module available to other parts of my program?

By default, all items within a module are **private** and cannot be accessed from outside that module.

- **The `pub` Keyword:** You use the **`pub` keyword** to make an item public.
    
- **Visibility Rules:**
    
    - **Public Enums:** If an `enum` is declared `pub`, all of its variants (e.g., `Red`, `Green`) automatically become public as well.
        
    - **Public Structs:** If a `struct` is declared `pub`, its fields remain **private by default**. You must explicitly add `pub` to each field you want to make accessible from outside the module.
        
    - **Instantiation:** If a `pub struct` has any private fields, you cannot directly instantiate it from another module; it must provide a public associated function (like a `new()` constructor) for creation.
        

### 5. What are the different ways to declare a module and organize its files?

The `mod` keyword is used to declare a module, and there are three ways to define its contents:

1. **Inline Modules:** The module's contents are placed directly inside a code block (`{}`) in the same file.
    
    - **Syntax:** `mod my_module { ... }`
        
2. **File-based Modules:** The module's contents are placed in a separate file with the same name.
    
    - **Syntax:** In `src/main.rs` (or `src/lib.rs`), you write `mod my_module;`. The code for the module then goes into a file named **`src/my_module.rs`**.
        
3. **Folder-based Modules:** The module's contents are placed in a folder with the same name, which contains a special file.
    
    - **Syntax:** In `src/main.rs`, you write `mod my_module;`. The code for the module then goes into a directory named **`src/my_module/`** and is defined inside a file named **`mod.rs`** (or `my_module.rs` in newer Rust).
        

### 6. How do I access items from other modules?

- **Paths:** You access items using a path of module names separated by the scope resolution operator (`::`).
    
    - **Absolute Paths:** Start from the crate root using the **`crate`** keyword. Example: `crate::my_module::my_function()`.
        
    - **Relative Paths:** Start from the current module using **`self`** or from the parent module using **`super`**. Example: `super::sibling_module::my_function()`.
        
- **The `use` Keyword:** To avoid writing long paths, you use the **`use` keyword** to bring an item into the current scope.
    
    - **Syntax:** `use crate::my_module::MyStruct;` allows you to simply write `MyStruct` later in your code.
        
    - **Aliases:** The **`as` keyword** renames an item on import to avoid conflicts (e.g., `use crate::a::Name as AName;`).
        
    - **Glob Operator:** The **`*` (glob) operator** imports all public items from a module (`use crate::my_module::*;`). This is generally discouraged.
        
    - **Re-exporting:** The **`pub use`** keyword is used in a library crate to simplify a public API by re-exporting key items from nested modules, making them available at the top level of the crate.
        

### 7. Can a single project have more than one executable?

Yes. A single package can contain multiple binary crates.

- **Convention:** You place additional `.rs` files that contain a `main()` function inside a directory named **`src/bin/`**.
    
- **Running a specific binary:** You use the `cargo run` command with the `--bin` flag, followed by the filename of the binary you want to run.
    
    - **Example:** If you have `src/bin/cli.rs`, you run it with `cargo run --bin cli`.
        
- **`src/main.rs`** is treated as the primary binary and is run by default with `cargo run`.
    

### 8. How do I use external code libraries or the standard library?

- **External Crates:** You declare dependencies in the `[dependencies]` section of your **`Cargo.toml`** file. `cargo` automatically fetches them from crates.io. You then import them into your code using the **`use`** keyword and the crate's name.
    
- **Standard Library:** The standard library (`std`) is a collection of built-in modules in Rust. You import items from it using the same `use` keyword (e.g., `use std::io;`). Some very common items are automatically included via the **prelude** (e.g., `Option`, `Result`).
