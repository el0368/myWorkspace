### Summary of Rust Enums

This course section reviewed **enums** (short for "enumerations"), a custom data type in Rust that allows you to define a type with a fixed set of possible values, known as **variants**.

---

### Declaring and Instantiating Enums

Enums are declared using the **`enum`** keyword, followed by a name in **PascalCase**. Inside a pair of curly braces `{}`, you define the variants. Like structs, enums do not implement the `Copy` trait by default, so standard ownership rules apply.

There are three ways to define variants, which dictate how they store **associated data**:

1. **Empty Variant:** An enum variant that holds no data. This is useful for simple, distinct states (e.g., `enum TrafficLight { Red, Yellow, Green }`).
    
2. **Tuple Variant:** This variant stores associated data based on position, similar to a tuple. You define the types in parentheses `()` after the variant name. Different variants can store different types and numbers of data.
    
3. **Struct Variant:** This variant stores associated data with named fields, much like a struct. You define the fields and their types in curly braces `{}` after the variant name.
    

When you **instantiate** an enum, you specify both the enum name and the variant, providing the correct values for any associated data. The syntax for instantiation mirrors the variant's definition (parentheses for a tuple variant, curly braces for a struct variant).

---

### The `match` Keyword

The **`match`** keyword is a powerful control flow operator often used with enums. It allows you to execute different code blocks based on which enum variant a value holds.

- **Exhaustive Checking:** The compiler will ensure that you handle **every possible variant** of the enum. This prevents bugs from unhandled cases.
    
- **Destructuring:** A `match` expression can directly **extract** the associated data from a tuple or struct variant and bind it to a new variable within the code block.
    
- **Catch-all Pattern:** The underscore `_` acts as a **catch-all** pattern, matching any variant that hasn't been explicitly handled yet. This is useful for cases where you don't need to perform specific logic for every single variant.
    

---

### Methods on Enums

Similar to structs, enums can have **methods** defined in an **`impl` block**. A method is a function that belongs to an enum instance.

- Methods are declared with the **`impl`** keyword, followed by the enum's name.
    
- The first parameter of an enum method is always **`self`**, which represents the instance on which the method is called.
    
- `self` can be passed by **ownership** (`self`) or by **reference** (`&self` or `&mut self`), just like with structs.
    
- Rust automatically provides the `self` argument during method invocation, so you only need to provide arguments for any additional parameters.
    

---

### The `if let` Construct

For cases where you only care about one specific enum variant and want to ignore all others, the **`if let`** construct is a concise alternative to `match`.

- `if let` combines an `if` condition with a `let` variable declaration.
    
- The syntax is **`if let Variant::Name(variable) = enum_value`**.
    
- The `if` block will only execute if `enum_value` matches the specified variant.
    
- If a match occurs, the associated data is extracted and bound to the `variable`, which can then be used inside the `if` block.
    
- This construct avoids the verbosity of a `match` expression when you don't need to handle every possible variant.
