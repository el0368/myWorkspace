### Part 1: `match` Statement Fundamentals & Enum Setup

This progressive example starts by reviewing the `match` keyword and its core principle: it must be exhaustive. It then sets up the basic enum and function that will be used to demonstrate this principle.

- **`match` Keyword:** The `match` keyword compares a given value against a series of patterns (called "arms"). It executes the code of the first arm that successfully matches the value.
    
- **Exhaustiveness:** A core rule of `match` is that it must be **exhaustive**, meaning it must cover every possible value that the type being matched could hold. This makes it ideal for use with `enum`s, which have a finite, known set of variants.
    
- **The Code:** This part defines the `OperatingSystem` enum and the `years_since_release` function signature, which will be the context for our `match` statement.

### Part 2: The Compiler's Role in Exhaustiveness (The Problem)

This part demonstrates the crucial role of the Rust compiler in ensuring `match` statements are exhaustive. We create a `match` statement that is **non-exhaustive** and see the resulting compile-time error.

- **Non-Exhaustive Match:** A `match` statement that does not cover all possible variants of an `enum` is considered non-exhaustive.
    
- **The Compiler's Warning:** The compiler will immediately catch this error and refuse to compile the program. The error message is very helpful, as it explicitly lists the missing variants that need to be covered.
    

Rust

```Rust
// The enum from Part 1
#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    // This `match` statement is non-exhaustive; it only covers `Windows`.
    match os {
        OperatingSystem::Windows => 39,
        // The compiler will produce an error here, stating that `MacOS` and `Linux`
        // are not covered by any pattern.
    }
}

fn main() {
    // This code will not compile.
    // The compiler prevents a potential runtime error of matching an unknown variant.
}
```

### Part 3: The Solution - An Exhaustive Match

This part presents the solution to the problem from Part 2. We write an exhaustive `match` statement that covers all possible `enum` variants, satisfying the compiler's requirements.

- **Exhaustive `match`:** The `match` statement now contains an arm for `Windows`, `MacOS`, and `Linux`.
    
- **`match` as an Expression:** Each arm returns a `u32` value (`39`, `23`, `34`). The `match` statement itself will evaluate to one of these values, which is then implicitly returned by the `years_since_release` function.
    

Rust

```Rust
// The enum from Part 1
#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    // This `match` statement is exhaustive, covering all possible variants.
    // The compiler is now happy, and the code will compile.
    match os {
        // `match` works as an expression, returning one of these `u32` values.
        OperatingSystem::Windows => 39,
        OperatingSystem::MacOS => 23,
        OperatingSystem::Linux => 34,
    } // No semicolon, as this is the implicit return of the function.
}

fn main() {
    // This part will be completed in the next example.
}
```

### Part 4: Putting It All Together (The Final Working Code)

This final part ties all the concepts together into a complete, working program. It demonstrates how to create an enum instance, pass it to a function, and use the returned value.

- **Code Flow:** An `OperatingSystem` variant is created, passed to `years_since_release`, matched against the exhaustive arms, and the result is used in `main` to print a final message.
    
- **Ownership:** The `my_computer` variable's ownership is moved into the `years_since_release` function, but since we don't try to use it afterward, the code remains valid.
    

Rust

```Rust
// The enum and function from Part 3.
#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => 39,
        OperatingSystem::MacOS => 23,
        OperatingSystem::Linux => 34,
    }
}

fn main() {
    // 1. Create a variable and assign an enum variant instance.
    let my_computer = OperatingSystem::MacOS;

    // 2. Call the function with our enum instance.
    // Ownership of `my_computer` moves to the `os` parameter.
    let age = years_since_release(my_computer);
    
    // 3. Print the final result using the value returned by the function.
    println!("My computer's operating system is {} years old.", age);
    // Output: My computer's operating system is 23 years old.
    
    // To demonstrate the exhaustiveness check, change `my_computer` to `Linux` or `Windows`.
    // The `match` statement will correctly handle each case.
}
```
