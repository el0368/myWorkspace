### Rust Enums Study Guide: Struct Variants and Comparison with Tuple Variants

This study guide expands on the concepts of struct variants in Rust enums, as detailed in the provided transcript. It contrasts struct variants with tuple variants, highlighting the advantages of named fields for clarity and context, similar to structs versus tuples. We'll explore using a separate struct as associated data versus inline struct variants, their trade-offs, and how they integrate with the `match` keyword for data access. Examples use the `PaymentMethodType` enum, building progressively from tuple variants to struct variants, with complete, runnable Rust code (Rust 1.78+). The focus is on practical application, with minimal boilerplate, and includes the `match` construct as requested for handling associated data.

#### 1. Review: Tuple Variants for Sequential Data
Tuple variants store data positionally, which is concise but lacks field names, reducing clarity for multiple fields.

**Key Concepts:**
- **Syntax**: `Variant(Type1, Type2, ...)` for definition; `Enum::Variant(val1, val2, ...)` for instantiation.
- **Advantages**: Simple for few fields; less verbose.
- **Disadvantages**: Positional data can be ambiguous (e.g., two `String`s for PayPal lack context).
- **Use Case**: When order is clear or data is minimal.

**Progressive Example 1: Tuple Variants in PaymentMethodType**
Define an enum with tuple variants.

```rust
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String),      // Account number
    DebitCard(String),       // Account number
    PayPal(String, String),  // Username, password (positional)
}

fn main() {
    let paypal = PaymentMethodType::PayPal(String::from("bob@gmail.com"), String::from("password"));
    println!("{:?}", paypal);
}
```

**Output:**
```
PayPal("bob@gmail.com", "password")
```

**Explanation:**
- `PayPal` uses two `String`s; order implies username, password, but lacks explicit names.
- Pitfall: Swapping username/password silently changes meaning; no compile-time check.

#### 2. Using a Separate Struct as Associated Data
To add clarity, a separate struct can be used as associated data in a tuple variant, decoupling the data structure.

**Key Concepts:**
- **Separate Struct**: Defined independently; reusable across contexts.
- **Tuple Variant**: Holds the struct as a single value (e.g., `Variant(Struct)`).
- **Advantages**: Reusability; can be passed to functions or used elsewhere.
- **Disadvantages**: More verbose; requires extra struct definition.
- **Matching**: Destructure the struct in `match`.

**Progressive Example 2: Separate Credentials Struct**
Use a `Credentials` struct for PayPal.
```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate,
}

fn wash_laundry(cycle: LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature } => {
            println!("Running the laundry with a temperature of {}", temperature);
        }
        LaundryCycle::Delicate => println!("Running the laundry with delicate cycle"),
    }
}

fn main() {
    let cycle = LaundryCycle::Hot { temperature: 100 };
    wash_laundry(cycle);
}
```

**Output:**
```
PayPal: username bob@gmail.com, password [hidden]
```

**Explanation:**
- `Credentials` is a standalone struct; used as a single value in `PayPal`.
- `match` destructures `PayPal(creds)` to access `creds.username`.
- Progressive: Adds struct and `match` for data access.
- Pitfall: Forgetting to borrow (`&`) moves ownership, preventing reuse.

#### 3. Introducing Struct Variants
Struct variants embed named fields directly in the enum, simplifying syntax while maintaining clarity.

**Key Concepts:**
- **Syntax**: `Variant { field1: Type1, field2: Type2 }` for definition; `Enum::Variant { field1: val1, field2: val2 }` for instantiation.
- **Advantages**: Less code than separate struct; fields named for clarity.
- **Disadvantages**: Coupled to the enum; not reusable independently.
- **Matching**: Use `{ field1, field2 }` to destructure in `match`.

**Progressive Example 3: Converting PayPal to Struct Variant**
Replace `PayPal(Credentials)` with a struct variant.
```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),  // Tuple variant
}

fn wash_laundry(cycle: LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature } => {
            println!("Running the laundry with a temperature of {}", temperature);
        }
        LaundryCycle::Delicate(fabric_type) => {
            println!("Running the laundry with a delicate cycle for {}", fabric_type);
        }
    }
}

fn main() {
    let cycle = LaundryCycle::Delicate(String::from("silk"));
    wash_laundry(cycle);
}
```
**Output:**
```
PayPal: username bob@gmail.com, password [hidden]
```

**Explanation:**
- `PayPal` uses `{}` for named fields, mirroring struct syntax.
- `match` uses `{ username, password }` to destructure.
- Progressive: Simplifies by removing `Credentials` struct.
- Pitfall: Using `()` instead of `{}` for struct variant causes syntax error.

#### 4. Mixing Variant Types and Matching
Combine unit, tuple, and struct variants; use `match` to handle all.

**Key Concepts:**
- **Mixing Variants**: Enums can have unit, tuple, and struct variants.
- **Match Syntax**: Varies by variant: `()` for tuples, `{}` for structs, nothing for unit.
- **Exhaustiveness**: `match` ensures all variants are handled.

**Progressive Example 4: Mixed Variants with Match**
Add a unit variant `Cash`.
```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

fn wash_laundry(cycle: &LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature } => {
            println!("Running the laundry with a temperature of {}", temperature);
        }
        LaundryCycle::Delicate(fabric_type) => {
            println!("Running the laundry with a delicate cycle for {}", fabric_type);
        }
    }
}

fn main() {
    let cold = LaundryCycle::Cold;
    let hot = LaundryCycle::Hot { temperature: 100 };
    let delicate = LaundryCycle::Delicate(String::from("silk"));
    
    wash_laundry(&cold);
    wash_laundry(&hot);
    wash_laundry(&delicate);
}
```

**Output:**
```
Credit: 0012-3456
PayPal: username bob@gmail.com, password [hidden]
Cash payment
```

**Explanation:**
- Mixes all variant types; `match` handles each differently.
- Borrow `&` for reuse.
- Progressive: Shows full enum flexibility.
- Pitfall: Missing `Cash` arm causes "non-exhaustive patterns" error.

#### 5. Advanced: Reassignment and Validation in Match
Reassign variants and add logic in `match` arms.

**Key Concepts:**
- **Reassignment**: Use `mut` to switch variants.
- **Validation**: Add logic in `match` blocks (e.g., check password length).
- **Trade-offs**: Struct variants for inline clarity; separate structs for reusability.

**Progressive Example 5: Reassignment and Validation**
Reassign and validate in `match`.
```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32, duration: u32 },  // Multi-field struct
    Delicate(String, bool),                   // Multi-field tuple
}

fn wash_laundry(cycle: &LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature, duration } => {
            println!("Hot cycle: {}°C for {} minutes", temperature, duration);
        }
        LaundryCycle::Delicate(fabric, prewash) => {
            println!("Delicate cycle for {}, prewash: {}", fabric, prewash);
        }
    }
}

fn main() {
    let hot = LaundryCycle::Hot { temperature: 100, duration: 45 };
    let delicate = LaundryCycle::Delicate(String::from("silk"), true);
    
    wash_laundry(&hot);
    wash_laundry(&delicate);
}
```
**Output:**
```
Credit: 0012-3456
PayPal: username bob@gmail.com, weak password
```

**Explanation:**
- Reassigns from tuple to struct variant.
- `match` validates password length in `PayPal` arm.
- Progressive: Adds mutability and logic.
- Pitfall: Incorrect field names in `match` (e.g., `{ user }`) cause errors.
