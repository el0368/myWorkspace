### Part 1: Initial Enum Definition and the Need for Different Data

This progressive example starts with a simple enum definition where variants have different associated data. This sets the stage for a demonstration of how Rust handles these varying data requirements.

- **Enum Definition:** We define a `PaymentMethodType` enum. The `CreditCard` and `DebitCard` variants each require one piece of data (a `String`), while the `PayPal` variant requires two pieces of data (two `String`s).
    
- **The Code:** This example shows the initial `enum` definition, where the variants have different data signatures.
    

Rust

```Rust
// Our enum definition with variants storing different data.
#[derive(Debug)]
enum PaymentMethodType {
    // These variants require one piece of data (a String for the account number).
    CreditCard(String),
    DebitCard(String),
    // This variant requires two pieces of data (two Strings for email and password).
    PayPal(String, String),
}

fn main() {
    // This part will be filled in by the following examples.
}
```

### Part 2: Instantiating Variants with Different Data

This part demonstrates how to correctly create instances of enum variants that have different data requirements. Each variant acts like a constructor function, and you must provide the correct number and type of arguments.

- **Instantiation Syntax:** You call the enum variant as a function, providing the concrete values for its associated data inside parentheses.
    
- **Compiler Check:** The Rust compiler strictly checks that you provide the correct number of arguments and that their types match what was specified in the enum definition.
    

Rust

```Rust
// The enum from Part 1.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String),
    DebitCard(String),
    PayPal(String, String),
}

fn main() {
    // Instantiating a `CreditCard` variant with one String argument.
    let visa = PaymentMethodType::CreditCard(String::from("5678"));

    // Instantiating a `PayPal` variant with two String arguments.
    let paypal_account = PaymentMethodType::PayPal(
        String::from("bob@gmail.com"),
        String::from("password")
    );
    
    // Attempting to instantiate PayPal with one argument would cause a compile-time error.
    // let invalid_paypal = PaymentMethodType::PayPal(String::from("bob@gmail.com"));
    // ERROR: this enum variant takes 2 arguments but 1 argument was supplied

    println!("Visa account: {:?}", visa);
    println!("PayPal account: {:?}", paypal_account);
}
```

### Part 3: Reassigning a Mutable Enum Variable

This part demonstrates that an enum variable can be reassigned to a new variant. This is possible even if the new variant holds a different number and type of associated data.

- **Mutability:** The variable holding the enum instance must be declared as `mut` to allow it to be reassigned to a new variant.
    
- **Reassignment:** The new value is simply a call to the new enum variant constructor.
    
- **Compiler Check:** The compiler again ensures that the new variant is provided with the correct number and type of associated data.
    

Rust

```Rust
// The enum from Part 1.
#[derive(Debug)]
enum PaymentMethodType {
    CreditCard(String),
    DebitCard(String),
    PayPal(String, String),
}

fn main() {
    // `my_payment_method` is declared mutable so we can reassign its variant.
    let mut my_payment_method = PaymentMethodType::CreditCard(
        String::from("5678")
    );
    
    println!("Initial payment method: {:?}", my_payment_method);
    
    // Reassigning `my_payment_method` to a new variant (`PayPal`).
    // The new variant requires two arguments, so we provide them.
    my_payment_method = PaymentMethodType::PayPal(
        String::from("bob@gmail.com"),
        String::from("password")
    );

    // The variable now holds the new variant with its new data.
    println!("Final payment method: {:?}", my_payment_method);
}
```
