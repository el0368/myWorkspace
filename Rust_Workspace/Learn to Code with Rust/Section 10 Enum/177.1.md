### Rust Match Study Guide: Matching Multiple Values in a Single Arm

This study guide covers advanced `match` techniques in Rust, focusing on matching multiple values or variants in a single arm using the pipe `|` operator and the catch-all `_` pattern (with or without binding), as described in the transcript. These allow concise handling of multiple cases with shared logic, while maintaining exhaustiveness. We'll start with basic `match` on enums, progress to multi-pattern arms, catch-all patterns, and binding for dynamic access. Examples use the `OnlineOrderStatus` enum and are complete, runnable Rust code (Rust 1.78+). The guide emphasizes practical use, pitfalls, and integration with methods.

#### 1. Basics of `match` with Enums
`match` requires exhaustive coverage of all variants. Each arm handles one pattern, but multiple can share logic.

**Key Concepts:**
- Arms: Pattern => code; evaluated top-to-bottom.
- Exhaustiveness: All variants must be covered; compiler enforces.
- Basic Usage: One variant per arm for specific logic.
- Use Case: Branching on enum status with variant-specific messages.

**Progressive Example 1: Basic Match on Enum Variants**
Define enum and method with individual arms.

```rust
// src/main.rs

#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn check(&self) {
        match self {
            OnlineOrderStatus::Ordered => println!("Your item has been ordered"),
            OnlineOrderStatus::Packed => println!("Your item has been packed"),
            OnlineOrderStatus::Shipped => println!("Your item has been shipped"),
            OnlineOrderStatus::Delivered => println!("Your item has been delivered"),
        }
    }
}

fn main() {
    let status = OnlineOrderStatus::Shipped;
    status.check();
}
```

**Output:**
```
Your item has been shipped
```

**Explanation:**
- Each variant has a dedicated arm.
- Method uses `&self` for borrowing.
- Pitfall: Missing an arm (e.g., `Shipped`) causes "non-exhaustive patterns" error.

#### 2. Using Catch-All `_` for Multiple Variants
Use `_` as a last arm to catch all unmatched variants, executing shared logic.

**Key Concepts:**
- **Catch-All (`_`)**: Matches anything; must be last (top-to-bottom evaluation).
- **Advantages**: Handles multiple variants with one block; simplifies code.
- **Disadvantages**: No access to the specific variant (use binding for that).
- **Placement**: Always last; earlier placement makes other arms unreachable.

**Progressive Example 2: Catch-All for Non-Delivered Variants**
Group non-delivered with `_`.

```rust
// src/main.rs

#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn check(&self) {
        match self {
            OnlineOrderStatus::Delivered => println!("Your item has been delivered"),
            _ => println!("Your item is not there yet"),
        }
    }
}

fn main() {
    let delivered = OnlineOrderStatus::Delivered;
    let shipped = OnlineOrderStatus::Shipped;
    let ordered = OnlineOrderStatus::Ordered;
    
    delivered.check();
    shipped.check();
    ordered.check();
}
```

**Output:**
```
Your item has been delivered
Your item is not there yet
Your item is not there yet
```

**Explanation:**
- `Delivered` has specific logic; `_` catches `Ordered`, `Packed`, `Shipped`.
- Progressive: Simplifies multiple variants.
- Pitfall: Placing `_` first causes "unreachable pattern" warnings for later arms.

#### 3. Matching Multiple Specific Variants with `|`
Use `|` (pipe) to combine multiple patterns in one arm for shared logic.

**Key Concepts:**
- **Pipe (`|`)**: "Or" for patterns; e.g., `Pattern1 | Pattern2 => code`.
- **Readability**: Add spaces around `|` (e.g., `A | B`).
- **Use with Catch-All**: Combine with `_` for full coverage.
- **Advantages**: Groups related variants without duplication.

**Progressive Example 3: Grouping with Pipe**
Group prep stages with `|`.

```rust
// src/main.rs

#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn check(&self) {
        match self {
            OnlineOrderStatus::Ordered | OnlineOrderStatus::Packed => {
                println!("Your item is being prepped for shipment");
            }
            OnlineOrderStatus::Shipped => println!("Your item is on the way"),
            OnlineOrderStatus::Delivered => println!("Your item has been delivered"),
        }
    }
}

fn main() {
    let ordered = OnlineOrderStatus::Ordered;
    let packed = OnlineOrderStatus::Packed;
    let shipped = OnlineOrderStatus::Shipped;
    
    ordered.check();
    packed.check();
    shipped.check();
}
```

**Output:**
```
Your item is being prepped for shipment
Your item is being prepped for shipment
Your item is on the way
```

**Explanation:**
- `Ordered | Packed` shares one arm.
- Exhaustiveness requires covering all (no `_` here).
- Progressive: Introduces `|` for grouping.
- Pitfall: Forgetting a variant causes "non-exhaustive" error.

#### 4. Binding with Catch-All for Dynamic Access
Bind a name to `_` (e.g., `_ => let var = ...`) to capture the variant for use in the arm.

**Key Concepts:**
- **Binding**: `_ =>` becomes `name @ _ =>` or just name the catch-all (e.g., `other =>`).
- **Advantages**: Access specific variant in catch-all (e.g., print its name).
- **Debug Requirement**: Derive `Debug` for printing variants.
- **Use Case**: Generic handling with variant-specific details.

**Progressive Example 4: Binding in Catch-All**
Bind and print in `_`.

```rust
// src/main.rs

#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn check(&self) {
        match self {
            OnlineOrderStatus::Delivered => println!("Your item has been delivered"),
            other_status => println!("Your item is {:?}", other_status),
        }
    }
}

fn main() {
    let shipped = OnlineOrderStatus::Shipped;
    let delivered = OnlineOrderStatus::Delivered;
    
    shipped.check();
    delivered.check();
}
```

**Output:**
```
Your item is Shipped
Your item has been delivered
```

**Explanation:**
- `other_status` binds the unmatched variant; printed with `{:?}` (requires `Debug`).
- Covers `Ordered`, `Packed`, `Shipped` dynamically.
- Progressive: Adds binding to catch-all.
- Pitfall: Without `Debug`, `println!("{:?}", other_status)` fails.

#### 5. Advanced: Combining `|`, Catch-All, and Binding
Mix techniques for complex logic; add returns or mutations.

**Key Concepts:**
- **Combination**: Use `|` in arms, bind in catch-all.
- **Returns**: `match` can return values (consistent types).
- **Mutable Methods**: Bind and mutate if `&mut self`.

**Progressive Example 5: Combined Techniques with Return**
Method returning status string.

```rust
// src/main.rs

#[derive(Debug)]
enum OnlineOrderStatus {
    Ordered,
    Packed,
    Shipped,
    Delivered,
}

impl OnlineOrderStatus {
    fn get_message(&self) -> String {
        match self {
            OnlineOrderStatus::Ordered | OnlineOrderStatus::Packed => {
                "Your item is being prepped for shipment".to_string()
            }
            other_status => format!("Your item is {:?}", other_status),
        }
    }
}

fn main() {
    let packed = OnlineOrderStatus::Packed;
    let shipped = OnlineOrderStatus::Shipped;
    let delivered = OnlineOrderStatus::Delivered;
    
    println!("{}", packed.get_message());
    println!("{}", shipped.get_message());
    println!("{}", delivered.get_message());
}
```

**Output:**
```
Your item is being prepped for shipment
Your item is Shipped
Your item is Delivered
```

**Explanation:**
- `Ordered | Packed` shares message; catch-all binds and formats.
- Returns `String`; consistent across arms.
- Progressive: Adds returns, combines features.
- Pitfall: Inconsistent types (e.g., `u32` in one arm) causes errors.
