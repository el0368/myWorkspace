### Rust Enums Study Guide: Matching Enum Variants with Associated Data

This study guide focuses on using the `match` keyword to access associated data in enum variants, as described in the transcript. It covers the differing syntax for tuple and struct variants, emphasizing how `match` destructures data for use in code blocks. Examples use the `LaundryCycle` enum and progress from simple unit variants to tuple and struct variants, demonstrating practical usage. All code is complete, runnable in Rust 1.78+, and keeps the explanation concise and aligned with prior lessons.

#### 1. Basics of `match` with Enums
`match` is used to handle enum variants, ensuring all possibilities are covered. When variants have associated data, `match` can destructure it for use in code blocks.

**Key Concepts:**
- **Exhaustiveness**: `match` must cover all variants; compiler enforces this.
- **Destructuring**: Extract associated data using variant-specific syntax.
- **Unit Variants**: No data, match directly (e.g., `Variant => ...`).
- **Tuple Variants**: Use parentheses `(x, y)` to bind positional data.
- **Struct Variants**: Use curly braces `{ field1, field2 }` to bind named fields.
- **Code Blocks**: Use `{}` for multi-line logic; typically no return value for side-effect functions.

**Progressive Example 1: Matching Unit Variant**
Start with a simple enum and unit variant.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot,
    Delicate,
}

fn wash_laundry(cycle: LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot => println!("Running the laundry with hot temperature"),
        LaundryCycle::Delicate => println!("Running the laundry with delicate cycle"),
    }
}

fn main() {
    let cycle = LaundryCycle::Cold;
    wash_laundry(cycle);
}
```

**Output:**
```
Running the laundry with cold temperature
```

**Explanation:**
- Simple `match` on unit variants; no data to destructure.
- Function takes ownership (fine for unit variants).
- Pitfall: Missing a variant (e.g., `Delicate`) causes "non-exhaustive patterns" error.

#### 2. Matching Struct Variants with Associated Data
Struct variants use named fields, destructured with `{ field: var }` in `match`.

**Key Concepts:**
- Syntax: `Variant { field1: var1, field2: var2 } => ...`
- Field Names: Must match those defined in the variant.
- Access: Variables (e.g., `var1`) are usable in the block.

**Progressive Example 2: Adding Struct Variant**
Add `Hot` as a struct variant with a temperature field.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate,
}

fn wash_laundry(cycle: LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature } => {
            println!("Running the laundry with a temperature of {}", temperature);
        }
        LaundryCycle::Delicate => println!("Running the laundry with delicate cycle"),
    }
}

fn main() {
    let cycle = LaundryCycle::Hot { temperature: 100 };
    wash_laundry(cycle);
}
```

**Output:**
```
Running the laundry with a temperature of 100
```

**Explanation:**
- `Hot` has a named field `temperature`; destructured as `{ temperature }`.
- Instantiation uses `{}` with field name.
- Progressive: Adds struct variant.
- Pitfall: Wrong field name (e.g., `{ temp }`) causes compile error.

#### 3. Matching Tuple Variants with Associated Data
Tuple variants use positional data, destructured with `(var1, var2)` in `match`.

**Key Concepts:**
- Syntax: `Variant(var1, var2) => ...`
- Variable Names: Chosen by developer; order matches variant definition.
- Flexibility: Names are arbitrary, unlike struct variants.

**Progressive Example 3: Adding Tuple Variant**
Make `Delicate` a tuple variant with a `String`.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),  // Tuple variant
}

fn wash_laundry(cycle: LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature } => {
            println!("Running the laundry with a temperature of {}", temperature);
        }
        LaundryCycle::Delicate(fabric_type) => {
            println!("Running the laundry with a delicate cycle for {}", fabric_type);
        }
    }
}

fn main() {
    let cycle = LaundryCycle::Delicate(String::from("silk"));
    wash_laundry(cycle);
}
```

**Output:**
```
Running the laundry with a delicate cycle for silk
```

**Explanation:**
- `Delicate` uses `(String)`; destructured as `(fabric_type)`.
- Name `fabric_type` is arbitrary but reflects position.
- Progressive: Adds tuple variant.
- Pitfall: Wrong number of variables (e.g., `(a, b)`) causes mismatch error.

#### 4. Mixing All Variant Types
Combine unit, struct, and tuple variants; test all in `main`.

**Key Concepts:**
- Mixed Variants: Enums can mix all variant types.
- Destructuring: Match syntax mirrors variant definition (`{}` for structs, `()` for tuples).
- Ownership: Borrow if reuse needed.

**Progressive Example 4: Testing All Variants**
Invoke all variants with borrowing.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

fn wash_laundry(cycle: &LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature } => {
            println!("Running the laundry with a temperature of {}", temperature);
        }
        LaundryCycle::Delicate(fabric_type) => {
            println!("Running the laundry with a delicate cycle for {}", fabric_type);
        }
    }
}

fn main() {
    let cold = LaundryCycle::Cold;
    let hot = LaundryCycle::Hot { temperature: 100 };
    let delicate = LaundryCycle::Delicate(String::from("silk"));
    
    wash_laundry(&cold);
    wash_laundry(&hot);
    wash_laundry(&delicate);
}
```

**Output:**
```
Running the laundry with cold temperature
Running the laundry with a temperature of 100
Running the laundry with a delicate cycle for silk
```

**Explanation:**
- All variant types used; `match` destructures accordingly.
- Borrow `&` to reuse instances.
- Progressive: Tests all cases together.
- Pitfall: Incorrect destructuring syntax (e.g., `Hot(f)` or `Delicate { f }`) fails.

#### 5. Advanced: Multi-Field Variants
Extend to multi-field tuple/struct variants.

**Key Concepts:**
- Multi-Field Struct: `{ field1, field2 }`
- Multi-Field Tuple: `(var1, var2)`
- Complex Logic: Use blocks for validation or processing.

**Progressive Example 5: Multi-Field Variants**
Add fields to `Hot` and `Delicate`.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32, duration: u32 },  // Multi-field struct
    Delicate(String, bool),                   // Multi-field tuple
}

fn wash_laundry(cycle: &LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature, duration } => {
            println!("Hot cycle: {}°C for {} minutes", temperature, duration);
        }
        LaundryCycle::Delicate(fabric, prewash) => {
            println!("Delicate cycle for {}, prewash: {}", fabric, prewash);
        }
    }
}

fn main() {
    let hot = LaundryCycle::Hot { temperature: 100, duration: 45 };
    let delicate = LaundryCycle::Delicate(String::from("silk"), true);
    
    wash_laundry(&hot);
    wash_laundry(&delicate);
}
```

**Output:**
```
Hot cycle: 100°C for 45 minutes
Delicate cycle for silk, prewash: true
```

**Explanation:**
- `Hot` destructures multiple named fields; `Delicate` multiple positional ones.
- Progressive: Adds complexity to variants.
- Pitfall: Mismatched field counts/names cause compile errors.
