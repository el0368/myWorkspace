### Rust Enums Study Guide: Advanced `match` with Code Blocks and Consistent Return Types

This study guide expands on the `match` keyword in Rust, focusing on using code blocks in match arms and ensuring consistent return types, as described in the transcript. We'll explore how to execute multi-line logic in match arms, the importance of implicit returns without semicolons, and maintaining type consistency. Examples build on the `OperatingSystem` enum, with ages updated for September 2, 2025: Windows (1985) is 40 years old, macOS (2001) is 24 years old, Linux (1991) is 34 years old. All code is runnable in Rust 1.78+ and progresses from simple to complex usage.

#### 1. Review: Basic `match` with Direct Values
`match` arms typically return direct values, but they must all produce the same type.

**Key Concepts:**
- Arms: Patterns (e.g., `Enum::Variant`) followed by `=>` and a value or block.
- Type Consistency: All arms must yield the same type (e.g., `u32`).
- Direct Values: Simple scalars (e.g., `40`) or expressions.

**Progressive Example 1: Simple `match` with Direct Values**
Match `OperatingSystem` to return ages.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => 40,  // 2025 - 1985
        OperatingSystem::MacOS => 24,    // 2025 - 2001
        OperatingSystem::Linux => 34,    // 2025 - 1991
    }
}

fn main() {
    let my_computer = OperatingSystem::MacOS;
    let age = years_since_release(my_computer);
    println!("My computer's OS is {} years old.", age);
}
```

**Output:**
```
My computer's OS is 24 years old.
```

**Explanation:**
- Direct values (`40`, `24`, `34`) are returned; all `u32`.
- Pitfall: Missing an arm causes "non-exhaustive patterns" error.

#### 2. Using Code Blocks in `match` Arms
Arms can include curly braces `{}` for multi-line logic, with the last expression as the implicit return.

**Key Concepts:**
- Code Blocks: Use `{}` for multiple statements.
- Implicit Return: Last expression without `;` is the arm’s value.
- Type Consistency: Block’s final value must match other arms’ types.
- No `return`: `return` exits the function, not the `match`.

**Progressive Example 2: Adding a Block to One Arm**
Add a block for `Windows`.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => {
            println!("Quite an old operating system!");
            40  // Implicit return, no semicolon
        }
        OperatingSystem::MacOS => 24,
        OperatingSystem::Linux => 34,
    }
}

fn main() {
    let dads_computer = OperatingSystem::Windows;
    let age = years_since_release(dads_computer);
    println!("My dad's computer is {} years old.", age);
}
```

**Output:**
```
Quite an old operating system!
My dad's computer is 40 years old.
```

**Explanation:**
- `Windows` arm uses a block; prints and returns `40`.
- No semicolon on `40` ensures it’s the return value.
- Progressive: Adds block to one arm.
- Pitfall: Adding `;` after `40` makes the arm return `()` (unit), causing type mismatch error.

#### 3. Mixing Blocks and Direct Values
Combine blocks and direct values, ensuring consistent types.

**Key Concepts:**
- Flexibility: Some arms can use blocks, others direct values.
- Error Checking: Rust enforces same return type across all arms.
- Debugging: Use blocks for logging or side effects.

**Progressive Example 3: Mixed Arms with Blocks**
Add blocks for multiple arms.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => {
            println!("Quite an old operating system!");
            40
        }
        OperatingSystem::MacOS => {
            println!("Running macOS!");
            24
        }
        OperatingSystem::Linux => 34,  // Direct value
    }
}

fn main() {
    let dads_computer = OperatingSystem::Windows;
    let age = years_since_release(dads_computer);
    println!("My dad's computer is {} years old.", age);
}
```

**Output:**
```
Quite an old operating system!
My dad's computer is 40 years old.
```

**Explanation:**
- `Windows` and `MacOS` use blocks; `Linux` uses direct value.
- All return `u32`.
- Progressive: Shows mixing styles.
- Pitfall: Returning `()` (e.g., only `println!()`) in a block causes type mismatch.

#### 4. Handling Ownership with Borrowing
Use borrowing to preserve enum for reuse.

**Key Concepts:**
- Borrowing (`&`): Avoids moving ownership.
- Blocks: Can include complex logic (e.g., calculations).
- Reassignment: Combine with `mut` for dynamic changes.

**Progressive Example 4: Borrowing with Blocks**
Use `&OperatingSystem` and reassign.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: &OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => {
            println!("Windows detected!");
            40
        }
        OperatingSystem::MacOS => {
            println!("macOS detected!");
            24
        }
        OperatingSystem::Linux => {
            println!("Linux detected!");
            34
        }
    }
}

fn main() {
    let mut computer = OperatingSystem::Windows;
    let age = years_since_release(&computer);
    println!("First check: {} years old.", age);
    
    computer = OperatingSystem::Linux;  // Reassign
    let new_age = years_since_release(&computer);
    println!("After switch: {} years old.", new_age);
}
```

**Output:**
```
Windows detected!
First check: 40 years old.
Linux detected!
After switch: 34 years old.
```

**Explanation:**
- Borrow `&` to reuse `computer`.
- Each arm logs and returns.
- Progressive: Adds borrowing, reassignment.
- Pitfall: Using `return 40` exits function early, not just arm.

#### 5. Advanced: Blocks with Associated Data
Handle enums with data, using blocks for logic.

**Key Concepts:**
- Destructuring: Extract data in arms (e.g., `Variant(x) => {}`).
- Complex Logic: Blocks for calculations or conditions.
- Type Consistency: Ensure blocks return expected type.

**Progressive Example 5: Matching with Data and Blocks**
Add release years to variants.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows(u32),  // Release year
    MacOS(u32),
    Linux(u32),
}

fn years_since_release(os: &OperatingSystem) -> u32 {
    let current_year = 2025;
    match os {
        OperatingSystem::Windows(year) => {
            println!("Windows released in {}", year);
            current_year - year
        }
        OperatingSystem::MacOS(year) => {
            println!("macOS released in {}", year);
            current_year - year
        }
        OperatingSystem::Linux(year) => {
            println!("Linux released in {}", year);
            current_year - year
        }
    }
}

fn main() {
    let computer = OperatingSystem::MacOS(2001);
    let age = years_since_release(&computer);
    println!("My computer is {} years old.", age);
}
```

**Output:**
```
macOS released in 2001
My computer is 24 years old.
```

**Explanation:**
- Destructure `year` in each arm; compute age in block.
- All arms return `u32`.
- Progressive: Adds data and calculations.
- Pitfall: Missing semicolon on non-final statements in block is okay, but final value needs no `;`.
