# 📘 Study Guide: `Option` and `Result` Enums in Rust

---

## 1. The `Option` Enum

### 1.1 Purpose

- Models a situation where a value may or may not exist.
    
- Represents **optional data**:
    
    - `Some(T)` → a value of type `T` is present.
        
    - `None` → no value is present.
        

This is Rust’s way of handling the concept of "nullable values" without unsafe `null` references.

---

### 1.2 Variants

- `Some(T)` → stores actual data of any type (`T` is generic).
    
- `None` → no data at all.
    

---

### 1.3 Methods

#### `unwrap()`

- Extracts the inner value if it’s `Some`.
    
- Panics if called on `None`.
    
- Example:
    
    ```rust
    let maybe = Some(10);
    println!("{}", maybe.unwrap()); // prints 10
    
    let none_val: Option<i32> = None;
    println!("{}", none_val.unwrap()); // runtime panic
    ```
    

#### `expect(message: &str)`

- Same as `unwrap()`, but lets you provide a **custom panic message**.
    
    ```rust
    let none_val: Option<i32> = None;
    println!("{}", none_val.expect("Expected a number but got None!"));
    ```
    

#### `unwrap_or(default_value)`

- Safer alternative.
    
- Returns the contained value if `Some`, or the provided fallback if `None`.
    
    ```rust
    let maybe = None;
    println!("{}", maybe.unwrap_or(100)); // prints 100
    ```
    

---

### 1.4 Best Practices

- Avoid `unwrap()` unless you are absolutely certain the value is `Some`.
    
- Prefer handling with:
    
    - `match` → ensures all cases are handled.
        
    - `if let` → concise handling when you only care about `Some`.
        

---

## 2. The `Result` Enum

### 2.1 Purpose

- Models **success or failure** of an operation.
    
- Rust’s idiomatic way to handle recoverable errors without crashing.
    

---

### 2.2 Variants

- `Ok(T)` → contains the success value of type `T`.
    
- `Err(E)` → contains the error value of type `E`.
    

Generics:

- `T` = type of success value.
    
- `E` = type of error value.
    
- Both can be **different types** or even the same, depending on design.
    

---

### 2.3 Example Use

```rust
fn divide(a: i32, b: i32) -> Result<i32, String> {
    if b == 0 {
        Err("Division by zero".to_string())
    } else {
        Ok(a / b)
    }
}

fn main() {
    match divide(10, 2) {
        Ok(result) => println!("Result: {}", result),
        Err(e) => println!("Error: {}", e),
    }
}
```

---

### 2.4 Methods

#### `unwrap()`

- Extracts the success value from `Ok`.
    
- Panics if called on `Err`.
    

#### `expect(message: &str)`

- Like `unwrap()`, but with a custom panic message.
    

#### `unwrap_or(default_value)`

- Returns the success value if `Ok`, or the provided fallback if `Err`.
    

---

### 2.5 Debug Support

- `Result` implements the **Debug trait**.
    
- You can use `{:?}` in formatting to print the variant and data.
    

```rust
let x: Result<i32, &str> = Ok(42);
println!("{:?}", x); // prints Ok(42)
```

---

## 3. Rust Prelude and Enum Variants

- **Prelude** = a collection of items automatically imported into every Rust program.
    
- Includes `Option`, `Result`, and all their variants (`Some`, `None`, `Ok`, `Err`).
    
- You can write:
    
    ```rust
    let value = Some(5);
    let result: Result<i32, &str> = Ok(10);
    ```
    
    without prefixing with `Option::Some` or `Result::Ok`.
    

---

## 4. Pattern Matching with `Option` and `Result`

### `match`

- Forces handling of all possible variants.
    
- Compiler ensures no case is missed.
    

```rust
let val = Some(7);
match val {
    Some(x) => println!("Got {}", x),
    None => println!("No value"),
}
```

### `if let`

- Concise when you only care about one variant.
    

```rust
if let Some(x) = val {
    println!("Got {}", x);
}
```

---

## 5. Core Takeaways

1. **Option**: models presence (`Some`) or absence (`None`) of a value.
    
2. **Result**: models success (`Ok`) or failure (`Err`) of an operation.
    
3. Both enums use **generics**, making them flexible across different types.
    
4. Methods like `unwrap()` are convenient but risky → may panic.
    
5. Safer handling:
    
    - `unwrap_or` for defaults.
        
    - `expect` with custom messages (still panics).
        
    - `match` and `if let` for explicit handling.
        
6. Prelude automatically imports `Option`, `Result`, and their variants.
