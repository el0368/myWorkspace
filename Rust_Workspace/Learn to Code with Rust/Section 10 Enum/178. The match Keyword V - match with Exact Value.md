## Matching Enum Variants with Specific Associated Data

This guide explores how to make `match` statements more granular by not only matching the enum variant but also specifying a particular value for its associated data. This allows for highly precise and expressive control flow.

### Part 1: The Enum Blueprint and `match` Setup

This part establishes the basic structure of an enum with associated data, and the method that will contain our `match` logic. The `Lowfat` variant has an `i32` to represent fat percentage, and the `Whole` variant is a simple unit variant.

```Rust
// Our enum with a tuple variant and a unit variant.
#[derive(Debug)]
enum Milk {
    Lowfat(i32), // Holds one i32 value (fat percentage)
    Whole,
}

impl Milk {
    // A method that takes ownership (`self`) of a `Milk` instance.
    fn drink(self) {
        // The `match` statement will go here.
    }
}
fn main() {
    // This part will be completed in the next examples.
}
```

### Part 2: Matching Specific Values (The Challenge)

This part shows how to write a `match` arm that targets a **specific value** of an associated data field. It then highlights a crucial compiler error: a `match` statement must be exhaustive and cover all possible values.

- **Specific Match Syntax:** A pattern like `Milk::Lowfat(2)` will only match if the variant is `Lowfat` AND the associated `i32` value is exactly `2`.
    
- **The Compiler Problem:** If you only match against a specific value like `2`, the compiler will point out that the `Lowfat` variant with any other `i32` value is not covered, and the code will fail to compile.
    

Rust

```Rust
// The enum from Part 1
#[derive(Debug)]
enum Milk {
    Lowfat(i32),
    Whole,
}

impl Milk {
    fn drink(self) {
        match self {
            // This arm is extremely specific: it only matches if the value is exactly `2`.
            Milk::Lowfat(2) => {
                println!("Delicious, 2% milk is my favorite!");
            },
            // This arm matches the unit variant.
            Milk::Whole => {
                println!("You've got the whole milk!");
            },
            // The compiler will produce an error here, stating that `Lowfat(i32)` for all
            // other integer values is not covered.
        }
    }
}
fn main() {
    // let my_milk = Milk::Lowfat(1);
    // This code would not compile due to the `match` arm error.
}
```

### Part 3: The Solution - Matching a Specific Value and a General Value

This part presents the solution to the exhaustiveness problem from Part 2. To satisfy the compiler, we must add a more general `match` arm that uses a variable to capture all other possible values for `Lowfat`, and we demonstrate the importance of arm order.

- **General Match Syntax:** A pattern like `Milk::Lowfat(percent)` will match any `Lowfat` variant. The value of its associated `i32` will be bound to the `percent` variable, which can then be used in the code block.
    
- **Order of Arms:** The more specific `Lowfat(2)` arm **must come before** the general `Lowfat(percent)` arm. If the general arm came first, it would match everything, making the specific arm unreachable.
    

Rust

```Rust
// The enum from Part 1
#[derive(Debug)]
enum Milk {
    Lowfat(i32),
    Whole,
}

impl Milk {
    fn drink(self) {
        match self {
            // 1. The specific arm must come first. It matches only if the value is 2.
            Milk::Lowfat(2) => {
                println!("Delicious, 2% milk is my favorite!");
            },
            // 2. This general arm must come second. It matches any other `Lowfat` variant.
            Milk::Lowfat(percent) => {
                println!("You've got the lowfat {} percent version.", percent);
            },
            // 3. The `Whole` variant is also covered.
            Milk::Whole => {
                println!("You've got the whole milk!");
            },
        }
    }
}
fn main() {
    // This code now compiles and is ready to be used.
}
```

### Part 4: The Final Progressive Example

This final part ties all the concepts together into a complete, working program. It demonstrates how to invoke the `drink` method with different `Milk` variants to see each of the match arms execute correctly.

- **Code Flow:** We create three different `Milk` instances and pass them one by one to the `drink` method.
    
- **Output:** The output will show that the specific `Lowfat(2)` arm is chosen for `my_favorite_milk`, while `Lowfat(1)` is correctly handled by the general `Lowfat(percent)` arm.
    

Rust

```Rust
// The final enum and method from Part 3.
#[derive(Debug)]
enum Milk {
    Lowfat(i32),
    Whole,
}

impl Milk {
    fn drink(self) {
        match self {
            Milk::Lowfat(2) => {
                println!("Delicious, 2% milk is my favorite!");
            },
            Milk::Lowfat(percent) => {
                println!("You've got the lowfat {} percent version.", percent);
            },
            Milk::Whole => {
                println!("You've got the whole milk!");
            },
        }
    }
}

fn main() {
    let my_1_percent_milk = Milk::Lowfat(1);
    let my_favorite_milk = Milk::Lowfat(2);
    let my_whole_milk = Milk::Whole;

    println!("--- Drinking Milk Samples ---");
    
    // Call 1: Matches the general `Lowfat(percent)` arm.
    my_1_percent_milk.drink();
    
    // Call 2: Matches the specific `Lowfat(2)` arm.
    my_favorite_milk.drink();
    
    // Call 3: Matches the `Whole` arm.
    my_whole_milk.drink();
}
```
