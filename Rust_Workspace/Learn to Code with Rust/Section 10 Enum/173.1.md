### Rust Enums Study Guide: Using `match` for Exhaustive Pattern Matching

This study guide covers the `match` keyword in Rust, with a focus on its use with enums for safe, exhaustive branching logic, as described in the transcript. `match` compares a value against patterns (arms) and executes code for the first match, ensuring all cases are handled. Combined with enums, it enforces coverage of every variant, preventing runtime errors. Examples are updated for the current date (September 02, 2025), with OS ages recalculated: Windows (released 1985) is 40 years old, macOS (released 2001) is 24 years old, and Linux (released 1991) is 34 years old. We'll start with basic `match` on numbers, then progress to enums, functions, and ownership. All code is runnable in Rust 1.78+.

#### 1. Basics of `match` with Primitive Types
`match` evaluates arms sequentially until a match, executing the corresponding code. Use `_` as a catch-all at the end.

**Key Concepts:**
- Syntax: `match value { pattern => code, ... }`
- Arms: Patterns (e.g., literals) followed by `=>` and code/value.
- Exhaustiveness: Must cover all possibilities; compiler enforces this.
- Catch-all: `_` matches anything; place last.
- Use: For conditional logic without fall-through like switch.

**Progressive Example 1: Simple `match` on Integers**
Match a number against specific values.

```rust
// src/main.rs

fn main() {
    let number = 20;
    
    match number {
        5 => println!("It's five!"),
        8 => println!("It's eight!"),
        _ => println!("It's something else: {}", number),
    }
}
```

**Output:**
```
It's something else: 20
```

**Explanation:**
- Checks 5 (no), 8 (no), then `_` matches and executes.
- No exhaustiveness issue since `_` covers all.
- Pitfall: Placing `_` first makes other arms unreachable (compiler error).

#### 2. `match` with Enums: Basic Exhaustive Matching
Enums pair perfectly with `match`—compiler ensures all variants are handled.

**Key Concepts:**
- Patterns: Use `Enum::Variant` for matching.
- No Data: Simple variants match directly.
- Return Values: `match` produces a value (e.g., for assignments or returns).
- Benefits: Safe; catches missing cases at compile time.

**Progressive Example 2: Matching Enum Variants**
Define `OperatingSystem` and match in `main`.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn main() {
    let my_os = OperatingSystem::MacOS;
    
    match my_os {
        OperatingSystem::Windows => println!("Windows"),
        OperatingSystem::MacOS => println!("macOS"),
        OperatingSystem::Linux => println!("Linux"),
    }
}
```

**Output:**
```
macOS
```

**Explanation:**
- Matches the variant and prints.
- Compiler errors if a variant is missing (e.g., omit `Linux`).
- Progressive: Introduces enum matching.
- Pitfall: Forgetting a variant causes "non-exhaustive patterns" error.

#### 3. Using `match` in Functions with Enums
Pass enums to functions; use `match` for logic and returns.

**Key Concepts:**
- Ownership: Passing by value moves ownership (fine if not reused).
- Implicit Return: Last expression in `match` can be function return.
- Dynamic Values: `match` handles runtime-variant enums.

**Progressive Example 3: Function Returning Value from `match`**
Compute years since release.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => 40,  // 2025 - 1985
        OperatingSystem::MacOS => 24,    // 2025 - 2001
        OperatingSystem::Linux => 34,    // 2025 - 1991
    }
}

fn main() {
    let my_computer = OperatingSystem::MacOS;
    let age = years_since_release(my_computer);
    println!("My computer's operating system is {} years old.", age);
}
```

**Output:**
```
My computer's operating system is 24 years old.
```

**Explanation:**
- Function takes ownership of `os`; `match` returns u32 implicitly.
- Updated ages for 2025.
- Progressive: Adds function and return.
- Pitfall: Semicolon after `match` makes it not return (add `return` or remove).

#### 4. Handling Ownership and Reassignment
Borrow or clone if reuse needed after matching.

**Key Concepts:**
- Borrow: Use `&Enum` to avoid moving.
- Reassignment: Change variant and rematch.
- Blocks in Arms: Use `{ }` for multi-line code.

**Progressive Example 4: Borrowing and Multi-Line Arms**
Borrow enum; use code blocks.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows,
    MacOS,
    Linux,
}

fn years_since_release(os: &OperatingSystem) -> u32 {
    match os {
        OperatingSystem::Windows => {
            println!("Matching Windows...");
            40
        }
        OperatingSystem::MacOS => {
            println!("Matching macOS...");
            24
        }
        OperatingSystem::Linux => {
            println!("Matching Linux...");
            34
        }
    }
}

fn main() {
    let mut my_computer = OperatingSystem::MacOS;
    let age = years_since_release(&my_computer);
    println!("Age: {}", age);
    
    // Reassign and reuse
    my_computer = OperatingSystem::Linux;
    let new_age = years_since_release(&my_computer);
    println!("New age: {}", new_age);
}
```

**Output:**
```
Matching macOS...
Age: 24
Matching Linux...
New age: 34
```

**Explanation:**
- Borrow `&` keeps ownership in `main`.
- Arms use blocks for extra logic.
- Progressive: Adds borrowing, mutability.
- Pitfall: Non-borrow move prevents reuse (compiler error).

#### 5. Advanced: `match` with Associated Data
Extend to enums with data; destructure in arms.

**Key Concepts:**
- Destructuring: Bind variables to variant data (e.g., `Variant(x) => ...`).
- Exhaustiveness: Still enforced for data variants.

**Progressive Example 5: Matching Enums with Data**
Add release year as data.

```rust
// src/main.rs

#[derive(Debug)]
enum OperatingSystem {
    Windows(u32),  // Release year
    MacOS(u32),
    Linux(u32),
}

fn years_since_release(os: &OperatingSystem) -> u32 {
    let current_year: u32 = 2025;
    match os {
        OperatingSystem::Windows(year) => current_year - year,
        OperatingSystem::MacOS(year) => current_year - year,
        OperatingSystem::Linux(year) => current_year - year,
    }
}

fn main() {
    let my_computer = OperatingSystem::MacOS(2001);
    let age = years_since_release(&my_computer);
    println!("My computer's OS is {} years old.", age);
}
```

**Output:**
```
My computer's OS is 24 years old.
```

**Explanation:**
- Variants hold release year; destructured as `Variant(year)`.
- Compute age dynamically.
- Progressive: Integrates data; uses current year.
- Pitfall: Missing destructuring (e.g., no `(year)`) causes mismatch errors.
