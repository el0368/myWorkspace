### 1. What are Enums?

An **enum** (short for enumeration) is a custom data type that allows you to define a set of named, fixed-value variants. Think of it as a way to create a type that can be one of a specific, finite set of possibilities. This is useful for representing concepts that have a limited number of distinct options.

For example, a traffic light can only be red, yellow, or green. An enum is a perfect way to model this, as it prevents your code from accidentally using an invalid state like "blue" or "purple".

---

### 2. Defining and Using an Enum

To define an enum, you use the **`enum`** keyword, followed by the name of your enum (in `PascalCase`), and a pair of curly braces. Inside the braces, you list the variants, also in `PascalCase`.

To create an instance of an enum, you use the enum's name followed by the scope resolution operator (`::`) and the variant you want to use.

#### Example: Traffic Light Enum

Rust

```
// The enum definition
#[derive(Debug)] // This attribute lets us print the enum for debugging
enum TrafficLight {
    Red,
    Yellow,
    Green,
}

fn main() {
    // Creating an instance of the enum
    let current_light = TrafficLight::Red;

    // We can then use this instance in our code, for example, with a match statement
    match current_light {
        TrafficLight::Red => println!("Stop!"),
        TrafficLight::Yellow => println!("Slow down."),
        TrafficLight::Green => println!("Go!"),
    }
}
```

- **Variants as Constructors:** Each variant acts like a constructor function. `TrafficLight::Red` is a way of creating a value of the `TrafficLight` type.
    
- **Type Safety:** The compiler knows that a `TrafficLight` can only be `Red`, `Yellow`, or `Green`. It will prevent you from assigning an invalid value to a variable of this type.

### 3. Enum Variants with Associated Data

The real power of enums comes from their ability to hold associated data. Each variant can optionally carry a value or multiple values with it. This allows you to represent not just a state, but also data related to that state.

There are two main types of associated data:

#### a. **Tuple Variants**

This is the most common form. You attach a tuple of types to a variant, similar to a tuple struct. The data is accessed by its position (index).

Rust

```
#[derive(Debug)]
enum Shape {
    Circle(f64), // The variant holds one `f64` value (radius)
    Rectangle(f64, f64), // The variant holds two `f64` values (width, height)
    Triangle { height: f64, width: f64 } // Not a tuple variant
}

fn main() {
    let my_circle = Shape::Circle(10.0);
    let my_rectangle = Shape::Rectangle(5.0, 8.0);
    
    // We use a match statement to access the data.
    match my_circle {
        Shape::Circle(radius) => println!("Circle radius: {}", radius),
        _ => (), // This match arm handles other variants.
    }
}
```

#### b. **Struct Variants**

This form uses a named-field struct syntax to provide more context to the associated data. This is useful when the data fields are not immediately clear from their types alone.

Rust

```
#[derive(Debug)]
enum UserAccount {
    Guest, // A variant without data
    RegisteredUser { username: String, email: String }, // A variant with named fields
}

fn main() {
    let guest_user = UserAccount::Guest;
    let registered_user = UserAccount::RegisteredUser { 
        username: String::from("alice"), 
        email: String::from("alice@example.com"),
    };
    
    match registered_user {
        UserAccount::RegisteredUser { username, email } => {
            println!("Registered user: {} ({})", username, email);
        },
        _ => (),
    }
}
```
