### Rust Enums Study Guide: Implementing Methods on Enums

This study guide covers implementing methods on enums in Rust using the `impl` keyword, as described in the transcript. Methods allow shared behavior across enum variants, with access to `self` for the instance. We'll explore transitioning from standalone functions to methods, handling borrowing (`&self`), and how associated data is accessed (as references in borrowed methods). Examples use the `LaundryCycle` enum and progress from basic functions to methods, including ownership considerations and variant-specific logic. All code is complete, runnable in Rust 1.78+, and builds on prior enum concepts.

#### 1. Review: Standalone Functions with Enums
Before methods, functions can operate on enums, but they lack direct association with the type.

**Key Concepts:**
- Functions take enums as parameters; use `match` for variant-specific logic.
- Ownership: Passing by value moves the enum; borrowing (`&`) preserves it.
- Limitation: Not tied to the enum; must pass instance explicitly.

**Progressive Example 1: Standalone Function for Washing**
Define a function to handle `LaundryCycle`.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

fn wash_laundry(cycle: &LaundryCycle) {
    match cycle {
        LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
        LaundryCycle::Hot { temperature } => {
            println!("Running the laundry with a temperature of {}", temperature);
        }
        LaundryCycle::Delicate(fabric_type) => {
            println!("Running the laundry with a delicate cycle for {}", fabric_type);
        }
    }
}

fn main() {
    let cold = LaundryCycle::Cold;
    let hot = LaundryCycle::Hot { temperature: 100 };
    let delicate = LaundryCycle::Delicate(String::from("silk"));
    
    wash_laundry(&cold);
    wash_laundry(&hot);
    wash_laundry(&delicate);
}
```

**Output:**
```
Running the laundry with cold temperature
Running the laundry with a temperature of 100
Running the laundry with a delicate cycle for silk
```

**Explanation:**
- Function borrows `&LaundryCycle`; `match` destructures data.
- Borrowing allows reuse of instances.
- Pitfall: Passing without `&` moves ownership, preventing reuse.

#### 2. Introducing Methods on Enums
Use `impl EnumName { }` to add methods; `self` represents the instance.

**Key Concepts:**
- **Methods**: Defined in `impl`; invoked with `instance.method()`.
- **self Parameter**: First param; variants: `self` (ownership), `&self` (immutable borrow), `&mut self` (mutable borrow).
- **Associated Functions**: No `self`; like static methods (e.g., constructors).
- **Borrowing Data**: In `&self` methods, associated data is borrowed (e.g., `&u32`, `&String`).
- **Benefits**: Encapsulates behavior; uniform across variants.

**Progressive Example 2: Basic Method with &self**
Convert `wash_laundry` to a method.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

impl LaundryCycle {
    fn wash_laundry(&self) {
        match self {
            LaundryCycle::Cold => println!("Running the laundry with cold temperature"),
            LaundryCycle::Hot { temperature } => {
                println!("Running the laundry with a temperature of {}", temperature);
            }
            LaundryCycle::Delicate(fabric_type) => {
                println!("Running the laundry with a delicate cycle for {}", fabric_type);
            }
        }
    }
}

fn main() {
    let cold = LaundryCycle::Cold;
    let hot = LaundryCycle::Hot { temperature: 100 };
    let delicate = LaundryCycle::Delicate(String::from("silk"));
    
    cold.wash_laundry();
    hot.wash_laundry();
    delicate.wash_laundry();
}
```

**Output:**
```
Running the laundry with cold temperature
Running the laundry with a temperature of 100
Running the laundry with a delicate cycle for silk
```

**Explanation:**
- `impl LaundryCycle` adds `wash_laundry` method.
- `&self` borrows instance; `match self` handles variants.
- Associated data borrowed (e.g., `temperature: &u32`, `fabric_type: &String`); Rust dereferences automatically.
- Progressive: Transitions from function to method.
- Pitfall: Using `self` (no `&`) consumes instance; can't reuse after call.

#### 3. Methods with Ownership and Associated Functions
Methods can take ownership; associated functions (no `self`) act like constructors.

**Key Concepts:**
- **Ownership Methods**: Use `self` to consume instance (e.g., for transformations).
- **Associated Functions**: Called on type (e.g., `EnumName::func()`); useful for creation.
- **Deref in Match**: Rust handles references transparently in `match`.

**Progressive Example 3: Ownership Method and Associated Function**
Add a consuming method and constructor.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

impl LaundryCycle {
    // Associated function (constructor)
    fn new_hot(temp: u32) -> Self {
        LaundryCycle::Hot { temperature: temp }
    }
    
    // Consuming method (takes ownership)
    fn run_cycle(self) {
        match self {
            LaundryCycle::Cold => println!("Cold cycle complete"),
            LaundryCycle::Hot { temperature } => {
                println!("Hot cycle at {}°C complete", temperature);
            }
            LaundryCycle::Delicate(fabric_type) => {
                println!("Delicate cycle for {} complete", fabric_type);
            }
        }
        // Instance consumed here
    }
    
    // Borrowed method from before
    fn wash_laundry(&self) {
        match self {
            LaundryCycle::Cold => println!("Running cold"),
            LaundryCycle::Hot { temperature } => println!("Running hot at {}", temperature),
            LaundryCycle::Delicate(fabric_type) => println!("Running delicate for {}", fabric_type),
        }
    }
}

fn main() {
    let hot = LaundryCycle::new_hot(100);  // Associated function
    hot.wash_laundry();                    // Borrowed method
    
    hot.run_cycle();                       // Consuming method
    // hot.wash_laundry();                 // Error: hot moved
}
```

**Output:**
```
Running hot at 100
Hot cycle at 100°C complete
```

**Explanation:**
- `new_hot` creates instances without `self`.
- `run_cycle` uses `self` (consumes); can't use instance after.
- `wash_laundry` borrows; reusable.
- Progressive: Adds ownership and constructors.
- Pitfall: Calling consuming method then borrowing causes "value moved" error.

#### 4. Mutable Methods and Variant-Specific Logic
Use `&mut self` for mutation; logic can vary by variant.

**Key Concepts:**
- **Mutable Borrow**: `&mut self` allows modifying associated data.
- **Variant Logic**: `match` enables different behavior per variant.
- **Dereferencing**: Automatic for borrowed data.

**Progressive Example 4: Mutable Method**
Add a method to adjust temperature (only for `Hot`).

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

impl LaundryCycle {
    fn wash_laundry(&self) {
        match self {
            LaundryCycle::Cold => println!("Running cold"),
            LaundryCycle::Hot { temperature } => println!("Running hot at {}", temperature),
            LaundryCycle::Delicate(fabric_type) => println!("Running delicate for {}", fabric_type),
        }
    }
    
    fn adjust_temperature(&mut self, new_temp: u32) {
        match self {
            LaundryCycle::Hot { temperature } => *temperature = new_temp,  // Mutate borrowed field
            _ => println!("Cannot adjust temperature for this cycle"),
        }
    }
}

fn main() {
    let mut hot = LaundryCycle::Hot { temperature: 100 };
    hot.wash_laundry();
    
    hot.adjust_temperature(120);
    hot.wash_laundry();  // Updated temperature
}
```

**Output:**
```
Running hot at 100
Running hot at 120
```

**Explanation:**
- `adjust_temperature` mutates `Hot`'s temperature; uses `*` to dereference.
- `_` catches non-`Hot` variants.
- Progressive: Adds mutation.
- Pitfall: Forgetting `mut` on variable or `&mut self` causes immutability errors.

#### 5. Advanced: Methods with Return Values and Complex Logic
Methods can return values; integrate with associated data.

**Key Concepts:**
- **Returns**: Implicit or explicit; consistent across `match` arms.
- **Complex Logic**: Compute based on variant data.

**Progressive Example 5: Method Returning Duration**
Add a method computing cycle duration.

```rust
// src/main.rs

#[derive(Debug)]
enum LaundryCycle {
    Cold,
    Hot { temperature: u32 },
    Delicate(String),
}

impl LaundryCycle {
    fn wash_laundry(&self) {
        match self {
            LaundryCycle::Cold => println!("Running cold"),
            LaundryCycle::Hot { temperature } => println!("Running hot at {}", temperature),
            LaundryCycle::Delicate(fabric_type) => println!("Running delicate for {}", fabric_type),
        }
    }
    
    fn get_duration(&self) -> u32 {
        match self {
            LaundryCycle::Cold => 30,
            LaundryCycle::Hot { temperature } => {
                if *temperature > 80 { 45 } else { 35 }  // Logic based on data
            }
            LaundryCycle::Delicate(_) => 20,
        }
    }
}

fn main() {
    let hot = LaundryCycle::Hot { temperature: 100 };
    hot.wash_laundry();
    let duration = hot.get_duration();
    println!("Duration: {} minutes", duration);
}
```

**Output:**
```
Running hot at 100
Duration: 45 minutes
```

**Explanation:**
- `get_duration` returns `u32`; uses logic in `Hot` arm.
- Progressive: Adds returns and computation.
- Pitfall: Inconsistent return types (e.g., `String` in one arm) causes errors.
