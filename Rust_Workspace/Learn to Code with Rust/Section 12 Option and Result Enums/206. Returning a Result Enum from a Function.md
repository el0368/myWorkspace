### Part 1: The Function that Returns a `Result`

This progressive example starts by defining a function that returns a `Result` enum, which is Rust's idiomatic way of handling operations that can succeed or fail. The function `divide` encapsulates the logic for both a successful division and a failure (division by zero).

- **Return Type:** The function signature `-> Result<f64, String>` enforces that the function must return a `Result` enum. The `Ok` variant must hold an `f64` (the calculation), and the `Err` variant must hold a `String` (the error message).
    
- **The Logic:** An `if-else` statement is used to check the `denominator`. If it's zero, an `Err` is returned. Otherwise, the division is performed, and the `Ok` variant is returned.
    
- **The Code:** This part shows the full definition of the `divide` function.
    

Rust

```Rust
// A function that divides one f64 by another.
// It returns a `Result<f64, String>` to handle success or failure.
fn divide(numerator: f64, denominator: f64) -> Result<f64, String> {
    // If the denominator is zero, we return the `Err` variant.
    if denominator == 0.0 {
        // The `Err` variant holds a `String` with the error message.
        Err("Cannot divide by zero".to_string())
    } else {
        // Otherwise, we perform the division and return the `Ok` variant.
        // The `Ok` variant holds the `f64` result of the calculation.
        Ok(numerator / denominator)
    }
}
```

### Part 2: Matching on an `Ok` Result (The Success Path)

This part shows how to call the `divide` function with a successful division and use a `match` statement to safely handle the returned `Ok` variant.

- **`match` on `Result`:** The `match` keyword is the standard and safest way to consume a `Result` enum. It forces you to write logic for both the `Ok` and `Err` variants.
    
- **`Ok(value)` arm:** This arm pattern is used to extract the successful value. The `value` is a variable that is bound to the associated data (`f64` in this case) and can be used in the arm's code block.
    
- **The Code:** This example shows a successful call to `divide` and the `match` statement's `Ok` arm correctly executing.
    

Rust

```Rust
fn divide(numerator: f64, denominator: f64) -> Result<f64, String> {
    if denominator == 0.0 {
        Err("Cannot divide by zero".to_string())
    } else {
        Ok(numerator / denominator)
    }
}

fn main() {
    println!("--- Handling a successful division ---");
    let result = divide(10.0, 2.0);
    
    match result {
        Ok(calculation) => {
            println!("Success! The result is {}.", calculation);
        },
        // We still need to provide an `Err` arm to satisfy the compiler.
        Err(message) => {
            println!("Error! The message is: {}", message);
        },
    }
    // Output: Success! The result is 5.
```

### Part 3: Matching on an `Err` Result (The Failure Path)

This part shows how to call the `divide` function with an invalid input (division by zero) and demonstrates how the `match` statement's `Err` arm gracefully handles the failure without causing a program crash.

- **`Err(error)` arm:** This arm pattern is used to capture the error value from the `Err` variant. The `error` is a variable that is bound to the associated error data (`String` in this case).
    
- **Robustness:** The `Result` enum forces you to explicitly handle the failure case, making your code robust against potential errors.
    
- **The Code:** This example shows a call to `divide` with a `0.0` denominator, and the `match` statement's `Err` arm correctly executing.

### Part 4: The Final Progressive Example

This final part brings all the concepts together into a complete, working program. It shows both a successful and a failed call to `divide` and uses the `match` statement to gracefully handle both outcomes.

- **Unified Return Type:** The `Result` enum is a single, consistent return type that elegantly models two different outcomes. This allows for clean and predictable function signatures.
    
- **The Code:** This is the complete program that serves as a comprehensive example of using the `Result` enum.
    

Rust

```Rust
fn divide(numerator: f64, denominator: f64) -> Result<f64, String> {
    if denominator == 0.0 {
        Err("Cannot divide by zero".to_string())
    } else {
        Ok(numerator / denominator)
    }
}

fn main() {
    // Scenario 1: A successful division
    println!("--- Scenario 1: Valid Division ---");
    let result1 = divide(10.0, 2.0);
    match result1 {
        Ok(calculation) => println!("Result: {}", calculation),
        Err(message) => println!("Error: {}", message),
    }
    
    // Scenario 2: An unsuccessful division
    println!("\n--- Scenario 2: Division by Zero ---");
    let result2 = divide(10.0, 0.0);
    match result2 {
        Ok(calculation) => println!("Result: {}", calculation),
        Err(message) => println!("Error: {}", message),
    }
}
```
