### Part 1: The `parse()` Method - A Real-World `Result`

This progressive example starts by introducing a common scenario where the `Result` enum is used: parsing a string into a number. The `.parse()` method is a function that demonstrates how `Result` is a single, consistent return type that can represent two completely different outcomes.

- **The Problem:** Converting a string to a number can fail if the string contains non-numeric characters.
    
- **The Solution:** The `.parse()` method returns a `Result` enum, which forces the developer to handle both the success (`Ok`) and failure (`Err`) cases.
    
- **The Code:** This part shows a call to `.parse()` with a valid numeric string. The turbofish operator (`::<i32>`) is used to explicitly specify that we want to parse an `i32`, which is the type for the `Ok` variant.
    

Rust

```Rust
fn main() {
    let text = "50"; // A numeric string literal
    
    // We call the `.parse()` method and use the turbofish operator `::<i32>`
    // to specify that the `Ok` variant should contain an `i32`.
    let text_as_number = text.parse::<i32>();
    
    // The type of `text_as_number` is `Result<i32, ParseIntError>`.
    
    // Printing the `Result` with Debug formatting shows the success variant.
    println!("Successful parse result: {:?}", text_as_number);
    // Output: Successful parse result: Ok(50)

}
```

### Part 2: The `Ok` vs. `Err` Variants

This part shows the two different outcomes of the `.parse()` method. While the method always returns a `Result` enum, the specific variant it returns depends on the success of the operation.

- **Success (`Ok`):** When the string is successfully parsed, the `.parse()` method returns the `Ok` variant, which holds the successfully parsed value.
    
- **Failure (`Err`):** When the string cannot be parsed, the method returns the `Err` variant, which holds a corresponding error value (in this case, a `ParseIntError`).
    
- **The Code:** This example shows two identical calls to `.parse()` with different string inputs. The first input is a successful parse, and the second is a failure. The output clearly shows the two distinct variants.
    

Rust

```Rust
fn main() {
    // --- Successful Scenario ---
    let text1 = "50";
    let successful_parse = text1.parse::<i32>();
    println!("Parse of '{}': {:?}", text1, successful_parse);
    // Output: Parse of '50': Ok(50)
    
    // --- Failure Scenario ---
    let text2 = "Alabama"; // A non-numeric string
    let failed_parse = text2.parse::<i32>();
    println!("Parse of '{}': {:?}", text2, failed_parse);
    // Output: Parse of 'Alabama': Err(ParseIntError { kind: InvalidDigit })
    
    // The `Result` type is still `Result<i32, ParseIntError>` in both cases.
    // The `Ok` variant holds an `i32`, and the `Err` variant holds a `ParseIntError`.

}
```

### Part 3: Handling `Result` with a `match` Statement

This final part brings all the concepts together. It shows how the `Result` enum is a complete solution because you can use a `match` statement to safely and exhaustively handle both the `Ok` and `Err` variants.

- **Exhaustive `match`:** The `match` statement forces you to write logic for both the `Ok` and `Err` arms, ensuring you never accidentally ignore a potential error.
    
- **The Code:** This example shows a `main` function that uses a `match` statement to safely handle the output of the `.parse()` method.
    

Rust

```Rust
fn main() {
    let text = "50";
    let text_as_number = text.parse::<i32>();
    
    println!("--- Matching a successful Result ---");
    match text_as_number {
        // The `Ok` arm extracts the `i32` value.
        Ok(number) => println!("Success! The number is {}.", number),
        // The `Err` arm extracts the error value.
        Err(error) => println!("Error! Unable to parse: {:?}", error),
    }
    // Output: Success! The number is 50.
    
    // --- Matching a failed Result ---
    let text2 = "Alabama";
    let text_as_number2 = text2.parse::<i32>();
    
    match text_as_number2 {
        Ok(number) => println!("Success! The number is {}.", number),
        Err(error) => println!("Error! Unable to parse: {:?}", error),
    }
    // Output: Error! Unable to parse: ParseIntError { kind: InvalidDigit }
}
```
