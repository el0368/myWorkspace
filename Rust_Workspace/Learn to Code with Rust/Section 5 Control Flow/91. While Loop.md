## Rust Control Flow: The `while` Loop (Conditional Repetition)

This study guide introduces the `while` loop in Rust, an alternative iteration construct that automatically terminates based on a specified condition.

### I. Understanding the `while` Loop

What is the while loop?

A while loop is a control flow construct that allows a block of code to be repeatedly executed as long as a specified condition remains true. It automatically terminates when that condition becomes false.

- **Key Difference from `loop`:** Unlike the `loop` keyword (which creates an infinite loop by default and requires `break`), a `while` loop has a built-in mechanism for termination: its condition.
    
- **Syntax:**
    
    Rust
    
    ```Rust
    while condition {
        // Code to be repeated as long as 'condition' is true
    }
    ```
    
    - `while`: The keyword that initiates the loop.
        
    - `condition`: A **Boolean expression** that is evaluated _before each iteration_. The loop continues only if this condition is `true`.
        
    - `{}`: The code block that contains the instructions to be executed repeatedly.
        
- **Execution Flow:**
    
    1. The `condition` is evaluated.
        
    2. If `condition` is `true`, the code block inside the `while` loop is executed.
        
    3. After the block finishes, control returns to step 1, and the `condition` is re-evaluated.
        
    4. If `condition` is `false` (at step 1), the loop terminates, and execution continues with the code immediately following the `while` loop's block.
        

**Example: Countdown Timer with `while` Loop**

Let's refactor the countdown timer from previous lessons to use a `while` loop.

Rust

```Rust
fn main() {
    let mut seconds = 21; // The counter variable, declared as mutable

    println!("Initiating Launch Sequence Countdown (with while loop):");

    // The loop continues AS LONG AS 'seconds' is greater than 0
    while seconds > 0 {
        // 1. Conditional logic within the loop (same as previous example)
        if seconds % 2 == 0 { // Check if `seconds` is an even number
            println!("{} seconds (even number): Skipping 3 seconds.", seconds);
            seconds -= 3; // Decrement by 3 for even numbers
            // The `continue` keyword works the same way: it skips to the next loop iteration,
            // which for `while` means re-evaluating the `while` condition immediately.
            continue;
        }

        // 2. Normal iteration logic (only runs if 'continue' was NOT hit)
        println!("{} seconds to blastoff...", seconds);
        seconds -= 1; // Decrement by 1 for odd numbers
    } // The loop automatically terminates when `seconds` is no longer > 0

    // This code runs after the `while` loop finishes
    println!("Blastoff!");
    println!("Launch sequence complete. Have a great flight!");
}
```

### II. Ensuring Loop Termination

What is crucial for a while loop to terminate correctly?

It is absolutely vital that something inside the while loop's block modifies the variables involved in the condition in such a way that the condition will eventually become false. If the condition never becomes false, you will create an infinite while loop.

- **Example of potential infinite `while` loop:**
    
    Rust
    
    ```Rust
    // This would run forever because `x` never changes
    /*
    let x = 5;
    while x > 0 {
        println!("Still looping!");
    }
    */
    ```
    
    In our countdown example, `seconds -= 1` or `seconds -= 3` ensures that `seconds` will eventually become `0` or less, making `seconds > 0` false.

### III. Comparison: `loop` vs. `while`

|Feature|`loop`|`while condition`|
|---|---|---|
|**Termination**|**Manual**; requires `break` keyword.|**Automatic**; terminates when `condition` is `false`.|
|**Condition**|No inherent condition for repetition.|Explicit `condition` checked before each iteration.|
|**Use Case**|Repeating indefinitely until an internal `break` point. For "do this forever, until..." scenarios.|Repeating as long as a state remains true. For "as long as X, do Y" scenarios.|
|**Readability**|Can be less intuitive if the termination logic is complex and spread out.|Often clearer for simple, condition-driven repetition.|
|**Flexibility**|Offers more control over where `break` can occur within the loop body.|Less flexible than `loop`+`break` if termination point isn't at start/end of iteration.|

**Example where `loop` might be better:**

Rust

```Rust
// loop is often better when you need to run at least once OR
// when the termination condition might be in the middle of the loop body
let mut input = String::new();
loop {
    println!("Enter 'exit' to quit:");
    input.clear(); // Clear previous input
    std::io::stdin().read_line(&mut input).expect("Failed to read line");
    let trimmed = input.trim();

    if trimmed == "exit" {
        println!("Exiting loop.");
        break; // Break here, in the middle
    }

    println!("You entered: {}", trimmed);
}
```

**Example where `while` is ideal:**

Rust

```Rust
// while is great when the condition is simple and checked upfront
let mut counter = 0;
while counter < 5 {
    println!("Counter: {}", counter);
    counter += 1;
}
println!("Loop finished.");
```

### IV. Key Takeaways

- **`while` Loop:** Repeats a block of code _as long as_ its condition remains `true`.
    
- **Automatic Termination:** No `break` keyword is needed for basic termination; the loop stops when its condition becomes `false`.
    
- **Condition Modification:** It's essential that code inside the `while` loop modifies the variables in its condition so that it eventually evaluates to `false`, preventing infinite loops.
    
- **`continue` Compatibility:** The `continue` keyword works identically with `while` loops as it does with `loop` loops, skipping to the next iteration (re-evaluating the `while` condition).
    
- **Alternative to `loop`:** Offers a more elegant solution for iteration when the termination condition is clearly defined at the start of each cycle.
