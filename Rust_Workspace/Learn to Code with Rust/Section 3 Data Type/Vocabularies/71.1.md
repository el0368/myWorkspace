### Part 1 Vocabularies: Integers

1. **Integer**:
    
    - **Definition**: A whole number (a number without a fractional or decimal component).
        
    - **Characteristics**: Can be positive, negative, or zero.
        
    - **Example**: `5`, `-10`, `0`, `42`.
        
2. **Signed Integer (`i` family)**:
    
    - **Definition**: A subcategory of integers in Rust that can represent both **negative and positive** values, including zero.
        
    - **Naming Convention**: Denoted by an `i` prefix followed by the bit size (e.g., `i8`, `i16`, `i32`, `i64`, `i128`).
        
    - **Memory Allocation**: Uses one of its bits to store information about the number's sign (whether it's positive or negative).
        
    - **Example**: `let temperature: i32 = -7;`
        
3. **Unsigned Integer (`u` family)**:
    
    - **Definition**: A subcategory of integers in Rust that can represent **only zero and positive** values. They _cannot_ hold negative numbers.
        
    - **Naming Convention**: Denoted by a `u` prefix followed by the bit size (e.g., `u8`, `u16`, `u32`, `u64`, `u128`).
        
    - **Memory Allocation**: All of its bits are used to represent the magnitude (size) of the number, allowing it to store positive values that are roughly twice as large as a signed integer of the same bit size.
        
    - **Example**: `let quantity: u16 = 250;`
        
4. **Bit**:
    
    - **Definition**: The smallest unit of information in computing, a binary digit (either a `0` or a `1`).
        
    - **Relevance to Integers**: In Rust's integer types (e.g., `i32`, `u8`), the number after the `i` or `u` (e.g., `32`, `8`) specifies the exact number of bits that the integer value will occupy in the computer's memory. More bits allow the integer to represent a larger range of numbers, but also consume more memory.
        
5. **`usize`**:
    
    - **Definition**: A special **unsigned integer type** in Rust that acts as an **alias** (a nickname) for an underlying integer type. Its exact size (`u32` or `u64`) depends on the **architecture** of the computer (whether it's a 32-bit or 64-bit system) where the program is running.
        
    - **Versatility/Advantage**: The code written using `usize` remains the same, but it dynamically adapts to the most efficient integer size for memory addressing and indexing on the specific target system.
        
    - **Common Use**: Primarily used for sizes of collections (like arrays and vectors) and for indexing into them, as these often relate to memory addresses.
        
    - **Example**: `let array_index: usize = 0;`
        
6. **`isize`**:
    
    - **Definition**: A special **signed integer type** in Rust that acts as an **alias** (a nickname) for an underlying integer type. Similar to `usize`, its exact size (`i32` or `i64`) depends on the computer's architecture (32-bit or 64-bit system).
        
    - **Versatility/Advantage**: Offers the same versatility as `usize` but for signed integer values, adapting to the system's native integer size.
        
    - **Example**: `let memory_offset: isize = -128;`
        
7. **Alias**:
    
    - **Definition**: In programming, an alternative name or a nickname for an existing data type.
        
    - **Relevance**: `usize` and `isize` are aliases because they "point to" or "correspond to" either a 32-bit or 64-bit integer type, depending on the system's architecture, rather than being fundamentally distinct integer types themselves.
