Let's translate the theoretical knowledge of Rust's basic numeric data types into practical code examples within our text editor.

### Integer Type Declarations

Rust provides various integer types differing in their size (number of bits) and whether they can store negative values (signed vs. unsigned).

#### `i8` (8-bit Signed Integer)

- **Declaration:** We declare a variable `eight_bit` and assign it an initial value of `-112`.
    
- **Default Inference:** By default, Rust's compiler (and `rust-analyzer` in your IDE) will infer integer literals to be of type `i32`. You would see a hint like `(i32)` next to `eight_bit`.
    
- **Explicit Annotation:** To explicitly tell Rust to use an `i8` type, we must manually annotate the type after the variable name using a colon and the type name (`: i8`).
    
    Rust
    
    ```Rust
    fn main() {
        // Rust's default inference for an integer literal is i32
        // let eight_bit = -112; // Rust-analyzer would show this as `i32`
    
        // Explicitly annotate as i8
        let eight_bit: i8 = -112; // This is a signed 8-bit integer
        println!("i8 value: {}", eight_bit);
    }
    ```
    
- **Memory and Range:** An `i8` occupies 8 bits (or 1 byte) of memory, which is one-quarter the size of an `i32`. This smaller memory footprint comes with a constrained range of values: `-128` to `127`.
    
- **Invalid Value - Out of Range:** If you attempt to assign a value that falls outside this range, the Rust compiler will prevent the program from compiling.
    
    Rust
    
    ```Rust
    fn main() {
        // let eight_bit: i8 = -210; // ERROR: `literal out of range for i8`
                                  // This literal value of -210 is outside of the range for an i8.
                                  // It does not fit into the type whose range of values is -128 up to 127.
        // let eight_bit: i8 = 128; // ERROR: `literal out of range for i8`
    
        let eight_bit: i8 = 100; // This is valid
        println!("Valid i8 value: {}", eight_bit);
    }
    ```
    

#### `u8` (8-bit Unsigned Integer)

- **Declaration:** Declared with `u8`. It also occupies 8 bits (1 byte), identical to `i8` in memory consumption.
    
- **No Negative Values:** The key difference is that `u8` can only hold `0` or positive values, specifically ranging from `0` to `255`.
    
    Rust
    
    ```Rust
    fn main() {
        let eight_bit_unsigned: u8 = 200; // This is an unsigned 8-bit integer
        println!("u8 value: {}", eight_bit_unsigned);
    
        // let eight_bit_unsigned: u8 = 400; // ERROR: `literal out of range for u8`
                                          // Value `400` is outside the range `0..=255` for `u8`.
        // let eight_bit_unsigned: u8 = -15; // ERROR: `mismatched types`
                                          // Unsigned integer types do not support negative values.
    }
    ```
    

#### `i16` (16-bit Signed Integer)

- **Declaration:** Annotated as `i16`.
    
- **Memory and Range:** Occupies 16 bits (2 bytes), doubling the memory of an `i8`. This significantly expands its value range: `-32,768` to `32,767`.
    
    Rust
    
    ```Rust
    fn main() {
        let sixteen_bit_signed: i16 = -32_500; // Underscores improve readability for large numbers
        println!("i16 value: {}", sixteen_bit_signed);
    
        // let sixteen_bit_signed: i16 = 64_000; // ERROR: `literal out of range for i16`
                                              // This shows how signed integers halve their positive range
                                              // to accommodate negative values.
    }
    ```
    

#### `u16` (16-bit Unsigned Integer)

- **Declaration:** Annotated as `u16`.
    
- **Memory and Range:** Also 16 bits (2 bytes). It can store values from `0` to `65,535`, offering a larger positive range than `i16` due to the absence of negative values.
    
    Rust
    
    ```Rust
    fn main() {
        let sixteen_bit_unsigned: u16 = 64_000;
        println!("u16 value: {}", sixteen_bit_unsigned);
    }
    ```
    

#### `i32` (32-bit Signed Integer - Rust's Default)

- **Declaration:** Annotated as `i32`. This is Rust's default integer type when no explicit type is provided for an integer literal.
    
- **Memory and Range:** Occupies 32 bits (4 bytes). It can store a very wide range of values: `-2,147,483,648` to `2,147,483,647`.
    
    Rust
    
    ```Rust
    fn main() {
        // Explicitly annotate (optional as it's the default for integers)
        let thirty_two_bit_signed: i32 = -2_147_483_648;
        println!("i32 value (explicit): {}", thirty_two_bit_signed);
    
        // Implicitly inferred as i32 (Rust's default)
        let default_inferred_int = 1_000_000;
        println!("i32 value (inferred): {}", default_inferred_int);
    }
    ```
    

#### `u32` (32-bit Unsigned Integer)

- **Declaration:** Annotated as `u32`.
    
- **Memory and Range:** Also 32 bits (4 bytes). It ranges from `0` to `4,294,967,295`, twice the positive range of `i32`.
    
    Rust
    
    ```Rust
    fn main() {
        let thirty_two_bit_unsigned: u32 = 4_294_967_295;
        println!("u32 value: {}", thirty_two_bit_unsigned);
    }
    ```
    

### Alternate Syntax for Type Annotation

While the `variable_name: Type` syntax is generally preferred for its consistency across all data types, Rust offers an alternative for numeric literals where the type can be declared directly after the value.

- **Syntax:** `let variable_name = value_literalType;` (no space between literal and type).
    
    Rust
    
    ```Rust
    fn main() {
        // Default inference (i32)
        let some_value_default = 20;
        println!("Default inferred (i32): {}", some_value_default);
    
        // Alternate syntax for i8
        let some_value_i8 = 20i8;
        println!("Explicit i8 (alternate syntax): {}", some_value_i8);
    
        // Alternate syntax for i16
        let some_value_i16 = 20i16;
        println!("Explicit i16 (alternate syntax): {}", some_value_i16);
    
        // Alternate syntax for u16
        let some_value_u16 = 20u16;
        println!("Explicit u16 (alternate syntax): {}", some_value_u16);
    }
    ```
    

This alternative syntax is totally valid, but the `variable_name: Type` syntax is often seen as more consistent with Rust's overall declaration style and might be encountered more frequently in codebases.

This practical exploration demonstrates how to explicitly control the integer types in Rust, understanding their memory implications and value ranges, and how the compiler helps enforce these constraints at compile time.

This is a comprehensive summary of Rust's integer types based on the lesson.

In Rust, an **integer** is a number without a fractional component. By default, Rust will infer a standard integer to be an **`i32`**, which is a signed 32-bit integer. You can explicitly declare other integer types to use less memory or to fit specific data requirements.

Integer types are defined by two properties:

- **Size:** The number of bits in memory the integer occupies (e.g., 8, 16, 32, 64, 128). More bits allow for a larger range of values.
    
- **Sign:**
    
    - **Signed (`i` prefix):** Can be negative, zero, or positive.
        
    - **Unsigned (`u` prefix):** Can only be zero or positive.
        

Attempting to assign a value that is outside the valid range for a specific integer type will result in a compile-time error.

Rust

```Rust
fn main() {
    // By default, Rust infers an integer to be an i32.
    let default_integer = -112; // Inferred as i32

    // --- Explicit Type Annotation ---
    // You can explicitly annotate the type with a colon after the variable name.

    // --- 8-bit Integers (1 byte) ---
    // Signed 8-bit integer. Range: -128 to 127
    let eight_bit_signed: i8 = -112;
    // let invalid_i8: i8 = -210; // ERROR: literal out of range for i8

    // Unsigned 8-bit integer. Range: 0 to 255
    let eight_bit_unsigned: u8 = 250;
    // let invalid_u8: u8 = 400; // ERROR: literal out of range for u8
    // let negative_u8: u8 = -15; // ERROR: cannot apply unary negation to an unsigned integer

    // --- 16-bit Integers (2 bytes) ---
    // Signed 16-bit integer. Range: -32,768 to 32,767
    // Underscores can be used as visual separators in long numbers.
    let sixteen_bit_signed: i16 = -32_500;

    // Unsigned 16-bit integer. Range: 0 to 65,535
    let sixteen_bit_unsigned: u16 = 64_000;

    // --- 32-bit Integers (4 bytes) ---
    // Signed 32-bit integer. Range: -2,147,483,648 to 2,147,483,647
    let thirty_two_bit_signed: i32 = -2_147_483_648;

    // Unsigned 32-bit integer. Range: 0 to 4,294,967,295
    let thirty_two_bit_unsigned: u32 = 4_294_967_295;

    // --- Alternative Syntax (Type Suffix) ---
    // You can also specify the type directly after a numeric literal.
    // This tells Rust to treat '20' as an i8 instead of the default i32.
    let some_value = 20i8;
}
```
