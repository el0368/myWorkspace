### Study Guide: The Logical AND (`&&`) Operator

The logical **AND** operator, represented by two ampersands (`&&`), is used to combine two boolean expressions. It's for situations where multiple independent conditions must _all_ be true for an overall outcome to be true.

The entire expression evaluates to `true` **only if** the boolean on the left is `true` **AND** the boolean on the right is `true`. If either operand is `false`, the entire expression becomes `false`.

---

### The Logic of AND (Truth Table)

The behavior of the `&&` operator can be summarized in a "truth table," which shows the result for every possible combination of inputs.

|`A`|`B`|`A && B`|
|---|---|---|
|`true`|`true`|**`true`**|
|`true`|`false`|`false`|
|`false`|`true`|`false`|
|`false`|`false`|`false`|

### Practical Examples

#### Example from the Transcript (Catching a Flight)

To make an event, you must have a ticket AND the plane must be on time.

Rust

```Rust
fn main() {
    let purchased_ticket = true;
    let plane_on_time = false;

    // Both conditions must be true. Since one is false, the result is false.
    let can_make_event = purchased_ticket && plane_on_time;

    println!("Will I make the event? {}", can_make_event); // Prints false
}
```

#### My Example (Accessing a Secure File)

To access a secure file, a user must be logged in AND have admin permissions.

Rust

```Rust
fn main() {
    let is_logged_in = true;
    let has_admin_permission = true;

    let can_access_file = is_logged_in && has_admin_permission;

    println!("File access granted: {}", can_access_file); // Prints true
}
```

### Short-Circuit Evaluation ⚡

For performance, Rust uses **short-circuit evaluation** with the `&&` operator.

It evaluates the expression from left to right. If the first operand (on the left) is `false`, Rust knows the entire expression _must_ be `false`, regardless of the second operand. Therefore, it **stops** and does not evaluate the second operand at all.

This is a micro-optimization that saves processing time, especially if the second condition involves a complex or time-consuming calculation.

Rust

```Rust
fn main() {
    // Because `false` is on the left, the (hypothetical) complex_check() function on the right
    // is never even called.
    let result = false && complex_check();
    println!("{}", result);
}

fn complex_check() -> bool {
    // some very slow operation...
    println!("Complex check was run!"); // This line will never print
    true
}
```
