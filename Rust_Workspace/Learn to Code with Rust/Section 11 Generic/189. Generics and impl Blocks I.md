### Part 1: Implementing Methods for a Specific Concrete Type (`String`)

This progressive example demonstrates how to define methods for a generic struct, but only when the generic type parameter `T` is a specific, concrete type.

- **The Syntax:** To define a method that is only available for a `TreasureChest` struct with a `String` as its `treasure` field, you use the syntax `impl TreasureChest<String> { ... }`.
    
- **Behavior:** Inside this `impl` block, Rust guarantees that `self.treasure` will be a `String`. This allows you to call `String`-specific methods like `.trim()` and `.to_string()`.
    
- **Limitation:** The method `clean_treasure` will only exist on `TreasureChest` instances where `T` is a `String`.
    

Rust

```Rust
// Our generic struct blueprint from the previous lesson.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

// Implement methods specifically for `TreasureChest`s where `T` is `String`.
impl TreasureChest<String> {
    // `self.treasure` is guaranteed to be a `String` here.
    fn clean_treasure(&mut self) {
        // `String` has a `trim()` method, but it returns a string slice.
        // We call `to_string()` to get a new `String` back.
        self.treasure = self.treasure.trim().to_string();
    }
}

fn main() {
    // `T` is `&str` here. This instance will NOT have the `clean_treasure` method.
    let gold_chest = TreasureChest {
        captain: String::from("Firebeard"),
        treasure: "Gold",
    };

    // `T` is `String` here. This instance WILL have the `clean_treasure` method.
    let mut silver_chest = TreasureChest {
        captain: String::from("Bloodsail"),
        treasure: String::from("   Silver   "), // Has extra whitespace
    };

    println!("Silver Chest before cleaning: {:#?}", silver_chest);
    
    // This call is valid because `T` is `String`.
    silver_chest.clean_treasure();
    
    println!("Silver Chest after cleaning: {:#?}", silver_chest);

    // This line would cause a compile-time error! The method does not exist on `gold_chest`.
    // gold_chest.clean_treasure(); // ERROR: No method named `clean_treasure` found for type `TreasureChest<&str>`
}
```

### Part 2: Implementing Methods for Another Specific Type (`[&str; 3]`)

This part shows how to define a second `impl` block for a different, specific type. This demonstrates the granularity of this approach—a new `impl` block is needed for every unique type you want to support.

- **The Syntax:** We create a separate `impl` block with `impl TreasureChest<[&str; 3]> { ... }` to specify that these methods only apply to structs with an array treasure.
    
- **Behavior:** Inside this block, Rust guarantees that `self.treasure` will be an array, allowing array-specific methods like `.len()` to be called.
    

Rust

```Rust
// Our generic struct from Part 1.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

// First `impl` block for `T` as a `String`
impl TreasureChest<String> {
    fn clean_treasure(&mut self) {
        self.treasure = self.treasure.trim().to_string();
    }
}

// Second `impl` block for `T` as a three-element array of string slices.
impl TreasureChest<[&str; 3]> {
    // `self.treasure` is guaranteed to be a `[&str; 3]` here.
    fn amount_of_treasure(&self) -> usize {
        self.treasure.len() // The `.len()` method is specific to array/slice types.
    }
}

fn main() {
    // ... instances from Part 1 ...

    // `T` is `[&str; 3]` here. This instance will have the `amount_of_treasure` method.
    let special_chest = TreasureChest {
        captain: String::from("Bootyplunder"),
        treasure: ["Gold", "Silver", "Platinum"],
    };

    // This call is valid because `T` is a three-element array.
    let amount = special_chest.amount_of_treasure();
    println!("The amount of treasure is: {}", amount);

    // This line would cause a compile-time error! The method does not exist on `silver_chest`.
    // silver_chest.amount_of_treasure(); // ERROR: No method named `amount_of_treasure` found for type `TreasureChest<String>`
}
```

### Part 3: The Final Progressive Example

This final part brings all the concepts together. The single generic `TreasureChest` struct has two distinct `impl` blocks, and our `main` function demonstrates which methods are available on which specific instances.

- **The Limitation:** This approach is not scalable. If you wanted to add a method for `TreasureChest<[&str; 2]>` or `TreasureChest<i32>`, you would need to write a separate `impl` block for each one. This sets up the need for a more general solution, which will be discussed in the next lesson.
    

Rust

```Rust
// The final generic struct definition.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

// `impl` block for `T` as a `String`
impl TreasureChest<String> {
    fn clean_treasure(&mut self) {
        self.treasure = self.treasure.trim().to_string();
    }
}

// `impl` block for `T` as a `[&str; 3]`
impl TreasureChest<[&str; 3]> {
    fn amount_of_treasure(&self) -> usize {
        self.treasure.len()
    }
}

fn main() {
    // 1. Instance where `T` is `String`
    let mut silver_chest = TreasureChest {
        captain: String::from("Bloodsail"),
        treasure: String::from("   Silver   "),
    };

    // 2. Instance where `T` is a three-element array
    let special_chest = TreasureChest {
        captain: String::from("Bootyplunder"),
        treasure: ["Gold", "Silver", "Platinum"],
    };

    // Call the `clean_treasure` method, which is only available on `silver_chest`.
    silver_chest.clean_treasure();
    println!("Cleaned Silver Chest: {:#?}", silver_chest);

    // Call the `amount_of_treasure` method, which is only available on `special_chest`.
    let amount = special_chest.amount_of_treasure();
    println!("Special Chest has {} pieces of treasure.", amount);
}
```
