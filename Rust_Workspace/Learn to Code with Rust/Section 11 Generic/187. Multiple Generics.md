### Part 1: Functions with Mixed Generic and Concrete Types

This progressive example starts by showing how to combine a generic type parameter with a hard-coded, concrete type in a single function signature.

- **The Goal:** To create a function that is flexible for one parameter but has a strict requirement for another.
    
- **The Code:** This part defines a `make_tuple` function that accepts a generic type `T` for its first parameter, but requires a specific `i32` for its second.
    

Rust

```Rust
// This function combines a generic type `T` with a concrete type `i32`.
fn make_tuple<T>(first: T, second: i32) -> (T, i32) {
    (first, second)
}

fn main() {
    // 1. We pass a `&str` for the first parameter, so `T` becomes `&str`.
    //    The second parameter must be an `i32`.
    let my_tuple = make_tuple("hello", 5);
    
    // The tuple's type is inferred as `(&str, i32)`.
    println!("My tuple is: {:?}", my_tuple); // Output: My tuple is: ("hello", 5)

    // 2. We can pass a `bool` for the first parameter. `T` becomes `bool`.
    let another_tuple = make_tuple(true, 10);
    // The tuple's type is inferred as `(bool, i32)`.
    println!("Another tuple is: {:?}", another_tuple); // Output: Another tuple is: (true, 10)

    // 3. This would cause a compile-time error due to a type mismatch on the second parameter.
    // let invalid_tuple = make_tuple(1, "world"); // ERROR: expected `i32`, found `&str`
}
```

### Part 2: Functions with a Single Generic for Multiple Parameters

This part refactors the `make_tuple` function to use a **single generic type `T` for both parameters**. This imposes a stricter constraint: both parameters must be of the exact same type.

- **The Constraint:** This syntax mandates that the type used for `first` must be the same type used for `second`.
    
- **The Code:** This example shows the refactored function and demonstrates how it works with two values of the same type, and fails with two values of different types.
    

Rust

```Rust
// This function uses a single generic `T` for both parameters.
// This requires that `first` and `second` have the same type.
fn make_tuple<T>(first: T, second: T) -> (T, T) {
    (first, second)
}

fn main() {
    // 1. This call is valid because both arguments are `&str`. `T` becomes `&str`.
    let my_tuple = make_tuple("hello", "world");
    println!("My tuple is: {:?}", my_tuple); // Output: My tuple is: ("hello", "world")

    // 2. This call is valid because both arguments are `i32`. `T` becomes `i32`.
    let another_tuple = make_tuple(5, 10);
    println!("Another tuple is: {:?}", another_tuple); // Output: Another tuple is: (5, 10)

    // 3. This call would cause a compile-time error because the types do not match.
    // Rust sees an `i32` for `first` and deduces `T` is `i32`.
    // It then expects `second` to also be an `i32`, but finds a `&str`.
    // let invalid_tuple = make_tuple(5, "world"); // ERROR: expected `i32`, found `&str`
}
```

### Part 3: Functions with Multiple Generics for Multiple Parameters

This final part refactors the function again, this time to use **two distinct generic type parameters**, `T` and `U`. This is the most flexible approach and removes the constraint from Part 2.

- **The Possibility:** This syntax allows `first` and `second` to be either of the same type or of different types. It opens up the possibility for two placeholders, but doesn't require them to be different.
    
- **The Code:** This example shows the refactored function and demonstrates how it works with both different types and the same types.
    

Rust

```Rust
// This function uses two generics, `T` and `U`.
// This allows `first` and `second` to have different types.
fn make_tuple<T, U>(first: T, second: U) -> (T, U) {
    (first, second)
}

fn main() {
    // 1. This call is valid because the arguments are of different types.
    // `T` is `i32`, and `U` is `&str`.
    let my_tuple = make_tuple(5, "world");
    println!("My tuple is: {:?}", my_tuple); // Output: My tuple is: (5, "world")

    // 2. This call is also valid because the arguments can still be the same type.
    // `T` is `i32`, and `U` is also `i32`.
    let another_tuple = make_tuple(10, 20);
    println!("Another tuple is: {:?}", another_tuple); // Output: Another tuple is: (10, 20)

    // 3. This call is also valid, with a `bool` for `T` and an `f64` for `U`.
    let third_tuple = make_tuple(true, 3.14);
    println!("Third tuple is: {:?}", third_tuple); // Output: Third tuple is: (true, 3.14)
}
```
