### Part 1: The Problem & The Generic Struct Blueprint

This progressive example introduces the need for a generic struct. By using a generic type parameter, we can define a single struct blueprint that is flexible enough to hold various types of data for a specific field, without having to declare a separate struct for each type.

- **The Problem:** We need a `TreasureChest` struct. The `captain` field will always be a `String`, but the `treasure` field could be a `String`, a number, or a collection.
    
- **The Solution:** We use a generic type parameter `T` as a placeholder for the `treasure` field's type. This makes the `struct` definition reusable and versatile.
    
- **The Code:** This part shows the initial definition of our generic `TreasureChest` struct.
    

Rust

```Rust
// The `<T>` declares a generic type parameter named `T`.
// `T` is a placeholder for a future concrete type.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    // The `treasure` field's type is the generic placeholder `T`.
    treasure: T,
}

fn main() {
    // This part will be completed in the next examples.
}
```

### Part 2: Instantiating with Different Simple Types

This part shows how the Rust compiler deduces the concrete type for the generic `T` based on the value provided during instantiation. We create two instances of the `TreasureChest` struct, with two different types for `T`.

- **Type Deduction:** The compiler looks at the value assigned to the `treasure` field. Based on the value's type, it fills in the placeholder `T` for that specific instance.
    
- **The Code:** This example shows two instances of `TreasureChest`, where `T` is inferred as `&str` for the first and `String` for the second.
    

Rust

```Rust
// The generic struct from Part 1.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

fn main() {
    // 1. We instantiate with a string literal ("Gold").
    //    The compiler sees an `&str` and infers that `T` is `&str` for this instance.
    let gold_chest = TreasureChest {
        captain: String::from("Firebeard"),
        treasure: "Gold",
    };

    // 2. We instantiate with an owned `String`.
    //    The compiler sees a `String` and infers that `T` is `String` for this instance.
    let silver_chest = TreasureChest {
        captain: String::from("Bloodsail"),
        treasure: String::from("Silver"),
    };
    
    // We can print these instances with `Debug` to see the types.
    println!("Gold Chest: {:#?}", gold_chest);
    println!("\nSilver Chest: {:#?}", silver_chest);
    
    // The rest of this code is completed in the next parts.
}
```

### Part 3: Instantiating with a Complex Type

This part demonstrates the true versatility of a generic struct. The placeholder `T` is not limited to simple types; it can also be filled in by a complex type, such as an array.

- **Versatility:** The generic `T` can be any type, including collections like arrays, tuples, or even other structs. This allows a single struct definition to model a wide range of possibilities.
    
- **The Code:** This example shows a third instance of the `TreasureChest` struct where `T` is an array of string slices.
    

Rust

```Rust
// The generic struct from Part 1.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

fn main() {
    // ... instances from Part 2 ...

    // 3. We instantiate with an array of string slices.
    //    The compiler sees a `[&str; 3]` and infers that `T` is `[&str; 3]` for this instance.
    let special_chest = TreasureChest {
        captain: String::from("Bootyplunder"),
        treasure: ["Gold", "Silver", "Platinum"],
    };
    
    // We can print this new, complex instance with `Debug`.
    println!("\nSpecial Chest: {:#?}", special_chest);
    
    // The rest of this code is completed in the final part.
}
```

### Part 4: The Final Progressive Example

This final part ties all the concepts together into a complete, working program. It shows the definitions and invocations for all three `TreasureChest` instances.

- **Code Flow:** The program defines a single generic struct blueprint, then creates three different concrete instances from that blueprint, each with a different type of treasure.
    
- **The Result:** The output from the `println!` statements clearly shows how the single generic struct definition can be used to represent a variety of distinct data types, all within a single type framework.
    

Rust

```Rust
// The final generic struct definition with Debug derive.
#[derive(Debug)]
struct TreasureChest<T> {
    captain: String,
    treasure: T,
}

fn main() {
    // Instance 1: T is a string literal (&str)
    let gold_chest = TreasureChest {
        captain: String::from("Firebeard"),
        treasure: "Gold",
    };

    // Instance 2: T is a `String`
    let silver_chest = TreasureChest {
        captain: String::from("Bloodsail"),
        treasure: String::from("Silver"),
    };
    
    // Instance 3: T is an array of string slices ([&str; 3])
    let special_chest = TreasureChest {
        captain: String::from("Bootyplunder"),
        treasure: ["Gold", "Silver", "Platinum"],
    };
    
    // We can print all three instances, even though they have different types for `T`.
    println!("--- Treasure Chest Inventory ---");
    println!("Gold Chest: {:#?}", gold_chest);
    println!("\nSilver Chest: {:#?}", silver_chest);
    println!("\nSpecial Chest: {:#?}", special_chest);
}
```
