# 📘 Study Guide: Generics in Rust

---

## 1. What Are Generics?

- A **generic** is a **type argument**: a placeholder for a concrete type that will be substituted later.
    
- Analogy:
    
    - **Function parameter** → placeholder for a value.
        
    - **Generic type parameter** → placeholder for a type.
        
- The name "generic" comes from **not being specific** → it generalizes the code to work with many different types.
    

This provides **reusability** and **flexibility**, so we don’t have to hardcode types like `i32` or `bool`.

---

## 2. Generic Syntax

- Declared with **angle brackets `< >`**.
    
- Commonly use `T` for “type,” but names are up to the developer.
    
- Multiple generics are separated by commas: `<T, U, V>`.
    
- Multiple generics allow different types to be substituted, but they **don’t force** them to be different — the same type can be used for all.
    

Example:

```rust
fn identity<T>(x: T) -> T {
    x
}
```

Here `T` is a placeholder. At the call site:

```rust
let a = identity(5);     // T = i32
let b = identity("hi");  // T = &str
```

---

## 3. Where Generics Are Used

### 3.1 Functions

- Generics allow parameters and return values to be type-flexible.
    
- Example:
    
    ```rust
    fn add<T: std::ops::Add<Output = T>>(a: T, b: T) -> T {
        a + b
    }
    ```
    

Here both parameters must be the same type `T`, and the compiler enforces that.

---

### 3.2 Structs

- Struct fields can use generics to hold values of different future types.
    

Example:

```rust
struct Point<T> {
    x: T,
    y: T,
}
```

- At instantiation:
    
    ```rust
    let int_point = Point { x: 1, y: 2 };       // T = i32
    let float_point = Point { x: 1.0, y: 2.0 }; // T = f64
    ```
    

---

### 3.3 Enums

- Variants can carry generic data.
    

Example:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

- `T` allows `Option` to wrap any type.
    

---

### 3.4 Methods with Generics

- Generics extend naturally into methods.
    
- Example:
    
    ```rust
    struct Container<T> {
        item: T,
    }
    
    impl<T> Container<T> {
        fn get(&self) -> &T {
            &self.item
        }
    }
    ```
    

Here:

- `impl<T>` declares a new generic `T` for the `impl` block.
    
- Without this, Rust would look for a **concrete type named `T`** in your program instead of treating `T` as a placeholder.
    

---

## 4. Specialization in `impl` Blocks

There are two main patterns when implementing methods for generic types:

### 4.1 Generic `impl` for Any Type

```rust
impl<T> Container<T> {
    fn new(item: T) -> Self {
        Container { item }
    }
}
```

- Works with **any type `T`**.
    

---

### 4.2 Specialized `impl` for a Concrete Type

```rust
impl Container<i32> {
    fn is_positive(&self) -> bool {
        self.item > 0
    }
}
```

- Works **only when `T = i32`**.
    
- Useful for methods that only make sense for specific types.
    

---

## 5. Key Concepts to Remember

1. **Generics = type parameters** (placeholders for concrete types).
    
2. **Reusability**: one function/struct/enum definition works across multiple types.
    
3. **Type checking**:
    
    - Compiler enforces correct substitution.
        
    - For example, if parameters and return value all use `T`, they must be of the same type.
        
4. **Structs/Enums**: generics apply to fields and variants.
    
5. **impl blocks**:
    
    - Use `impl<T>` when defining methods for any generic `T`.
        
    - Use `impl<Type>` when specializing behavior for a specific type.
        
6. **Naming**: convention is short uppercase letters (`T`, `U`, `E`), but you can name them anything meaningful.
    

---

## 6. Mental Model

Think of **generics** as:

- A **promise** that at some later point, a concrete type will be provided.
    
- A **contract** that guarantees relationships between values:
    
    - If parameter is `T` and return is `T`, they must match.
        
    - If multiple generics exist, they may or may not differ, depending on the instantiation.
