# Accessing Values in Rust HashMaps

This document outlines two methods for accessing values in a Rust HashMap using keys, based on the provided transcript, with a focus on safety and ownership.

## Methods for Accessing Values

### 1. Using Square Brackets (`[]`)

- **Syntax**: Access a value by providing the key in square brackets, e.g., `coffee_pairings["Flat White"]`.
- **Behavior**: Returns the corresponding value (e.g., `"Almond Milk"` for key `"Flat White"`).
- **Risk**: If the key does not exist (e.g., `"Cappuccino"`), it causes a runtime panic (`"no entry found for key"`).
- **Use Case**: Suitable when you are certain the key exists, but less safe due to potential panics.

**Example**:

```rust
let value = coffee_pairings["Flat White"]; // Returns "Almond Milk"
println!("{}", value); // Outputs: Almond Milk
let value = coffee_pairings["Cappuccino"]; // Panics: no entry found
```

### 2. Using the `get` Method

- **Syntax**: Use the `get` method with the key, e.g., `coffee_pairings.get("Flat White")`.
- **Behavior**: Returns an `Option` enum:
    - `Some(&value)` if the key exists, containing a reference to the value.
    - `None` if the key does not exist.
- **Safety**: Prevents runtime panics by requiring explicit handling of the `Option`.
- **Ownership**: Returns a reference (`&T`) to avoid moving ownership out of the HashMap, ensuring the HashMap retains full control over its contents.
- **Handling References**: For a HashMap with string slice values (`&str`), `get` returns an `Option<&str>` (a reference to a string slice).

**Example**:

```rust
let value = coffee_pairings.get("Flat White"); // Returns Some(&"Almond Milk")
let value = coffee_pairings.get("Cappuccino"); // Returns None
```

#### Extracting Values Safely

- **Challenge**: The `Option<&str>` returned by `get` cannot be directly printed (lacks `Display` trait).
- **Solution**: Use the `copied` method to convert `Option<&str>` to `Option<&str>` (copying the string slice reference) and then extract the value with methods like:
    - `unwrap`: Assumes `Some` and extracts the value (panics on `None`).
    - `expect`: Extracts the value or panics with a custom message on `None`.
    - `unwrap_or`: Provides a fallback value if `None` (e.g., `"Unknown Milk"`).

**Example**:

```rust
let value = coffee_pairings.get("Flat White").copied().unwrap_or("Unknown Milk");
println!("{}", value); // Outputs: Almond Milk
let value = coffee_pairings.get("Cappuccino").copied().unwrap_or("Unknown Milk");
println!("{}", value); // Outputs: Unknown Milk
```

### Why `get` Returns a Reference

- Prevents accidental ownership transfer of values, especially for types like `String` that live on the heap.
- Ensures the HashMap retains ownership of its contents, avoiding partial ownership issues (similar to vectors or arrays).

## Key Takeaways

- **Square Brackets**: Simple but unsafe due to potential panics if the key is missing.
- **Get Method**: Safer, returns an `Option<&T>`, requiring explicit handling of missing keys.
- **Copied Method**: Converts `Option<&T>` to `Option<T>` for types like `&str`, enabling easier value extraction.
- **Safety First**: Rust’s design (references, `Option`, and methods like `unwrap_or`) ensures robust handling of missing keys and ownership, reducing runtime errors at the cost of verbosity.

This approach helps write safer, more predictable Rust code when accessing HashMap values.
