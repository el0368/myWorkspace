### Part 2: The `self` Parameter with Ownership

This study guide focuses on the `self` parameter in a method definition when it takes **ownership** of the struct instance. This is one of the four ways a method can interact with its associated `struct`.

#### 1. The Core Concept: Taking Ownership

When a method signature defines its first parameter as `self` or `mut self`, it means the method receives the **actual struct instance by value**, not a reference to it. This triggers a fundamental ownership transfer:

- **Move of Ownership:** Ownership of the struct is **moved** from the variable used to call the method (e.g., `song` in `main`) to the `self` parameter.
    
- **Original Variable Becomes Invalid:** After the method is called, the original variable **can no longer be used**. This is because it is no longer the owner of the struct's data.
    
- **Method's Responsibility:** The `self` parameter becomes the new owner. When the method finishes and its `self` parameter goes out of scope, `self` is then responsible for deallocating the struct's memory.
    

This approach is sometimes referred to as "consuming" the value, as the method uses it up and it's gone afterward.

#### 2. Option 1: Immutable Ownership (`self`)

This is the most basic form of taking ownership.

- **Syntax:** `fn method_name(self) { ... }`
    
- **Behavior:** The method takes ownership of the struct. Within the method body, you have **read-only access** to the struct's fields. You can use the data, but you cannot modify it.
    
- **Consequence:** The original variable is invalidated.
    

#### 3. Option 2: Mutable Ownership (`mut self`)

This option combines ownership with mutability.

- **Syntax:** `fn method_name(mut self) { ... }`
    
- **Behavior:** The method takes ownership of the struct and is granted permission to **mutate (modify)** its fields.
    
- **Consequence:** The original variable is still invalidated after the method call.
    

#### 4. Summary and Key Implications

In both of these ownership-based `self` scenarios (`self` and `mut self`):

- The method parameter becomes the new owner.
    
- The variable used to call the method becomes invalid.
    
- The struct's memory is deallocated when the method ends.
    

Because of this, these options are often less practical than using references, especially for methods that only read data. They are best reserved for situations where a method's logic truly means the struct should be consumed and should not exist afterward.

#### Example: `TaylorSwiftSong` Methods with Ownership `self`

Rust

```Rust
// The struct blueprint. We need `Clone` here to show a copy being used for the `mut self` example below.
#[derive(Debug, Clone)]
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

impl TaylorSwiftSong {
    // This `self` signature takes IMMUTABLE OWNERSHIP.
    // The original instance is consumed.
    fn display_song_info(self) {
        println!("Title: {}", self.title);
        println!("Release Year: {}", self.release_year);
        println!("Duration: {} seconds", self.duration_secs);
        // The `self` parameter and the struct it owns are deallocated here.
    }

    // This `mut self` signature takes MUTABLE OWNERSHIP.
    // It is a valid definition for a method that needs to modify a field.
    fn update_release_year(mut self, new_year: u32) {
        self.release_year = new_year;
        println!("Updated year: {}", self.release_year);
        // The `self` parameter and the struct it owns are deallocated here.
    }
}

fn main() {
    let song = TaylorSwiftSong::new(String::from("Blank Space"), 2014, 231);

    // Call `display_song_info`. Ownership of `song` is MOVED.
    // The `song` variable in main becomes invalid after this call.
    song.display_song_info();

    // The original `song` variable is now invalid and cannot be used.
    // This would result in a compile-time error:
    // println!("Cannot access original song: {}", song.title);

    // To show the `mut self` example, we must create a new instance, as the first one was consumed.
    let mut another_song = TaylorSwiftSong::new(String::from("Blank Space"), 2014, 231);

    // Call `update_release_year`. Ownership of `another_song` is MOVED.
    // `another_song` is now invalid after this call.
    another_song.update_release_year(2025);
}
```
