### Part 3: The Consequence of Ownership Moves on Chained Calls

This study guide explains a critical implication of methods that take ownership: you cannot make multiple consecutive calls to these methods on the same struct instance.

#### 1. The Problem: Invalidating the Original Owner

Methods that take ownership of a struct instance via the `self` or `mut self` parameter act as a **move operation**.

- **First Call:** When you call the first ownership-consuming method (e.g., `instance.method1()`), ownership of the struct moves from the `instance` variable to the method's `self` parameter.
    
- **Original Variable Invalidated:** The `instance` variable in the calling scope immediately becomes **invalid** and can no longer be used.
    

#### 2. The Consequence: No Chained Calls

Since the original variable is invalidated after the first method call, it is impossible to use that same variable to call a second method. Any attempt to do so will result in a compile-time error.

- **Reason:** The second method call requires a struct instance to operate on, but the original variable no longer owns a valid one to provide. Rust's compiler prevents this to enforce the "one owner at a time" rule and avoid memory-related bugs.
    

#### Example: Inability to Chain Ownership-Consuming Methods

Rust

```
// The struct blueprint
#[derive(Debug, Clone)]
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

impl TaylorSwiftSong {
    // This method takes immutable ownership (`self`).
    fn display_song_info(self) {
        println!("Displaying info for: {}", self.title);
        // Ownership is consumed here.
    }

    // This method takes mutable ownership (`mut self`).
    fn update_release_year(mut self, new_year: u32) {
        self.release_year = new_year;
        println!("Updated year to: {}", self.release_year);
        // Ownership is consumed here.
    }
}

fn main() {
    let song = TaylorSwiftSong::new(String::from("Blank Space"), 2014, 231);

    // This first method call is valid, but it moves ownership.
    song.display_song_info();

    // The following line would cause a compile-time error!
    // `song` is now invalid, so it cannot be used to call another method.
    // song.update_release_year(2025); // ERROR: borrow of moved value: `song`
    
    // To call a second method, you would need to create a new instance, like this:
    let another_song = TaylorSwiftSong::new(String::from("Style"), 2014, 221);
    another_song.display_song_info();
}

// Helper function for the main example
impl TaylorSwiftSong {
    fn new(title: String, release_year: u32, duration_secs: u32) -> Self {
        Self { title, release_year, duration_secs }
    }
}
```

**Conclusion:** Methods that take ownership of `self` are "consuming" methods. They use up the struct instance, making it unavailable for any further method calls. To make multiple calls, you would need to create a new instance each time or, more practically, use references to avoid the ownership transfer in the first place (as we will explore in the next section).
