### 1. Manual Struct Creation by Referencing Another Struct

This example shows how you can manually create a new struct instance by accessing and assigning the fields of an existing struct one by one. This works correctly for `Copy` types.

Rust

```Rust
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // Create a new struct instance by manually accessing `mocha`'s fields.
    // `price` and `is_hot` are Copy types, so their values are copied.
    let caramel_macchiato = Coffee {
        name: String::from("Caramel Macchiato"),
        price: mocha.price, // `mocha.price` (f64) is copied.
        is_hot: mocha.is_hot, // `mocha.is_hot` (bool) is copied.
    };

    println!("Original Mocha price: {}", mocha.price); // mocha.price is still valid.
    println!("New Macchiato price: {}", caramel_macchiato.price); // Macchiato has its own copy.
}
```

### 2. The `..` Struct Update Syntax

This is a shortcut to create a new struct instance. You can define new values for specific fields, and then use the `..` syntax to automatically copy all remaining fields from an existing struct.

Rust

```Rust
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // Create a new struct. We only specify the `name` field with a new value.
    // The `..mocha` syntax copies the remaining fields (`price` and `is_hot`) from `mocha`.
    let caramel_macchiato = Coffee {
        name: String::from("Caramel Macchiato"),
        ..mocha
    };

    println!("Original Mocha is still valid: {}", mocha.name); // This works because `name` was NOT copied via `..`
    println!("New Macchiato price: {}", caramel_macchiato.price); // The `price` was copied over from `mocha`.
}
```

---

### 3. `..` Syntax with Ownership Move (The Problem)

The `..` syntax is not a "magical copy." It's a shorthand for assignment. If a field's type does not implement the `Copy` trait (like `String`), the `..` syntax will **move ownership** of that field's value. This invalidates the original struct.

Rust

```Rust
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"), // `name` field owns this String.
        price: 4.99,
        is_hot: true,
    };

    // This is a struct update that copies all fields from `mocha`.
    // It's a shorthand for `name: mocha.name, price: mocha.price, is_hot: mocha.is_hot`.
    let caramel_macchiato = Coffee {
        name: String::from("Caramel Macchiato"),
        ..mocha
    };

    // mocha.name was moved implicitly by the `..` syntax.
    // This line would cause a compile-time error!
    // println!("Original Mocha price: {}", mocha.name);
}
```

---

### 4. Avoiding the Move with `.clone()` (The Solution)

To create a full copy of a struct that contains non-`Copy` fields and keep the original struct valid, you must explicitly call `.clone()` on those specific fields before using the `..` syntax.

Rust

```Rust
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // Create a full copy by explicitly cloning the non-Copy `name` field,
    // and then using `..mocha` to copy the remaining Copy fields.
    let caramel_macchiato = Coffee {
        name: mocha.name.clone(), // Explicitly clone the String.
        ..mocha
    };

    // Now, because we cloned the `name` field, the original `mocha` is still valid.
    println!("Original Mocha is still valid: {}", mocha.name);
    println!("New Macchiato is also valid: {}", caramel_macchiato.name);
}
```
