### 1. Ownership Hierarchy in Structs

A struct represents a hierarchy of ownership:

1. A `struct` instance (the variable holding the struct) is the **owner** of all its fields.
    
2. Each individual field, in turn, is the **owner** of its corresponding value.
    

This means that when you interact with a field's value, you are interacting with data that is owned by that field, and Rust's ownership rules apply at this granular level.

### 2. Accessing Fields with `Copy` Types

For fields whose data type implements the `Copy` trait (e.g., `i32`, `f64`, `bool`), accessing and assigning the value will perform an automatic copy.

- **Behavior:** Ownership of the value is **not moved**. Instead, a new, independent copy of the value is created for the new variable.
    
- **Result:** The original field within the struct remains valid and usable.
    

#### Example: Accessing a `Copy` Field (`f64`)

Rust

```Rust
#[derive(Debug)]
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99, // `f64` is a Copy type
        is_hot: true,
    };

    // Accessing `mocha.price` and assigning it to `favorite_price`.
    // The `f64` value is copied, not moved.
    let favorite_price = mocha.price;

    println!("Favorite price is: {}", favorite_price); // Output: Favorite price is: 4.99

    // The original `mocha` struct is still completely valid because its `price` field
    // was only copied, not moved.
    println!("Original Mocha price is still here: {}", mocha.price); // Output: Original Mocha price is still here: 4.99
    println!("Original Mocha struct: {:?}", mocha);
}
```

### 3. Accessing Fields with Non-`Copy` Types

For fields whose data type **does not** implement the `Copy` trait (e.g., `String`, `Vec<T>`), accessing and assigning the value will perform a **move of ownership** for that specific field.

- **Behavior:** Ownership of the field's value is **moved** out of the struct and transferred to the new variable.
    
- **Result:** The original field within the struct becomes **invalid**. Because a part of the struct's data is now missing, the entire struct is considered "partially moved," and you cannot use it in contexts that require that field.
    

#### Example: Accessing a Non-`Copy` Field (`String`)

Rust

```Rust
#[derive(Debug)] // The Debug derive will fail later, proving the move happened.
struct Coffee {
    name: String, // `String` is a non-Copy type
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"), // `name` field owns this String.
        price: 4.99,
        is_hot: true,
    };

    // This is a move operation! Ownership of the `String` "Mocha"
    // is moved from `mocha.name` to `favorite_coffee_name`.
    let favorite_coffee_name = mocha.name;

    println!("My favorite coffee name is: {}", favorite_coffee_name); // Output: My favorite coffee name is: Mocha

    // The `mocha` struct is now partially moved. The following lines would cause compile-time errors:
    
    // ERROR: The `name` field is invalid and cannot be accessed.
    // println!("Original Mocha name: {}", mocha.name);
    
    // ERROR: The entire `mocha` struct cannot be used because a part of it (`name`) is gone.
    // println!("Original Mocha struct: {:?}", mocha);
}
```

### 4. Solutions to Avoid a Move

If you need to access a non-`Copy` field _and_ keep the original struct valid, you must prevent the move from happening.

- **Borrowing (`&`):** To read a non-`Copy` field without a move, create a reference to it. The `&` operator borrows access without transferring ownership.
    
    Rust
    
    ```Rust
    let name_ref = &mocha.name;
    println!("Name by reference: {}", name_ref); // mocha.name is still valid.
    ```
    
- **Cloning (`.clone()`):** To create a new, independent owned copy of the field's value, you must explicitly call the `.clone()` method. This duplicates the data on the heap.
    
    Rust
    
    ```Rust
    let cloned_name = mocha.name.clone();
    println!("Cloned Name: {}", cloned_name); // mocha.name is still valid.
    ```
