### 1. The Problem: Default Structs Cannot Be Printed

By default, a `struct` that you define in Rust **cannot be printed** using standard `println!` macros.

- **Reason:** Printing a value requires a defined way to convert that value into a string. In Rust, this is handled by **traits**. Custom structs do not automatically implement the `Display` or `Debug` traits, which are the contracts that provide this conversion functionality.
    
- **Result:** Attempting to `println!("{}", my_struct)` or `println!("{:?}", my_struct)` will result in a **compile-time error** because the required trait implementation is missing.
    

### 2. The Solution: The `Debug` Trait and the `derive` Attribute

The most common and simplest solution to this problem is to automatically implement the `Debug` trait for your struct using a compiler directive called the **`derive` attribute**.

- **`Debug` Trait:** The `Debug` trait's purpose is to provide a **programmer-friendly string representation** of a value, which is ideal for debugging and inspection.
    
- **`derive` Attribute:** The `#[derive(Debug)]` attribute is a shortcut that tells the Rust compiler to **automatically generate** a default `Debug` implementation for your struct.
    
- **Syntax:** You place `#[derive(Debug)]` on the line immediately above your `struct` definition.
    

### 3. Key `Debug` Formatters

Once your struct implements `Debug`, you can print it using specific format specifiers within the `println!` macro.

- **`{:?}`**: The standard `Debug` formatter. It prints the struct's name and all its fields and values on a single line.
    
- **`{:#?}`**: The "pretty-print" `Debug` formatter. It adds newlines and indentation, making the output more readable, especially for structs with many fields or nested data.
    

### 4. Code Example

This example shows a `struct` that initially cannot be printed and then demonstrates how to fix it with the `#[derive(Debug)]` attribute.

Rust

```Rust
// The struct blueprint without the `derive` attribute (conceptual)
/*
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };
    // This would be a compiler error!
    // println!("{:?}", mocha);
}
*/

// The solution: add the `derive` attribute.
#[derive(Debug)]
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    println!("Using `{:?}`: {:?}", mocha);
    // Output: Using `{:?}`: Coffee { name: "Mocha", price: 4.99, is_hot: true }

    println!("\nUsing `{:#?}`:");
    println!("{:#?}", mocha);
    // Output:
    // Using `{:#?}`:
    // Coffee {
    //     name: "Mocha",
    //     price: 4.99,
    //     is_hot: true
    // }
}
```

### 5. `Debug` vs. `Display` (Important Distinction)

- **`Debug` (for Developers):** Provides a technical, structured output that shows the internal state of the struct. It's for debugging purposes and can be automatically derived with `#[derive(Debug)]`.
    
- **`Display` (for End-Users):** Provides a clean, user-friendly output. It is **never automatically derived** for structs because Rust can't know what a "user-friendly" representation of your struct should look like. To get `Display` functionality, you must implement it manually.
    

This distinction reinforces the idea that `Debug` is for inspecting your code, while `Display` is for controlled, polished output to a user.
