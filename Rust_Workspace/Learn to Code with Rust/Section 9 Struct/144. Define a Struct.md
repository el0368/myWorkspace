### In-Depth Study Guide: Defining a Struct in Rust

This guide explains what a struct is, why you would use one over a tuple, and the precise syntax for defining your own custom data types.

---

### 1. What is a Struct?

A **struct** (short for structure) is a **custom, compound data type** that allows you to group together related data. The individual pieces of data within a struct are called **fields** (or members).

If you have experience with object-oriented programming, a Rust struct is comparable to an object's data attributes. It allows you to create more complex and meaningful types than the built-in primitives like `i32` or `bool`.

Rust has three kinds of structs, but this guide focuses on the most common type: a **named-field struct**.

---

### 2. Why Use a Struct Over a Tuple?

Both structs and tuples can hold multiple values of different types. However, they serve different purposes.

- **Tuples:** Group data by **position**. You access elements with an index (e.g., `my_tuple.0`). This is useful for simple groupings where the order is obvious and you don't need named fields. The downside is a lack of context—`my_tuple.1` doesn't tell you what that value represents.
    
- **Structs:** Group data by **name**. You access elements with their field name (e.g., `my_coffee.price`). This provides clear context and makes the data's meaning self-evident. The order in which you define the fields does not matter for accessing them.
    

**Conclusion:** For any complex data that you want to model, a struct is superior because the named fields make your code more readable and less error-prone.

---

### 3. Defining a Struct: The Blueprint

When you define a struct, you are creating a **blueprint** or a template for a new data type in your program. You are not creating a concrete value yet, just as defining what an `i32` is doesn't create the number `5`.

#### Syntax Breakdown

Rust

```Rust
struct Coffee {
    // field_name: Type,
    name: String,
    price: f64,
    is_hot: bool,
}
```

1. **`struct` keyword:** This begins the definition of a struct.
    
2. **Struct Name (`Coffee`):** The name of your new custom type. The community convention is to use **`PascalCase`**, where the first letter of every word is capitalized.
    
3. **Curly Braces `{}`:** These enclose the list of fields.
    
4. **Fields (`name`, `price`, `is_hot`):**
    
    - Each field has a name, followed by a colon (`:`), and then its data type.
        
    - The convention for field names is **`snake_case`** (all lowercase, with underscores between words).
        
    - Fields are separated by commas. It is idiomatic to place a comma after the final field as well.
        

---

### 4. Ownership within Structs

The principles of ownership apply to structs in a hierarchical way.

- A variable that holds a struct instance is the **owner** of that instance.
    
- The struct instance, in turn, is the **owner** of the data stored in its fields.
    

This is especially important for fields that own heap-allocated data, like a `String`. In our `Coffee` example, when an instance of `Coffee` is created, it will own the `String` data for its `name`. When the `Coffee` instance goes out of scope, it is responsible for dropping its fields, which will deallocate the `String` data from the heap.

After defining the `Coffee` struct, you have effectively added a new, custom type to your program's vocabulary. It can now be used just like built-in types such as `i32` or `bool`. The next step, covered in the following lesson, is to create concrete instances (values) from this blueprint.
