Here are the four different ways to pass a `struct` into a function, with each method shown in a separate, self-contained Rust code example.

This will cover all the details from the transcript, focusing on the syntax and the effect on ownership and mutability.

---

### 1. Passing by Immutable Value (Ownership Move)

This method moves ownership of the struct to the function. The parameter is immutable, so you can only read its fields. The original variable becomes invalid.

Rust

```Rust
// The struct blueprint
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

// This function takes ownership of the `Coffee` instance.
// The parameter `coffee` is immutable by default.
fn drink_coffee(coffee: Coffee) {
    println!("Drinking my delicious {}", coffee.name);
    // coffee.is_hot = false; // ERROR: cannot assign to a field of an immutable parameter.
    // The `coffee` parameter and the struct it owns are deallocated here.
}

fn main() {
    let mocha = Coffee { // `mocha` is the owner of this `Coffee` instance.
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // Ownership of `mocha` moves into the `drink_coffee` function.
    drink_coffee(mocha);

    // This line would cause a compile-time error because `mocha` is no longer the owner.
    // println!("Mocha is still valid: {}", mocha.name); // ERROR: borrow of moved value: `mocha`
}
```

### 2. Passing by Mutable Value (Ownership Move)

This method also moves ownership to the function, but the `mut` keyword on the parameter gives it permission to modify the struct's fields. The original variable still becomes invalid.

Rust

```Rust
// The struct blueprint
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

// This function takes mutable ownership of the `Coffee` instance.
fn update_and_drink(mut coffee: Coffee) { // `mut` keyword on the parameter gives mutation permission.
    println!("Price before update: {}", coffee.price);
    coffee.price = 10.99; // Mutation is allowed.
    println!("Price after update: {}", coffee.price);

    println!("Drinking my delicious {}", coffee.name);
    // The `coffee` parameter and the modified struct it owns are deallocated here.
}

fn main() {
    let mocha = Coffee { // `mocha` is the owner of this `Coffee` instance.
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // Ownership of `mocha` moves into the `update_and_drink` function.
    update_and_drink(mocha);

    // `mocha` is invalid after the function call.
    // println!("Mocha is still valid: {}", mocha.name); // ERROR: borrow of moved value: `mocha`
}
```

### 3. Passing by Immutable Reference (No Ownership Transfer)

This is the most common way to pass a struct for read-only access. The function borrows a reference to the struct, so no ownership moves. The original variable remains valid and can be used after the function call.

Rust

```Rust
// The struct blueprint
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

// This function takes an immutable reference to the `Coffee` instance.
fn print_coffee_details(coffee: &Coffee) { // `&Coffee` is the parameter type.
    // We can access fields as normal. Rust automatically dereferences the reference.
    println!("This coffee is {}, costing {}.", coffee.name, coffee.price);

    // coffee.is_hot = false; // ERROR: cannot assign to a field of an immutable reference.
    // The `coffee` parameter (the reference) is deallocated here, but the original struct remains.
}

fn main() {
    let mocha = Coffee { // `mocha` is the owner.
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // We pass an immutable reference using the `&` borrow operator.
    print_coffee_details(&mocha);

    // `mocha` is still valid here because ownership was not moved.
    println!("Mocha is still valid: {}", mocha.name); // This works without error.
}
```

### 4. Passing by Mutable Reference (No Ownership Transfer, but Modifiable)

This is the most common way to pass a struct when you need to modify it. The function borrows a mutable reference, so ownership doesn't move. The original variable must be declared as `mut` to allow for the mutable borrow.

Rust

```Rust
// The struct blueprint
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

// This function takes a mutable reference to the `Coffee` instance.
fn update_price(coffee: &mut Coffee, new_price: f64) { // `&mut Coffee` is the parameter type.
    println!("Price before update: {}", coffee.price);
    coffee.price = new_price; // Mutation is allowed.
    // The `coffee` parameter (the reference) is deallocated here. The original struct remains, but is now modified.
}

fn main() {
    let mut mocha = Coffee { // The owner variable must be declared `mut` to allow a mutable reference.
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // We pass a mutable reference using the `&mut` borrow operator.
    update_price(&mut mocha, 10.99);

    // `mocha` is still valid here and its `price` field has been updated by the function.
    println!("Mocha is still valid, and price is updated: {}", mocha.price); // Output: 10.99
}
```
