Here are Rust code examples illustrating the concepts of traits, attributes, and deriving `Debug` for structs, based on your review. Each example is separated for clarity.

---

### 1. The Default Problem: `struct`s Do Not Implement `Display` or `Debug`

This example demonstrates that by default, a custom `struct` cannot be printed with `println!` because it doesn't support the necessary traits.

Rust

```Rust
// A simple struct definition without any attributes
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // The following lines will NOT compile by default:

    // This relies on the `Display` trait, which `Coffee` does not implement.
    // println!("{}", mocha); // ERROR: the trait `Display` is not implemented for `Coffee`

    // This relies on the `Debug` trait, which `Coffee` does not implement.
    // println!("{:?}", mocha); // ERROR: the trait `Debug` is not implemented for `Coffee`

    // This also relies on `Debug` and will fail.
    // println!("{:#?}", mocha); // ERROR: the trait `Debug` is not implemented for `Coffee`
}
```

---

### 2. The Solution: `#[derive(Debug)]` Attribute

This example shows how to use the `derive` attribute to automatically implement the `Debug` trait, enabling a `struct` to be printed for debugging.

Rust

```Rust
// The #[derive(Debug)] attribute automatically implements the Debug trait.
#[derive(Debug)]
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };

    // This code now compiles and outputs a standard debug representation.
    println!("Standard Debug: {:?}", mocha);
    // Output: Standard Debug: Coffee { name: "Mocha", price: 4.99, is_hot: true }

    // This code also compiles and outputs a more readable "pretty-printed" representation.
    println!("Pretty-Printed Debug:\n{:#?}", mocha);
    // Output:
    // Pretty-Printed Debug:
    // Coffee {
    //     name: "Mocha",
    //     price: 4.99,
    //     is_hot: true,
    // }
}
```

### 3. Array Printing (for context from the transcript)

This example shows that arrays do not implement the `Display` trait, but do implement `Debug` by default, which is similar behavior to our derived struct.

Rust

```Rust
fn main() {
    let values: [&str; 2] = ["first", "second"];

    // An array does NOT implement `Display`, so this line will NOT compile.
    // println!("{}", values); // ERROR: the trait `Display` is not implemented for `[&str; 2]`

    // However, an array DOES implement `Debug` by default.
    println!("Array Debug: {:?}", values);
    // Output: Array Debug: ["first", "second"]

    println!("Array Pretty-Printed Debug:\n{:#?}", values);
    // Output:
    // Array Pretty-Printed Debug:
    // [
    //     "first",
    //     "second",
    // ]
}
```

### 4. The `allow` Attribute

This example demonstrates how an attribute can be used to suppress a compiler warning, as discussed in the transcript's context of attributes.

Rust

```Rust
// Our struct needs the `derive(Debug)` attribute again for printing
#[derive(Debug)]
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}

fn main() {
    // The `allow` attribute is a compiler directive.
    // It tells the compiler to ignore a specific warning for the following code.
    #[allow(unused_variables)]
    let mocha = Coffee {
        name: String::from("Mocha"),
        price: 4.99,
        is_hot: true,
    };
    
    // We can also apply it to a whole function.
    // #[allow(unused_variables)]
    // fn my_function() {
    //   let x = 10;
    // }

    // Without the `allow` attribute, the compiler would issue a warning here:
    // "warning: unused variable `mocha`"
    // With the attribute, the warning is suppressed.
    println!("The variable `mocha` was declared but not used in a printing context (which is okay now).");
}
```
