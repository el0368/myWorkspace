### 5. Ownership of Struct Fields

**Explanation in the Scope of the Transcript:**

The transcript highlights that a **named field struct owns its fields**, and each field, in turn, owns its values. This ownership model is a core Rust concept, ensuring that data within a struct adheres to Rust’s strict memory management rules. When a struct instance is created, it becomes the owner of its field values, meaning it is responsible for managing their lifetime and eventual deallocation when the struct goes out of scope. This ownership extends to the values stored in the fields, which can impact how the struct behaves when assigned, passed to functions, or copied, especially for types that do not implement the `Copy` trait. The transcript emphasizes that this ownership ensures the struct maintains control over its data, preventing issues like dangling references or unintended data movement.

**Rust Code Example:**

Below is a minimal code example demonstrating ownership of struct fields, aligned with the transcript’s description.
```rust
struct Book {
    title: String, // Field owns a heap-allocated String
    pages: u32,    // Field owns a stack-allocated u32
}

fn main() {
    // Create a Book instance that owns its fields
    let book = Book {
        title: String::from("Rust Guide"),
        pages: 300,
    };

    // Ownership moves to new variable
    let book2 = book; // book is no longer valid
    println!("Book: {} with {} pages", book2.title, book2.pages);

    // Uncommenting the next line would cause a compile error
    // println!("Original book: {}", book.title); // Error: value moved
}
```

**Code Explanation:**

1. **Struct Declaration**:
   - The `Book` struct is defined with two fields: `title: String` (a heap-allocated type that does not implement `Copy`) and `pages: u32` (a stack-allocated type that implements `Copy`).

2. **Ownership of Fields**:
   - When `book` is instantiated, it owns its fields: the `title` field owns the `String` value, and the `pages` field owns the `u32` value, as per the transcript’s note that “the struct owns its fields, and the fields own their values.”
   - The `String` in `title` is heap-allocated, so the struct manages its memory, while `pages` is a simple stack value.

3. **Ownership Movement**:
   - Assigning `book` to `book2` moves ownership of the entire struct, including its fields, to `book2`. Since `String` does not implement `Copy`, the `title` field’s ownership moves, making `book` invalid.
   - Attempting to access `book.title` after the move would cause a compile error, illustrating that the struct’s ownership of its fields is transferred, as implied by the transcript’s discussion of ownership rules.

**Key Takeaways**:
- A struct owns its fields, and each field owns its value, tying the struct to Rust’s ownership model.
- Moving a struct transfers ownership of all its fields, impacting usability if fields contain non-`Copy` types like `String`.
- The example is minimal, focusing on ownership and movement as described in the transcript.
