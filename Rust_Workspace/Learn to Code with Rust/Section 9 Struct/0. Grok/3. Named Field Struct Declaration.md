### 3. Named Field Struct Declaration

**Explanation in the Scope of the Transcript:**

The transcript describes the **named field struct** as the most common type of struct in Rust, used to define a blueprint or template for data with explicitly named fields. This declaration specifies the structure’s fields and their corresponding data types, creating a new custom type without instantiating any concrete values. The declaration uses the `struct` keyword, followed by the struct’s name in PascalCase (capitalizing the first letter of each word), and a pair of curly braces `{}`. Inside the braces, fields are listed with their names, a colon, the associated data type, and separated by commas. This blueprint ensures that any instances created from it adhere to the defined structure, with the compiler enforcing the correct number and types of fields.

```rust

struct Book {
    title: String,   // Field with name and type
    pages: u32,      // Field with name and type
}

fn main() {
    // No instantiation here, just showing the declaration
    // The struct defines a template for a Book with title and pages

```

1. **Struct Declaration**:

   - Inside curly braces `{}`, two fields are defined: `title: String` and `pages: u32`, each with a name, colon, and type, separated by a comma, matching the transcript’s syntax description.
   - This declaration creates a blueprint for a `Book` type, specifying that any `Book` instance must have a `title` (a `String`) and `pages` (a `u32`).

2. **Blueprint Without Values**:
   - As noted in the transcript, this declaration defines the structure but does not create concrete values. No instantiation is shown in the `main` function to keep it minimal, emphasizing that the declaration is just a template.
   - The compiler will use this blueprint to validate instances created later, ensuring they provide a `String` for `title` and a `u32` for `pages`.

**Key Takeaways**:
