## Rust Structs: Section Review Study Guide

This section provided an in-depth look at **structs** (structures), a core feature for creating custom, complex data types in Rust. It covered struct definitions, instantiation, methods, associated functions, and the different types of structs available.

### I. What is a Struct?

- **Definition:** A `struct` is a container for **related data**. It allows you to group multiple pieces of information (fields) under a single, meaningful name, creating a new custom type.
    
- **Purpose:** Structs are used to model complex, real-world types where multiple attributes describe a single entity (e.g., a `User` struct might have `name`, `email`, and `age` fields).
    
- **Advantage:** Structs provide more clarity and context than simple collections like tuples, as each piece of data is tied to a descriptive name.
    

### II. Types of Structs

Rust supports three types of structs, each with a different syntax for defining and accessing fields:

1. **Named-Field Structs:**
    
    - **Description:** The most common type. Each field has a name and a type.
        
    - **Definition Syntax:** Uses `struct` keyword, a `PascalCase` name, and curly braces `{}` containing `field_name: Type, ...`.
        
    - **Advantage:** Order of fields is irrelevant, and field names provide excellent readability.
        
2. **Tuple-Like Structs:**
    
    - **Description:** Assigns a position/order to each field rather than a name.
        
    - **Definition Syntax:** Uses `struct` keyword, `PascalCase` name, and parentheses `()` containing `Type, Type, ...`.
        
    - **Access:** Fields are accessed by their numerical index (`.0`, `.1`, etc.).
        
    - **Advantage:** Provides a distinct new type that is not interchangeable with a regular tuple, even if the fields and order are the same. This is useful for type safety.
        
3. **Unit-Like Structs:**
    
    - **Description:** A struct with no fields.
        
    - **Definition Syntax:** Uses `struct` keyword, `PascalCase` name, and a semicolon `;`.
        
    - **Purpose:** Used when you need to define a new type for which you can still implement traits or methods, but which has no data of its own.
        

### III. Structs: From Blueprint to Instance

- **Blueprint (`struct` definition):** The `struct` keyword and definition create a **template** for a new type, but no actual data exists yet.
    
- **Instance (concrete value):** An instance is a realized, concrete struct value. You create one by providing actual data for all the fields in the blueprint.
    

#### A. Creating a Named-Field Struct Instance

- **Syntax:** `let instance_name = StructName { field: value, ... };`
    
- **Rules:**
    
    - **Provide All Fields:** You must provide a concrete value for every field defined in the `struct`.
        
    - **Correct Types:** Each value must match its corresponding field's data type.
        
    - **Order is Irrelevant:** You can list the fields in any order.
        

#### B. Shortcuts for Instantiation

- **Field Init Shorthand:** If a variable name in the current scope matches a struct field name, you can simplify `field: field` to just `field`.
    
- **Struct Update Syntax (`..`):** The double-dot syntax `..` allows you to create a new struct instance based on an existing one, copying over all its remaining fields. You can override specific fields by defining them before the `..` syntax.
    
    - **Ownership Rules Apply:**
        
        - For **`Copy` types** (e.g., integers), a full copy is made.
            
        - For **non-`Copy` types** (e.g., `String`), ownership of the field's value is **moved** from the old struct to the new one, invalidating that field in the original struct. To prevent this, you would need to manually `clone()` the field's value.
            

### IV. Accessing Fields and Ownership

- **Access:** Use **dot notation** (`instance_name.field_name`) to read or get the value of a specific field.
    
- **Ownership Hierarchy:** A struct instance is the owner of its fields, and each field is the owner of its value.
    
- **Move Semantics with Fields:** This is a crucial detail.
    
    - When you access a field whose type implements `Copy` (e.g., `i32`), a copy of the value is made, and the original field remains valid.
        
    - When you access a field whose type **does not implement `Copy`** (e.g., `String`) and assign it to a new variable (`let var = my_struct.string_field;`), **ownership of that specific field's value is moved**. The field within the struct becomes invalid. As a result, the entire original struct instance is considered "partially moved" and cannot be used in contexts that rely on the moved field.
        

### V. Struct Behaviors: Methods and Associated Functions

- **Methods:** Functions that are attached to a `struct` instance. They define the behaviors, actions, or commands that a specific instance can perform.
    
    - **Declaration:** Methods are defined in an `impl` block (`impl StructName { ... }`).
        
    - **Syntax:** Methods are just functions, but they **always have a first parameter called `self`**.
        
    - **`self` Parameter:** `self` represents the `struct` instance that the method is being called on. It can be passed in different ways, dictating the method's permissions:
        
        - `self`: Takes **ownership** of the instance (a move). The instance is consumed by the method.
            
        - `&self`: Takes an **immutable reference** to the instance (a shared borrow). Allows reading data but no mutation. This is the most common option.
            
        - `&mut self`: Takes a **mutable reference** to the instance (an exclusive borrow). Allows reading and modifying the instance.
            
        - `mut self`: Takes **mutable ownership** of the instance.
            
    - **Invocation:** `instance.method_name(args);` (Rust automatically handles passing the correct form of `self`).
        
- **Associated Functions:**
    
    - **Definition:** Functions that are defined within an `impl` block but **do not take `self` as a parameter**. They are associated with the _struct type itself_, not a specific instance.
        
    - **Invocation:** `StructName::associated_function_name(args);` (uses double-colons `::`).
        
    - **Common Use Case:** Constructors, which are functions that create and return a new instance of the struct (e.g., `String::from()`, `String::new()`). By convention, these are often named `new()`.
        

### VI. The `Debug` Trait and Printing Structs

- **Default Behavior:** By default, you cannot print a `struct` instance using `println!` with the `{}` or `{:?}` formatters because structs do not automatically implement the `Display` or `Debug` traits.
    
- **Derive Macro (`#[derive(Debug)]`):** This attribute, placed above the `struct` definition, instructs the compiler to automatically generate a default implementation of the `Debug` trait for that struct.
    
- **Printing with Debug:** With `Debug` implemented, you can print a struct using the `{:?}` (standard) or `{:#?}` (pretty-print) format specifiers. This output typically includes the struct's name and all its field names and values, making it ideal for debugging.
    

### VII. Key Takeaways

- **Structs for Complex Types:** Use structs to create new, meaningful data types that bundle related data.
    
- **`struct` vs. Instance:** A struct is a blueprint; an instance is the concrete value.
    
- **Ownership Rules:** Ownership applies hierarchically to structs and their fields. Be mindful of `Move` semantics when accessing non-`Copy` fields. Use `&` to borrow a field or `clone()` to explicitly duplicate it when a move is not desired.
    
- **Methods for Behavior:** `impl` blocks define methods (which take `self` as a parameter) to give structs actions and a consistent interface.
    
- **Associated Functions for Constructors:** Use `StructName::function()` syntax for type-level functions, most often for creating new instances.
    
- **`#[derive(Debug)]`:** A simple way to get a readable, default print-out of your structs for debugging purposes.
    
- **Modeling the World:** Structs are your first real tool for modeling real-world concepts (like a `Coffee` or a `User`) in a structured and organized way in Rust.
