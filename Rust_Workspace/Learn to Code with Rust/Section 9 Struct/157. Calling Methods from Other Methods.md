## Rust Structs: Calling Methods from Other Methods

This study guide explains the idiomatic practice of having a method invoke another method on the same struct instance. This technique is a key part of writing clean, organized, and reusable code in Rust.

### I. The Rationale for Calling Methods from Other Methods

- **Single Responsibility Principle:** A core programming principle suggests that each method or function should have a single, clearly defined responsibility.
    
- **Code Reusability:** If a piece of logic (e.g., a calculation) is needed in multiple places, it's better to isolate it into its own method.
    
- **Code Organization and Decoupling:** By breaking down complex tasks into a series of smaller, single-purpose methods, your code becomes easier to read, understand, and maintain. If the logic for a specific operation needs to change, you only have to update it in one place (the small, dedicated method).
    

### II. Syntax for Calling an Internal Method

Within a method's body, you can invoke another method on the same instance using the `self` parameter.

- **Syntax:** `self.other_method_name(arguments)`
    
- **The `self` Parameter:** You must use the `self` parameter (or `&self`, `&mut self`) to access the other method. This is because the method you are calling is associated with the `struct` instance itself.
    
- **Arguments:** If the method you are calling accepts any additional parameters (beyond its own `self`), you must pass the corresponding arguments in the parentheses `()`.
    

### III. Example: `years_since_release` and `display_song_info`

Let's use the `TaylorSwiftSong` struct to demonstrate this. The goal is to calculate the years since a song was released in a separate, reusable method and then call that method from a method that displays all the song's information.

Rust

```Rust
#[derive(Debug)]
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

impl TaylorSwiftSong {
    // This is the new, small helper method.
    // It's a read-only calculation, so it takes an immutable reference `&self`.
    fn years_since_release(&self) -> u32 {
        // We get the current year (2025) and subtract the song's release year.
        // `self` represents the instance we are on, so we can access its fields.
        let current_year = 2025;
        current_year - self.release_year
    }

    // This method displays information about the song.
    // It also takes an immutable reference `&self` as it only reads data.
    fn display_song_info(&self) {
        println!("Title: {}", self.title);

        // --- Calling a method from within this method's body ---
        // We use `self.` to access the helper method on the same instance.
        // `self.years_since_release()` returns a u32, which is then interpolated here.
        println!("Years since Release: {}", self.years_since_release());

        println!("Duration: {} seconds", self.duration_secs);
    }
}

fn main() {
    let blank_space = TaylorSwiftSong {
        title: String::from("Blank Space"),
        release_year: 2014,
        duration_secs: 231,
    };

    // We only need to call `display_song_info`.
    // It handles the internal call to `years_since_release` for us.
    blank_space.display_song_info();
}
```

**Output:**

```Rust
Title: Blank Space
Years since Release: 11
Duration: 231 seconds
```

**Step-by-Step Execution:**

1. `blank_space.display_song_info()` is called. `&blank_space` is passed as `self`.
    
2. Inside `display_song_info`, the first `println!` executes.
    
3. The second `println!` is encountered. Its dynamic value comes from the expression `self.years_since_release()`.
    
4. The method `years_since_release` is invoked on the same `blank_space` instance.
    
5. `years_since_release` performs its calculation (`2025 - 2014`) and returns the `u32` value `11`.
    
6. The `println!` in `display_song_info` receives `11` and prints it.
    
7. The final `println!` in `display_song_info` executes, and the method completes.
    

### IV. Ownership and Method Chaining

- **No `self` Argument in Invocation:** The invocation `self.other_method()` does not require you to explicitly pass `self` in the parentheses. Rust automatically provides `&self` or `&mut self` as the first argument, depending on the signature of the `other_method`.
    
- **Borrowing Rules Apply:** If the helper method takes a mutable reference (`&mut self`), the outer method must also take a mutable reference (`&mut self`) and the original variable must be mutable. For example, if `years_since_release` needed to modify `self`, `display_song_info` would also need to take `&mut self`.
    
- **The Benefit of `&self`:** In our example, both methods take `&self` (immutable reference). This is efficient and allows for powerful and clean method chaining without any ownership transfers. The `blank_space` variable remains the owner and is still valid after the method call.
    

### V. Key Takeaways

- **Method Reusability:** Methods are designed to be invoked from other methods on the same instance.
    
- **Clean Code:** This promotes a modular design where methods are kept small, focused, and decoupled from each other.
    
- **Readability:** A method like `display_song_info` becomes much clearer, as it shows what it does at a high level (`display some info`) without cluttering its body with low-level details (like the calculation for `years_since_release`).
    
- **Treat it Like a Function:** Calling `self.other_method()` is conceptually no different from calling a regular function, except that the method implicitly receives the instance's data via `self`.
