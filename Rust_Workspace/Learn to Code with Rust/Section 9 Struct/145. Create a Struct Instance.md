## Rust Structs: Creating a Struct Instance

This study guide explains how to create concrete values (instances) from a `struct` definition in Rust. A `struct` definition acts as a blueprint, and creating an instance means bringing that blueprint to life with actual data.

### 1. Review: Structs as Blueprints

- **Struct Definition:** In Rust, a `struct` (short for "structure") is a custom data type that allows you to group related pieces of data (fields) together under a single name. It defines the _shape_ and _types_ of the data that will belong to that custom type.
    
- **Blueprint Analogy:** Think of a `struct` definition (e.g., `struct Coffee { ... }`) as a **blueprint** or a **template**. It tells Rust what kind of information a `Coffee` _should_ contain (e.g., a `name`, a `price`, whether it `is_hot`), but it doesn't actually create any specific coffee item.
    

### 2. What is a Struct Instance?

- **Definition:** A **struct instance** is a concrete, realized value created from a `struct` blueprint. It contains actual data for all the fields defined in the `struct`.
    
- **Analogy:** If the `struct Coffee` definition is the blueprint for a coffee drink, then a specific "Mocha" coffee with a price of $4.99 and being hot is a `Coffee` instance.
    
- **Quantity:** You can create as many instances of a `struct` type as you want. Each instance is an independent value in memory.
    

### 3. Syntax for Creating a Struct Instance

To create a struct instance, you use a syntax similar to the `struct` definition itself, but you provide concrete values instead of types for each field.

**Basic Syntax:**

Rust

```Rust
let instance_name = StructName {
    field1: value1,
    field2: value2,
    // ... all defined fields ...
};
```

- `let instance_name`: Declares a variable to hold the new struct instance.
    
- `StructName`: The name of the `struct` type you are instantiating (e.g., `Coffee`).
    
- `{}`: A pair of curly braces, similar to the `struct` definition.
    
- `field: value`: Inside the curly braces, you list each field name followed by a colon `:` and the actual concrete value for that field.
    

### 4. Key Rules for Instantiating Structs

When creating a struct instance, the Rust compiler enforces strict rules to ensure the instance conforms to its blueprint:

1. **All Fields Must Be Provided:** You **must provide a value for every single field** defined in the `struct` blueprint. Omitting even one field will result in a compile-time error.
    
    - **Error Example:** "missing structure fields: `price`"
        
2. **Correct Field Types:** The value provided for each field **must match the data type specified in the `struct` definition**. Type mismatches will cause compilation errors.
    
    - **Error Example:** "mismatched types; expected `bool`, found integer"
        
3. **Order Does Not Matter:** Unlike arrays or tuples where order is crucial, the order in which you list the fields when creating a struct instance is **irrelevant**. Rust matches the values to the fields by their names.
    
    - **Benefit:** This makes structs very flexible and readable, as you don't have to remember a specific sequence of fields.
        
4. **Field Names Must Match:** The field names you use in the instance creation must exactly match the field names defined in the `struct`.
    

### 5. Step-by-Step Example: Creating a `Coffee` Instance

Let's assume we have the following `Coffee` struct definition:

Rust

```Rust
#[derive(Debug)] // Added for easy printing later
struct Coffee {
    name: String,
    price: f64,
    is_hot: bool,
}
```

Now, let's create instances:

Rust

```Rust
fn main() {
    // Creating the first Coffee instance: a "Mocha"
    let mocha = Coffee {
        name: String::from("Mocha"), // Field `name` gets String value "Mocha"
        price: 4.99,                 // Field `price` gets f64 value 4.99
        is_hot: true,                // Field `is_hot` gets bool value true
    }; // Semicolon needed here as it's a `let` statement

    println!("Created coffee: {:?}", mocha); // Output: Created coffee: Coffee { name: "Mocha", price: 4.99, is_hot: true }

    // Creating a second Coffee instance: an "Iced Latte"
    // Note: Fields are in a different order, which is perfectly valid.
    let iced_latte = Coffee {
        price: 3.50,
        name: String::from("Iced Latte"),
        is_hot: false,
    };
    println!("Created coffee: {:?}", iced_latte); // Output: Created coffee: Coffee { name: "Iced Latte", price: 3.5, is_hot: false }

    // --- Examples of Compile-Time Errors ---

    // 1. Missing a field:
    /*
    let missing_field = Coffee {
        name: String::from("Espresso"),
        is_hot: true,
        // ERROR: missing structure fields: `price`
    };
    */

    // 2. Mismatch in field type:
    /*
    let wrong_type = Coffee {
        name: String::from("Cappuccino"),
        price: 5.25,
        is_hot: 1, // ERROR: mismatched types; expected `bool`, found integer
    };
    */

    // 3. Extra field (not defined in struct):
    /*
    let extra_field = Coffee {
        name: String::from("Americano"),
        price: 3.00,
        is_hot: true,
        size: "large", // ERROR: field `size` is not in `Coffee`
    };
    */
}
```

### 6. Struct Instances and Ownership

- **Ownership:** When you create a struct instance, the variable (`mocha`, `iced_latte` in our example) becomes the **owner** of that entire struct instance.
    
- **Memory:**
    
    - If all fields within the struct are stack-allocated types (like `f64`, `bool`), the entire struct instance will primarily live on the **Stack**.
        
    - If any field within the struct is a heap-allocated type (like `String`), the struct itself (the `Coffee` variable) will primarily live on the **Stack**, but it will contain pointers to its heap-allocated data (e.g., the `String`'s actual text data will be on the **Heap**). The struct variable on the stack is considered the owner of its heap-allocated fields.
        
- **Cleanup:** When the struct instance variable goes out of scope, Rust automatically drops the entire struct. This involves recursively dropping any heap-allocated fields it owns (e.g., freeing the `String`'s text from the heap).
    

### 7. Key Takeaways

- A **struct instance** is a concrete value created from a `struct` blueprint.
    
- To create an instance, list all field names with their corresponding **concrete values** within curly braces.
    
- The Rust compiler strictly enforces that **all fields are provided** and their **types match** the `struct` definition.
    
- The **order of fields does not matter** when creating an instance.
    
- Struct instances are values that are managed by Rust's ownership system, with their memory handled automatically upon going out of scope.
