### Part 6: Summary of `self` Parameter Options and the Benefits of Methods

This study guide summarizes the four ways a method can receive the `self` parameter, which represents the struct instance. It also reinforces why methods are a fundamental tool for creating organized and reusable code in Rust.

#### 1. Summary of `self` Parameter Options

The `self` parameter's signature dictates how the method interacts with the struct instance and its ownership. There are four main options:

|Option|Syntax for `self`|Ownership/Borrowing|Mutability|Use Case|
|---|---|---|---|---|
|**Immutable Ownership**|`self`|**Moves** ownership|No (read-only)|Consumes the struct (e.g., `drink(self)`)|
|**Mutable Ownership**|`mut self`|**Moves** ownership|Yes (read-write)|Consumes and modifies the struct|
|**Immutable Reference**|`&self`|**Borrows** (read-only)|No (read-only)|Read-only access (Most common)|
|**Mutable Reference**|`&mut self`|**Borrows** (read-write)|Yes (read-write)|Read-write access|

- **Key Rule:** The `self` parameter is **required in the method definition** but is **never passed in the method invocation**. Rust automatically determines the correct value to pass based on the invocation context.
    

#### 2. The Relationship Between Methods and the Struct Instance

A method is a function whose sole responsibility is to work on the struct's data.

- **Owner of the Data:** The method receives the struct instance itself (or a reference to it) via the `self` parameter. It then uses dot notation (`self.field_name`) to access and work with the struct's internal fields.
    
- **No `self` in Invocation:** The invocation `song.display_song_info()` automatically provides the `song` instance as the `self` argument. The compiler handles this for you.
    

#### 3. The Power and Benefits of Struct Methods

- **Organization and Encapsulation:** Methods keep a struct's data and its associated behaviors together in a single conceptual unit. The `impl` block serves as a central place to define all the common functionality for that type.
    
- **Consistency:** Once a method is defined in an `impl` block, **every instance** of that struct type automatically has access to that method. This creates a reliable and consistent interface for your types.
    
- **Reusability:** You define the method once, and it can be called on any number of instances, avoiding repetitive code.
    

#### Example: Methods and `self` in Action

Rust

```Rust
// Our struct blueprint
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

// Our `impl` block with methods
impl TaylorSwiftSong {
    // This method is for read-only access (immutable reference).
    fn display_song_info(&self) {
        println!("Title: {}", self.title);
        println!("Release Year: {}", self.release_year);
        println!("Duration: {} seconds", self.duration_secs);
    }
    
    // This method is for read-write access (mutable reference).
    fn change_title(&mut self, new_title: String) {
        self.title = new_title;
    }
}

fn main() {
    // We create a mutable instance of our struct.
    let mut song = TaylorSwiftSong {
        title: String::from("Blank Space"),
        release_year: 2014,
        duration_secs: 231,
    };
    
    // We can call methods on it using `.` syntax.
    // Rust automatically provides `&song` as the `self` argument.
    song.display_song_info();

    // We can call a mutable method.
    // Rust automatically provides `&mut song` as the `self` argument.
    song.change_title(String::from("Shake It Off"));

    // Since these methods use references, `song` is still a valid owner here.
    song.display_song_info(); // The changes from `change_title` are now visible.
}
```
