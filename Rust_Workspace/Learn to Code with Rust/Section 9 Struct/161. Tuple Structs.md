### Part 1: Defining and Instantiating Tuple Structs

This guide explains the syntax for defining and using a **tuple-like struct** (or "tuple struct"). These structs are a way to create a new, distinct type from a collection of fields that are ordered by position rather than having a name.

- **Declaration Syntax:** You use the `struct` keyword, followed by the name of your new type, and then a tuple of the field types.
    
- **Instantiation Syntax:** To create an instance, you use the struct's name followed by a tuple of concrete values.
    
- **Accessing Fields:** Fields are accessed by their zero-based index using dot notation (`.0`, `.1`, etc.).
    

Rust

```Rust
// A tuple struct to model a short duration of time (hours, minutes).
struct ShortDuration(u32, u32);

// Another tuple struct to model a long duration (years, months).
// Note: It has the same field types as `ShortDuration`, but is a completely different type.
struct LongDuration(u32, u32);

fn main() {
    // Instantiating a `ShortDuration` struct.
    let work_shift = ShortDuration(8, 0); // 8 hours, 0 minutes.

    // Instantiating a `LongDuration` struct.
    let era = LongDuration(5, 3); // 5 years, 3 months.

    // Accessing fields by their index position, starting from zero.
    println!("Work shift is {} hours and {} minutes.", work_shift.0, work_shift.1);
    println!("An era is {} years and {} months.", era.0, era.1);
}
```

### Part 2: The Problem with Plain Tuples (Type Ambiguity)

This part demonstrates the core problem that tuple structs solve. When using regular tuples, the compiler cannot distinguish between different concepts if they have the same data types and order.

- **The Problem:** The compiler treats a `(u32, u32)` tuple meant for a work shift as the exact same type as a `(u32, u32)` tuple meant for an era. This can lead to subtle bugs where the wrong kind of data is passed to a function, and the compiler fails to catch the error.
    

Rust

```Rust
// This function expects a duration as a regular tuple.
// Note: It's defined to take a `(u32, u32)` tuple.
fn go_to_work_plain_tuple(length: (u32, u32)) {
    println!("Passing time: {} hours and {} minutes.", length.0, length.1);
}

fn main() {
    // We define two concepts using regular tuples.
    let work_shift_tuple = (8, 0); // Represents a work shift
    let era_tuple = (5, 3);        // Represents an era

    // Passing the work shift is a valid use case.
    go_to_work_plain_tuple(work_shift_tuple); // Output: Passing time: 8 hours and 0 minutes.

    // This is a logical error in our program, but the compiler sees no type mismatch.
    // Both tuples have the type `(u32, u32)`, so this call is also allowed.
    go_to_work_plain_tuple(era_tuple); // Output: Passing time: 5 hours and 3 minutes.
}
```

### Part 3: The Solution: Type Safety with Tuple Structs

This part shows how using named tuple structs solves the problem from Part 2. By giving the type a unique name, you provide the compiler with a way to enforce that only the correct kind of data is passed to a function.

- **The Solution:** Named tuple structs create new, distinct types. A `ShortDuration` is not the same type as a `LongDuration`, even if they contain the same data types.
    
- **The Advantage:** This allows the compiler to catch logical errors at compile time, preventing invalid data from being used in the wrong context.
    

Rust

```Rust
// The same tuple structs from Part 1.
struct ShortDuration(u32, u32);
struct LongDuration(u32, u32);

// This function now expects a specific tuple struct type.
fn go_to_work_with_struct(length: ShortDuration) {
    println!("Passing time: {} hours and {} minutes.", length.0, length.1);
}

fn main() {
    let work_shift_struct = ShortDuration(8, 0); // A `ShortDuration` tuple struct
    let era_struct = LongDuration(5, 3);        // A `LongDuration` tuple struct

    // This is a valid call: we are passing a `ShortDuration` where one is expected.
    go_to_work_with_struct(work_shift_struct); // Output: Passing time: 8 hours and 0 minutes.

    // This call would cause a compile-time error!
    // The compiler correctly identifies that `era_struct` is a `LongDuration`,
    // which is not the expected type.
    // go_to_work_with_struct(era_struct); // ERROR: expected `ShortDuration`, found `LongDuration`
}
```
