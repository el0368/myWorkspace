Here's a study guide covering the essential topics related to structs in Rust.

### Defining, Instantiating, and Using Structs 📦

A **struct** (or structure) is a custom data type that lets you group together related values of different types into a single, meaningful unit.

- **Defining a Struct:** Use the `struct` keyword followed by the name (in `PascalCase`) and the fields with their types in curly braces.
    

    
    ```Rust
    struct User {
        username: String,
        email: String,
        active: bool,
    }
    ```
    
- **Instantiating a Struct:** Create an instance by specifying the concrete values for each field. The entire instance must be **mutable** to change any of its fields.
    

    
    ```Rust
    let mut user1 = User {
        email: String::from("user@example.com"),
        username: String::from("user123"),
        active: true,
    };
    // Reading and writing fields is done with dot notation.
    println!("Username is: {}", user1.username);
    user1.active = false;
    ```
    
- **Struct Update Syntax:** You can create a new instance using some of the values from an old instance with the `..` syntax.
    

    
    ```Rust
    let user2 = User {
        email: String::from("user2@example.com"),
        ..user1 // Fills `username` and `active` from user1
    };
    ```
    
- **Tuple Structs:** These are structs that look like tuples, used when you want a distinct type but the field names aren't important.
    

    
    ```Rust
    struct Color(i32, i32, i32);
    let black = Color(0, 0, 0);
    ```

### `impl` Blocks: Methods and Associated Functions ⚙️

The `impl` (implementation) block is where you define behavior associated with a struct.

- **Methods:** These are functions inside an `impl` block that operate on an instance of the struct. They always take a form of `self` as their first parameter.
    
- **The `self` Keyword:** Refers to the instance the method is being called on. There are three primary variations:
    
    1. **`&self`** (Immutable Borrow): The most common. Allows the method to **read** the instance's data but not change it.
        
    2. **`&mut self`** (Mutable Borrow): Allows the method to **read and modify** the instance's data.
        
    
    - **`self`** (Takes Ownership): The method takes full ownership of the instance, effectively consuming it. This is useful for converting one type into another.
        
- **Associated Functions:** These are functions inside an `impl` block that are associated with the struct but don't work on a specific instance (they don't take `self`). They are called using the `::` syntax. The most common associated function is `new`, which acts as a constructor.
    
```rust
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    // A method that reads data (`&self`) and takes another parameter.
    fn area(&self) -> u32 {
        self.width * self.height
    }
    
    // An associated function (constructor)
    fn new(width: u32, height: u32) -> Self {
        Self { width, height }
    }
}

fn main() {
    // Using the new() associated function to create a Rectangle
    let rect1 = Rectangle::new(10, 20);
    let rect2 = Rectangle::new(5, 8);
    
    // Using the rectangles
    println!("Rectangle 1 - Width: {}, Height: {}", rect1.width, rect1.height);
    println!("Rectangle 1 area: {}", rect1.area());
    
    println!("Rectangle 2 - Width: {}, Height: {}", rect2.width, rect2.height);
    println!("Rectangle 2 area: {}", rect2.area());
    
    // You can also create rectangles the traditional way
    let rect3 = Rectangle { width: 15, height: 10 };
    println!("Rectangle 3 area: {}", rect3.area());
}
```

### Structs with Functions and Traits 🤝

- **Passing Structs as Arguments:** By default, passing a struct to a function moves its ownership. It's more common to pass a reference (`&` or `&mut`) to borrow it instead.
    
- **Deriving `Debug`:** To easily print a struct for debugging, add the `#[derive(Debug)]` attribute. This automatically implements the `Debug` trait, allowing you to print the struct using the `{:?}` or `{:#?}` (pretty-print) format specifier.
    


```Rust
#[derive(Debug)] // <-- Allows this struct to be printed for debugging
struct Point {
    x: i32,
    y: i32,
}

// This function borrows a Point to avoid taking ownership.
fn display_point(p: &Point) {
    println!("{:#?}", p); // Pretty-print debug format
}

fn main() {
    let point1 = Point { x: 10, y: 20 };
    
    // BORROWING: We pass a reference (&point1) instead of moving point1
    display_point(&point1);
    
    // We can still use point1 after the function call because we borrowed it
    println!("Point1 is still accessible: x={}, y={}", point1.x, point1.y);
    
    // We can call display_point multiple times with the same point
    display_point(&point1);
    display_point(&point1);
    
    // Let's compare different debug formatting options:
    println!("Regular debug: {:?}", point1);      // Compact format
    println!("Pretty debug: {:#?}", point1);     // Pretty format (what display_point uses)
    
    // Example of what would happen if we took ownership instead:
    let point2 = Point { x: 5, y: 15 };
    take_ownership(point2); // This MOVES point2 into the function
    // println!("{:?}", point2); // <-- This would cause a compile error!
    
    // But with borrowing, we can keep using our data:
    let point3 = Point { x: 100, y: 200 };
    borrow_point(&point3);
    println!("point3 is still usable: {:?}", point3); // This works fine!
}

// Function that takes ownership (moves the value)
fn take_ownership(p: Point) {
    println!("Took ownership of: {:?}", p);
    // p is dropped when this function ends
}

// Function that borrows (doesn't take ownership)
fn borrow_point(p: &Point) {
    println!("Borrowed point: {:?}", p);
    // p reference goes out of scope, but the original Point is still owned by caller
}
```

### The Builder Pattern 🏗️

The **Builder Pattern** is a design pattern used to construct complex objects, especially those with many optional fields. Instead of a single `new` function with lots of parameters, you create a `Builder` struct that allows you to set fields step-by-step and then finally build the object. This makes the code more readable and manageable.
