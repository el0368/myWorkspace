Here are Rust code examples illustrating the concepts of defining and invoking methods on a struct, based on your review. Each example is separated for clarity, demonstrating the different `self` parameter options and their implications.

---

### 1. The Struct Blueprint and an `impl` Block

This example sets up the basic structure for a named-field struct and its associated methods.


```Rust
// The struct blueprint for a Taylor Swift song.
#[derive(Debug, Clone)] // `Clone` is for later examples. `Debug` is for printing.
struct TaylorSwiftSong {
    title: String,
    release_year: u32,
    duration_secs: u32,
}

// The `impl` block, short for implementation, where methods are defined.
// Everything inside this block is associated with the `TaylorSwiftSong` struct.
impl TaylorSwiftSong {
    // An associated function (not a method) that acts as a constructor.
    // It does not take `self` but returns an instance of `Self`.
    fn new(title: String, release_year: u32, duration_secs: u32) -> Self {
        Self { title, release_year, duration_secs }
    }
}

fn main() {
    // This part will be filled in by the following examples.
}
```

### 2. Method with Immutable Ownership (`self`)

This method takes full ownership of the struct instance. The original variable is consumed (moved) and becomes invalid after the method call.


```Rust
// Using the same struct definition and `new` function from the previous example.
// ...

impl TaylorSwiftSong {
    // This `self` signature takes immutable ownership.
    fn display_song_info(self) {
        println!("Title: {}", self.title);
        println!("Release Year: {}", self.release_year);
        println!("Duration: {} seconds", self.duration_secs);
    }
}

fn main() {
    let song = TaylorSwiftSong::new(String::from("Blank Space"), 2014, 231);

    // Invoking the method on `song`. Ownership of the instance MOVES here.
    song.display_song_info();

    // This line would cause a compile-time error!
    // `song` is no longer the owner, as ownership was moved into the method.
    // println!("The song's title is: {}", song.title); // ERROR: borrow of moved value: `song`
}
```

---

### 3. Method with Immutable Reference (`&self`)

This is the most common method signature. It takes an immutable reference (a borrow) to the struct. The original variable remains valid and can be used after the method call.


```Rust
// Using the same struct definition and `new` function from the previous example.
// ...

impl TaylorSwiftSong {
    // This `&self` signature takes an immutable reference (a borrow).
    fn get_title(&self) -> &String {
        &self.title // Returns a reference to the `title` field.
    }
    
    // This is the same `display_song_info` method, refactored to borrow.
    fn display_song_info_by_ref(&self) {
        println!("Title: {}", self.title);
        println!("Release Year: {}", self.release_year);
        println!("Duration: {} seconds", self.duration_secs);
    }
}

fn main() {
    let song = TaylorSwiftSong::new(String::from("Blank Space"), 2014, 231);

    // Invoking the method on `song`. `&self` is automatically passed.
    // Ownership of `song` is NOT moved.
    song.display_song_info_by_ref();

    // `song` is still a valid owner and can be used afterward.
    println!("The song's title is: {}", song.title);
}
```

---

### 4. Method with Mutable Reference (`&mut self`)

This method takes a mutable reference (a mutable borrow). The original variable must be `mut` to allow this borrow, but it remains the owner and is modified in place.


```Rust
// Using the same struct definition and `new` function from the previous example.
// ...

impl TaylorSwiftSong {
    // This `&mut self` signature takes a mutable reference.
    fn change_duration(&mut self, new_duration: u32) {
        self.duration_secs = new_duration;
    }
}

fn main() {
    // The original instance must be mutable to allow a mutable reference.
    let mut song = TaylorSwiftSong::new(String::from("Blank Space"), 2014, 231);

    println!("Original duration: {}", song.duration_secs);

    // Invoking the method on `song`. `&mut self` is automatically passed.
    // Ownership of `song` is NOT moved, but its duration is modified.
    song.change_duration(250);

    // `song` is still valid and its field has been modified.
    println!("New duration: {}", song.duration_secs);
}
```

---

### 5. Method with Mutable Ownership (`mut self`)

This method also takes full ownership, just like `self` alone, but it also has permission to modify the struct before it is consumed.


```Rust
// Using the same struct definition and `new` function from the previous example.
// ...

impl TaylorSwiftSong {
    // This `mut self` signature takes mutable ownership.
    fn change_title_and_consume(mut self, new_title: String) {
        self.title = new_title;
        println!("Consumed song with new title: {}", self.title);
    }
}

fn main() {
    // The original instance must be mutable to allow a mutable ownership transfer.
    let mut song = TaylorSwiftSong::new(String::from("Blank Space"), 2014, 231);

    // Invoking the method on `song`. Ownership of the instance MOVES here.
    song.change_title_and_consume(String::from("Shake It Off"));

    // This would fail, as `song`'s ownership was moved.
    // println!("The song is: {}", song.title); // ERROR: borrow of moved value: `song`
}
```
