### In-Depth Study Guide: Mutable Array Slices (`&mut [T]`)

This guide explains how to create and use mutable slices to modify portions of an array, and how this feature interacts with Rust's ownership and borrowing rules.

---

### 1. Introduction to Mutable Slices

A **mutable array slice** (type `&mut [T]`) is a mutable reference to a contiguous sequence of elements within an array. Its key capability is that it allows you to **modify the elements of the original array** directly through the slice "view."

#### Crucial Distinction: Array Slices vs. String Slices

- Rust **does not** permit mutable string slices (`&mut str`). The internal structure of a `String` is complex, and allowing partial mutation could break UTF-8 invariants.
    
- Rust **does** permit mutable array slices (`&mut [T]`). Because arrays contain discrete, independent elements, modifying one element does not affect the validity of others.
    

---

### 2. Prerequisites and Syntax

To create and use a mutable slice, two conditions must be met:

1. The original array must be declared as **mutable** (using `let mut`). The owner must grant permission for its data to be changed.
    
2. You must create a **mutable borrow** using the `&mut` syntax.
    

The full syntax is a combination of what we've learned about mutable references and slicing:

`let my_slice = &mut my_array[range];`

- **`&mut`**: Creates a mutable reference (a mutable borrow).
    
- **`my_array`**: The source mutable array.
    
- **`[range]`**: The range of element indices to include in the slice.
    

---

### 3. Practical Example: Modifying an Array via a Slice

This example from the transcript demonstrates how changing an element in the slice directly affects the original array.

Rust

```Rust
fn main() {
    // 1. The original array MUST be mutable.
    let mut my_array = [10, 15, 20, 25, 30];
    println!("Original array before: {:?}", my_array);

    // 2. Create a mutable slice of a portion of the array (indices 2 and 3).
    let my_slice: &mut [i32] = &mut my_array[2..4];
    println!("Slice before modification: {:?}", my_slice); // Prints [20, 25]

    // 3. Modify an element OF THE SLICE.
    // Index 0 of the slice corresponds to index 2 of the original array.
    my_slice[0] = 100;

    println!("Slice after modification:  {:?}", my_slice); // Prints [100, 25]

    // 4. Observe that the ORIGINAL array has been changed.
    println!("Original array after:  {:?}", my_array); // Prints [10, 15, 100, 25, 30]
}
```

The mutable slice `my_slice` doesn't own the data, but it has borrowed the right to change it. When it modifies its element at index `0`, it's directly changing the value at index `2` in `my_array`.

---

### 4. Ownership and Borrowing Rules in Action

A mutable slice is a type of mutable borrow, and therefore it follows Rust's strict "one writer" rule. While a mutable slice is active, you cannot have any other borrows (mutable or immutable) of the original data.

The compiler will prevent you from reading or writing to the original array while a mutable slice of it exists.

#### Example of a Borrowing Error

Rust

```Rust
fn main() {
    let mut my_array = [10, 15, 20, 25, 30];

    // We create a mutable slice. This places a "lock" on `my_array`.
    let my_slice = &mut my_array[2..4];

    // ERROR: This line will not compile.
    // We cannot immutably borrow `my_array` to print it, because `my_slice`
    // currently holds a mutable borrow.
    // println!("Original array while slice is active: {:?}", my_array);

    // To fix this, we must use the mutable slice first, which ends its lifetime.
    my_slice[0] = 100;
    println!("Slice has been used: {:?}", my_slice);

    // NOW it's okay to use `my_array` again, because the mutable borrow's
    // lifetime is over.
    println!("Original array can now be accessed: {:?}", my_array);
}
```

This demonstrates how the borrow checker guarantees that you can't read from the array while a part of it could be changing, thus preventing data races.
