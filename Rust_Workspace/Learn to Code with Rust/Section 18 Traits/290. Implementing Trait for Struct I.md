Now that we have our `Accommodation` trait defined, let’s create our first concrete type that will implement it.

A natural example of an accommodation in the real world is a **hotel**. A hotel has the distinguishing quality of being a place where people can stay overnight. So, let’s model that in code.

### Step 1: Defining the `Hotel` struct

We’ll start by creating a new struct called `Hotel`. This struct will have two fields:

1. **`name`** – a `String` to hold the name of the hotel.
    
2. **`reservations`** – a data structure to track who has booked the hotel and how many nights they’re staying. For this, we’ll use a `HashMap`.
    

Since `HashMap` lives in Rust’s standard library under the `collections` module, we need to import it first:

```rust
use std::collections::HashMap;

#[derive(Debug)]
struct Hotel {
    name: String,
    reservations: HashMap<String, u32>,
}
```

- The **keys** in the `HashMap` will be guest names (`String`).
    
- The **values** will be the number of nights they are staying (`u32`).
    

So, for example, a booking might look like `("Dave".to_string(), 5)`, meaning Dave is staying for 5 nights.

Notice we’ve also derived the `Debug` trait with `#[derive(Debug)]`. This allows us to quickly print hotel instances for debugging. Behind the scenes, this is actually Rust implementing the `Debug` trait for us automatically.

### Step 3: Implementing the `Accommodation` Trait

To link the `Hotel` struct with the `Accommodation` trait, we write an `impl` block that specifies both the trait name and the type:

```rust
impl Accommodation for Hotel {
    fn get_description(&self) -> String {
        format!("{} is the pinnacle of luxury!", self.name)
    }

    fn book(&mut self, name: &str, nights: u32) {
        self.reservations.insert(name.to_string(), nights);
    }
}
```

- **`get_description`**:  
    Returns a `String` describing the hotel. In this case, we just return a sentence that includes the hotel’s name.
    
    - Notice the method signature matches the trait’s contract exactly: it takes `&self` and returns a `String`.
        
- **`book`**:  
    Takes a guest’s name and number of nights, then inserts them into the `reservations` map.
    
    - Here we use `&mut self` because modifying the reservations changes the hotel’s internal state.
        
    - The trait required this method signature, so we’re simply filling in the implementation details.

### Key Insight

The beauty of traits is that the `Accommodation` trait doesn’t care _how_ `Hotel` stores its reservations.

- For `Hotel`, we chose a `HashMap`.
    
- Another type (say, `Airbnb`) might use a completely different data structure.  
    But both will still conform to the same `Accommodation` contract by providing the required methods.
    

This is the power of traits: they enforce consistency while leaving the implementation details flexible for each type.
