# Default Implementations - Simple Analogy

## Think of it like a **Recipe Book Contract**

Imagine you're creating a "Recipe Book" contract that all chefs must follow:

### Without Default Implementation (Old Way)

```rust
trait Chef {
    fn cook_main_dish(&self);     // Every chef MUST define this
    fn make_dessert(&self);       // Every chef MUST define this  
    fn greet_customers(&self);    // Every chef MUST define this
}
```

**Problem**: Every chef has to write their own greeting, even though most greetings are similar.

### With Default Implementation (Better Way)

```rust
trait Chef {
    fn cook_main_dish(&self);     // REQUIRED - every chef cooks differently
    fn make_dessert(&self);       // REQUIRED - desserts vary a lot
    
    // DEFAULT - most chefs can use this standard greeting
    fn greet_customers(&self) {
        println!("Welcome to our restaurant! Enjoy your meal!");
    }
}
```

## How It Works

### Chef A (Uses the Default)

```rust
struct ItalianChef;

impl Chef for ItalianChef {
    fn cook_main_dish(&self) {
        println!("Making pasta!");
    }
    
    fn make_dessert(&self) {
        println!("Making tiramisu!");
    }
    
    // NO greet_customers - uses the default greeting
}
```

### Chef B (Overrides the Default)

```rust
struct FrenchChef;

impl Chef for FrenchChef {
    fn cook_main_dish(&self) {
        println!("Making coq au vin!");
    }
    
    fn make_dessert(&self) {
        println!("Making crème brûlée!");
    }
    
    // Custom greeting - overrides the default
    fn greet_customers(&self) {
        println!("Bonjour! Welcome to ze finest French cuisine!");
    }
}
```

## What Happens When You Call Them

```rust
fn main() {
    let italian = ItalianChef;
    let french = FrenchChef;
    
    italian.greet_customers();  
    // Uses DEFAULT: "Welcome to our restaurant! Enjoy your meal!"
    
    french.greet_customers();   
    // Uses CUSTOM: "Bonjour! Welcome to ze finest French cuisine!"
}
```

## The Simple Rule

- **Default implementation** = "Here's a standard way to do it, but you can customize if you want"
- **No default** = "You MUST write your own version"

It's like having a **template** that you can use as-is or customize to fit your needs!

**Default = Optional Override** **No Default = Mandatory Implementation**
