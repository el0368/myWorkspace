# Study guide: calling trait-mandated methods from other methods (with progressive code)

## 1) Set up: a trait with a default method

We’ll give `get_description` a default body so types may opt out of defining it, while `book` must be implemented.

```rust
use std::collections::HashMap;

trait Accommodation {
    // Default (fallback) implementation:
    fn get_description(&self) -> String {
        String::from("A wonderful place to stay.")
    }

    // Must be implemented by each type:
    fn book(&mut self, guest: &str, nights: u32);
}
```

---

## 2) A concrete type (`Hotel`) with its own methods

Define an _inherent_ `impl` block for methods that belong to `Hotel` itself (not tied to any trait).  
Inside these methods you can freely call trait methods like `get_description` and `book` on `self`.

```rust
#[derive(Debug)]
struct Hotel {
    name: String,
    reservations: HashMap<String, u32>,
}

impl Hotel {
    fn new(name: &str) -> Self {
        Self {
            name: name.to_string(),
            reservations: HashMap::new(),
        }
    }

    /// Regular method (not part of any trait).
    /// Calls a trait-mandated method from within.
    fn summarize(&self) -> String {
        // This will call whichever `get_description` applies to `self`:
        // - the trait's default (if we don't override), or
        // - our custom trait impl (if we do override later).
        format!("{}: {}", self.name, self.get_description())
    }
}
```

> Why this works: within any method body you can use other methods available on the same receiver (`self`). Since `Hotel` implements `Accommodation` (below), `get_description` is in method resolution and can be called like any other method.

---

## 3) Implement the trait for the type (first pass: use default `get_description`)

Define a _trait impl_ block that provides the required `book`. We’ll omit `get_description` here so the default kicks in.

```rust
impl Accommodation for Hotel {
    fn book(&mut self, guest: &str, nights: u32) {
        self.reservations.insert(guest.to_string(), nights);
    }
}
```

Try it:

```rust
fn main() {
    let mut hotel = Hotel::new("The Luxe");

    // Call a regular method that internally calls a trait method.
    println!("{}", hotel.summarize()); // uses the trait's default get_description

    // Mutating call to a trait method:
    hotel.book("Piers", 2);
    println!("{:#?}", hotel);
}
```

**Output (conceptually):**

```
The Luxe: A wonderful place to stay.
Hotel {
    name: "The Luxe",
    reservations: {
        "Piers": 2,
    },
}
```

Key point: `summarize()` called `self.get_description()`, which resolved to the **trait default** because we didn’t override it.

---

## 4) Override the trait method and see resolution change

Now add a custom `get_description` **in the trait impl**. Nothing else changes—`summarize()` still calls `self.get_description()`, but method resolution will now use our override.

```rust
impl Accommodation for Hotel {
    fn get_description(&self) -> String {
        format!("{} is the pinnacle of luxury.", self.name)
    }

    fn book(&mut self, guest: &str, nights: u32) {
        self.reservations.insert(guest.to_string(), nights);
    }
}
```

Running `main` again yields (conceptually):

```
The Luxe: The Luxe is the pinnacle of luxury.
...
```

So: **default if no override; your override if present.**

---

## 5) Where to put which methods (and a common compiler error)

- **Inherent methods** (your own extras like `summarize`, constructors like `new`) belong in `impl Hotel { ... }`.
    
- **Trait methods** must be defined only inside `impl Accommodation for Hotel { ... }`, and you may define _exactly_ those required by the trait (plus any with defaults if you choose to override).
    

If you try to define an extra method inside the trait-impl block:

```rust
impl Accommodation for Hotel {
    // ❌ Not allowed: 'summarize' is not part of the 'Accommodation' trait
    fn summarize(&self) -> String {
        format!("{}: {}", self.name, self.get_description())
    }

    fn book(&mut self, guest: &str, nights: u32) { /* ... */ }
}
```

You’ll get an error like: _method `summarize` is not a member of trait `Accommodation`_.

---

## 6) You can’t “chain” the default + your override

Rust doesn’t provide a built-in “super call” to the trait’s default body once you override it. That is, you cannot do “call the default, then add extra text”. Inside your override:

```rust
impl Accommodation for Hotel {
    fn get_description(&self) -> String {
        // There is NO way to call the default `Accommodation::get_description` here.
        // You must fully replace behavior yourself.
        format!("{} is the pinnacle of luxury.", self.name)
    }

    fn book(&mut self, guest: &str, nights: u32) { /* ... */ }
}
```

> Note: Fully-qualified syntax like `<Hotel as Accommodation>::get_description(self)` still refers to _the trait method for this type_, i.e., your override if you defined one. It does **not** bypass to the default.

If you need to reuse default behavior and then extend it, reorganize your code (e.g., move the shared logic into a helper function) or design a separate “base” trait — but that’s beyond this lesson’s scope.

## 7) Progressive mini-exercises

### A) Verify default resolution

1. Comment out the custom `get_description` in the trait impl.
    
2. Run `main` and confirm `summarize()` prints the trait’s default text.
    
3. Restore the override and confirm `summarize()` now prints your custom text.
    

### B) Call a mutating trait method internally

Add an inherent method that books and then returns a summary:

```rust
impl Hotel {
    fn book_and_summarize(&mut self, guest: &str, nights: u32) -> String {
        // Call a trait-mandated mutating method from a regular method:
        self.book(guest, nights);
        self.summarize()
    }
}

fn main() {
    let mut hotel = Hotel::new("The Luxe");
    println!("{}", hotel.book_and_summarize("Piers", 3));
    println!("{:#?}", hotel);
}
```

---

### C) Add another type to confirm consistency (optional)

You can repeat the pattern with an `Airbnb` struct (different fields, different storage), implement `Accommodation`, and call `get_description`/`book` from that type’s own methods. The same rules apply: inherent methods go in `impl Airbnb`, and trait methods in `impl Accommodation for Airbnb`.

---

## 8) Summary (what to remember)

- **Call trait methods from within your own methods:** just use `self.method_name()`—Rust resolves to either the default body or your override.
    
- **Keep method placement clean:** extras in `impl Type {}`, trait items in `impl Trait for Type {}`.
    
- **Default vs override is exclusive:** you either use the default (omit override) or fully replace it (override). There’s no direct “default + extra” call path within the same trait.
