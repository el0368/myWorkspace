### Step 1: Defining the `Airbnb` struct

For this type, let’s call it `Airbnb`. Unlike a hotel, which has a name and a reservations map, an Airbnb has:

- A **host**: the name of the person renting out their property, stored as a `String`.
    
- A **guests** list: instead of a `HashMap`, we’ll store a `Vec` of tuples. Each tuple will hold two elements:
    
    1. The guest’s name (`String`)
        
    2. The number of nights they’re staying (`u32`)
        

This gives us:

```rust
#[derive(Debug)]
struct Airbnb {
    host: String,
    guests: Vec<(String, u32)>,
}
```

So we’ve chosen a very different internal representation compared to `Hotel`: a `Vec` instead of a `HashMap`. The important point is that both structs represent types of accommodations but manage their data in their own way.

### Step 3: Implementing the `Accommodation` Trait

Now let’s make `Airbnb` actually implement `Accommodation`. The syntax looks just like before:

```rust
impl Accommodation for Airbnb {
    fn get_description(&self) -> String {
        format!("Please enjoy {}'s apartment!", self.host)
    }

    fn book(&mut self, name: &str, nights: u32) {
        self.guests.push((name.to_string(), nights));
    }
}
```

- **`get_description`**: returns a friendly message using the host’s name.
    
- **`book`**: instead of inserting into a `HashMap`, we simply push a tuple into the vector.
    

Notice how the trait forces the **method signatures** to be identical to those in `Hotel`, but the **implementation details** are entirely up to us.

### Step 4: Comparing `Hotel` and `Airbnb`

Even though `Hotel` and `Airbnb` are completely different structs with different fields and data structures, they both implement the same `Accommodation` trait.

That means we can use them consistently:

```rust
fn main() {
    // A Hotel
    let mut hotel = Hotel::new("The Luxe");
    println!("{}", hotel.get_description());
    hotel.book("Piers", 5);
    println!("{:#?}", hotel);

    // An Airbnb
    let mut airbnb = Airbnb::new("Peter");
    println!("{}", airbnb.get_description());
    airbnb.book("Piers", 3);
    println!("{:#?}", airbnb);
}
```

```
    ],

```

Here’s the key insight:

- `Hotel` stores reservations in a `HashMap`.
    
- `Airbnb` stores guests in a `Vec` of tuples.
    
- But both expose the **same interface** (`get_description`, `book`) thanks to the trait.

### The Beauty of Traits

This demonstrates the real power of traits in Rust:

- **Consistency**: any type that implements `Accommodation` will always provide `get_description` and `book`.
    
- **Flexibility**: each type can choose its own internal strategy for storing data.
    
- **Safety**: the compiler enforces the contract — if you implement the trait, you must supply all required methods.
    

So, even though `Hotel` and `Airbnb` are totally different under the hood, they can be treated in the same way from the outside, because they both honor the `Accommodation` trait.
