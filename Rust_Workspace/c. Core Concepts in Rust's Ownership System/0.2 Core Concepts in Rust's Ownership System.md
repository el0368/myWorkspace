### Core Concepts in Rust's Ownership System

1. **Ownership Basics**
   - Definition of ownership: Every value in Rust has a single owner that manages its memory.
   - Scope and dropping: How values are automatically deallocated when their owner goes out of scope (via the `Drop` trait).
   - Stack vs. Heap allocation: Understanding how ownership interacts with memory allocation (e.g., fixed-size data on the stack, dynamic data on the heap).

2. **Move Semantics**
   - Moving ownership: What happens when assigning a value to another variable or passing it to a function (ownership transfer without copying).
   - Use-after-move errors: Common compiler errors and how to resolve them.
   - Partial moves: Moving individual fields out of structs or enums.

3. **Copy and Clone Traits**
   - `Copy` trait: For types that are cheaply copied (e.g., primitives like `i32`), allowing implicit copying instead of moving.
   - `Clone` trait: Explicit deep copying for types that don't implement `Copy`.
   - Differences between shallow copies, deep copies, and moves.

4. **References (Borrowing Without Ownership Transfer)**
   - Immutable references (`&T`): Allowing read-only access to data without owning it.
   - Mutable references (`&mut T`): Allowing read-write access, but with restrictions to prevent data races.
   - Deref coercion: How references behave like pointers (e.g., using `*` to dereference) and smart pointer integration.

5. **Borrowing Rules (The Borrow Checker)**
   - Core rules: At any given time, you can have either one mutable reference or any number of immutable references to a piece of data—but not both simultaneously.
   - Scope of borrows: How borrows are limited to the lifetime of the reference.
   - Non-lexical lifetimes (NLL): How Rust's borrow checker analyzes control flow to allow more flexible borrowing.
   - Common borrow errors: Mutable borrow while immutable borrow exists, borrowing mutably twice, etc.

6. **Lifetimes**
   - Lifetime parameters (`'a`): Annotating references to specify how long they must be valid.
   - Lifetime elision rules: When Rust infers lifetimes automatically (e.g., in function signatures).
   - Dangling references: Prevention through lifetime checks and compiler errors.
   - `'static` lifetime: For references that live for the entire program duration.

7. **Ownership in Functions and Methods**
   - Passing by value (moves ownership) vs. passing by reference (borrows).
   - Returning values: Ownership transfer back to the caller.
   - Borrowing in method signatures (e.g., `&self` vs. `&mut self` vs. `self`).

8. **Ownership with Data Structures**
   - Structs and enums: Owning fields and borrowing them.
   - Slices: References to contiguous sequences (e.g., `&[T]` as a borrowed view).
   - Strings: Differences between `String` (owned) and `&str` (borrowed slice).

9. **Smart Pointers and Advanced Ownership**
   - `Box<T>`: Owning heap-allocated data.
   - `Rc<T>` and `Arc<T>`: Reference counting for shared ownership (single-threaded and multi-threaded).
   - `RefCell<T>`: Interior mutability to allow mutable borrows at runtime (with runtime checks).
   - `Mutex<T>` and `RwLock<T>`: Thread-safe borrowing.

10. **Patterns and Best Practices**
    - Matching with references: Using `ref` and `ref mut` in patterns.
    - Error handling patterns: Avoiding common pitfalls like borrowing across awaits in async code.
    - Performance implications: How ownership enables zero-cost abstractions and prevents memory leaks.

11. **Related Advanced Topics**
    - Interior mutability: Bypassing borrow rules safely (e.g., via `Cell<T>`, `UnsafeCell`).
    - Pinning: For self-referential structs and async futures.
    - Unsafe Rust: When to use `unsafe` to manually manage borrows (as a last resort).
