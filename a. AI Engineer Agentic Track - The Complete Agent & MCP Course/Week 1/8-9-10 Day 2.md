# What Is an AI Agent? A Beginner's Guide

If you've heard the term "AI Agent" recently, you're not alone. It's a term that has generated a lot of excitement and hype, but it's often used to describe many different things. This can make it difficult to pin down a single, clear definition.

To cut through the noise, a great place to start is with a simple, crisp definition from Hugging Face's small agents project: **AI agents are programs where LLM outputs control the workflow.**

This means that instead of just generating text, the Large Language Model (LLM) is used to decide what actions to take and in what order. While this definition is a useful anchor, an AI system is often called "agentic" if it displays a few key characteristics.

## 1. The Core Idea: What Makes AI "Agentic"?

Beyond a simple definition, certain "hallmarks" signal that an AI system is behaving like an agent. If a system demonstrates one or more of these qualities, people will often describe it as being agentic.

- **Multiple LLM Calls**
    - When a system makes a sequence of calls to one or more LLMs to accomplish a task, it's often described as agentic.
- **Tool Use**
    - This is the ability of an LLM to use external tools—like a calculator, an API, or even a command to turn on smart lights. This is often considered the "litmus test for whether something is agentic."
- **Coordination**
    - When a system is set up to allow different LLMs to send information to each other, this coordination is a sign of agentic behavior.
- **Planning**
    - This involves using an LLM to act as a "planner" that coordinates the sequence of activities needed to achieve a goal.
- **Autonomy**
    - This is the ability of an LLM to "choose its own adventure" by deciding what actions to take and in what order. While the word sounds complex, it's helpful to know it's "just sort of fancy use of language in many ways."

These characteristics can be organized into a helpful framework that divides agentic systems into two main categories: structured "Workflows" and dynamic "Agents."

## 2. A Helpful Framework: Agentic "Workflows" vs. "Agents"

The AI company Anthropic provides a useful way to think about these systems by using the umbrella term **agentic system**. Under this umbrella, there are two distinct categories: _Workflows_ and _Agents_.

|   |   |   |
|---|---|---|
|Feature|Workflows|Agents|
|**Path**|These systems operate on **predefined paths**. The steps and structure of the task are already laid out.|These systems operate on **dynamic paths**. There is no fixed sequence of steps; the model decides its own path.|
|**Control**|A predefined structure orchestrates the models and tools. The LLM follows the established flow.|Models **dynamically direct their own processes** and tools, maintaining control over how the task is accomplished.|
|**Predictability**|Because the path is predefined, workflows are generally **more predictable** in their behavior, cost, and output.|Their open-ended nature makes them **less predictable**. The final path, cost, and output quality are not guaranteed.|

While this framework is a helpful way to organize the concepts, it's important to know that the line between Workflows and Agents can be blurry. This distinction is "a little bit artificial," as even structured 'Workflows' can exhibit a degree of autonomy, making this less of a rigid boundary and more of a spectrum.

We will now explore the common design patterns found within the more structured and predictable "Workflows" category.

## 3. Building Blocks: 5 Common Agentic Workflow Patterns

Anthropic identifies five common design patterns for building structured agentic "Workflows." These are the fundamental building blocks developers use to create sophisticated, multi-step AI systems.

**1. Prompt Chaining** A simple workflow where the output of one LLM call is passed as the input to the next, creating a chain of sequential tasks.

- **Primary Benefit:** It allows a complex task to be decomposed into a fixed set of subtasks, where each step's prompt can be carefully engineered for the highest quality response.

**2. Routing** An initial LLM acts as a "router" that analyzes an input and decides which specialized LLM or tool is best suited to handle the task.

- **Primary Benefit:** This pattern enables a "separation of concerns," allowing you to use different models with different expertise and have an LLM intelligently route tasks to the right expert.

**3. Parallelization** A task is broken down into multiple subtasks that can be executed simultaneously by different LLMs, with the results later combined.

- **Primary Benefit:** It allows for multiple parts of a problem to be worked on concurrently, which can speed up processing and handle tasks that have independent components.

**4. Orchestrator-Worker** A "master" LLM, the orchestrator, breaks a complex task into smaller steps, assigns those steps to "worker" LLMs, and then synthesizes their outputs into a final result. It's worth noting that even experts find it "quite artificial to categorize this as a workflow rather than an agent pattern," reinforcing the idea of a blurred line between the two concepts.

- **Primary Benefit:** This creates a more dynamic system than simple parallelization because an LLM, rather than fixed code, is intelligently dividing the labor and recombining the results to tackle a challenging task.

**5. Evaluator-Optimizer** One LLM generates a solution, and a second LLM acts as an "evaluator" to check the work. If the work is rejected, the evaluator provides feedback, and the generator tries again, creating a feedback loop. This is a personal favorite and "the one that I use most commonly...it's very powerful."

- **Primary Benefit:** This is an extremely powerful pattern for increasing the accuracy and quality of the final output. The feedback loop helps ensure the system produces more robust and reliable results.

These structured workflows provide a great deal of power and control. However, to tackle even more complex and open-ended problems, developers turn to the more flexible (and less predictable) world of "true" agents.

## 4. The Next Level: The Power and Problems of "True" Agents

The more advanced "Agent" pattern operates as an open-ended, dynamic loop. An LLM interacts with an environment (e.g., a set of files, a database, or even the physical world, like the smart lights mentioned in the source), takes actions, observes the results as feedback, and repeats this cycle until it determines the task is complete.

If this definition feels a bit abstract or "quite hand-wavy," you're not alone. That's the nature of these flexible systems. This flexibility allows agents to solve much more complex problems where the path to the solution isn't known in advance. However, this power comes with a new set of challenges.

### Key Challenges

- **Unpredictable Path:** You don't know exactly what steps the agent will take to solve the problem, or even which tasks it will choose to perform.
- **Unpredictable Output:** There are no guarantees on the quality of the final result. Giving the LLM autonomy means accepting uncertainty in what it will produce.
- **Unpredictable Cost:** Because you don't know how long the agent will run or how many resources it will use, you can't be sure what the final cost will be.

To manage these challenges, developers rely on two key strategies:

1. **Monitoring:** Implementing tools that provide visibility into what the agent is doing "under the hood." This allows developers to trace the agent's actions and understand its decision-making process.
2. **Guardrails:** Writing software protections that set safety boundaries for the agent. These rules ensure that the agent behaves safely, consistently, and within the constraints you define.

## 5. Conclusion: Your Key Takeaways on AI Agents

As we've seen, "AI Agent" is a broad term, but it describes a powerful shift in how we use AI. Here are the three most important takeaways for a beginner:

1. **It's About Control.** At its core, an AI agent is a program where a Large Language Model controls the workflow, deciding what actions to perform and in what sequence.
2. **It's a Spectrum.** Agentic systems range from highly structured **Workflows** with predefined steps (like Prompt Chaining) to highly flexible **Agents** that can dynamically choose their own path to solve a problem, with a blurry line in between.
3. **Power Comes with Trade-offs.** Giving an AI autonomy makes it more powerful but also less predictable. Developers manage the challenges of unpredictability using essential tools like **monitoring** and safety **guardrails**.
