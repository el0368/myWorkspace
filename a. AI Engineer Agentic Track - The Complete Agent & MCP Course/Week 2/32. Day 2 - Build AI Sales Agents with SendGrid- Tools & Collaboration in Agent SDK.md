# SDR Agent: Building Three Layers of Agentic Architecture

This project marks the shift from simple chatbot interactions to **Agentic Workflows**. We are building an AI Sales Development Rep (SDR) for "Comply.AI," a SOC2 compliance SaaS company.

## 1. The Core Infrastructure

Before building the agents, the environment must be configured for communication. We use **SendGrid** for transactional emails and the **OpenAI Agents SDK** for orchestration.

### Key Imports & Setup

The logic relies on `openai-agents` for specialized behavior and `sendgrid` for real-world actions.

```python
from openai_agents import Agent, Runner
from openai_agents.tools import function_tool
import os
from dotenv import load_dotenv

load_dotenv(override=True)
```

## 2. Layer 1: The Manual Agent Workflow

In the first stage, we define three distinct personas (agents) using specialized system prompts. We orchestrate the flow manually in Python, showing how agents can be "chained" together.

### The Three Personas:

1. **Professional Agent**: Serious, corporate tone.
    
2. **Humorous Agent**: Witty, high-engagement hooks.
    
3. **Concise Agent**: Busy, straight-to-the-point style.
    

### Code Implementation (Streaming)

Using `run_streamed` allows for a more responsive UI, handling the AI output as it's generated.

```python
# Defining instructions (System Prompts)
prof_instr = "You are a professional sales agent for Comply.AI..."
humor_instr = "You are a witty, engaging sales agent for Comply.AI..."

# Creating the Agents
prof_agent = Agent(name="Professional SDR", instructions=prof_instr, model="gpt-4o-mini")

# Running a streamed response
async def run_professional_workflow(user_query):
    runner = Runner()
    async for chunk in runner.run_streamed(prof_agent, [{"role": "user", "content": user_query}]):
        if chunk.type == "text":
            print(chunk.text, end="", flush=True)
```

## 3. Layer 2: Agents with Tools

The "spiced up" version introduces **Function Calling**. Here, the agent isn't just talking; it's doing work (like sending the actual email via SendGrid).

```python
def send_email(to_email, subject, body):
    # Logic to interface with SendGrid API
    return {"status": "success", "message": f"Email sent to {to_email}"}

# Converting the Python function into an Agent-ready tool
email_tool = function_tool(send_email)

# Attaching the tool to the agent
sdr_with_tools = Agent(
    name="Action-Oriented SDR",
    instructions="Write the email and then use the send_email tool to send it.",
    tools=[email_tool]
)
```

## 4. Layer 3: Collaborative Agents (Handoffs)

This is the most advanced layer. Instead of one agent trying to do everything, agents can "transfer" the conversation to a specialist.

### Two Methods of Collaboration:

1. **Agents as Tools**: An agent "calls" another agent like a function to get a specific sub-task done.
    
2. **Handoffs**: The current agent "hands the baton" to another agent. The second agent takes over the entire conversation context.
    

## 5. Lab Observations & Best Practices

- **Model Choice**: We use `gpt-4o-mini` throughout to keep development costs low while maintaining high logic capabilities.
    
- **Environment Variables**: Crucial for API security (SendGrid keys, OpenAI keys).
    
- **Boilerplate vs. SDK**: We are moving away from the manual JSON boilerplate used in Week 1 and leveraging the `openai-agents` library for cleaner, more readable code.
