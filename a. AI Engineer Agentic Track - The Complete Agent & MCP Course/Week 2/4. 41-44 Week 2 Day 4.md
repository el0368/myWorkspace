# Deep Research Agent Concepts

This lesson focuses on building a **Deep Research Agent**, a classic and highly impactful use case for Agentic AI. Unlike standard chat interactions, a deep research agent is granted the autonomy to navigate the internet, evaluate multiple sources, and synthesize disparate information into a comprehensive, high-quality report.

### 1. The Core Architecture

Building a robust Deep Research system relies on three critical architectural pillars:

- **Tools:** This is the "agency" in agentic AI. By providing the model with internet access, we transform it from a static knowledge base into a dynamic browser capable of retrieving real-time data and verifying facts.
    
- **Structured Outputs:** When agents work together, the handoff between them must be seamless. Structured outputs (often via Pydantic or JSON schemas) ensure that the data returned by a search agent can be programmatically parsed and analyzed by a secondary synthesis agent without "hallucinated" formatting issues.
    
- **Hosted Tools:** Rather than managing the complex infrastructure of web scraping, headless browsers, and proxy rotation yourself, you utilize tools managed and optimized by the model provider (OpenAI). This allows the developer to focus on the agent's logic rather than the plumbing of the internet.
    

### 2. OpenAI Hosted Tools

OpenAI provides three primary remote capabilities that serve as the "senses" for your agent:

1. **Web Search Tool:** This tool acts as the agent's gateway to the live web. It performs optimized searches and returns curated content from high-authority sources, essentially giving the model a real-time pulse on current events and technical documentation.
    
2. **File Search Tool:** This allows for RAG (Retrieval-Augmented Generation) at scale. The agent can search across vast remote vector stores containing your uploaded proprietary documents, making it an expert on your specific internal data.
    
3. **Computer Tool:** A more advanced capability where the agent can interact with a computer interface—interpreting screenshots, moving cursors, and clicking buttons—to perform tasks that require navigating complex UI-based software.
    

### 3. The Search Agent Workflow

A "Deep Research" task is often too complex for a single prompt. Instead, the process begins with a specialized **Search Agent** acting as an internal "Research Assistant."

- **Role & Persona:** The agent is instructed to behave as a technical researcher. It doesn't need to worry about being "polite" to a human user; its primary objective is the extraction and compression of data.
    
- **Goal:** It takes a specific search term, evaluates the results for relevance, and produces a dense summary of 2-3 paragraphs.
    
- **Synthesized Output:** The instructions prioritize content density over stylistic flourishes or perfect grammar. Because this output is intended for a "Synthesis Agent" later in the chain, the focus is on capturing every relevant fact, name, and date to ensure no critical information is lost during the handoff.
    

### 4. Implementation Details

- **Tool Choice (Mandatory):** By setting `tool_choice: required`, we enforce a strict operational protocol. This removes the model's ability to "chat" or "speculate" and forces it to use the search utility, ensuring that every response is grounded in external evidence.
    
- **Context Size & Granularity:** Parameters like "search context size" (low, medium, or high) allow developers to tune the level of detail the search tool returns. Higher settings provide more "surrounding text" for better context but increase processing time and cost.
    
- **Cost Management:** While powerful, hosted web search is a premium feature (roughly $0.025 per call). In a deep research loop that might require 10-20 searches, costs can escalate. Developers must balance the use of high-reasoning models (GPT-4o) for synthesis with faster, cheaper models (GPT-4o-mini) for the initial high-volume search phase.
    

### 5. Why "Deep Research"?

The primary limitation of standard LLMs is the "knowledge cutoff"—the date their training data ends. A deep research agent effectively shatters this barrier.

By retrieving live data, the AI becomes capable of tasks that were previously impossible, such as analyzing this morning's stock market shifts, researching a software framework released last week, or performing competitive intelligence on a brand-new startup. This turns the AI into a "sidekick" capable of high-level business intelligence and technical auditing.
