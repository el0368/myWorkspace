While the `@function_tool` decorator is a major convenience, the core of "agentic architecture" is actually about **shifting control from you (the programmer) to the AI**.

Beyond just converting functions to JSON, the next main core ideas are **Orchestration Patterns**, **State Persistence**, and **The Handoff Mechanism**.

---

### 1. Orchestration: Manager vs. Handoffs

The SDK allows you to structure how agents collaborate. There are two primary ways they work together:

|**Pattern**|**Description**|**Best For...**|
|---|---|---|
|**Agents as Tools**|A "Manager" agent treats other agents like functions. It sends them a task, waits for a result, and stays in control.|Hierarchical tasks (e.g., a CEO agent delegating to a Research agent).|
|**Handoffs**|An agent "passes the baton." It completely transfers the conversation and history to a new agent who takes over.|Conversational routing (e.g., a Support bot handing you off to a Billing specialist).|

### 2. Automatic "Agent Loops"

In traditional coding, you'd have to write logic like: _If AI wants to use a tool, run the tool, then send the result back to the AI, then ask again._

- **The SDK Way:** The "Runner" handles the **Agent Loop** automatically.
    
- It will keep calling tools and looking at the results until it decides the task is finished. You don't have to write the "while loop" that manages these turns; the SDK does it for you.
    

### 3. Unified Context and Memory

When agents talk to each other or use tools, they need to remember what just happened.

- **Context Injection:** The SDK manages the "conversation state" so that if the Professional Sales Agent writes an email, the Sales Picker Agent can actually "see" it without you manually passing strings around.
    
- **Metadata:** It also tracks dependencies (like API keys or user IDs) across the entire trace, making sure the right data is available at the right step.
    

### 4. Tracing and Observability

Because agentic systems are "stochastic" (they can behave differently each time), you need a way to see what they were thinking.

- **Traces and Spans:** The SDK automatically logs every single step—every tool call, every reasoning step, and every handoff—into a visual timeline.
    
- This allows you to debug exactly why a "Picker" chose one email over another or why a tool call failed.
    

---

### Summary of the "Next Level"

If Layer 1 was "talking" and Layer 2 was "doing (tools)," then **Layer 3 is "Coordinating."** The main core idea is building a **team of specialists** that can manage a complex workflow autonomously, rather than one giant prompt trying to do everything at once.
