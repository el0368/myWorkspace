# In-Depth Study Guide: Defining Table Columns - The `status` Column & `ENUM` Data Type (MySQL vs. PostgreSQL)

This study guide focuses on defining the `status` column for our `users` table, specifically addressing how to handle fixed sets of text values using the `ENUM` concept, highlighting the important syntax differences between MySQL and PostgreSQL by presenting them side-by-side.

## 1. The `status` Column Requirement

- **Purpose:** To store the employment status of a user/talent (e.g., 'employed', 'self-employed', 'unemployed').
    
- **Constraint:** The column should **only accept a predefined set of text values**, blocking any arbitrary or invalid input.
    

## 2. Introduction to `ENUM`

- **Concept:** `ENUM` (Enumerated Type) allows you to define a column that can only store one value from a specified list of allowed string values. It's ideal for categorical data where the options are known and fixed.
    
- **Standardization:** It's crucial to note that `ENUM` is **NOT a standard SQL type**. This is why its implementation and syntax differ significantly between various database systems like MySQL and PostgreSQL. Despite not being standard, it's a common and useful feature.
    

## 3. Implementing `ENUM` in MySQL vs. PostgreSQL

The core difference lies in whether the `ENUM` type is defined inline with the table creation or as a separate custom type.

### 3.1. MySQL Syntax and Example

MySQL directly supports the `ENUM` data type, making its definition straightforward within the `CREATE TABLE` statement.

**Key Characteristics:**

- `ENUM` is used directly as a column's data type.
    
- The allowed values are listed within parentheses, separated by commas, enclosed in single quotes.
    
- No prior type creation is necessary.
    

SQL

```SQL
-- MySQL Syntax for creating the users table with ENUM
-- Note: 'ENUM' keyword might not be highlighted in all IDEs as a standard SQL type,
-- but it is valid in MySQL.

CREATE TABLE users (
    full_name VARCHAR(200),
    yearly_salary INT,
    current_status ENUM('employed', 'self-employed', 'unemployed') -- MySQL specific ENUM
);

-- How to add comments in SQL: Two hyphens (--) for single-line comments.
-- Everything after -- on the same line is ignored.
```

**Execution Steps (MySQL in VS Code):**

1. Ensure you are connected to your **MySQL** database in VS Code (check the active connection in the SQLTools tab).
    
2. Run the `CREATE TABLE` statement above.
    
3. **Troubleshooting "Access Denied" error:** If encountered, close and reconnect to your MySQL database in SQLTools, re-entering your password. Then, retry running the command.
    
4. **Verification:**
    
    - Refresh the SQLTools database explorer (left sidebar).
        
    - Expand your `talently` database -> `Tables`. You should see `users`.
        
    - Expand `users` or right-click `users` and select "Describe Table" to confirm columns and `ENUM` data type.
        

### 3.2. PostgreSQL Syntax and Example

PostgreSQL does not support `ENUM` as a direct, inline data type within `CREATE TABLE`. It requires a two-step process:

1. First, create a **custom type** that functions as an `ENUM`.
    
2. Then, use that custom type in your table definition.
    

**Key Characteristics:**

- A `CREATE TYPE` command is executed _before_ `CREATE TABLE`.
    
- The `CREATE TYPE` command defines a new, reusable custom data type.
    
- The `AS ENUM` clause specifies that the custom type will be an enumerated list.
    
- The allowed values are listed within parentheses, separated by commas, enclosed in single quotes.
    
- The name of the custom type is then used as the column's data type in `CREATE TABLE`.
    

SQL

```SQL
-- PostgreSQL Syntax for creating the users table with an ENUM-like type

-- STEP 1: Create a Custom ENUM Type (must be executed as a standalone command)
CREATE TYPE employment_status AS ENUM('employed', 'self-employed', 'unemployed');

-- STEP 2: Create the users table, using the custom type
CREATE TABLE users (
    full_name VARCHAR(200),
    yearly_salary INT,
    current_status employment_status -- Using the custom type defined above
);

-- Note: The CREATE TYPE command is specific to PostgreSQL and would fail if executed against MySQL.
```

**Execution Steps (PostgreSQL in VS Code):**

1. Ensure you are connected to your **PostgreSQL** database in VS Code.
    
2. **Crucial:** First, execute the `CREATE TYPE employment_status AS ENUM(...)` command. This must succeed first.
    
3. Then, execute the `CREATE TABLE users (...)` command.
    
4. **Verification:**
    
    - Refresh the SQLTools database explorer.
        
    - Expand your `talently` database -> `Schemas` -> `public` -> `Tables`. You should see `users`.
        
    - Right-click `users` and select "Describe Table." The output will show `current_status` using your custom `employment_status` type.
        

## 4. Summary of Differences and Key Takeaways

|Feature|MySQL|PostgreSQL|
|---|---|---|
|**ENUM Definition**|Direct, inline in `CREATE TABLE`|Two-step process: `CREATE TYPE` then use the custom type in `CREATE TABLE`|
|**`ENUM` Keyword**|Used as a data type (e.g., `ENUM('a','b')`)|Used within `CREATE TYPE` (e.g., `AS ENUM('a','b')`)|
|**`CREATE TYPE` Command**|Not supported; would result in an error|Supported; essential for creating custom `ENUM` types|
|**SQL Standard**|`ENUM` is a non-standard feature in both DBMS|`ENUM` is a non-standard feature in both DBMS|
|**Data Integrity**|Both methods achieve the goal of restricting values to a predefined set, ensuring data integrity.|Both methods achieve the goal of restricting values to a predefined set, ensuring data integrity.|
