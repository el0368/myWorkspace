# In-Depth Study Guide: Key SQL Data Types - Numeric, Date/Time, and Others

## 1. Introduction to Diverse Data Types

Beyond text, databases frequently handle various other data types, especially numbers, dates, and simple true/false values. Understanding these types is crucial for accurate data representation and efficient database operations. As with text types, the specific implementation and range of these types can vary slightly between different database systems (MySQL, PostgreSQL, etc.), so consulting official documentation remains vital.

## 2. Numeric Data Types

Numbers are fundamental for storing quantities, prices, salaries, and more. SQL provides distinct numeric types to handle whole numbers versus numbers with decimal places, and to manage precision and storage efficiently.

### 2.1. Integers (Whole Numbers)

- **Definition:** Integers are whole numbers without any decimal places.
    
- **Common Type Name:** `INTEGER` or `INT`.
    
- **Variations:** Database systems offer different sizes of integers to accommodate varying ranges of numbers, which also affects storage space:
    
    - `SMALLINT`: For smaller integer values (e.g., age, count of small items).
        
    - `INT` or `INTEGER`: Standard integer size.
        
    - `BIGINT`: For very large integer values (e.g., large counts, IDs that grow very big).
        
    - Other variations might include `TINYINT`, `MEDIUMINT` (MySQL).
        
- **Use Cases:** Counters, IDs, quantities of discrete items, age, year, number of employees, salaries (if whole numbers).
    
- **Examples:** `5`, `10`, `-20`, `1000000`.
    

### 2.2. Fractional Numbers (Numbers with Decimal Places)

For numbers that require decimal precision (e.g., prices, percentages, averages, revenue figures like 12.5 million), SQL offers two main categories, distinguished by how they handle precision:

#### 2.2.1. Exact Fractional Numbers (`DECIMAL`, `NUMERIC`)

- **Definition:** These data types store fractional numbers with **exact precision**. They are designed to prevent any loss of precision when dealing with decimal values.
    
- **Common Type Names:** `DECIMAL` and `NUMERIC`.
    
- **Precision and Scale:** When defining these types, you typically specify two values:
    
    - **Precision:** The total number of digits allowed (both before and after the decimal point).
        
    - **Scale:** The number of digits allowed after the decimal point.
        
    - **Example:** `DECIMAL(5, 2)` could store `123.45` (5 total digits, 2 after the decimal).
        
- **Behavior:** The database system dedicates specific storage and uses internal representations (often BCD - Binary Coded Decimal) to guarantee that the number is stored precisely as entered, without rounding errors inherent to floating-point arithmetic.
    
- **Performance:** Storing and performing calculations on exact fractional numbers can be slightly more performance-intensive than inexact types due to the precise handling required by the computer.
    
- **Use Cases:** Crucial for financial data (money, prices, balances), scientific measurements where exactness is paramount, or any scenario where rounding errors are unacceptable.
    
- **Example:** `3.14`, `5.58`, `-10.999`.
    

#### 2.2.2. Inexact Fractional Numbers (`FLOAT`, `REAL`, `DOUBLE`)

- **Definition:** These data types store fractional numbers, but their precision is **inexact** or approximate. They are typically based on floating-point arithmetic standards (like IEEE 754).
    
- **Common Type Names:**
    
    - `FLOAT`: Single-precision floating-point number.
        
    - `REAL`: Often synonymous with `FLOAT` or a specific float precision.
        
    - `DOUBLE` or `DOUBLE PRECISION`: Double-precision floating-point number (offers more precision than `FLOAT`, but still inexact).
        
- **Behavior:** Due to the nature of how computers represent floating-point numbers, values stored with these types may have tiny rounding errors, meaning `10.15` might be stored as `10.149999999999999` or `10.150000000000001`.
    
    - (An attached resource would explain the computer science reasons for this, which are beyond the scope of a basic SQL course).
        
- **Performance:** Generally faster for calculations and require less storage than exact fractional types because they align better with how computer processors handle numbers.
    
- **Use Cases:** Scientific calculations where small rounding errors are acceptable, non-monetary measurements, graphical coordinates, or large datasets where storage and speed are prioritized over absolute decimal precision.
    
- **Example:** If storing `10.15` and `10.16` for approximate measurements, the minor precision difference might not matter for the use case.
    

## 3. Date and Time Data Types

Databases often need to store information about when events occurred.

- **`DATE`:**
    
    - **Definition:** Stores only the date (year, month, day) without any time component.
        
    - **Format Example:** `YYYY-MM-DD` (e.g., `2025-07-27`).
        
    - **Use Cases:** Birthdays, anniversaries, specific transaction dates where the time of day is irrelevant.
        
- **`DATETIME` / `TIMESTAMP`:**
    
    - **Definition:** Stores both date and time information. The specific name and behavior (e.g., whether it automatically updates on record modification, how time zones are handled) can differ between DBMS.
        
    - **Information Stored:** Includes year, month, day, hour, minute, second, and often milliseconds/microseconds. Some variations also store or convert based on time zone information.
        
    - **Use Cases:** Recording when a record was created or last updated, event logs, scheduling, chat message timestamps.
        
    - **Example:** `2025-07-27 15:55:51.123456` (with potential time zone information).
        

## 4. Other Selected Data Types

### 4.1. Boolean Data Types

- **Definition:** Stores simple true/false, yes/no, or on/off values.
    
- **Common Representations:**
    
    - `TRUE`/`FALSE` (often in PostgreSQL)
        
    - `1`/`0` (common in MySQL for `TINYINT(1)`)
        
- **Use Cases:** Flags or indicators (e.g., `is_hiring` for a company, `is_active` for a user, `is_admin`).
    

### 4.2. Advanced Data Types (JSON, XML - Not a Focus of This Course)

- **Definition:** Some modern database systems support storing complex, semi-structured data formats directly within a column.
    
- **Examples:** `JSON` (for JavaScript Object Notation data), `XML` (for Extensible Markup Language data).
    
- **Use Cases:** Can be useful for storing flexible data that doesn't fit neatly into traditional relational columns, like configuration settings or nested user preferences.
    
- **Course Stance:** These types are **not a focus of this course**. While they exist, they can sometimes contradict the principles of relational database design that this course emphasizes. The primary focus remains on structured data within traditional columns.
