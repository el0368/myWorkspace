# In-Depth Study Guide: Creating Tables with `CREATE TABLE`

## 1. Introduction: From Database to Tables

Having successfully created our `talently` database, the next essential step in building our application's data model is to create the tables that will store the actual data. This process involves not only naming the table but also meticulously defining its internal structure, specifically its columns and their respective data types.

## 2. The `CREATE TABLE` Statement

The fundamental SQL command to create a new table is `CREATE TABLE`. This command is universally supported across most relational database systems, including both MySQL and PostgreSQL.

- **Syntax (Basic):**
    
    SQL
    
    ```SQL
    CREATE TABLE table_name (
        column1_name DATATYPE [CONSTRAINTS],
        column2_name DATATYPE [CONSTRAINTS],
        -- ... more columns
    );
    ```
    
- **`CREATE TABLE`:** The essential keywords to initiate table creation.
    
- **`table_name`:** The name you choose for your table.
    
- **Parentheses `()`:** Enclose the definitions of all the columns that will belong to this table.
    
- **Column Definitions:** Each column is defined with its `column_name`, its `DATATYPE`, and optionally, `CONSTRAINTS` (rules that govern the data in that column).
    
- **Commas `,`:** Column definitions within the parentheses must be separated by commas.
    
- **Semicolon `;`:** The entire `CREATE TABLE` statement ends with a semicolon.
    

## 3. Naming Your Table

Choosing a clear and consistent name for your table is crucial for database readability and maintainability.

- **Avoid Keyword Clashes:** Just like with database names, avoid using SQL reserved keywords (e.g., `CREATE`, `SELECT`, `TABLE`) as table names.
    
    - **Escaping Keywords (if necessary):** If you _must_ use a reserved word as a table name, you can "escape" it:
        
        - **PostgreSQL:** Use double quotes (e.g., `CREATE TABLE "order" (...)`).
            
        - **MySQL:** Use backticks (e.g., `CREATE TABLE` order `(...)`).
            
    - **Recommendation:** It's generally best to avoid reserved words entirely to minimize confusion and ensure better cross-DBMS compatibility.
        
- **Naming Convention (Singular vs. Plural):**
    
    - **Plural Form (e.g., `users`, `products`, `orders`):** This is the preference adopted in this course. It makes logical sense as a table holds _multiple_ records (rows) of a given entity.
        
    - **Singular Form (e.g., `user`, `product`, `order`):** Also a valid and common convention, indicating that the table stores information about the `user` _entity_.
        
    - **Choice:** Both conventions are widely seen. The choice often depends on personal preference or established team/company standards. Consistency within a project is key.
        

## 4. Defining Table Structure: Columns and Data Types

Unlike `CREATE DATABASE`, which only requires a name, `CREATE TABLE` necessitates a detailed definition of its internal structure: the columns it will contain and the type of data each column is expected to hold.

### 4.1. Planning Ahead for Columns

Before writing the SQL, it's vital to have a clear idea of what data each table will store. For our "Talently" example, we are starting with the `users` table:

- **`users` table (initial columns):**
    
    - User's name (which we'll likely split into first and last name for better structure).
        
    - Yearly salary (if employed).
        
    - Current status (e.g., employed, self-employed, unemployed).
        
    - (Note: The `employer` column, which would link to the `employers` table, will be added later once that table is also defined.)
        

### 4.2. Column Definition Syntax

Within the parentheses of `CREATE TABLE`, each column is defined as:

SQL

```SQL
column_name DATATYPE [additional_settings/constraints]
```

- **`column_name`:** The name you give to that specific column. Follow the same naming conventions as tables (lowercase, `snake_case` for multi-word names, avoid keywords).
    
- **`DATATYPE`:** The specific data type (e.g., `VARCHAR(255)`, `INT`, `DECIMAL`, `DATE`, `TEXT`) that the column will enforce for all data inserted into it. This is where the knowledge from previous lectures on data types becomes crucial.
    
- **`[additional_settings/constraints]`:** Optional attributes like `NOT NULL`, `PRIMARY KEY`, `DEFAULT` values, etc. (These will be explored in detail in subsequent lectures).
    

### 4.3. Formatting for Readability

While SQL statements can technically be written on a single line, it is highly recommended to format `CREATE TABLE` statements for readability, especially when defining multiple columns or complex structures:

- **Line Breaks:** Using line breaks after each column definition (and indentation) makes the statement much easier to read and understand. SQL ignores whitespace and line breaks between keywords and definitions.
    
- **One Column Per Line:** A common practice is to place each column definition on its own line.
    

**Example of improved readability:**

SQL

```
CREATE TABLE users (
    id INT,                      -- Column 1: User ID
    first_name VARCHAR(255),     -- Column 2: First Name
    last_name VARCHAR(255),      -- Column 3: Last Name
    yearly_salary DECIMAL(10, 2),-- Column 4: Salary
    status VARCHAR(50)           -- Column 5: Status
    -- more columns...
);
```

## 5. Consulting Official Documentation for `CREATE TABLE`

As with other SQL commands, the `CREATE TABLE` statement has a vast array of options, clauses, and variations.

- **Extensive Options:** The official documentation (e.g., PostgreSQL's `CREATE TABLE` definition) will show a comprehensive list of all possible configurations.
    
- **Focus on Key Options:** Do not be intimidated by the sheer volume of options. Many are highly specialized and typically used only by database administrators or for very advanced scenarios. This course will focus on the most important and frequently used options.
    
- **Always Refer Back:** The documentation is your ultimate reference for precise syntax, behavior, and detailed information on every available option.
