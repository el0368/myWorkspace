# In-Depth Study Guide: Numeric Data Types in Detail & Choosing for `yearly_salary`

This study guide delves deeper into the nuances of numeric data types and provides a thought process for selecting the appropriate type, specifically for the `yearly_salary` column in our `users` table.

## 1. Recap: Categories of Numeric Data Types

Before diving into the `yearly_salary` decision, let's briefly reiterate the three main categories of numeric data types:

### 1.1. Integers (Whole Numbers)

- **Definition:** Store whole numbers without decimal places.
    
- **Behavior:** If a number with decimal places is inserted into an integer column, it will typically be rounded (or truncated, depending on the DBMS) to the nearest whole number.
    
- **Benefits:** Excellent performance for calculations, efficient storage.
    
- **Variations:** `SMALLINT`, `INT`, `BIGINT`, etc., which define the range of values and impact storage space. Choosing the smallest type that fits your expected range saves resources.
    

### 1.2. Exact Fractional Numbers (`DECIMAL`, `NUMERIC`)

- **Definition:** Store numbers with decimal places with **guaranteed exact precision**.
    
- **Behavior:** No data loss occurs in the fractional part. You define the total number of digits (precision) and the number of digits after the decimal point (scale).
    
- **Benefits:** Absolutely critical for financial data (e.g., product prices, balances) where even a tiny discrepancy (like a cent) can have significant consequences.
    
- **Downside:** Slightly higher performance cost for storage and calculations compared to integers or approximate types.
    

### 1.3. Approximate Fractional Numbers (`FLOAT`, `REAL`, `DOUBLE`)

- **Definition:** Store numbers with decimal places using **approximate precision** (floating-point arithmetic).
    
- **Behavior:** Small rounding errors can occur.
    
- **Benefits:** Generally offer better performance and storage efficiency than exact fractional types.
    
- **Downside:** Not suitable for data where exactness is paramount (e.g., money).
    
- **Variations:** `FLOAT`, `REAL`, `DOUBLE` provide different levels of approximation/precision.
    

## 2. Decision Process: Choosing Data Type for `yearly_salary`

For the `yearly_salary` column, we need to decide which numeric data type is most appropriate. This decision involves considering the nature of salary data and its typical use within our "Talently" application.

### 2.1. Initial Thought: `DECIMAL` (Exact Fractional)

- **Argument for:** Salary deals with money, and money usually implies the need for exactness (like product prices). A salary _could_ technically have decimal values (e.g., $19,000.12).
    
- **Argument against:** While it's money, the context matters. Is this `yearly_salary` used for precise financial transactions within the app (like processing payroll), or more for informational/statistical purposes? Exact types have a performance cost.
    

### 2.2. Alternative Thought: `FLOAT`/`REAL` (Approximate Fractional)

- **Argument for:** If salaries might have decimal values (e.g., 19000.12), but the absolute exactness of the cents doesn't critically impact the application (e.g., used for statistical reporting, not exact billing). This offers better performance than `DECIMAL`.
    
- **Argument against:** Still introduces potential rounding errors, which might be undesirable even for statistical purposes if high fidelity is expected.
    

### 2.3. The Chosen Approach: `INT` (Integer / Whole Number)

- **Argument for (Lecturer's Choice):**
    
    - **Common Representation:** In everyday conversation, salaries are most often expressed as whole numbers (e.g., "25 thousand," not "25,000.15"). This suggests that the decimal part is often negligible or rounded in real-world use.
        
    - **Application Context:** For a "talents pool" application like Talently, the `yearly_salary` might primarily be used for:
        
        - **Statistical Analysis:** Averages, ranges, distributions. For these, rounding to the nearest dollar/cent might be acceptable, or even preferred for simplicity.
            
        - **Filtering/Sorting:** "Show me talents with salary > 50000."
            
        - **Display:** Presenting to users in a simplified format.
            
    - **Performance:** Integers offer the best performance among numeric types due to their simplicity and direct mapping to computer's native number handling.
        
    - **Simplicity:** Avoids the complexities of fractional number storage and potential precision issues.
        
- **Conclusion:** Given that the exact cents of a salary might not be crucial for _this specific application's_ use case (primarily statistical and display), an `INT` provides an excellent balance of performance, simplicity, and sufficient accuracy. If a salary of `19000.12` is entered, it would be rounded to `19000` (or similar integer conversion), which is deemed acceptable for this context.
