# In-Depth Study Guide: Creating Databases with `CREATE DATABASE`

## 1. Introduction: The First Step in Data Definition

Having understood the database hierarchy, the next logical step is to create a dedicated database to house our application's tables. This lecture focuses on the `CREATE DATABASE` SQL statement, which is the foundational command for establishing a new database on your database server.

## 2. Project Setup and File Management

- **Environment:** The lecture utilizes Visual Studio Code (VS Code) with the SQLTools extension.
    
- **Database Servers:** Ensure both MySQL and PostgreSQL servers are up and running and that you are connected to them in VS Code via the SQLTools extension.
    
- **Creating a SQL File:**
    
    - Navigate to your empty project folder (set up previously).

## 3. The `CREATE DATABASE` Statement

The fundamental SQL command to create a database is straightforward:

SQL

```SQL
CREATE DATABASE database_name;
```

- **`CREATE`:** The SQL keyword indicating an object is to be created.
    
- **`DATABASE`:** The SQL keyword specifying that the object to be created is a database.
    
- **`database_name`:** The desired name for your new database.
    

### 3.1. Choosing a Database Name: Naming Conventions

Adhering to common naming conventions is crucial for readability and avoiding issues:

- **Lowercase Identifiers:** The convention in SQL is to use **all lowercase characters** for database names (and later, table and column names). While uppercase might work in some systems, lowercase is widely preferred.
    
- **No Whitespace/Blanks:** Database names (and other identifiers) **cannot contain spaces or blanks**.
    
- **Multi-word Names:** If your database name consists of multiple words (e.g., "talent pool"), separate them using **underscores (`_`)**.
    
    - **Example:** `talent_pool`
        
- **Avoiding Keywords:** Do not use SQL keywords (like `CREATE`, `DATABASE`, `SELECT`, etc.) as database names.
    
    - **Escaping Keywords (If Necessary):** If you absolutely _must_ use a keyword or a name with special characters (though generally discouraged for simplicity), you can escape the name:
        
        - **Double Quotes (`"`):** Supported by many SQL systems, including PostgreSQL.
            
            - **Example:** `CREATE DATABASE "create";`
                
        - **Backticks (`` ` ``):** Supported by MySQL. (Note: This is _not_ a single quote).
            
            - **Example:** `CREATE DATABASE` create`;`
                
        - **Recommendation:** If you are not clashing with a keyword, you don't need any quotes. Simplicity is preferred.
            

### 3.2. Example: Creating the "Talently" Database

For this course, we will create a database named "talently":

SQL

```SQL
CREATE DATABASE talently;
```

- This database will serve as the main container for the `employers`, `users`, and `conversations` tables for our fictional company.
    

### 3.3. Statement Terminator: Semicolon (`;`)

- Always end your SQL statement with a semicolon (`;`). This tells the SQL interpreter where one command finishes and another can begin.
    

## 4. `CREATE SCHEMA` (MySQL Specific)

- **MySQL Synonym:** In MySQL, `CREATE SCHEMA` is effectively a **synonym for `CREATE DATABASE`**. They perform the same action.
    
- **Portability:** For better cross-database compatibility (especially with PostgreSQL or other systems where `SCHEMA` has a different meaning), it is **recommended to consistently use `CREATE DATABASE`**.
    

## 5. Optional Clauses and Database System Differences

While the basic `CREATE DATABASE database_name;` works across most systems, individual database systems offer additional, optional clauses for more specific configurations.

- **Consult Documentation:** Always refer to the official documentation for your specific database system (MySQL, PostgreSQL, etc.) to explore all available options for a given command.
    
    - Search terms: `[Database System Name] CREATE DATABASE` (e.g., `MySQL CREATE DATABASE`, `PostgreSQL CREATE DATABASE`).
        
- **`IF NOT EXISTS` Clause (MySQL Example):**
    
    - **Purpose:** This clause prevents an error if you try to create a database that already exists. If the database exists, the command simply does nothing.
        
    - **Syntax (MySQL):** `CREATE DATABASE IF NOT EXISTS talently;`
        
    - **System Specificity:** **Not supported by all systems (e.g., PostgreSQL does not support `IF NOT EXISTS` for `CREATE DATABASE`)**. This highlights the importance of checking documentation.
        
- **Other Options (e.g., Collation, Encoding):**
    
    - Database systems provide options for character sets, collation (sorting rules), and other low-level configurations.
        
    - **Defaults are usually fine** for most development purposes.
        
    - These options are often more relevant to database administrators than end-users. This course will not delve deep into these highly specific configurations.
        

## 6. Executing the `CREATE DATABASE` Command

1. **Open SQL File:** Ensure your `01-create-database.sql` file is open in VS Code.
    
2. **Select Connection:** In the SQLTools extension, ensure you have an active connection selected (e.g., `mysql1` or `postgresql1`).
    
3. **Run Command:** Click the "Run on Active Connection" button (the play icon) in the top right of the SQL file window.
    
4. **Verify:**
    
    - The results window at the bottom should show a success message (e.g., "Query executed successfully").
        
    - You have now successfully created the "talently" database on both your MySQL and PostgreSQL servers (by running the command against each connection).
        

## 7. Updating Existing Connections

After creating the "talently" database, it's a good practice to update your SQLTools connections to default to this new database.

- **Reason:** Your existing connections might be configured to connect to a default database (e.g., `default` for MySQL, `postgres` for PostgreSQL). To easily work with your new "talently" database without explicitly specifying it in every query, update the connection settings.
    
- **Steps for MySQL and PostgreSQL:**
    
    1. In the SQLTools connection list (left sidebar), **right-click** on your existing MySQL connection (e.g., `mysql1`).
        
    2. Select "Edit Connection."
        
    3. Locate the "Database" field.
        
    4. Change the database name from `default` (or whatever it was) to `talently`.
        
    5. Save the connection.
        
    6. **Disconnect and Reconnect:** Click the disconnect icon (red X) and then the connect icon (green arrow) for that connection. Re-enter your password if prompted.
        
    7. Repeat these steps for your PostgreSQL connection, changing its default database to `talently`.
        

By following these steps, you've successfully created your first custom database and configured your tools to work seamlessly with it.
