**Why Use Relational Database Management Systems (RDBMS) & SQL?**

- **Not Limited to RDBMS:** While most prominent, SQL can be used with other software (e.g., data science frameworks).
    
- **Standardization:** SQL is generally standardized, meaning knowledge gained in one RDBMS is largely transferable to others (though minor variations exist).
    
- **Main Reasons for Using RDBMS:**
    
    1. **Transactional/Application Data:** Storing and handling data generated by user interactions with applications (e.g., website, mobile app), like online shop orders.
        
    2. **Data Analytics:** Storing and analyzing data from various sources (e.g., sales data, weather data).
        
        - _Note:_ No hard border; application data can be analyzed.
            
- **Alternatives:** Non-SQL databases like MongoDB exist but are not the focus here.
    

**Key Terminology & Hierarchy:**

- **Database Management System (DBMS) / Database Server / Database Cluster:**
    
    - This is the **software** you install and run (e.g., MySQL, PostgreSQL).
        
    - It _manages_ databases.
        
    - When you start the software, you typically start a "server."
        
- **Database:**
    
    - A container _within_ the DBMS/server.
        
    - A single server can host multiple databases (e.g., one database per application).
        
    - Data _between_ different databases on the same server is often unrelated.
        
- **Table:**
    
    - Contained _within_ a database.
        
    - A database can hold one or many tables.
        
    - Data _between_ different tables within the same database is often related.
        
- **Columns (Fields):** Define the structure and data types of information in a table.
    
- **Rows (Records/Entries):** The actual data entries stored within the columns of a table.
    

**Important Note:** The terms "database" and "database management system" might sometimes be used interchangeably in casual conversation or this course, but the context will make the meaning clear. The hierarchy (DBMS > Database > Table > Columns/Rows) is important to understand.
