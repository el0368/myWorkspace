## Core SQL Syntax Rules: An Introduction

This module serves as a gentle introduction to SQL syntax. The goal is to provide a foundational understanding of how SQL statements are structured, rather than requiring immediate memorization. You will gain a deeper understanding and practical application throughout the course.

### 1. SQL Commands/Statements

- A SQL command or statement is a single instruction given to the database.
    
- The terms "command" and "statement" will be used interchangeably.
    
- An example SQL command:
    
    SQL
    
    ```SQL
    SELECT name, salary
    FROM employees
    WHERE salary > 8000;
    ```
    

### 2. Semicolon (`;`) as a Statement Terminator

- **Rule:** Every SQL statement should end with a semicolon (`;`).
    
- **Purpose:** The semicolon acts as a statement terminator, signaling the end of a command to the database system.
    
- **Exception:** While generally required, there might be specific environments or scenarios where it's not strictly necessary, especially for single statements. However, it's considered a **best practice** to always include it for clarity, consistency, and compatibility, as it's part of the standardized SQL grammar and often required when executing multiple statements in a script.
    

### 3. Tokens

- A **token** is each individual, distinct part that makes up a SQL statement.
    
- In the example `SELECT name, salary FROM employees WHERE salary > 8000;`, the tokens include: `SELECT`, `name`, `,`, `salary`, `FROM`, `employees`, `WHERE`, `salary`, `>`, `8000`, `;`.
    

### 4. Types of Tokens

SQL tokens can be categorized into different types:

#### a. Keywords

- **Definition:** Keywords are specific, reserved words in SQL that define the actual _action_ or _operation_ that should be performed by the command. They have predefined meanings.
    
- **Examples from the transcript:**
    
    - **`SELECT`**: Indicates that you want to retrieve or read specific information from the database.
        
    - **`FROM`**: Specifies the table (or tables) from which the information should be retrieved.
        
    - **`WHERE`**: Defines a _filter_ or condition that must be true for data to be included in the result.
        
- **Case Sensitivity:** While not explicitly mentioned in this transcript, it's worth noting that SQL keywords are generally **case-insensitive** (e.g., `SELECT`, `select`, and `Select` are all treated the same). However, using uppercase for keywords is a common convention for readability.
    

#### b. Identifiers

- **Definition:** Identifiers are names given to database objects, such as columns, tables, databases, etc. They represent the data elements you are working with.
    
- **Examples from the transcript:**
    
    - `name`: An identifier for a column.
        
    - `salary`: An identifier for a column.
        
    - `employees`: An identifier for a table.
        
- **Usage with Keywords:** Identifiers are used in conjunction with keywords to specify _which_ specific data or objects the keyword should act upon. For example, `SELECT name, salary` means "select the data from the 'name' and 'salary' columns."
    

### 5. Clauses

- **Definition:** A clause is a combination of a keyword and its corresponding identifiers or conditions that together form a logical part of an SQL statement, defining a specific aspect of the operation.
    
- **Examples from the transcript:**
    
    - **`SELECT name, salary`**: This is a "SELECT clause." It specifies which columns to retrieve.
        
    - **`FROM employees`**: This is a "FROM clause." It specifies the source table for the data.
        
    - **`WHERE salary > 8000`**: This is a "WHERE clause" (or filter clause). It specifies the condition for filtering rows.
        

### 6. Operators

- **Definition:** Operators are symbols or keywords used in expressions to perform comparisons, calculations, or logical operations.
    
- **Example from the transcript:**
    
    - `>` (greater than sign): This is an **operator** used in the `WHERE` clause to compare the value in the `salary` column with `8000`.
        
- **Values/Expressions:** The `8000` in `salary > 8000` is referred to as a **value** or an **expression**. It's the specific information or data point being used in the comparison.
    
- **Other common comparison operators (not explicitly in transcript, but implied):**
    
    - `<` (less than)
        
    - `=` (equals)
        
    - `<=` (less than or equal to)
        
    - `>=` (greater than or equal to)
        
    - `!=` or `<>` (not equal to)
        

### Summary of the Example Command:

Let's break down the example: `SELECT name, salary FROM employees WHERE salary > 8000;`

- `SELECT`: Keyword (action: retrieve data)
    
- `name, salary`: Identifiers (columns to retrieve) - part of the SELECT clause.
    
- `FROM`: Keyword (source of data)
    
- `employees`: Identifier (table to retrieve from) - part of the FROM clause.
    
- `WHERE`: Keyword (filter condition)
    
- `salary`: Identifier (column to filter on)
    
- `>`: Operator (comparison: greater than)
    
- `8000`: Value/Expression (the condition's threshold) - these last three form the WHERE clause.
    
- `;`: Semicolon (statement terminator)
    

This command effectively asks the database: "Show me the `name` and `salary` of all records from the `employees` table where the `salary` is greater than 8000."
