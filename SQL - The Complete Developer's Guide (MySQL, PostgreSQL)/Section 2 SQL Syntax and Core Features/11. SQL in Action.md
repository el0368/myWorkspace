## Core SQL Syntax in Practice: A `SELECT` Example

This section aims to demonstrate how the theoretical SQL syntax concepts translate into a real-world query. The specific environment and database setup will be covered in later modules; for now, the focus is purely on observing the application of SQL syntax.

### The Scenario

Imagine you have a database for an online shop, and within this database, there's a table named `customers`. This `customers` table contains various pieces of information about your customers, including their email addresses. Your goal is to retrieve _all_ the email addresses from this table.

### Constructing the SQL Command

To achieve this, we'll use a `SELECT` statement. Based on the previously discussed core syntax, a simple `SELECT` query requires:

1. The `SELECT` keyword: This tells SQL that you intend to retrieve data.
    
2. The column(s) you want to retrieve: These are the identifiers that specify _what_ data you're interested in.
    
3. The `FROM` keyword: This tells SQL from which table the data should be retrieved.
    
4. The table name: This is the identifier for the source table.
    
5. A semicolon (`;`): This terminates the statement.
    

Given our scenario, we want to retrieve the `email` column from the `customers` table.

Therefore, the SQL command would look like this:

SQL

```SQL
SELECT email
FROM customers;
```

### Breaking Down the Command

- **`SELECT`**: This is the **keyword** indicating the desire to read data.
    
- **`email`**: This is an **identifier**, specifically the name of the column from which we want to retrieve values. It's assumed that the underlying `customers` table indeed has a column named `email`.
    
- **`FROM`**: This is the **keyword** specifying the source of the data.
    
- **`customers`**: This is an **identifier**, specifically the name of the table where the `email` column can be found.
    
- **`;`**: This is the **semicolon**, which terminates the SQL statement.
    

### Executing the Command and Interpreting the Result

When this SQL query is executed (or "run"), the database system processes it and returns a **result set**. In this specific example, the result set would be a single column, `email`, listing all the email addresses of the customers stored in the `customers` table.

This demonstrates the fundamental logic of SQL syntax: you `SELECT` specific `columns` `FROM` a particular `table` to retrieve desired information.

### Important Practical Considerations

1. **Semicolon Usage:**
    
    - As mentioned, the semicolon (`;`) should generally be used to terminate each SQL statement.
        
    - **Exception:** If you are executing a _single_ SQL statement in your environment, some systems might allow you to omit the semicolon. However, it is a **best practice** to always include it. This ensures your code is standard-compliant, more readable, and prevents potential issues when executing multiple statements or in different SQL environments where the semicolon might be strictly required as a statement separator.
        
2. **Case Sensitivity of Keywords:**
    
    - In the example (`SELECT email FROM customers;`), the keywords `SELECT` and `FROM` were written in `CAPITAL LETTERS`.
        
    - **General Rule:** SQL keywords (like `SELECT`, `FROM`, `WHERE`, `INSERT`, `UPDATE`, etc.) are generally **case-insensitive** across most major Relational Database Management Systems (RDBMS) like MySQL, PostgreSQL, and SQL Server. This means `SELECT`, `select`, or `SeLeCt` would all be understood by the database.
        
    - **Best Practice/Convention:** It is a widely adopted **convention** to write SQL keywords in **uppercase**. This significantly enhances the readability of SQL code, making it easier to distinguish keywords from identifiers (like table and column names). This practice also promotes consistency, especially in collaborative environments. The upcoming lecture will delve deeper into why specific formatting choices are made.
        

By understanding these initial practical applications and syntax rules, you are building a solid foundation for more complex SQL operations.
