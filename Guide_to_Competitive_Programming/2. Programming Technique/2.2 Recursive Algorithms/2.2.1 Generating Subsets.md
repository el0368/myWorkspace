### Rust Recursive Algorithms for Competitive Programming

In competitive programming, recursion offers an elegant approach to implement algorithms, especially for systematically exploring candidate solutions. This section covers recursive techniques in Rust, focusing on generating subsets and permutations, with an introduction to the broader backtracking technique. Below is a detailed explanation tailored for Rust, starting with generating subsets, structured to match the style of previous responses.

#### 2.2.1 Generating Subsets

One of the first applications of recursion is generating all subsets of a set with \(n\) elements. For example, for the set $\{1, 2, 3\}$, the subsets are $(\emptyset)$, $\{1\}$, $\{2\}$, $\{3\}$, $\{1, 2\}$, $\{1, 3\}$, $\{2, 3\}$, and $\{1, 2, 3\}$.

Rust can implement this using a recursive function called `search`, which maintains a `Vec<i32>` to store the current subset. The function starts with a parameter $(k = 1)$ and recursively builds all possible subsets.

Here’s the Rust implementation:

```rust
use std::io::{self, BufRead, BufWriter, Write};

fn search(k: i32, n: i32, subset: &mut Vec<i32>, stdout: &mut BufWriter<io::StdoutLock>) {
    if k == n + 1 {
        // Process the subset (e.g., print it)
        if subset.is_empty() {
            writeln!(stdout, "{}", "[]").expect("Failed to write");
        } else {
            write!(stdout, "[{}]", subset.iter().map(|&x| x.to_string()).collect::<Vec<String>>().join(", ")).expect("Failed to write");
            writeln!(stdout).expect("Failed to write newline");
        }
    } else {
        // Include k in the subset
        subset.push(k);
        search(k + 1, n, subset, stdout);
        subset.pop(); // Backtrack by removing k

        // Don’t include k in the subset
        search(k + 1, n, subset, stdout);
    }
}

fn main() {
    let mut stdin = io::stdin().lock();
    let stdout = io::stdout();
    let mut stdout = BufWriter::new(stdout.lock());

    // Read input (e.g., n = 3 for set {1, 2, 3})
    let mut line = String::new();
    stdin.read_line(&mut line).expect("Failed to read line");
    let n: i32 = line.trim().parse().expect("Expected an integer");

    let mut subset: Vec<i32> = Vec::new();
    search(1, n, &mut subset, &mut stdout);
}
```

- **Explanation**:
  - The `search` function takes parameters `k` (the current element to consider), `n` (the total number of elements), a mutable reference to `subset` (a `Vec<i32>` storing the current subset), and a mutable reference to a buffered `stdout` for output.
  - When `k == n + 1`, all elements have been processed, and the function outputs the current `subset`. If `subset` is empty, it prints `[]`; otherwise, it joins the elements with commas (e.g., `[1, 2]`).
  - For each `k`, the function:
    1. Includes `k` in `subset`, calls `search` recursively with `k + 1`, and then removes `k` with `pop()` to backtrack.
    2. Excludes `k` and calls `search` recursively with `k + 1`.
  - The recursion explores all combinations, generating each subset exactly once.

For \(n = 3\), the output will be:

```
[]
[3]
[2]
[2, 3]
[1]
[1, 3]
[1, 2]
[1, 2, 3]
```

This order reflects the recursion tree (as shown in Figure 2.1), where each node represents a `search` call, branching into including or excluding the current element.

Figure 2.1 illustrates the recursion tree for $(n = 3)$. Starting from `search(1)`, it branches:
- Upper branch: Includes 1, leading to `search(2)` with $\{1\}$, which further branches for 2 and 3, generating $\{1, 2\}$, $\{1, 3\}$, and $\{1, 2, 3\}$.
- Lower branch: Excludes 1, leading to `search(2)` with $\emptyset$, which branches for 2 and 3, generating $\{2\}$, $(\{3\}$, $\{2, 3\}$, and $\emptyset$.

- **Explanation of Figure 2.1**:
  - The root node is `search(1)`, representing the initial call.
  - Each `search(k)` call splits into two branches:
    - Upper: Includes $k$, adding it to `subset` (e.g., `search(2)` with $\{1\}$.
    - Lower: Excludes $k$, keeping `subset` unchanged (e.g., `search(2)` with $\emptyset$.
  - The process continues until `k = n + 1`, where each leaf node (e.g., `search(4)` with $\{1, 2, 3\}$ represents a complete subset.

#### 2. Additional Notes

- **Recursion Depth**: For \(n\) elements, the recursion depth is $(n + 1)$, and the total number of calls is $(2^n)$ (since each element can be included or excluded), generating all $(2^n)$ subsets.
- **Memory Efficiency**: Using `Vec::pop` for backtracking ensures `subset` reuses memory, avoiding allocations for each recursive call.
- **Output Customization**: The example prints subsets as strings. In contests, you might modify the `if k == n + 1` block to compute a result (e.g., sum of elements) instead of printing.
- **Performance**: Rust’s recursion is optimized in release builds (`cargo build --release`), but for large $(n)$ (e.g., $(n > 20)$, stack overflow may occur unless tail recursion optimization is applied or iteration is used.

#### Example: Enhanced Template with Subset Sum

A template computing the sum of each subset:

```rust
use std::io::{self, BufRead, BufWriter, Write};

fn search(k: i32, n: i32, subset: &mut Vec<i32>, stdout: &mut BufWriter<io::StdoutLock>) {
    if k == n + 1 {
        let sum: i32 = subset.iter().sum();
        writeln!(stdout, "Sum: {}", sum).expect("Failed to write");
    } else {
        subset.push(k);
        search(k + 1, n, subset, stdout);
        subset.pop();

        search(k + 1, n, subset, stdout);
    }
}

fn main() {
    let mut stdin = io::stdin().lock();
    let stdout = io::stdout();
    let mut stdout = BufWriter::new(stdout.lock());

    let mut line = String::new();
    stdin.read_line(&mut line).expect("Failed to read line");
    let n: i32 = line.trim().parse().expect("Expected an integer");

    let mut subset: Vec<i32> = Vec::new();
    search(1, n, &mut subset, &mut stdout);
}
```

- **Explanation**: For \(n = 3\), outputs sums like `Sum: 0`, `Sum: 3`, `Sum: 2`, etc., reflecting the sum of each subset’s elements.

Rust’s recursive approach to generating subsets uses a `search` function that builds subsets by including or excluding each element, leveraging `Vec` for dynamic storage and backtracking. The recursion tree (Figure 2.1) visualizes this process, ensuring all \(2^n\) subsets are explored.
