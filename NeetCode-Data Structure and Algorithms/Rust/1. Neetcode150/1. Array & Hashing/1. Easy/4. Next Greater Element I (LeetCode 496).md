The goal of LeetCode 496 "Next Greater Element I" is to find the "next greater element" for each number in a `nums1` array, where the search is performed in a second array, `nums2`.

The "next greater element" for a number `x` is the first number that appears to its right in `nums2` which is larger than `x`. If no such element exists, the answer is -1.

---

### The Approach 📈

A naive solution would be too slow. The efficient approach uses a **monotonic stack** and a **HashMap** to find the next greater element for every number in `nums2` in a single pass.

The monotonic stack will be kept in decreasing order.

#### Algorithm

1. **Pre-computation using `nums2`:**
    
    - Create an empty `HashMap` to store the mapping `number -> next_greater_number`.
        
    - Create an empty `stack`.
        
    - Iterate through each number `n` in `nums2`:
        
        - While the stack is not empty and the number on top of the stack is less than `n`, it means `n` is the next greater element for the number on top.
            
        - So, pop from the stack and insert into the `HashMap`: `map.insert(popped_element, n)`.
            
        - After the loop, push the current number `n` onto the stack.
            
2. **Building the Result:**
    
    - Now that the `HashMap` contains all the answers, iterate through `nums1`.
        
    - For each number in `nums1`, look it up in the `HashMap`. If it exists, use its value. If not, use -1.
        

---

### Rust Solution

Rust

```Rust
use std::collections::HashMap;

impl Solution {
    pub fn next_greater_element(nums1: Vec<i32>, nums2: Vec<i32>) -> Vec<i32> {
        // map: number -> next_greater_number
        let mut map = HashMap::new();
        let mut stack: Vec<i32> = Vec::new();

        // 1. Pre-compute next greater elements for nums2
        for &num in &nums2 {
            while let Some(&top) = stack.last() {
                if top < num {
                    // num is the next greater element for top
                    map.insert(stack.pop().unwrap(), num);
                } else {
                    break;
                }
            }
            stack.push(num);
        }

        // 2. Build the result for nums1 using the map
        nums1
            .iter()
            .map(|&num| *map.get(&num).unwrap_or(&-1))
            .collect()
    }
}
```

---

### Complexity

- **Time Complexity:** O(m+n), where `m` is the length of `nums2` and `n` is the length of `nums1`. We iterate through `nums2` once, and each element is pushed and popped from the stack at most once (O(m)). Then we iterate through `nums1` once (O(n)).
    
- **Space Complexity:** O(m). In the worst case (a strictly decreasing `nums2`), both the stack and the HashMap will store all `m` elements from `nums2`.
