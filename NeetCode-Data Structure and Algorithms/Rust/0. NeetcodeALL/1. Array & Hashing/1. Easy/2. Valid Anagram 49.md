The goal of LeetCode 49 "Group Anagrams" is to take a list of strings and group all the anagrams together.

---

### The Approach 🥈

This problem is a direct application of the "Valid Anagram" concept. The core idea is to find a unique "signature" or "key" for each anagram group. All strings that are anagrams of each other (like "eat", "tea", and "ate") should produce the same key.

A **HashMap** is the perfect tool for this. We can use the anagram signature as the key and a list of strings as the value.

#### Algorithm

1. Create an empty HashMap where keys are `String`s and values are `Vec<String>`.
    
2. Iterate through each string in the input list.
    
3. For each string, create its canonical key. The easiest way is to sort its characters. For example, "tea" becomes "aet".
    
4. Use this sorted key to store the original string in the HashMap. If the key doesn't exist, create a new list for it. If it does, append the string to the existing list.
    
5. After checking all strings, the values of the HashMap will be the groups of anagrams. Return these groups.
    

---

### Rust Solution

Rust

```Rust
use std::collections::HashMap;

impl Solution {
    pub fn group_anagrams(strs: Vec<String>) -> Vec<Vec<String>> {
        // The map will store: sorted_key -> [list_of_anagrams]
        let mut map = HashMap::new();

        for s in strs {
            // Create the key by sorting the string's bytes
            let mut key_bytes = s.as_bytes().to_vec();
            key_bytes.sort_unstable();
            // The sorted key is now a String
            let key = String::from_utf8(key_bytes).unwrap();
            
            // Find the entry for this key, or create a new one,
            // and push the original string `s` into its vector.
            map.entry(key).or_default().push(s);
        }

        // The values of the map are the groups we want.
        map.into_values().collect()
    }
}
```

### Complexity

- **Time Complexity:** $O(n \cdot k \log k)$
    
    - `n` is the number of strings in the list.
    - `k` is the maximum length of a string.
    - We iterate through `n` strings, and for each one, we sort its `k` characters, which takes $O(k \log k)$ time.
- **Space Complexity:** $O(n \cdot k)$
    
    - In the worst case, we store all the characters of all the strings in our HashMap.
