## Study Guide: 2.3 How to Analyze Code

This guide provides a set of simple rules to analyze the time complexity of your code. The goal is to look at any function and determine its Big O notation.

### Rule 1: Analyze Loops

A single loop is the most common structure you'll analyze. Its complexity is the length of the loop.

- **Rule:** A loop that runs `n` times is **O(n)**.
    
- **Example:**
    
    Go
    
    ```Go
    // This loop runs 'n' times. It's O(n).
    for i := 0; i < n; i++ {
        fmt.Println(i)
    }
    ```
    

---

### Rule 2: Analyze Nested Loops

When you have loops inside other loops, you multiply their complexities.

- **Rule:** Nested loops are **multiplied**. A loop running `n` times that contains another loop running `n` times is **$O(n \* n)$** or **O(n2)**.
    
- **Example:**
    
    Go
    
    ```Go
    // The outer loop is O(n). The inner loop is O(n).
    // Total complexity is O(n * n) = O(n^2).
    for i := 0; i < n; i++ {
        for j := 0; j < n; j++ {
            fmt.Println(i, j)
        }
    }
    ```
    

---

### Rule 3: Analyze Consecutive Statements

When you have multiple statements or loops in a row (not nested), you add their complexities.

- **Rule:** Add the complexity of each statement: O(A)+O(B).
    
- **Example:**
    
    Go
    
    ```Go
    // First loop is O(n).
    for i := 0; i < n; i++ {
        fmt.Println(i)
    }
    
    // Second loop is O(n).
    for j := 0; j < n; j++ {
        fmt.Println(j)
    }
    // Total complexity is O(n) + O(n) = O(2n).
    ```
    

---

### Rule 4: Drop Constants and Non-Dominant Terms

This is the most important rule for simplifying the final result.

1. **Drop Constants:** Big O doesn't care about how many times you loop, only about the relationship to `n`. `O(2n)` or `O(100n)` is simplified to just **O(n)**.
    
2. **Drop Non-Dominant Terms:** You only keep the term that grows the fastest. `O(n^2 + n)` is simplified to just **O(n2)**.
    

- **Rule:** Find the fastest-growing term and drop everything else.
    
- Example:
    
    Consider the code from Rule 3, which we calculated as O(2n). Applying this rule, we drop the constant 2, and the final complexity is O(n).
    
    Consider a function with a loop followed by a nested loop:
    
    Its complexity would be O(n)+O(n2). We drop the non-dominant n term, and the final complexity is O(n2).
    

---

### Rule 5: How to Spot O(logn)

Logarithmic complexity often appears when the problem size is **divided** in each step (usually by half).

- **Rule:** Look for loops where the counting variable is multiplied or divided in each step.
    
- **Example:**
    
    Go
    
    ```Go
    // The variable 'i' doubles each time, quickly reaching 'n'.
    // This is O(log n).
    for i := 1; i < n; i = i * 2 {
        fmt.Println(i)
    }
    ```
