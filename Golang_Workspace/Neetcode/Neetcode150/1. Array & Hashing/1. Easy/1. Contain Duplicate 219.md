The goal of LeetCode 219 "Contains Duplicate II" is to determine if an array contains two identical numbers where the difference between their indices is at most `k`.

---

### The Approach 🥈

This problem builds on the first "Contains Duplicate" challenge. Instead of just knowing _if_ we've seen a number, we now also need to know _where_ we last saw it (its index). A **HashMap** is the perfect tool for this.

The algorithm is:

1. Create an empty HashMap to store each number and its most recent index (`number -> index`).
    
2. Iterate through the input array, getting both the number and its current index `i`.
    
3. For each number, check if it's already in the HashMap.
    
    - If it is, get its previous index from the map.
        
    - Calculate the distance: `current_index - previous_index`.
        
    - If this distance is less than or equal to `k`, you've found a valid pair. Return `true`.
        
4. If the number wasn't in the map or the distance was too large, insert (or update) the number and its current index `i` into the map.
    
5. If you finish the loop, no such pair exists, so return `false`.
    

---

### Rust Solution

Rust

```Rust
use std::collections::HashMap;

impl Solution {
    pub fn contains_nearby_duplicate(nums: Vec<i32>, k: i32) -> bool {
        // 1. Create a HashMap to store number -> last_seen_index.
        let mut map = HashMap::new();

        // 2. Iterate through the array with indices.
        for (i, num) in nums.iter().enumerate() {
            // 3. Check if we've seen this number before.
            if let Some(prev_index) = map.get(num) {
                // If the distance is within k, we found our pair.
                if i - prev_index <= k as usize {
                    return true;
                }
            }
            // 4. Update the map with the number and its current index.
            map.insert(num, i);
        }

        // 5. If the loop completes, no such pair was found.
        false
    }
}
```

---

### Complexity

- **Time Complexity:** O(n)
    
    - We iterate through the array of `n` elements once. The HashMap operations (get and insert) take, on average, constant time, O(1).
        
- **Space Complexity:** O(n)
    
    - In the worst case (all elements are unique), the HashMap will store all `n` elements. In cases with many duplicates, the space complexity could be closer to O(k).
