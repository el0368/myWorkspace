After you create the factory function, the next step is to **use it exclusively** throughout your application whenever you need to create an instance of that struct.

This involves two parts: calling the function and immediately checking the returned `error`.

---

### How to Use It

You call your `New<TypeName>` function and handle both possible outcomes:

1. **Success**: If the `error` is `nil`, the returned object is valid, and you can proceed to use it.
    
2. **Failure**: If the `error` is **not** `nil`, you must handle the error and **not** use the returned object (which will be `nil`).
    

### Example

Here is the completed `main` function for the `User` example, showing how to use the `NewUser` factory.

Go

```Go
package main

import (
	"fmt"
	"log"
)

type User struct {
	ID    string
	Email string
}

func NewUser(id, email string) (*User, error) {
	if id == "" || email == "" {
		return nil, fmt.Errorf("id and email cannot be empty")
	}
	user := &User{
		ID:    id,
		Email: email,
	}
	return user, nil
}

func main() {
	// --- What's Next: Using the Factory ---

	// 1. Success Case
	u1, err := NewUser("user-123", "alex@example.com")
	if err != nil {
		// This block is skipped because err is nil
		log.Fatalf("Failed to create user: %v", err)
	}
	// The factory guarantees that 'u1' is a valid user.
	fmt.Printf("Successfully created user: %s\n", u1.Email)


	// 2. Failure Case
	_, err = NewUser("user-456", "") // Pass an invalid empty email
	if err != nil {
		// This block runs because err is NOT nil.
		fmt.Printf("Error creating user as expected: %v\n", err)
		// Do not proceed with the user object because it's nil.
	}
}
```

By always using the factory, you ensure that your application only ever works with valid `User` objects, making your code safer and more predictable.
