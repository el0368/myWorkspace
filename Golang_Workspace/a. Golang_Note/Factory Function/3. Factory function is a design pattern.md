The **Factory Function** is a design pattern where you use a function to create objects instead of using a class constructor directly.1

The main purpose is to **decouple** the code that _uses_ an object from the code that _creates_ the object. Your code asks a central "factory" for an object of a certain type, and the factory handles the logic of which specific class to instantiate.

---

### The Core Idea 🏭

Imagine a pizza restaurant. As a customer, you don't go into the kitchen to make your pizza. You just tell the cashier (the factory) that you want a "pepperoni pizza." The kitchen (the implementation) then creates the specific pizza you asked for and gives it to you. You don't need to know the exact recipe or cooking process.

The factory function pattern works the same way: your code asks the factory for an object, and the factory returns an instance of the correct struct, hidden behind a common interface.

---

### Key Components

1. **Product (Interface)**: A common interface that defines the methods all created objects will have.2
    
2. **Concrete Products (Structs)**: The specific structs that implement the Product interface.
    
3. **Factory Function**: The function that takes some input and decides which Concrete Product to create and return.
    

---

### Go Code Example

In this example, the `NewPizza` function is our factory. The `main` function (the client) only knows about the `Pizza` interface, not the specific `PepperoniPizza` or `VeggiePizza` structs.

Go

```Go
package main

import (
	"fmt"
)

// 1. The Product (Interface)
type Pizza interface {
	Prepare()
}

// 2. Concrete Products (Structs)
type PepperoniPizza struct{}

func (p *PepperoniPizza) Prepare() {
	fmt.Println("Preparing pepperoni pizza with salami and cheese.")
}

type VeggiePizza struct{}

func (v *VeggiePizza) Prepare() {
	fmt.Println("Preparing veggie pizza with bell peppers and onions.")
}

// 3. The Factory Function
func NewPizza(pizzaType string) (Pizza, error) {
	switch pizzaType {
	case "pepperoni":
		return &PepperoniPizza{}, nil
	case "veggie":
		return &VeggiePizza{}, nil
	default:
		return nil, fmt.Errorf("invalid pizza type: %s", pizzaType)
	}
}

func main() {
	// The client code asks the factory for pizzas without knowing the concrete types.
	pizza1, _ := NewPizza("pepperoni")
	pizza2, _ := NewPizza("veggie")

	pizza1.Prepare()
	pizza2.Prepare()
}
```

---

### Why Use It?

- **Decoupling**: The code that uses the objects doesn't need to know how they are created.
    
- **Centralized Logic**: All object creation logic is in one place, making it easy to manage and modify.3
    
- **Flexibility**: You can add new types of pizzas without changing the client code at all.4
