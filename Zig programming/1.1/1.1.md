### Lesson 1.1: Primitives & Space

In Zig, there are no "Numbers." There are only specific containers.

**The Integer Ladder:**

- `u8`: Small (0 to 255). Perfect for: Age, Days of Month, Color Values (0-255).
    
- `u16`: Medium (0 to 65,535). Perfect for: Map coordinates, RPG Health points.
    
- `u32`: Standard (0 to 4 Billion). Perfect for: Database IDs, High Scores.
    
- `usize`: The size of your RAM (Addressable Memory). Used for counting items in a list.
    

**The Boolean:**

- `bool`: True or False. Uses 1 byte (usually).

### The Fix: Syntax

You wrote: var level u8

This is Wrong. Zig demands precision. You must use a colon : to define the type and an equal sign = to give it a starting value.

**The Correct Zig Code:**

Code snippet

```
const std = @import("std");

pub fn main() void {
    var level: u8 = 1;          // Start at Level 1
    var gold: u32 = 0;          // Start with 0 Gold
    var is_alive: bool = true;  // Start Alive
    var xp: u32 = 0;            // Start with 0 XP
}
```

> **Note:** In Zig, we usually use `snake_case` (lowercase with underscores) for variables, not `CamelCase` or `PascalCase`. `IsAlive` should be `is_alive`.

### New Concept: Integer Overflow (The Trap)

You chose u8 for Level because it fits 100. Smart.

But what happens if your game has a bug?

Imagine this scenario:

1. The player is at Level **255** (the maximum a `u8` can hold).
    
2. You give them a "Level Up" bonus: `level + 1`.
    

Question:

In Zig, if you try to calculate 255 + 1 and put it into a u8 container, what happens?

A) It becomes 256.

B) It wraps around to 0 (Level 0).

C) The program crashes immediately.

**Choose carefully. This defines how safe Zig is compared to other languages.**

---
**Wrong.** The answer is **C) The program crashes immediately.**

This is the "Zig Difference."

In many other languages (like C or Java), the answer would be **B** (Wrap to 0). This is called "Silent Overflow," and it is responsible for billions of dollars in software bugs.

### The Logic: Why Crash?

If your character is Level 255 and gains a level, do you want them to reset to Level 0? **No.** That would make your user uninstall the game.

Zig believes that **a Crash is better than a Bug.**

- **Crash:** You see the error, you fix the logic.
    
- **Wrap (Bug):** The game continues, the player is Level 0, and you have no idea why.
    

### Syntax: How to force wrapping

If you actually _want_ the behavior you described (Option B), you must explicitly tell Zig using the **Wrapping Operator**: `+%`.

Code snippet

```
var level: u8 = 255;

// Normal Add: CRASH if level is 255
level += 1; 

// Wrapping Add: SAFE, level becomes 0
level +%= 1; 
```

**Lesson:** In Zig, symbols matter. `+` means "Add safely." `+%` means "Add and wrap if needed."

## Lesson 1.2: The Line (Arrays & Bounds)

Now that you know Zig watches your numbers, let's see how it watches your lists.

### The Syntax: Fixed Arrays

We are still on the **Stack**. We are making a list where we know the size _before_ we start.

Code snippet

```
// Format: [Size]Type = {Values}
var inventory: [3]u8 = [3]u8{ 5, 0, 10 }; 
// Index 0: 5 items
// Index 1: 0 items
// Index 2: 10 items
```

### The DSA Concept: Random Access (O(1))

Arrays are the fastest way to read data.

- **Concept:** To get the item at Index 2, the computer does not count "0, 1, 2". It calculates the exact address and teleports there.
    
- **Speed:** Instant. This is called **O(1)** or "Constant Time."
    

### The "Safety" Trap

Just like the Integer Overflow, Zig protects the Array boundaries.

Code snippet

```
var items = [3]u8{ 1, 2, 3 };
const hidden_item = items[5]; // ?
```
