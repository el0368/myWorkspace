## Lesson 1.1 (Part B): The Stuff Between the Integers

We covered whole numbers (`u8`, `u32`), but the world isn't always whole.

### 1. The Float (Decimals)

In Zig, if you want a decimal, you cannot use `u` or `i`. You must use `f` (Floating Point).

- `f16`: Very imprecise (rarely used).
    
- `f32`: Standard precision. Good for games, positions, physics. (7 digits of accuracy).
    
- `f64`: Double precision. Mandatory for financial math or scientific simulation. (15 digits of accuracy).
    

**The Syntax:**

Code snippet

```zig
const player_speed: f32 = 5.5; 
const pi: f64 = 3.14159265358979;
```

**The DSA Concept: Precision Drift**

**Warning:** Floats are not exact. `0.1 + 0.2` in a computer often equals `0.30000000000000004`.

- **Rule:** Never use floats for money. If you have $10.50, store it as `1050` cents (integer `u32`).
    

---

### 2. The Strictness (Type Conversion)

This is where Zig makes beginners cry. In other languages, if you try to put a small number (`u8`) into a big box (`u32`), the machine does it automatically.

**Zig does NOT trust you.** It forces you to be explicit.

**Scenario:** You want to add a `u8` (Level) to a `u32` (Score).

Code snippet

```zig
var level: u8 = 10;
var score: u32 = 1000;

// ERROR: Zig will stop here. You are mixing types!
score = score + level; 
```

The Fix: Explicit Casting

You must tell the machine: "Yes, I know level is small. Pretend it is big for a second."

Code snippet

```zig
// Correct Way
score = score + @as(u32, level);
```

- `@as`: This is a "Built-in Function" that casts a value.
    
- `(u32, level)`: "Treat `level` as a `u32`."
    

---

### 3. The Special Type: `usize`

We mentioned `usize` briefly, but you must understand it because you will see it _everywhere_.

- **Definition:** `usize` is an unsigned integer.
    
- **Size:** It depends on your computer.
    
    - If your chip is 64-bit, `usize` is 64 bits (`u64`).
        
    - If your chip is 32-bit, `usize` is 32 bits (`u32`).
        
- **The Usage:** You **MUST** use `usize` for counting things in a list (Arrays) or tracking memory size. Zig will not let you use a `u32` to index an array if the machine expects `usize`.

## The Completion Test (Lesson 1.1 Final)

Now we have actually covered Lesson 1.1. To prove you are ready for Arrays, solve this specific "Type Mixing" problem.

The Scenario:

You are calculating the total damage of an attack.

1. **Base Damage:** `250` (It fits in `u8`... barely).
    
2. **Multiplier:** `1.5` (This is a decimal).
    
3. **Result:** You need to store the final result as a whole number (`u32`).
    

**The Rules:**

1. Define `base_damage` (use `u8`).
    
2. Define `multiplier` (use `f32`).
    
3. Calculate `final_damage`.
    

_Hint: You cannot multiply a `u8` by an `f32` directly. You need to cast one of them. And then, the result will be a decimal... how do you get it back to an integer?_

**This is a hard challenge for a beginner. Give it your best shot.**

```zig
my answer

var base_damage: u8 = 250;
var multiplier: f32 = 1.5;
var final_damage: u32 = base_damage * @as(u32, multiplier);
```

---

You fell into the **"Truncation Trap."**

If you run your code, the answer will be `250`, not `375`.

### The Logic Failure

Let's look at your line: `base_damage * @as(u32, multiplier)`

1. **The Order of Operations:** You told the machine to convert `multiplier` (1.5) to an integer **BEFORE** multiplying.
    
2. **The Truncation:** When you force a float (`1.5`) into an integer, the machine chops off the decimal. `1.5` becomes `1`.
    
3. **The Math:** `250 * 1 = 250`.
    

You just lost 50% of your damage because you cast the types too early.

---

### The Correct Path: The "Float Sandwich"

To get the correct answer (`375`), you must:

1. **Promote** the integer up to a float. (`250` $\to$ `250.0`)
    
2. **Multiply** float by float. (`250.0 * 1.5` $\to$ `375.0`)
    
3. **Demote** the result back to an integer. (`375.0` $\to$ `375`)
    

### The Zig Syntax: `@floatFromInt` and `@intFromFloat`

In Zig, `@as` is mostly for simple integer-to-integer widening. For jumping between Integers and Floats, we use specific built-in functions.

**The Correct Code:**

Code snippet

```
const std = @import("std");

pub fn main() void {
    var base_damage: u8 = 250;
    var multiplier: f32 = 1.5;

    // Step 1: Convert u8 to f32 so we can do math
    var base_as_float = @floatFromInt(base_damage); 
    
    // Step 2: Do the math (250.0 * 1.5 = 375.0)
    var result_float = base_as_float * multiplier;

    // Step 3: Convert f32 back to u32
    var final_damage: u32 = @intFromFloat(result_float); 
    
    // final_damage is now 375
}
```

### Why is Zig so annoying about this?

You might think, "Why can't I just type `base * mult`?"

Because **conversion is dangerous.**

- `@intFromFloat` involves rounding or truncating. Zig wants you to know _exactly_ where you are losing data.
    
- If `result_float` was `375.9`, `@intFromFloat` would make it `375`. Are you okay with that? Zig forces you to write the code so you admit, "Yes, I am okay with losing the .9".

## Phase 1, Lesson 1.2: The Array (Static Lists)

Now we move to **Collections**. We are still on the **Stack** (Fixed memory).

### The Syntax: Defining an Array

An array is a block of memory for **Multiple items of the SAME type**.

Code snippet

```
// const name: [Size]Type = { values };
const scores: [5]u32 = [5]u32{ 10, 20, 30, 40, 50 };
```

There is a shortcut for the size. You can use `_` and let Zig count for you:

Code snippet

```
const scores = [_]u32{ 10, 20, 30, 40, 50 }; // Zig knows size is 5
```

### The DSA Concept: Random Access vs. Searching

This is your first major Algorithm lesson.

If I ask you: _"Is the number 50 in this list?"_

- **The Computer's Problem:** It cannot "see" the whole list at once. It has to check box 0, then box 1, then box 2...
    
- **Linear Search ($O(N)$):** If the list has 1 million items, it might have to check 1 million times. This is **Slow**.
    

If I ask you: _"Give me the 5th number."_

- **The Computer's Superpower:** It knows exactly where the 5th box is.
    
- **Random Access ($O(1)$):** It takes 1 step. This is **Fast**.
