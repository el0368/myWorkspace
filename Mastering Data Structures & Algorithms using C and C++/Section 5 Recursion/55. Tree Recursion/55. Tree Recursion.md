## Tree Recursion Study Guide

### 1. What is Tree Recursion?

- **Definition:** A recursive function is called "Tree Recursion" if it **calls itself more than one time** within its definition.
    
- **Contrast with Linear Recursion:**
    
    - **Linear Recursion:** A function calls itself only **one time**. (e.g., Head recursion, Tail recursion).
        
    - **Tree Recursion:** A function calls itself **two or more times**.
        
- **Structure Example:**
    
    C
    
    ```C
    void fun(int n) {
        if (n > 0) {
            // ... (optional operations)
            fun(n - 1); // First recursive call
            // ... (optional operations)
            fun(n - 1); // Second recursive call
            // ... (optional operations)
        }
    }
    ```
    

### 2. Example and Tracing Tree:

Let's use the provided example:

C

```C
void fun(int n) {
    if (n > 0) {
        printf("%d ", n);
        fun(n - 1); // First call
        fun(n - 1); // Second call
    }
}
// Calling fun(3);
```

- **How it Works (Tracing `fun(3)`):**
    
    - The function starts with `fun(3)`. It prints `3`.
        
    - It then makes its first recursive call: `fun(2)`.
        
    - Inside `fun(2)`: It prints `2`.
        
    - It makes its first recursive call: `fun(1)`.
        
    - Inside `fun(1)`: It prints `1`.
        
    - It makes its first recursive call: `fun(0)`.
        
    - `fun(0)`'s `if (n > 0)` condition is false, so it does nothing and returns.
        
    - Control goes back to `fun(1)`. `fun(1)` now makes its _second_ recursive call: `fun(0)`.
        
    - `fun(0)` again does nothing and returns.
        
    - Control goes back to `fun(1)`. `fun(1)` has now completed both its calls, so it returns.
        
    - Control goes back to `fun(2)`. `fun(2)` has now completed its first call (`fun(1)`).
        
    - `fun(2)` now makes its _second_ recursive call: `fun(1)`.
        
    - This `fun(1)` will print `1`, then call `fun(0)` (returns), then call `fun(0)` (returns), and then return itself.
        
    - Control goes back to `fun(2)`. `fun(2)` has now completed both its calls, so it returns.
        
    - Control goes back to `fun(3)`. `fun(3)` has now completed its first call (`fun(2)`).
        
    - `fun(3)` now makes its _second_ recursive call: `fun(2)`.
        
    - This `fun(2)` will essentially repeat the entire process that `fun(2)` went through earlier (print `2`, call `fun(1)` twice, which in turn calls `fun(0)` twice each).
        
- **Output:** The values are printed in a specific order due to the `printf` before the calls. The output for `fun(3)` will be: `3 2 1 1 2 1 1`
    

### 3. Activation Records and Stack Usage:

- Each recursive call, just like any function call, creates a new **activation record (stack frame)** on the call stack.
    
- For `fun(3)` in the example:
    
    - The maximum height/depth of the stack observed is `n+1` (e.g., for `n=3`, the max depth is 4: `fun(3)`, `fun(2)`, `fun(1)`, `fun(0)`).
        
    - Stack frames are pushed as calls are made and popped as they return.
        
    - The image shows how the stack dynamically grows and shrinks, reusing space as calls complete and new ones are initiated from different branches of the "tree."
        

### 4. Time Complexity of Tree Recursion:

- **Depends on Number of Calls:** The time complexity is determined by the total number of function calls made.
    
- **Exponential Growth:** For a function like `fun(n)` calling itself twice with `n-1`:
    
    - Level 0 (`fun(n)`): 1 call
        
    - Level 1 (`fun(n-1)`): 2 calls
        
    - Level 2 (`fun(n-2)`): 4 calls
        
    - Level `k`: 2k calls
        
- **Formula:** The total number of calls for an input `n` (down to base case 0) is roughly 2n+1−1.
    
- **Big O Notation:** This leads to an **exponential time complexity: O(2n)**.
    
    - **Important Note:** Not _all_ tree recursions will have O(2n). This specific example (like Fibonacci numbers without memoization) results in O(2n). Other tree recursions might have different complexities based on the number of calls and reduction of `n`.
        

### 5. Space Complexity of Tree Recursion:

- **Depends on Maximum Stack Height:** The space complexity is determined by the maximum depth of the call stack at any given time.
    
- **Linear Growth:** Even though many calls are made in total, the stack only needs to hold frames for one active "path" down the tree at a time. Once a branch finishes, its frames are popped, and new frames for another branch can reuse that space.
    
- **Big O Notation:** For the given example, the maximum stack depth is `n+1`. Therefore, the space complexity is **O(n)**.
    

### 6. Key Takeaways:

- Tree recursion involves multiple recursive calls within a single function.
    
- It often leads to **exponential time complexity** due to the branching nature of the calls.
    
- Despite exponential time, its **space complexity is typically linear (O(n))** because the call stack only grows to the maximum depth of the recursion, not the total number of calls.
    
- Understanding the order of calls (pre-order traversal in the example) is crucial for tracing execution and predicting output.
