## Study Guide: Sum of First N Natural Numbers

This guide explores three approaches to calculating the sum of the first N natural numbers (e.g., 1+2+3+...+n), analyzing each method's logic, implementation, and performance.

### 1. The Recursive Approach 🧠

The problem can be defined recursively. The sum of N numbers is simply the sum of the first (N-1) numbers, plus N itself.

#### a. The Recurrence Relation

This logic can be written as a mathematical formula called a **recurrence relation**:

- Sum(n)=Sum(n−1)+n
    
- **Base Case:** Sum(0)=0 (The sum of zero numbers is zero).
    

A **base case** is essential to prevent infinite recursion. It provides a direct answer for the smallest input, stopping the recursive calls.

#### b. Rust Implementation

This recurrence relation translates directly into a recursive function.

Rust

```Rust
fn sum_recursive(n: i32) -> i32 {
    // Base Case: If n is 0, stop and return 0.
    if n == 0 {
        0
    } else {
        // Recursive Step: Call itself with a smaller value.
        sum_recursive(n - 1) + n
    }
}
```

#### c. Performance Analysis

- **Time Complexity: O(n)** — To find `sum(n)`, the function must make `n+1` separate calls (from `n` down to `0`). The number of operations grows linearly with the input `n`.
    
- **Space Complexity: O(n)** — Each function call creates an "activation record" on the program's stack. For `sum(n)`, `n+1` frames are stored on the stack before they start returning, consuming memory that grows linearly with `n`.
    

**Key Takeaway:** The recursive solution is elegant and easy to write from the mathematical definition, but it is costly in both time and memory due to the overhead of function calls.

### 2. The Iterative (Loop) Approach ⚙️

This method uses a simple loop to add each number from 1 to `n` to a running total.

#### a. Rust Implementation

Rust

```Rust
fn sum_iterative(n: i32) -> i32 {
    let mut total = 0;
    // Loop from 1 up to and including n.
    for i in 1..=n {
        total += i;
    }
    total
}
```

#### b. Performance Analysis

- **Time Complexity: O(n)** — The loop runs `n` times. The work is directly proportional to the input `n`.
    
- **Space Complexity: O(1)** — This function uses a fixed amount of memory (for the variables `total`, `i`, and `n`) regardless of the size of `n`. This is much more memory-efficient than the recursive approach.
    

**Key Takeaway:** The iterative solution is less elegant than recursion but far more efficient in terms of space.

### 3. The Formula Approach 🚀

Mathematics provides a direct formula to calculate the sum of the first N natural numbers.

#### a. The Formula

Sum(n)=2n(n+1)​

#### b. Rust Implementation

Rust

```Rust
fn sum_formula(n: i32) -> i32 {
    // A single, direct calculation.
    n * (n + 1) / 2
}
```

#### c. Performance Analysis

- **Time Complexity: O(1)** — The function performs a fixed number of operations (one addition, one multiplication, one division) regardless of the value of `n`. This is called **constant time** and is extremely fast.
    
- **Space Complexity: O(1)** — It uses a fixed, minimal amount of memory.
    

**Key Takeaway:** If a direct mathematical formula exists for a problem, it is almost always the most efficient solution.

|Method|Time Complexity|Space Complexity|Ease of Writing|Main Advantage|

|**Recursion**|O(n)|O(n)|Easy (from definition)|Elegant, good for problems that are naturally recursive.|

While recursion is a powerful tool for learning and for solving problems that are inherently recursive (like traversing trees), in practical applications like this one, **iteration** is generally preferred over recursion for its efficiency.
