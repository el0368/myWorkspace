He was explaining the subtle but important difference between the `.nodeName` and `.tagName` properties.

The main point is: **`.nodeName` works on all node types, while `.tagName` only works on Element nodes.1**

---

### The Analogy: Roles in a Company 🏢

Think of all the nodes in the DOM as people inside a company building.

- **`.nodeName`** is like asking anyone, "What is your role here?"
    
    - An employee will say "Manager" (`<h1>`).
        
    - A visitor will say "Visitor" (`#text`).
        
    - A security guard will say "Security" (`#comment`).
        
    - **Everyone has an answer.**
        
- **`.tagName`** is like asking, "What is your official employee job title?"
    
    - An employee will say "Manager" (`H1`).
        
    - A visitor or security guard **doesn't have an employee job title**, so the question doesn't apply to them (`undefined`).
        

---

### The Key Difference in Practice

|Property|Works On...|Example on an `<h1>`|Example on a Comment|
|---|---|---|---|
|`.nodeName`|**All Node Types**|`'H1'`|`'#comment'`|
|`.tagName`|**Only Element Nodes**|`'H1'`|`undefined`|

### Which One Should You Use?

As the lecturer mentioned, when you are working with an element, both `.nodeName` and `.tagName` will give you the same result (the tag name in uppercase).

However, **`.nodeName` is a slightly safer and more consistent choice** because it will always return a value, no matter what type of node you are inspecting.
