
## JavaScript DOM Manipulation Study Guide (Part 3: Events)

This guide focuses on **events** in JavaScript, which enable interactivity on your web pages. You'll learn how to listen for various user actions (like clicks, key presses, mouse movements) and execute JavaScript code in response.

---

### 7. Understanding Events and Event Listeners

- **What are Events?** (00:12)
    
    - Actions or occurrences that happen in the browser, such as a user clicking a button, typing in an input field, or moving their mouse.
        
    - They are a crucial part of making web pages interactive.
        
- **Why use Event Listeners?** (02:33)
    
    - The modern and best practice approach for handling events.
        
    - Separates JavaScript logic from HTML markup, leading to cleaner, more maintainable code (avoid `onclick="..."` directly in HTML).
        
    - Allows multiple event handlers for the same event on the same element.
        

#### 7.1. Adding an Event Listener

- **`element.addEventListener(eventType, functionToRun)`** (03:09)
    
    - **Purpose:** Attaches an event handler function to a specific element. When the specified `eventType` occurs on that `element`, the `functionToRun` will be executed.
        
    - **`eventType`**: A string representing the type of event (e.g., `'click'`, `'keydown'`, `'mousemove'`).
        
    - **`functionToRun`**: The JavaScript function to be executed when the event fires. This can be an anonymous function or a named function.
        
- **Example (Click Event):**
    
    JavaScript
    
    ```JavaScript
    // HTML (under the UL, just above where the script tag would be)
    // <button id="button" class="btn btn-dark btn-block">Click Here</button>
    
    var button = document.getElementById("button");
    
    // Option 1: Anonymous function
    button.addEventListener("click", function () {
        console.log("Button clicked!");
    });
    
    // Option 2: Named function (better for reusability/readability)
    function runEvent(e) { // 'e' or 'event' is the event object, passed automatically
        console.log("Event Type: " + e.type);
    }
    button.addEventListener("click", runEvent); // No parentheses for runEvent!
    ```
    
- **Integrating with DOM Manipulation:** (03:48)
    
    - Inside your event handler function, you can use any of the DOM selection and manipulation methods learned in previous parts to change elements, styles, content, etc.
        
    - Example: Change header title and main background on button click.
        
        JavaScript
        
        ```JavaScript
        button.addEventListener('click', function() {
            document.getElementById("header-title").textContent = "Changed!";
            document.querySelector("#main").style.backgroundColor = "lightgray";
        });
        ```
        

### 8. The Event Object (`e` or `event`)

- When an event fires, JavaScript automatically passes an **Event Object** to the event handler function (commonly named `e` or `event`). (05:03)
    
- This object contains valuable information about the event that occurred.
    
- **Key Event Object Properties:**
    
    - **`e.target`**: (06:02) The actual DOM element that triggered the event.
        
        - `e.target.id`: Get the ID of the clicked element.
            
        - `e.target.className`: Get the string of classes.
            
        - `e.target.classList`: Get a `DOMTokenList` (array-like) of classes, useful for adding/removing classes. (07:07)
            
    - **`e.type`**: (08:46) The type of event that was fired (e.g., `'click'`, `'mouseover'`, `'keydown'`).
        
    - **Mouse Coordinates:**
        
        - `e.clientX` / `e.clientY`: (09:14) X and Y coordinates of the mouse pointer _relative to the browser window_.
            
        - `e.offsetX` / `e.offsetY`: (10:05) X and Y coordinates of the mouse pointer _relative to the element itself_ that triggered the event.
            
    - **Keyboard Modifiers:** (10:52)
        
        - `e.altKey`: `true` if the Alt key was held down during the event, `false` otherwise.
            
        - `e.ctrlKey`: `true` if the Control key was held down.
            
        - `e.shiftKey`: `true` if the Shift key was held down.
            
        - These are useful for creating different behaviors based on key combinations.
            

### 9. Common Event Types

#### 9.1. Mouse Events

- **`click`**: (12:39) Fires when an element is clicked (mouse down and up on the same element).
    
- **`dblclick`**: (14:18) Fires when an element is double-clicked.
    
- **`mousedown`**: (14:40) Fires when a mouse button is pressed down on an element.
    
- **`mouseup`**: (15:03) Fires when a mouse button is released over an element.
    
- **`mouseenter`**: (16:33) Fires when the mouse pointer enters the element's bounding box. _Does not bubble to children._
    
- **`mouseleave`**: (17:09) Fires when the mouse pointer leaves the element's bounding box. _Does not bubble to children._
    
- **`mouseover`**: (17:23) Fires when the mouse pointer enters an element _or one of its child elements_. (17:45)
    
- **`mouseout`**: (17:23) Fires when the mouse pointer leaves an element _or one of its child elements_.
    
- **`mousemove`**: (19:15) Fires repeatedly as the mouse pointer moves while inside an element. This is often used for interactive effects (e.g., changing background color based on mouse position). (21:05)
    
    - Example: Changing `document.body` background color using `e.offsetX` and `e.offsetY` with `rgb()` values.
        

#### 9.2. Keyboard & Input Events

- **`keydown`**: (24:15) Fires when a key is pressed down. (24:29)
    
- **`keyup`**: (26:17) Fires when a key is released. (26:28)
    
- **`keypress`**: (26:34) Fires when a key is pressed (not all keys fire this, e.g., Alt, Ctrl, Shift).
    
- **Accessing Input Value:** Within keyboard event handlers, `e.target.value` gives you the current text in the input field. (24:43)
    
- **`focus`**: (27:02) Fires when an element (like an input field) gains focus (e.g., user clicks into it).
    
- **`blur`**: (27:23) Fires when an element loses focus (e.g., user clicks outside an input field).
    
- **`cut`**: (27:37) Fires when the user cuts content from an input field.
    
- **`paste`**: (28:39) Fires when the user pastes content into an input field.
    
- **`input`**: (28:52) Fires when the `value` of an `<input>`, `<select>`, or `<textarea>` element has been changed by the user. This is a very versatile event as it covers typing, cutting, pasting, and selecting options.
    

#### 9.3. Form & Select Events

- **`change`**: (30:19) Fires when the value of an `<input>`, `<select>`, or `<textarea>` element has been changed and the element _loses focus_. For `<select>` elements, it fires immediately when an option is chosen.
    
    - Example: Getting the selected value from a dropdown: `e.target.value`. (31:16)
        
- **`submit`**: (31:51) Fires when a form is submitted.
    
    - **`e.preventDefault()`**: (32:38) Crucial for `submit` events! By default, forms will cause a page reload (or navigate to an action URL). Calling `e.preventDefault()` stops this default behavior, allowing you to handle the form submission purely with JavaScript (e.g., sending data via AJAX, validating inputs, or just manipulating the DOM).
