## Module 2: The Node Family Tree & Identification

Welcome to Module 2. In the first module, we learned that everything in the DOM is a "node." Now, we'll learn how these nodes are organized into a logical structure and how we can identify them, giving us the power to navigate the page with precision.

### Lesson 2.1: Node Relationships - Parent, Child, & Siblings

The DOM organizes all nodes into a strict hierarchy, just like a **family tree** 🌳. Understanding these relationships is the key to moving around the page.

- **`parentNode`**: This property lets you travel up the tree from the current node to the one that contains it. Every child has exactly one parent.
    
- **`.children`**: This property gives you a list of all the **Element Nodes** directly inside the current node. This is your most common tool for moving down the tree, as it conveniently ignores the "invisible" text nodes created by whitespace.
    
- **`.nextElementSibling`** / **`.previousElementSibling`**: These properties let you move sideways to the next or previous "sibling" element, ignoring any text or comment nodes in between.
    

JavaScript

```JavaScript
const parentElement = document.querySelector('.parent');
const firstChild = parentElement.children[0];
const secondChild = firstChild.nextElementSibling;

console.log(secondChild.textContent); // Accesses the second child
```

### Lesson 2.2: Identifying Nodes (`.nodeType` & `.nodeName`)

Once you've selected a node, you often need to confirm what kind of node it is. Every node has properties that act like an **ID card** 🪪.

- **`.nodeType`**: This returns a number code that identifies the node's general category. You don't need to memorize the numbers, but the two most important are:
    
    - **`1`**: An **Element Node** (e.g., `<div>`, `<h1>`).
        
    - **`3`**: A **Text Node**.
        
- **`.nodeName`**: This returns a human-readable string with the node's specific name.
    
    - For an element, it returns the tag name in uppercase (e.g., `'DIV'`, `'H1'`).
        
    - For a text node, it returns `'#text'`.
        

JavaScript

```JavaScript
const myElement = document.querySelector('h1');
console.log(myElement.nodeType); // Outputs: 1
console.log(myElement.nodeName); // Outputs: 'H1'
```

### Lesson 2.3: Seeing the Full Picture with `.childNodes`

As we just learned, the `.children` property is convenient because it only gives you the element nodes. But what if you need to see _everything_, including the invisible text nodes for whitespace? For that, you use `.childNodes`.

- **Analogy**: `.childNodes` is like putting on **X-ray goggles** 👓. It reveals the complete, unfiltered structure, including all the hidden text and comment nodes.
    

This property is less common in day-to-day use but is an essential tool for debugging tricky layout issues where whitespace might be causing a problem.

HTML

```HTML
<div class="parent">
  <p>Child 1</p>
  <p>Child 2</p>
</div>
```

JavaScript

```JavaScript
const parentElement = document.querySelector('.parent');

console.log(parentElement.children.length);   // Outputs: 2 (the two <p> elements)
console.log(parentElement.childNodes.length); // Outputs: 5 (text, p, text, p, text)
```
