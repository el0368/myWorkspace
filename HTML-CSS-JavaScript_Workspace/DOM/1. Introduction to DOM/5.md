### ## Part 5 (Elaborated): Let's Build! A Practical "Light Switch"

This is the grand finale where we stop talking and start doing. We'll build a simple "light switch" to see how the HTML blueprint, the DOM model, and our JavaScript "hands" all work together in perfect harmony.

Our goal: When a user clicks a button, the background of a "room" will toggle between light and dark, and the button's text will update accordingly.

---

### Phase 1: The Blueprint (The HTML & CSS)

First, we create our static instruction manual. This file defines the initial structure and the potential styles.

HTML

```HTML
<style>
  /* The "Room" element's default style */
  #light-switch-room {
    height: 200px;
    border: 2px solid black;
    background-color: #FFFFFF; /* White background by default */
    transition: background-color 0.5s; /* Smooth transition */
  }

  /* A style rule that is currently NOT being used.
     It's waiting for JavaScript to apply it. */
  .dark-mode {
    background-color: #333333; /* Dark background */
  }
</style>

<div id="light-switch-room"></div>
<button id="light-switch-btn">Turn Off The Lights</button>
```

- **What we've done:** We've created two key elements: a `<div>` to be our "room" and a `<button>` to be our "switch."
    
- **The `id` attributes:** We've given them unique IDs (`light-switch-room` and `light-switch-btn`). This is like putting a unique serial number on our most important LEGO bricks so we can find them easily later.
    
- **The `.dark-mode` class:** We've defined a CSS class that changes the `background-color`. Right now, this style is inactive because no element has this class. It's a potential state waiting to be triggered.
    

---

### Phase 2: Finding Our Pieces & Preparing for Action (The JavaScript)

Now, we use our JavaScript "hands" to interact with the live DOM model that the browser built from our HTML.

JavaScript

```JavaScript
// 1. Finding our elements (Querying)
// We're telling the document: "Find the node with the ID 'light-switch-room' and hand it to me."
const room = document.getElementById('light-switch-room');

// "Now, find the node with the ID 'light-switch-btn'."
const switchBtn = document.getElementById('light-switch-btn');

// At this point, `room` and `switchBtn` are live DOM objects. We have "grabbed" our pieces.

// 2. Creating the interaction (Adding an Event Listener)
// We're attaching an instruction to our button object.
// "Listen for a 'click' event. When you hear one, run the function I'm giving you."
switchBtn.addEventListener('click', function() {
    // All the manipulation code will go inside here.
});
```

- **The "Finding" Step:** We use `document.getElementById()` to get direct references to our two important DOM nodes. Our JavaScript now holds these live objects in the `room` and `switchBtn` variables.
    
- **The "Listening" Step:** `addEventListener` is the key to interactivity. It tells the browser to pay attention to a specific event on a specific node. It bridges the gap between a user's action and our code's reaction.
    

---

### Phase 3: The Action! (DOM Manipulation)

This is the code that runs _only when the button is clicked_. This is where we change the live LEGO model.

JavaScript

```JavaScript
// This is the full JavaScript code
const room = document.getElementById('light-switch-room');
const switchBtn = document.getElementById('light-switch-btn');

switchBtn.addEventListener('click', function() {

  // Action A: Toggle the class on the room element
  room.classList.toggle('dark-mode');

  // Action B: Check the state of the room and update the button's text
  if (room.classList.contains('dark-mode')) {
    // If the room now has the 'dark-mode' class...
    switchBtn.textContent = 'Turn On The Lights';
  } else {
    // If it does not...
    switchBtn.textContent = 'Turn Off The Lights';
  }
});
```

- **`room.classList.toggle('dark-mode')`:** This is a powerful manipulation method. `toggle` checks if the `dark-mode` class exists on the `room` element. If it doesn't, it adds it. If it does, it removes it. The browser sees this class change and instantly applies or removes the corresponding CSS.
    
- **`room.classList.contains('dark-mode')`:** This is an example of _reading_ from the DOM. We are asking the live model, "Does the room element currently have this class?" to determine its state.
    
- **`switchBtn.textContent = '...'`:** Based on the state we just read, we perform another manipulation, this time changing the text inside the button to give the user proper feedback.
    

You've now seen the full journey: from a static HTML blueprint to a live DOM model that can be found, listened to, and changed by JavaScript to create an interactive experience.
