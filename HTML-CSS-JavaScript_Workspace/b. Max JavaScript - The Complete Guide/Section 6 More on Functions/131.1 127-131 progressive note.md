## JavaScript Functions & Methods: A Study Guide

This guide covers functions and methods, how they relate to objects, and different ways to create them in JavaScript, based on what we've learned.

---

### Part 1: Functions vs. Methods

**Core Idea:** Functions let us define code to use on-demand. When a function is attached to an object and called using dot notation, we call it a **method**.

1. **Direct Function Execution:**
    
    - You define a function using the `function` keyword and a name.
        
    - To run it immediately, you call its name followed by parentheses `()`.
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        function startGame() {
          console.log("Game is starting....");
        }
        startGame(); // Runs right away on script execution.
        ```
        
    - This is a **direct execution**.
        
2. **Indirect Function Execution (Event Listener):**
    
    - You can attach a function to an event on an HTML element (like a button).
        
    - We use `addEventListener` for this. You pass the function's name _without_ parentheses.
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        const startGameBtn = document.getElementById('start-game-btn');
        function startGame() {
          console.log("Game is starting....");
        }
        startGameBtn.addEventListener("click", startGame); // Function runs only when button is clicked.
        ```
        
    - This is an **indirect execution** because the `addEventListener` mechanism triggers it, not your direct code call.
        
3. **Understanding Methods:**
    
    - The `addEventListener` isn't a function _we_ defined; it's provided by the browser.
        
    - We call it on `startGameBtn` using **dot notation** (`startGameBtn.addEventListener`). This suggests `startGameBtn` is an **object**.
        
    - Objects can have **properties** (like `person.name`). But here, `addEventListener` is executed, not just accessed.
        
    - This means **functions can be stored inside objects**.
        
    - When a function is stored as a property of an object, it's called a **method**.
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        const person = {
          greet: function() { // 'greet' is a method
            console.log("hello there!");
          }
        };
        person.greet(); // Calling the method on the 'person' object.
        ```
        
    - `addEventListener` is a **method** on the `startGameBtn` object.
        
    - `getElementById` is a **method** on the `document` object (which represents the HTML document). It gives us the button object.
        

**Summary of Part 1:** Methods are functions attached to objects, accessed with dot notation. They perform actions for that object.

### Part 2: Functions Are Objects

**Core Idea:** Functions in JavaScript are actually a special type of **object**.

1. **Proof with `typeof`:**
    
    - The `typeof` operator tells us the type of a value.
        
    - If you check the `typeof` a function (without calling it), it returns `"function"`.
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        function startGame() { /* ... */ }
        console.log(typeof startGame); // Output: "function"
        // Note: console.log(typeof startGame()); would be "undefined" because
        // startGame() returns nothing, and typeof checks the return value.
        ```
        
    - While it says "function," it's important to know that `function` is _based on object_.
        
2. **Proof with `console.dir()`:**
    
    - `console.dir()` gives a detailed, interactive view of an object's properties in the console.
        
    - If you use `console.dir()` on a function, you'll see it has various **properties** (like `name`, `arguments`, `prototype`, `scopes`).
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        function startGame() { /* ... */ }
        console.dir(startGame); // In console, you can expand this to see properties.
        ```
        
    - This proves that functions are indeed objects; they are key-value pairs just like other objects.
        
3. **Implications of Functions Being Objects:**
    
    - Functions are **reference types** (like arrays and regular objects), meaning they're stored in the **heap**.
        
    - This allows them to be passed around, assigned to variables, and generally treated like other data values in JavaScript.
        

**Summary of Part 2:** Functions are objects, even though `typeof` returns "function." This is evident through `console.dir()` showing their properties, and it means they're reference types stored in the heap.

### Part 3: Function Declarations vs. Function Expressions

**Core Idea:** There are two main syntaxes for defining functions, and their key difference lies in how JavaScript handles them during the "hoisting" phase.

1. **Function Declaration (or Function Statement):**
    
    - **Syntax:** `function functionName() { ... }`
        
    - **Hoisting:** JavaScript automatically "hoists" (moves) **the entire function definition** to the top of its scope.
        
    - **Benefit:** You can **call the function before it's defined** in your code, and it will work.
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        myOldSchoolFunction(); // This works!
        function myOldSchoolFunction() {
          console.log("I'm defined with a declaration.");
        }
        ```
        
    - **Semicolon:** Typically **no semicolon** after the closing curly brace.
        
2. **Function Expression:**
    
    - **Syntax:** `const variableName = function [optionalFunctionName]() { ... };`
        
    - **Core Idea:** The function definition is created as a value and then assigned to a variable or constant.
        
    - **Hoisting:** Only the **variable declaration** (`const variableName`) is hoisted, _not_ the function's definition. The variable might be hoisted as `undefined` (for `var`) or be in a Temporal Dead Zone (for `const`/`let`).
        
    - **Implication:** You **cannot call the function before the line where it is assigned** to the variable.
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        // myExpressionFunction(); // ERROR: Cannot access before initialization!
        const myExpressionFunction = function() {
          console.log("I'm defined with an expression.");
        };
        myExpressionFunction(); // This works!
        ```
        
    - **Semicolon:** A **semicolon is conventional** after the closing curly brace, as it's an assignment statement.
        
3. **Why Choose One?**
    
    - **Declarations:** Useful if you prefer to define functions at the bottom of your file and call them at the top.
        
    - **Expressions:** Often preferred for enforcing a "define before use" style, which can make code flow clearer. Both styles are perfectly valid.
        

**Summary of Part 3:** Function Declarations are fully hoisted, allowing calls before definition. Function Expressions only hoist the variable, requiring definition before calls.

### Part 4: Anonymous Functions (and Debugging with Names)

**Core Idea:** Anonymous functions have no name, but they are incredibly useful, especially as callbacks. Giving them an internal name helps with debugging.

1. **Anonymous Functions Defined:**
    
    - A function with **no name** after the `function` keyword.
        
    - **Example:** `function() { ... }`
        
    - You must either assign them to a variable or pass them as an argument to another function, since they can't be called by name.
        
2. **Anonymous Functions in Event Listeners:**
    
    - They are commonly used when you need a function only for one specific event, right where the event listener is set up.
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        const startGameBtn = document.getElementById("start-game-btn");
        startGameBtn.addEventListener("click", function() { // Anonymous function in-place
          console.log("Game is starting via anonymous function!");
        });
        ```
        
    - **Benefit:** The code for the event is immediately visible where the listener is defined, which can make it easier to read.
        
    - **Important:** Don't add `()` after the anonymous function when passing it to `addEventListener`. That would make it run immediately, not on click.
        
3. **Debugging Anonymous Functions (Using Named Function Expressions):**
    
    - If an error occurs inside a purely anonymous function, the browser's error message might just say `<anonymous>`. This isn't very helpful for identifying the source.
        
    - **Solution:** You can give an anonymous function an **internal name**. This doesn't let you call it by that name directly, but it _will_ appear in error messages.
        
    - **Example (Named Function Expression as callback):**
        
        JavaScript
        
        ```JavaScript
        startGameBtn.addEventListener("click", function startGameHandler() { // 'startGameHandler' is the internal name
          console.log("Game started!");
          // console.log(nonExistent); // If this causes an error...
        });
        ```
        
    - If an error occurs, the console will show `at startGameHandler (...)`, making debugging much easier.
        

**Summary of Part 4:** Anonymous functions are unnamed functions useful for in-place callbacks. Giving them an internal name (creating a named function expression) is a good practice for clearer error messages during debugging.
