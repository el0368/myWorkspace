## JavaScript Functions & Methods: A Study Guide

### 130. Function Expressions vs Function Declarations

**Core Idea:** There are two main ways to define functions in JavaScript, and they behave differently, especially regarding when they become available to be called (hoisting).

1. **Function Expressions: A New Way to Create Functions:**
    
    - So far, we've used `function startGame() { ... }` (a **Function Declaration**).
        
    - A **Function Expression** is when you create a function on the **right side of an assignment operator** (like an equals sign `=` or a colon `:` in an object).
        
    - **Example:**
        
        JavaScript
        
        ```JavaScript
        // Assigning a function to a constant 'start'
        const start = function startGame() { // 'startGame' here is an *internal* name
          console.log("Game is staring....");
        };
        ```
        
    - You then call this function using the variable name it was assigned to: `start()`.
        
    - If you try to call `start()` _before_ its definition line when defined this way, you'll get an error (`start is not defined` or `Cannot access 'start' before initialization`). This is different from how declarations work.
        
    - You can also **omit the internal name** (like `startGame` in the example above) when using a function expression if you don't really need it. This creates an **anonymous function expression**.
        
        JavaScript
        
        ```JavaScript
        const start = function() { // Anonymous function assigned to 'start'
          console.log("Game is staring....");
        };
        ```
        
    - **Convention:** For function expressions, typically place the parentheses `()` right after `function` (no whitespace) and add a **semicolon** `;` at the end of the line (because it's an assignment statement).
        
2. **The Key Difference: Hoisting:**
    
    - **Function Declarations (`function name() { ... }`):**
        
        - JavaScript **automatically hoists** the function to the top of its scope and **fully initializes it**.
            
        - This means you **can call a function declaration before you define it** in your code. JavaScript acts as if it was defined at the top.
            
        - **Example:**
            
            JavaScript
            
            ```JavaScript
            myDeclaration(); // This works fine!
            function myDeclaration() {
              console.log("I am a function declaration.");
            }
            ```
            
    - **Function Expressions (`const name = function() { ... };`):**
        
        - **Hoisting still happens, but differently:** The variable (e.g., `const start`) gets hoisted, but it's initially hoisted as `undefined` (or in a "Temporal Dead Zone" for `const`/`let`).
            
        - The **function itself is not initialized** until its line of definition is executed.
            
        - This means you **cannot call a function expression before it's defined** in your code. You _must_ define it before trying to call it.
            
        - **Example:**
            
            JavaScript
            
            ```JavaScript
            // myExpression(); // ERROR: Cannot access 'myExpression' before initialization!
            const myExpression = function() {
              console.log("I am a function expression.");
            };
            myExpression(); // This works.
            ```
            
3. **Why Choose One? (Preferences):**
    
    - **Declarations:** Can be convenient if your code style places functions at the end of the file, allowing calls from anywhere above.
        
    - **Expressions:** Force you to define functions before you use them, which some developers (including your instructor) find to be a cleaner and more organized code style.
        
    - **Ultimately:** Both are valid and perfectly fine. The choice is often a matter of personal or team preference. There is no "bad" approach here.
        

Summary of 130. Function Expressions vs Function Declarations:

Function Declarations are fully hoisted and can be called before definition. Function Expressions are stored in variables/constants, and only the variable is hoisted, meaning the function must be defined before it's called.
