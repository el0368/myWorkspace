# Elixir Pattern Matching: สุดยอดเครื่องแยกรูปทรง (The Ultimate Shape Sorter)

ถ้าคุณมาจากภาษาอย่าง C, Java หรือ Python คุณคงคุ้นเคยกับเครื่องหมาย `=` ในฐานะ "ตัวดำเนินการกำหนดค่า" (Assignment Operator) แต่ใน Elixir นั้นไม่ใช่ครับ! ที่นี่ `=` คือ **ตัวดำเนินการจับคู่ (Match Operator)** ให้ลองนึกภาพว่ามันไม่ใช่ถังน้ำที่คุณจะโยนค่าใส่อะไรก็ได้ แต่เป็นเหมือน **ของเล่นแยกรูปทรง** ของเด็กๆ ครับ มันจะเช็คว่าฝั่งซ้ายและฝั่งขวา "เข้ากันได้" ไหม และถ้าเข้ากันได้ มันก็จะผูกค่า (Bind) เข้ากับตัวแปรให้เราทันที

เรามาเจาะลึกกันครับว่ากลไกเดียวนี้เข้าไปแทนที่ตรรกะที่ยุ่งเหยิงที่คุณเคยเขียนมาได้อย่างไร

### 1. พื้นฐาน: มันไม่ใช่การกำหนดค่า!

ใน Elixir เมื่อคุณเขียน `x = 1` คุณไม่ได้แค่บอกว่า "x มีค่าเป็น 1" แต่คุณกำลังถามว่า "ฉันสามารถทำให้ฝั่งซ้าย (x) จับคู่กับฝั่งขวา (1) ได้ไหม?" เนื่องจาก `x` เป็นตัวแปรที่ยังว่างอยู่ (Unbound Variable) Elixir เลยตอบว่า "ได้เลย!" แล้วก็ผูกเลข `1` เข้ากับ `x` ให้

แต่ถ้าคุณเขียน `1 = x` ต่อจากนั้น Elixir จะเช็คว่า: "เลข 1 แมตช์กับค่าที่อยู่ใน x ไหม?" ซึ่งในกรณีนี้ `x` คือ 1 มันจึงผ่านครับ แต่ถ้าคุณลองเขียน `2 = x` คุณจะเจอ **MatchError** ทันที นี่คือรากฐานของสิ่งที่เรียกว่า **การแยกโครงสร้างข้อมูล (Destructuring)** หรือการแตกข้อมูลก้อนใหญ่ให้กลายเป็นส่วนย่อยๆ ครับ

### 2. Tuples: รูปแบบ "กล่องที่ล็อกไว้"

Tuples เป็นกลุ่มข้อมูลที่มีขนาดตายตัว และเป็นหัวใจหลักของการจัดการข้อผิดพลาดใน Elixir คุณจะเห็นรูปแบบอย่าง `{:ok, result}` หรือ `{:error, reason}` อยู่ตลอดเวลา

- **มันทำงานยังไง:** เมื่อคุณเขียน `{:ok, data} = {:ok, "Success"}` Elixir จะเช็คตัวแรกก่อน เมื่อเห็นว่าเป็น **Atom** ตัวเดียวกันคือ `:ok` มันก็จะขยับไปตัวที่สองแล้วผูกค่า `"Success"` เข้ากับตัวแปร `data`
    
- **คำอธิบายแบบเห็นภาพ:** มันเหมือนกล่องที่ล็อกไว้ครับ ตัวแรก (`:ok`) คือกุญแจ ถ้าคุณมีกุญแจที่ถูกต้อง Elixir จะเปิดกล่องแล้วให้คุณหยิบของข้างใน (`data`) ออกไปได้ แต่ถ้ากุญแจเป็น `:error` รูปแบบจะไม่แมตช์ และโค้ดส่วนนั้นก็จะไม่ถูกรัน
    
- **ตัวแปร "ฉันไม่สน":** ถ้าคุณสนใจแค่ผลลัพธ์แต่ไม่สนเหตุผลที่พัง คุณสามารถใช้ **อันเดอร์สโกร (_)** ได้ เช่น `{:error, _} = {:error, "File not found"}` แบบนี้จะผ่านครับ แต่ Elixir จะโยนข้อความแจ้งเตือนทิ้งลงถังขยะไปเลย
    

### 3. Lists: เคล็ดลับ "ส่วนหัวและส่วนหาง"

List ใน Elixir คือ **Linked List** ครับ มันไม่ใช่แค่อาร์เรย์ธรรมดา แต่มันคือโครงสร้างแบบเรียกซ้ำ (Recursive) ที่ประกอบด้วย **ส่วนหัว (Head)** คือไอเทมชิ้นแรก และ **ส่วนหาง (Tail)** คือลิสต์ของไอเทมที่เหลือทั้งหมด

- **ไวยากรณ์ `[h | t]`:** คุณสามารถแยกส่วนลิสต์ได้ทันที เช่น `[first | rest] = [1, 2, 3]` จะทำให้คุณได้ `first = 1` และ `rest = [2, 3]`
    
- **ทำไมถึงสำคัญ:** นี่คือหัวใจของ **การเรียกซ้ำ (Recursion)** เลยครับ คุณจัดการ "ส่วนหัว" แล้วก็ส่ง "ส่วนหาง" กลับเข้าไปในฟังก์ชันเดิมทำแบบนี้ซ้ำไปเรื่อยๆ จนกว่าลิสต์จะว่าง
    
- **การแมตช์แบบตายตัว:** คุณยังสามารถแมตช์ตามความยาวที่แน่นอนได้ด้วย เช่น `[a, b, c] = [1, 2, 3]` แต่ถ้าลิสต์ฝั่งขวามี 4 ตัว การจับคู่จะพังทันที วิธีนี้ดีมากในการเช็คว่าข้อมูลที่ได้รับมามีขนาดตรงตามที่ต้องการเป๊ะๆ หรือไม่
    

### 4. Maps: การแมตช์แบบ "เลือกหยิบ"

Maps คือที่เก็บข้อมูลแบบ Key-Value ของ Elixir ความพิเศษของการแมตช์บน Map คือมันยอมให้ทำ **การจับคู่แบบบางส่วน (Partial Matching)** ได้

- **การจับคู่บางส่วน:** ไม่เหมือนกับ Tuple ตรงที่ Pattern ของ Map ไม่จำเป็นต้องใส่ Key ให้ครบทุกตัว ถ้าคุณมี Map ที่มีฟิลด์ข้อมูล 50 อย่าง คุณเขียนแค่ `%{name: name} = user_map` เพื่อดึงแค่ชื่อออกมาก็ได้ ขอแค่ให้มี Key ชื่อ `:name` อยู่ Elixir ก็แฮปปี้แล้วครับ
    
- **การดึงข้อมูลแบบเจาะลึก:** คุณสามารถล้วงเข้าไปใน Map ที่ซ้อนกันหลายชั้นได้ในบรรทัดเดียว เช่น `%{address: %{city: city}} = user` จะดึงค่าเมืองออกมาได้เลย ไม่ต้องมานั่งเขียน `user.address.city` แล้วคอยเช็คว่าเป็นค่าว่าง (Null) หรือเปล่าให้เหนื่อยครับ
    

### 5. ส่วนหัวของฟังก์ชัน: "ตัวฆ่า If-Else" ตัวจริง

นี่คือจุดที่ Pattern Matching กลายเป็นซูเปอร์พาวเวอร์ครับ ใน Elixir คุณสามารถนิยามฟังก์ชันชื่อเดียวกันซ้ำได้หลายครั้งโดยใช้ **ข้อกำหนดของฟังก์ชัน (Function Clauses)** ที่ต่างกัน

```
defmodule Messenger do
  # แบบที่ 1: จะรันก็ต่อเมื่ออินพุตเป็น :hello เป๊ะๆ เท่านั้น
  def greet(:hello), do: "Well, hi there!"

  # แบบที่ 2: จะรันก็ต่อเมื่ออินพุตเป็น Map ที่มี Key ชื่อ name
  def greet(%{name: name}), do: "Hello, #{name}!"

  # แบบที่ 3: ตัวรับจบสำหรับกรณีอื่นๆ ทั้งหมด
  def greet(_), do: "I'm not sure who you are."
end
```

- **การเลือกทำงาน (Dispatch):** เมื่อคุณเรียก `greet/1` Elixir จะลองไล่เช็คดูทีละอันจากบนลงล่าง มันจะรันอันแรกที่ "แมตช์" กับรูปร่างข้อมูลของคุณ เราเรียกสิ่งนี้ว่า **การเลือกทำงานตามรูปแบบ (Pattern-Based Dispatch)**
    
- **โค้ดที่สะอาด:** วิธีนี้ช่วยกำจัดความจำเป็นในการใช้ `switch` หรือ `if/else` กองโตข้างในฟังก์ชันไปเลยครับ แต่ละ "กรณี" จะถูกแยกออกมาอยู่ในส่วนหัวของฟังก์ชันที่ชัดเจนและเข้าใจง่าย
    

### 6. Guards: "การ์ดเฝ้าประตู"

บางครั้งแค่ "รูปร่าง" ของข้อมูลก็ยังไม่พอ คุณอาจจะอยากแมตช์ "ตัวเลขจำนวนเต็มใดๆ" แต่ต้องมีค่า "มากกว่าศูนย์" เท่านั้น ตรงนี้แหละครับที่ **Guards** จะเข้ามาช่วย

- **คีย์เวิร์ด `when`:** คุณสามารถเติมเงื่อนไขต่อท้าย Pattern ได้ เช่น `def factorial(n) when n > 0`
    
- **การเช็คที่รัดกุม:** Guards จะถูกจำกัดให้เช็คได้เฉพาะเรื่องง่ายๆ ที่รวดเร็ว (เช่น `is_integer`, `is_list` หรือการเปรียบเทียบทางคณิตศาสตร์) เพื่อให้แน่ใจว่าเครื่องแยกรูปทรงของเราจะทำงานได้เร็วสายฟ้าแลบ ไม่ไปสะดุดกับตรรกะที่ซับซ้อนเกินไป
    

### 7. ทำไมเราถึงรักมัน: ผลตอบแทนที่ยิ่งใหญ่

Pattern Matching ไม่ใช่แค่ "ลูกเล่นเจ๋งๆ" แต่มันเปลี่ยนโครงสร้างการออกแบบแอปของคุณไปเลย:

1. **รูปแบบการเขียนแบบบอกความต้องการ (Declarative Style):** คุณแค่บอกว่าข้อมูลที่ต้องการ "ควรจะมีหน้าตายังไง" แทนที่จะเขียนคู่มือการแกะข้อมูลทีละชิ้น
    
2. **ลดโค้ดแบบ "ตั้งรับ" (Defensive Code):** คุณไม่ต้องคอยเช็คว่าตัวแปรเป็น `null` ไหม หรือลิสต์ว่างเปล่าหรือเปล่า ถ้ามันแมตช์ผ่าน คุณก็ "มั่นใจ" ได้เลยว่าข้อมูลนั้นปลอดภัยและพร้อมใช้งาน
    
3. **อธิบายตัวเองได้ (Self-Documenting):** แค่คุณมองที่ส่วนหัวของฟังก์ชัน คุณก็จะเห็นภาพทันทีว่าฟังก์ชันนั้นต้องการข้อมูลหน้าตาแบบไหน มันเหมือนมีแผนผังโครงสร้างข้อมูลแถมมาให้ในตัวเลยครับ
    

### สรุป:

**Pattern Matching รวบรวมการตรวจสอบความถูกต้อง การดึงข้อมูล และการแตกแขนงตรรกะเข้าด้วยกันในการทำงานเพียงครั้งเดียว มันเปลี่ยนคำถามจาก "ทำอย่างไร" (How) ในแบบเดิมๆ มาเป็นการบอกว่า "คืออะไร" (What) ในแบบ Functional Programming ซึ่งช่วยให้โค้ด Elixir ของคุณสะอาดขึ้น สั้นลง และพังยากขึ้นเยอะเลยครับ!**
