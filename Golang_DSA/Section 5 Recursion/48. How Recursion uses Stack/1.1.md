### Visualizing Stack Usage with "Head Recursion"

This Go program demonstrates "head recursion," where the main action (printing) happens _before_ the recursive call. This leads to the stack building up to its maximum depth while performing the actions on the way "down."

**Go Code Example:**

Go

```Go
package main

import "fmt"

// This function prints the value of n, then calls itself with n-1.
// This is an example of "head recursion."
func fun1(n int) {
	// The base condition: the recursion stops when n is not > 0.
	if n > 0 {
		// Step 1: Perform an action (print the current value of n).
		fmt.Printf("Printing on the way down: %d\n", n)

		// Step 2: Make the recursive call with a reduced value.
		fun1(n - 1)
	}
}

func main() {
	x := 3
	fmt.Println("--- Starting fun1 ---")
	fun1(x)
	fmt.Println("--- Finished fun1 ---")
}
```

---

When this program runs, the memory it uses is divided into sections, including the **code section** (for instructions) and the **stack** (for managing function calls). Each time a function is called, an **activation record** (or stack frame) is pushed onto that goroutine's stack to hold its local variables.

Here is a step-by-step trace of how the stack is utilized:

1. **Entering `main`**: The program starts in the `main` function. An **activation record for `main` is created** on the stack. This frame holds its local variable `x` with the value `3`.
    
2. **First Call to `fun1(3)`**: The `main` function calls `fun1(3)`. A **new activation record for `fun1` is pushed on top of the stack**. This new frame contains its own local variable `n` with the value `3`. The function prints "Printing on the way down: 3".
    
3. **Recursive Call to `fun1(2)`**: Inside `fun1(3)`, the function calls itself with `n - 1`. A **third activation record is created and pushed onto the stack** for this new `fun1` call, this time with its own `n` having the value `2`. The function prints "Printing on the way down: 2".
    
4. **Deeper Calls**: This process repeats. The call to `fun1(2)` leads to a call to `fun1(1)`, which pushes another activation record (`n=1`) and prints its value. The call to `fun1(1)` then leads to a final call to `fun1(0)`, pushing one last activation record (`n=0`). At this point, the stack is at its maximum height.
    
5. **The Base Case and Unwinding**:
    
    - Inside the `fun1(0)` call, the condition `n > 0` is now **false**. The function does nothing and returns.
        
    - When that call ends, its **activation record is deleted** from the top of the stack. Control returns to the previous call (`fun1(1)`).
        
    - Since the recursive call was the last thing `fun1(1)` did, it also has nothing left to do. It finishes, and its activation record is deleted.
        
    - This continues in a chain reaction: the stack unwinds, and each activation record is deleted one by one until control finally returns to the `main` function.
        

This trace shows how recursion builds up activation records on the stack during its "calling" or "ascending" phase and then dismantles them during its "returning" phase.
