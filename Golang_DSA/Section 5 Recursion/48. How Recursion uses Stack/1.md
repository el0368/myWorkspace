### Visualizing Stack Usage with "Head Recursion"

When a Go program runs, the memory it uses is divided into sections, including the **code section** (for instructions) and the **stack** (for managing function calls). Each time a function is called, a block of memory called an **activation record** (or stack frame) is pushed onto that goroutine's stack to hold its local variables.

Following the instructor's step-by-step trace of the first recursive function (`fun1`), here is how the stack is utilized:

1. **Entering `main`**: The program starts by executing the `main` function. Immediately, an **activation record for `main` is created** on the stack. This frame holds its local variable `x` with the value `3`.
    
2. **First Call to `fun1(3)`**: The `main` function calls `fun1(3)`. A **new activation record for `fun1` is pushed on top of the stack**. This new frame contains its own local variable `n`, which receives the value `3`.
    
3. **Recursive Call to `fun1(2)`**: Inside `fun1(3)`, the condition `n > 0` is true, so it prints `3` and then calls itself with `n - 1`. This triggers another function call. A **third activation record is created and pushed onto the stack** for this new `fun1` call, this time with its own `n` having the value `2`.
    
4. **Deeper Calls**: This process repeats. The call to `fun1(2)` leads to a call to `fun1(1)`, which pushes another activation record with `n=1`. The call to `fun1(1)` then leads to a final call to `fun1(0)`, pushing a final activation record with `n=0`. At this point, the stack is at its maximum height for this process.
    
5. **The Base Case and Unwinding**:
    
    - Inside the `fun1(0)` call, the condition `n > 0` is now **false**. As the instructor explains, it "**will not enter inside...and it will come out of the function.**"
        
    - When that call ends, its **activation record is deleted** from the top of the stack. Control returns to the previous call (`fun1(1)`).
        
    - Since the recursive call was the last thing `fun1(1)` did, it also has nothing left to do. It finishes, and its activation record is deleted.
        
    - This continues in a chain reaction: the stack unwinds, and each activation record is deleted one by one until control finally returns to the `main` function.
        

This detailed trace shows exactly how recursion builds up a series of activation records on the stack during its "calling" or "ascending" phase and then dismantles them during its "returning" phase.
