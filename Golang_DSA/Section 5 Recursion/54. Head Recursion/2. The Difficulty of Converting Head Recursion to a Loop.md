## The Difficulty of Converting Head Recursion to a Loop ⚙️

The instructor demonstrates that unlike tail recursion, **head recursion "cannot be easily converted in the form of a loop"** on a direct, line-by-line basis. While you can write a loop to produce the same _result_, its logical structure will be completely different from the recursive version.

### 1. The Failed Direct Conversion

First, he attempts to convert the head-recursive function directly into a loop.

The Head-Recursive Function (Go Version):

This function prints 1, 2, 3 because the Println happens on the way back from the recursion.



```Go
func headRecur(n int) {
	if n > 0 {
		headRecur(n - 1)
		fmt.Println(n)
	}
}
```

The Failed Direct Loop Conversion:

If we try to convert this "as it is" into a loop, we get the following:


```Go
func failedLoop(n int) {
	for n > 0 {
		// This prints n before it changes
		fmt.Println(n)
		n--
	}
}
```

As the instructor points out, if you call this loop function with `3`, "it will print what 3. It will not print 1, first value that will be printed is 3." The output would be `3, 2, 1`, which is not the same as the recursive function.

### 2. A Correct (But Different) Loop

He then shows that to get the correct output (`1, 2, 3`), you must abandon the original structure and write a completely different kind of loop.

The Correct Loop:

This version uses a new counter variable i that starts at 1 and goes up to n.



```Go
func correctLoop(n int) {
	for i := 1; i <= n; i++ {
		fmt.Println(i)
	}
}
```

This loop correctly produces the `1, 2, 3` output.

### Conclusion

The main takeaway is that because head recursion performs its work during the "returning time," it relies on the call stack to save the state of each step (e.g., the values `n=3`, `n=2`, `n=1`). A simple loop doesn't have this built-in "memory" of past states. Therefore, as the instructor concludes, you can't just map the components directly. You have to write a loop with a different logical approach to achieve the same outcome.
