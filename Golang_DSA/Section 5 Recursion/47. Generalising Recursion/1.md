Okay, let's elaborate on the recursive function phases – the "ascending" and "descending" phases – which are fundamental to understanding how recursion works, especially for non-tail-recursive functions.

I will explain this using the general concepts, which fully apply to Go, even though Go doesn't perform Tail Call Optimization.

---

### Recursive Function Phases: Ascending and Descending

When a recursive function executes, especially one where the recursive call is _not_ the very last operation, its execution can be conceptually divided into two distinct phases:

1. **The Ascending Phase (or Calling/Winding Phase)**
    
2. **The Descending Phase (or Returning/Unwinding Phase)**
    

Let's break down what each phase entails.

#### 1. The Ascending Phase (Calling / Winding Phase)

This phase refers to the operations that occur **before** the recursive call is made. It's like the function is "winding up" or building up the sequence of calls on the call stack.

- **When it happens:** As the function is called repeatedly, moving from `fun(n)` to `fun(n-1)`, then `fun(n-2)`, and so on, down towards the base case.
    
- **What operations are performed:** Any statements or computations that are placed _before_ the recursive call within the function's body. These operations are executed on the current stack frame _before_ a new stack frame is pushed for the next recursive call.
    
- **Analogy:** Imagine pushing plates onto a stack. Each function call performs some work and then pushes another "plate" (a new stack frame) onto the stack before reaching the base case.
    
- **Example (Conceptual):**
    
    ```
    func recursive_function(n):
        // Operations here are part of the ASCENDING phase
        // They happen for n, then for n-1, then for n-2...
        // before the next recursive call.
        do_something_before_call(n)
    
        if n > base_case_condition:
            recursive_function(n - 1) // The recursive call
        else:
            handle_base_case()
    ```
    

#### 2. The Descending Phase (Returning / Unwinding Phase)

This phase refers to the operations that occur **after** the recursive call returns. It's like the function is "unwinding" or collapsing the stack frames as results are returned back up the call chain.

- **When it happens:** After the base case is reached and its result (if any) is returned, the functions on the call stack start returning one by one, from the deepest call back up to the initial call.
    
- **What operations are performed:** Any statements or computations that are placed _after_ the recursive call within the function's body. These operations are executed on the current stack frame _after_ the recursive call (which was made earlier by this very frame) has completed and returned its result.
    
- **Analogy:** Continuing the plate analogy, once the base of the stack is hit, you start popping plates off. As each plate is removed, you might perform some final work associated with that plate using results from the plate below it (the returned value from the deeper call).
    
- **Crucial Point:** If a function performs operations in this phase, it means the current stack frame _must remain active_ on the call stack until the recursive call returns and these post-call operations are completed. This is precisely why non-tail-recursive functions consume O(N) space.
    
- **Example (Conceptual):**
    
    ```
    func recursive_function(n):
        if n > base_case_condition:
            // Operations in ASCENDING phase
            do_something_before_call(n)
    
            result_from_sub_call := recursive_function(n - 1) // The recursive call
    
            // Operations here are part of the DESCENDING phase
            // They happen AFTER recursive_function(n-1) returns.
            // These often use 'result_from_sub_call'.
            do_something_after_call(n, result_from_sub_call)
    
        else:
            handle_base_case()
    ```

### Application to Your Go Example:

Let's re-examine your specific Go function:

Go

```Go
func fun(x int) {
    if x > 0 {
        fun(x - 1)         // (1) Recursive Call
        fmt.Println(x)     // (2) Print Statement
    }
}
```

When `fun(3)` is called:

1. **`fun(3)`:**
    
    - `if 3 > 0` is true.
        
    - Calls `fun(2)`. (This is the "winding up" part for `fun(3)`)
        
2. **`fun(2)`:**
    
    - `if 2 > 0` is true.
        
    - Calls `fun(1)`. (This is the "winding up" part for `fun(2)`)
        
3. **`fun(1)`:**
    
    - `if 1 > 0` is true.
        
    - Calls `fun(0)`. (This is the "winding up" part for `fun(1)`)
        
4. **`fun(0)`:**
    
    - `if 0 > 0` is false.
        
    - Function returns immediately. (Base case reached!)
        

Now the **Descending Phase (Unwinding)** begins:

5. **`fun(1)` (continued):**
    
    - The call to `fun(0)` has returned.
        
    - Now, `fmt.Println(1)` executes. (This operation is in the _descending_ phase for `fun(1)`)
        
    - `fun(1)` returns.
        
6. **`fun(2)` (continued):**
    
    - The call to `fun(1)` has returned.
        
    - Now, `fmt.Println(2)` executes. (This operation is in the _descending_ phase for `fun(2)`)
        
    - `fun(2)` returns.
        
7. **`fun(3)` (continued):**
    
    - The call to `fun(2)` has returned.
        
    - Now, `fmt.Println(3)` executes. (This operation is in the _descending_ phase for `fun(3)`)
        
    - `fun(3)` returns.
        

**Output:** `1 2 3`

This example clearly shows that the `fmt.Println(x)` operation is performed _after_ the recursive call returns, placing it squarely in the **descending phase**. This necessitates that previous `fun` calls remain on the call stack, waiting for their nested calls to complete, which leads to the O(N) space complexity.
