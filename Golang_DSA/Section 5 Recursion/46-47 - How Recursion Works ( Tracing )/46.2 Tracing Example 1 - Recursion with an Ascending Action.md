### Tracing Example 1: Action in the "Ascending" Phase 🔼

The instructor demonstrates how to trace a recursive function that performs an action *before* making the recursive call.

**Go Code Example:**

```go
package main

import "fmt"

// This function prints the value of n, then calls itself with n-1.
func fun1(n int) {
	// The base condition: the recursion stops when n is not > 0.
	if n > 0 {
		// Step 1: Perform an action (print the current value of n).
		fmt.Println(n)
		
		// Step 2: Make the recursive call with a reduced value.
		fun1(n - 1)
	}
}

func main() {
	x := 3
	// Initial call to the recursive function.
	fun1(x)
}
```

The instructor explains that "recursive functions are traced in the form of a tree." He then begins the trace based on the initial call from `main`: **"I'm calling function `fun1()` by passing x, that is value 3."**

Here is the step-by-step trace following his logic:

1.  **Call: `fun1(3)`**

      * The condition `3 > 0` is true.
      * **First step:** "print n," so the program prints **`3`**. The output so far is `3`.
      * **Second step:** "call itself" with `3 - 1`. A new call is made to **`fun1(2)`**.

2.  **Call: `fun1(2)`**

      * The condition `2 > 0` is true.
      * **First step:** "print 2." The program prints **`2`**. The total output is now `3, 2`.
      * **Second step:** It calls itself with `2 - 1`. A new call is made to **`fun1(1)`**.

3.  **Call: `fun1(1)`**

      * The condition `1 > 0` is true.
      * **First step:** "print 1." The program prints **`1`**. The total output is now `3, 2, 1`.
      * **Second step:** It calls itself with `1 - 1`. A new call is made to **`fun1(0)`**.

4.  **Call: `fun1(0)` — The Base Case**

      * The condition `0 > 0` is **false**.
      * The instructor explains, "it will not enter inside. So it will not perform these two steps...it will not enter inside and it will come out of the function. So this call **doesn't do anything**."

This final call terminates, and control returns to the previous call (`fun1(1)`), which has now finished its work. Control then returns to `fun1(2)`, then to `fun1(3)`, and finally back to `main`. Since the printing action was done before each call, no work is left to be done during this "returning phase."

The final output generated by this "tracing Tree of Recursive Function" is **`3, 2, 1`**.
