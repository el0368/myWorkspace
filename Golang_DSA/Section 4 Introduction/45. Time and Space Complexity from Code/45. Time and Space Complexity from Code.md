### The Basic Rule of Analysis

The instructor establishes a core assumption for analyzing code: "**We assume that every simple statement in function or the program takes one unit of time.**" A simple statement includes assignments, arithmetic operations, or conditional checks. The goal of the analysis is to derive a time function, `f(n)`, and from that, find the time complexity.

-----

### Example 1: The `swap` Function - `Order(1)`

First, he analyzes a simple function that swaps two values.

**Go Code:**

```go
// This is a pseudo-code version to match the instructor's analysis.
// Note: Idiomatic Go can swap in one line: x, y = y, x
func swap(x, y int) {
    temp := x  // Statement 1
    x = y      // Statement 2
    y = temp   // Statement 3
}
```

**Analysis:**
He breaks it down statement by statement:

  * Each of the three assignment statements is simple and takes **"one unit of time."**
  * The total time is `1 + 1 + 1 = 3`.
  * So, the time function is **`f(n) = 3`**.
  * This is a constant value. He explains, "the degree of n is 0 here, `3` means `3*n^0`...So it is constant."
  * **Conclusion:** The time complexity is **`Order(1)`**.

### Example 2: The `sum` Function - `Order(n)`

Next, he analyzes a function that sums the elements of a slice.

**Go Code:**

```go
func sum(arr []int) int {
    s := 0            // 1. Assignment
    n := len(arr)

    for i := 0; i < n; i++ { // 2. Loop
        s = s + arr[i]  // 3. Body of the loop
    }

    return s            // 4. Return statement
}
```

**Analysis:**
He performs a detailed, line-by-line analysis:

1.  **The first assignment (`s := 0`)**: This executes just once. Time = **1**.
2.  **The `for` loop**: The condition `i < n` is checked `n+1` times (n successful times and one final time to fail). The increment `i++` runs `n` times. He simplifies this by focusing on the dominant part: "this statement will execute for...`n+1`." Time = **`n+1`**.
3.  **The statement inside the loop (`s = s + arr[i]`)**: This "will repeat for n times." Time = **`n`**.
4.  **The `return s` statement**: This executes just once. Time = **1**.

Combining these gives the time function: `f(n) = (n + 1) + n + 1 + 1 = 2n + 3`.
He notes that you could be more precise and count the initialization and increment parts of the loop, which might yield `f(n) = 2(n+1) + n + 1`, but the result is the same.

  * The time function is **`f(n) = 2n + 3`**.
  * He asks, "what is the degree of this polynomial? This is order of N degree 1."
  * **Conclusion:** The time complexity is **`Order(n)`**.

He reinforces that while the line-by-line analysis is a good practice, you can also get the answer by analyzing the procedure: the function sums 'n' elements, so the time it takes must depend on 'n'.

### Example 3: Nested Loops - `Order(n²)`

He then analyzes a function with nested loops.

**Go Code:**

```go
func processMatrix(matrix [][]int) {
    n := len(matrix)

    for i := 0; i < n; i++ {      // Outer loop
        for j := 0; j < n; j++ {  // Inner loop
            // some simple statement
        }
    }
}
```

**Analysis:**
He applies the same logic, emphasizing the multiplication for nested loops:

1.  **The outer loop (`for i...`)**: This loop runs **`n+1`** times.
2.  **The inner loop (`for j...`)**: This is the crucial part. He asks, "shall I write `+(n+1)` or `*(n+1)`?" Because it's a "**Nested Lope is there right, so it should be (\*) multiplication.**" Therefore, the inner loop's condition check runs **`n * (n+1)`** times.
3.  **The statement inside the inner loop**: This will be executed `n` times for each of the `n` iterations of the outer loop. Time = **`n * n`** or **`n²`**.

Combining the most significant terms gives a time function like `f(n) = n² + n * (n+1) + (n+1)` which simplifies to `f(n) = 2n² + 2n + 1`.

  * The time function is approximately **`f(n) = 2n² + 2n + 1`**.
  * The highest degree of this polynomial is **2**.
  * **Conclusion:** The time complexity is **`Order(n²)`**.

### Example 4: The Complexity of Function Calls

Finally, he shows that you must look inside function calls to determine complexity.

**Go Code:**

```go
func fun2() {
    // A loop that takes Order(n) time
    for i := 0; i < n; i++ {
        // ...
    }
}

func fun1() {
    fun2() // This is a function call, not a simple statement
}
```

**Analysis:**
He warns against a common mistake. Looking at `fun1`, you see only one line of code. Is its complexity `Order(1)`?

  * He says, "**Wrong. That is a function. How much time that function is taking, you find out that one don't say that statement is one.**"
  * Since `fun2` contains a loop that takes `Order(n)` time, the time taken by the call to `fun2` inside `fun1` is also `Order(n)`.
  * **Conclusion:** The time taken by `fun1` is therefore **`Order(n)`**, not `Order(1)`. You must analyze the complexity of the functions you call.
