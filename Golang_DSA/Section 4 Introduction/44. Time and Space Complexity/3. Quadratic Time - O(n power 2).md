Ok, let's move on to the next type of complexity. This one can get slow very quickly.

---

### Quadratic Time - O(n²) 🐢

We call this next one **Quadratic Time**, and we write it as **`$O(n^2)$`**.

What this means is that the running time of your program grows by the **square** of your input size, `n`. This is a big deal. If you double the number of items in your slice, the time it takes doesn't just double, it gets **four times** longer (`2 * 2`). If you have 10 times more items, it can take **100 times** longer (`10 * 10`). You can see that for a large `n`, this can become very slow.2

A good real-world example is this: imagine you are in a room with `n` people, and everyone has to shake hands with everyone else. The total number of handshakes will grow much, much faster than the number of people in the room. This is a quadratic task.

---

#### How this looks in programming

In Go, this almost always happens when for **each** item in a slice, your code has to loop through the **entire** slice _again_. This is called a **nested loop**—a loop inside of another loop.3

There are two common ways you might see this:

1. **For each item, you process _all_ `n` items.** Imagine you have two slices, and for each number in the first slice, you need to see if it exists in the second slice. You'd take the first item, then loop through all `n` items of the second slice. Then you'd take the second item and do it all over again. This is `n` work, done `n` times, which gives you `$O(n^2)`.
    
2. **For each item, you process the _rest_ of the items.** This is a bit smarter, but still quadratic. Imagine you want to find if any two numbers in the _same_ slice are duplicates. You'd take the first item and compare it to the `n-1` items after it. Then you'd take the second item and compare it to the `n-2` items after it. Even though the amount of work gets smaller each time, when you add it all up, the final time function is still driven by `n^2`. The growth rate is the same.
    

So, the most important thing to remember is this: when you look at your Go code and see a `for` loop running inside _another_ `for` loop, and they are both working on the same `n` items, that is a very strong sign that your algorithm is `$O(n^2)`.
