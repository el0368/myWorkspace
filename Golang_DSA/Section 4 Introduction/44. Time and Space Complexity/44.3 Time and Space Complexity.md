### Quadratic Time Complexity - `Order(n²)` 🔲

The instructor moves to the next level of complexity by describing procedures that involve nested operations. He presents two common scenarios that both result in `Order(n²)`.

#### 1\. The Full Nested Loop (`n * n`)

This scenario involves processing every element in combination with every other element. As the instructor describes it: "**being on the 1st element, I am comparing or processing all other elements once. Then, being on the second element, Again I am processing all other elements...for each element, I'll be checking with all the rest of the elements.**"

He explains the calculation for this procedure simply: for one element, you do 'n' operations. Since you do this for all 'n' elements, the total time is "**n\*n, that is n². So, we can say Order(n²).**"

This procedure directly corresponds to a nested `for` loop structure in Go:

```go
// This Go code represents Order(n²) time.
// The inner loop runs 'n' times for each iteration of the outer loop.
for i := 0; i < n; i++ {
    for j := 0; j < n; j++ {
        // ... logic that compares or processes element i and element j ...
    }
}
```

His conclusion is direct: "**When you have two nested for loops, it's n², simple.**"

-----

#### 2\. The Triangular Nested Loop

This is a slightly optimized version where you avoid redundant comparisons. The instructor describes the process: "**being on first element, I'm processing the rest of the elements. So, n-1 elements I'm processing, then being on the second element, I'm processing the rest of the elements...n-2.**"

This pattern continues until the last element, creating a sum of `(n-1) + (n-2) + ... + 1`. He identifies this as the formula for the sum of the first `n-1` natural numbers, which results in the polynomial **`(n² - n)/2`**.

This is the most crucial part of the lesson: even though the total number of operations is roughly half, the complexity is still determined by the highest power of 'n'. He asks, "**what is the degree of this polynomial? This is n². So, it is Order(n²).**" The `n²` term grows so much faster than the `-n` term that the lesser term becomes insignificant for large 'n'.

This procedure corresponds to a nested Go `for` loop where the inner loop starts from the current position of the outer loop:

```go
// This Go code also represents Order(n²) time.
// The inner loop runs fewer times, but the complexity remains n-squared.
for i := 0; i < n; i++ {
    for j := i + 1; j < n; j++ {
        // ... logic that compares or processes element i and element j ...
    }
}
```
