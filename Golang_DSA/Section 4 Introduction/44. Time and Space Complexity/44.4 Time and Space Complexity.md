### Logarithmic Time Complexity - `Order(log n)` 🌲

The instructor introduces a new class of complexity for algorithms that don't need to process every element. He describes a procedure where you start by **"processing the middle element...Then next, either on the left side or on the right side again we go in the middle...in this way we are not processing the entire list. We are processing half of the list, then again it's half, then again it's half."**

This process of repeatedly cutting the problem size is the key to logarithmic time. He provides a simple rule to identify it: **"when something is successively divided until it reaches one, that is represented as log...So, the time complexity is log n."** This is formally written as **`Order(log n)`**.

He then shows the code structure that results in this complexity and gives a critical piece of advice. In Go, the code would look like this:

```go
// This Go code represents Order(log n) time because 'i' is halved each time.
for i := n; i > 1; i = i / 2 {
    // ... logic that processes a smaller part of the problem ...
}
```

His warning is crucial for accurate analysis: "just by looking at for loop, **don't tell blindly `Order(n)`...Read it, How the for loop is behaving.** That's why, we check it thoroughly...so that, we should not go wrong."

The instructor also mentions that for this type of logic, a `while` loop is often preferred. While Go doesn't have a `while` keyword, it uses the versatile `for` loop to achieve the same result. The equivalent Go code that looks more like a traditional `while` loop is:

```go
// This Go for loop functions exactly like a while loop in other languages.
i := n
for i > 1 {
    // ... some processing ...
    i = i / 2
}
```

This demonstrates that regardless of the exact loop syntax, the logic of repeatedly dividing the input size by two is what defines `Order(log n)` complexity.
