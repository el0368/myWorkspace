### The Stack and Sequential Function Calls 🥞

* **Activation Records are created for each function call.** When the program starts in the `main` function, its variables are allocated in an activation record on the stack. When `main` calls `fun1()`, a new activation record for `fun1()` is created on top of `main`'s. When `fun1()` calls `fun2()`, another activation record for `fun2()` is created on top of that.

* **The currently executing function uses the topmost record.** The instructor explains, "this topmost activation record belongs to which function? Currently executing function." While `fun2()` is running, the activation records for `main()` and `fun1()` are still present in memory beneath it.

* **Activation Records are deleted as functions end.** The process happens in reverse order. "When `fun2()` has finished, terminated, then, control goes back to `fun1()`... What happens to the activation record of that `fun2()`? This will be deleted." Then, "once the `fun1()` ends, its activation record is also removed... Then, `main` function also ends. So, its Activation record is also deleted."

* **This mechanism is why it's called a "stack".** The instructor summarizes the behavior: "The way, activation records are created like this, and then deleted like this. So this mechanism is stack, right? **Top and top and top, then, delete, delete, delete.** So this mechanism is stack."

* **Stack memory is managed automatically.** A key conclusion is that "this memory is **automatically created, and automatically destroyed**, the programmer doesn't have to do anything for its allocation and destruction, just programmer has to declare the variable."

### Dynamic Memory Allocation (The Heap) 🧱

* **The Heap is unorganized memory.** Unlike the stack, the instructor notes that, "Heap is the term used for **unorganized memory**. It's not organized, stack memory is organized, right?"

* **Heap memory must be treated like a resource.** He makes an analogy with a printer: "If your program wants to use a printer, then it can request for a printer... once it has finished using it, it should release the printer... Same way, Heap memory should be used like a resource, **when required, you take the memory, when you don't require, you release the memory.**"

* **Programs access the heap indirectly using pointers.** The instructor states a policy: "**Programs cannot access heap memory directly.** Then how do they access memory? **Using pointer.**"

* **Memory is allocated with special keywords.** To allocate memory on the heap, you first declare a pointer variable (which lives on the stack). Then you use a keyword like `new` (in C++) or `malloc()` (in C). The instructor states, "**wherever you see 'new', it means memory is allocated in heap.**" The pointer on the stack then stores the address of this new block of memory on the heap.

* **Heap memory must be explicitly released to avoid "memory leaks".** It is critical that "Heap memory should be **explicitly requested, and explicitly released**, or disposed." If a programmer is done with a piece of heap memory but doesn't release it (for example, by just setting the pointer to `null`), the memory "will not be de-allocated." This leads to a problem: "if you are not releasing it, then the memory will be still belonging to your program, and that memory cannot be used again, so it causes loss of memory, and **the loss of memory is called as memory leak.**" This can eventually cause the entire heap to run out of free space.
