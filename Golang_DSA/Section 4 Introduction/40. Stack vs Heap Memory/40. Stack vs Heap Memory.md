### Memory Fundamentals

* **Memory is a collection of addressable bytes.** The instructor explains that memory is "divided into smaller addressable units that are called as bytes." Every single byte has its own unique address.

* **Memory addresses are linear.** He emphasizes that even though diagrams might look two-dimensional, the addresses themselves are one-dimensional. In his words, "addresses are single dimension addresses, linear addresses...address will have just 1 value, not like coordinate system, (x,y)."

### Memory Model for the Discussion

* **A 64-kilobyte segment is assumed for all examples.** To make concepts easier to understand, the instructor sets a specific memory size for his discussion: "I'll be assuming that the size of the main memory is 64 kilobytes."
* **This model has addresses from 0 to 65535.** He details this calculation: "total, 0 to 65535 makes 65536...That is, 64*1024, so it is 64 kilobytes."
* **This relates to the concept of a "segment" in real computers.** He notes that in larger systems, RAM is "divided into manageable pieces, that are called as segment. And, usually the size of a segment will be 64 kilobytes. So I'm talking about a segment."

### How a Program Uses Main Memory

* **Memory is divided into three sections: Code, Stack, and Heap.** A program organizes the main memory it uses into these three distinct areas.
* **The Code Section holds the program's instructions.** When you run a program, "the machine code of the program, first it should be brought inside the main memory. So it is brought inside the code section." He defines this as the "area where the machine code of the program is loaded."
* **The Stack and Heap are used by the running program.** Once the program's code is loaded and the CPU begins executing it, "this program will utilize the remaining memory as divided into stack and heap."

### Static Memory Allocation (The Stack)

* **Memory for variables declared in a function is created on the stack.** The instructor states this as a rule: "whatever the variables you declare inside your program, or inside a function, the memory for those variables will be created inside the stack."
* **A function's memory block on the stack is its "activation record" or "stack frame."** The portion of memory that a function is given on the stack is called the "stack frame...or it is also called as activation record of that function."
* **This is called "static" because the memory size is determined at compile time.** The key reason for this term is that the "Compiler will see that, this needs some bytes, and this needs some bytes. So, it will beforehand decide that, this function needs so much memory."
* **"Static" means decided before runtime.** The instructor summarizes the concept: "What is static here? How many bytes of memory is required by this function was decided at compile time. So it is static...when everything is done at compile time, or before run time, it is called static."
