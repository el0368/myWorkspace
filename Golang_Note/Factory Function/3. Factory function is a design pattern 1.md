Of course. Here is the same example, but with data added to the structs.

The factory function (`NewPizza`) is now responsible for setting the initial data (the toppings) for each pizza it creates.

---

### The Updated Code

Go

```Go
package main

import (
	"fmt"
	"strings"
)

// 1. The Product (Interface)
type Pizza interface {
	Prepare()
}

// 2. Concrete Products (Structs with data)
type PepperoniPizza struct {
	Toppings []string
}

func (p *PepperoniPizza) Prepare() {
	fmt.Printf("Preparing pepperoni pizza with: %s\n", strings.Join(p.Toppings, ", "))
}

type VeggiePizza struct {
	Toppings []string
}

func (v *VeggiePizza) Prepare() {
	fmt.Printf("Preparing veggie pizza with: %s\n", strings.Join(v.Toppings, ", "))
}

// 3. The Factory Function (initializes the data)
func NewPizza(pizzaType string) (Pizza, error) {
	switch pizzaType {
	case "pepperoni":
		// The factory sets the initial data for the struct.
		return &PepperoniPizza{
			Toppings: []string{"salami", "cheese", "oregano"},
		}, nil
	case "veggie":
		return &VeggiePizza{
			Toppings: []string{"bell peppers", "onions", "olives"},
		}, nil
	default:
		return nil, fmt.Errorf("invalid pizza type: %s", pizzaType)
	}
}

func main() {
	// The client code does not need to change.
	pizza1, _ := NewPizza("pepperoni")
	pizza2, _ := NewPizza("veggie")

	pizza1.Prepare()
	pizza2.Prepare()
}
```

### Key Changes

- **Structs Have Data**: The `PepperoniPizza` and `VeggiePizza` structs now have a `Toppings` field to hold their ingredients.
    
- **Methods Use Data**: The `Prepare()` methods now use the `Toppings` field to create a dynamic message.
    
- **Factory Initializes Data**: The `NewPizza` factory is now responsible for setting the correct initial toppings for each pizza it creates.
