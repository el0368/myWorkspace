After learning about arrays, your goal for the

**Linked List** 1 is to understand it as the fundamental alternative for storing sequential data. You should focus on its unique structure, how its operations differ from an array's, and the critical performance trade-offs between the two.

Here’s a breakdown of what you should know about linked lists at this stage:

---

### 1. The Core Definition

- **What it is:** A linked list is a collection of items called **nodes**. Each node contains two pieces of information: the **data** itself and a **pointer** (or link) to the very next node in the sequence. Unlike an array, these nodes can be stored anywhere in memory.
    
- **Why it matters:** This non-contiguous, pointer-based structure is the direct cause of all the linked list's strengths (like fast insertions) and weaknesses (like slow access).
    

---

### 2. Key Properties

- **Dynamic Size:** Linked lists can easily grow and shrink one node at a time. You don't need to define their size beforehand.
    
- **Node-Based:** The entire structure is built from individual node objects linked together, not a single block of memory.
    
- **Sequential Access:** You **cannot** access an element by its index directly like in an array. To get to the 10th element, you must start at the first element (the "head") and follow the pointers nine times.
    

---

### 3. Types of Linked Lists

You should learn the two primary types and their differences:

- **Singly Linked List:** Each node has only **one pointer** to the next node in the list. Traversal is only possible in the forward direction.
    
- **Doubly Linked List:** Each node has **two pointers**: one to the next node and one to the previous node. This allows for both forward and backward traversal, which can make certain operations (like deleting a specific node) more efficient.
    

---

### 4. Essential Operations and Their Runtimes

Understanding these performance characteristics is crucial for comparing linked lists to arrays.

- **Accessing a specific element: Slow**
    
    - You must traverse the list from the beginning.
        
    - **Runtime:** Linear time or **O(n)**2.
        
- **Searching for a value: Slow**
    
    - Just like accessing, you have to perform a
        
        **Linear Search** 3 by traversing the list.
        
    - **Runtime:** Linear time or **O(n)**4.
        
- **Inserting/Deleting (at the beginning): Very Fast**
    
    - You only need to create a new node and update the head pointer. No shifting of other elements is required.
        
    - **Runtime:** Constant time or **O(1)**5. This is the primary advantage of a linked list.
        
- **Inserting/Deleting (at the end or middle): Can be slow**
    
    - To perform these operations, you first have to **traverse** to the desired position, which takes linear time. The actual pointer update is fast, but the traversal is the bottleneck.
        
    - **Runtime:** Linear time or **O(n)**6.
