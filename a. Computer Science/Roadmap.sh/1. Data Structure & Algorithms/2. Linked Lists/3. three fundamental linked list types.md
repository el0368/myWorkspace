### 1. Singly Linked List
- **Description:** A linear structure where each node has a value and a pointer to the next node, with the last node pointing to `None`. This is the base form listed under "Linked List" in the roadmap.
- **Key Operations:** Push front (O(1)), push back (O(n)), pop front (O(1)), traversal (O(n)).
- **Rust Implementation:**
  ```rust
  #[derive(Debug)]
  struct Node {
      value: i32,
      next: Option<Box<Node>>,
  }

  #[derive(Debug)]
  struct LinkedList {
      head: Option<Box<Node>>,
  }

  impl LinkedList {
      fn new() -> Self {
          LinkedList { head: None }
      }

      fn push_front(&mut self, value: i32) {
          let new_node = Box::new(Node {
              value,
              next: self.head.take(),
          });
          self.head = Some(new_node);
      }

      fn print(&self) {
          let mut current = &self.head;
          print!("Singly Linked List: ");
          while let Some(node) = current {
              print!("{} -> ", node.value);
              current = &node.next;
          }
          println!("None");
      }
  }

  fn main() {
      let mut list = LinkedList::new();
      list.push_front(3);
      list.push_front(2);
      list.push_front(1);
      list.print();
  }
  ```
  - **Output:**
    ```
    Singly Linked List: 1 -> 2 -> 3 -> None
    ```
  - **Roadmap Tie-In:** Fits under "Data Structures" and "Common Runtimes" (e.g., O(n) traversal). Used in "Common Algorithms" like linear search or reversal.

### 2. Circular Singly Linked List
- **Description:** A variation where the last node’s next pointer points back to the first node, forming a loop. This extends the singly linked list concept, often tied to "Graph" (cycles) or "Caches" (e.g., LRU) in the roadmap.
- **Key Operations:** Push (O(1) with tail), traversal requires loop detection, deletion (O(n) to find node).
- **Rust Implementation:**
  ```rust
  #[derive(Debug)]
  struct Node {
      value: i32,
      next: Option<Box<Node>>,
  }

  #[derive(Debug)]
  struct CircularLinkedList {
      head: Option<Box<Node>>,
      tail: Option<*mut Node>, // Raw pointer for tail (unsafe but common for circular lists)
  }

  impl CircularLinkedList {
      fn new() -> Self {
          CircularLinkedList { head: None, tail: None }
      }

      fn push(&mut self, value: i32) {
          let new_node = Box::new(Node {
              value,
              next: None,
          });
          let new_node_ptr = Box::into_raw(new_node); // Convert to raw pointer

          if self.head.is_none() {
              self.head = unsafe { Some(Box::from_raw(new_node_ptr)) };
              self.tail = Some(new_node_ptr);
              unsafe { (*self.tail.unwrap()).next = self.head.clone(); }
          } else {
              let tail = self.tail.unwrap();
              unsafe {
                  (*tail).next = Some(Box::from_raw(new_node_ptr));
                  (*new_node_ptr).next = self.head.clone();
                  self.tail = Some(new_node_ptr);
              }
          }
      }

      fn print(&self) {
          print!("Circular Singly Linked List: ");
          if let Some(head) = &self.head {
              let mut current = head;
              for _ in 0..3 { // Limit to 3 to avoid infinite loop in print
                  print!("{} -> ", current.value);
                  current = unsafe { current.next.as_ref().unwrap() };
              }
              println!("... (loops back to {})", head.value);
          } else {
              println!("None");
          }
      }
  }

  fn main() {
      let mut list = CircularLinkedList::new();
      list.push(1);
      list.push(2);
      list.push(3);
      list.print();
  }
  ```
  - **Output:**
    ```
    Circular Singly Linked List: 1 -> 2 -> 3 -> ... (loops back to 1)
    ```
  - **Note:** Uses unsafe Rust with raw pointers (`*mut Node`) for simplicity, as managing circular references with `Box` and `Option` requires careful ownership handling. In practice, you'd use a safer library or advanced techniques.
  - **Roadmap Tie-In:** Relates to "Graph" (cycle detection) and "Caches" (e.g., LRU with circular buffers).

### 3. Doubly Linked List
- **Description:** Each node has a value, a pointer to the next node, and a pointer to the previous node, allowing bidirectional traversal. This is a distinct evolution from singly linked lists, often introduced after mastering the basics.
- **Key Operations:** Push front/back (O(1)), deletion (O(1) with prev/next), traversal (O(n) both directions).
- **Rust Implementation:**
  ```rust
  #[derive(Debug)]
  struct Node {
      value: i32,
      next: Option<Box<Node>>,
      prev: Option<*mut Node>, // Raw pointer for previous (unsafe for simplicity)
  }

  #[derive(Debug)]
  struct DoublyLinkedList {
      head: Option<Box<Node>>,
      tail: Option<*mut Node>,
  }

  impl DoublyLinkedList {
      fn new() -> Self {
          DoublyLinkedList { head: None, tail: None }
      }

      fn push_front(&mut self, value: i32) {
          let new_node = Box::new(Node {
              value,
              next: self.head.take(),
              prev: None,
          });
          let new_node_ptr = Box::into_raw(new_node);

          if let Some(old_head) = &mut self.head {
              unsafe { (*new_node_ptr).next = Some(Box::from_raw(old_head.as_mut().unwrap())); }
              unsafe { (*old_head.as_mut().unwrap()).prev = Some(new_node_ptr); }
          } else {
              self.tail = Some(new_node_ptr);
          }
          self.head = unsafe { Some(Box::from_raw(new_node_ptr)) };
      }

      fn print(&self) {
          print!("Doubly Linked List (forward): ");
          let mut current = &self.head;
          while let Some(node) = current {
              print!("{} -> ", node.value);
              current = &node.next;
          }
          println!("None");
      }
  }

  fn main() {
      let mut list = DoublyLinkedList::new();
      list.push_front(3);
      list.push_front(2);
      list.push_front(1);
      list.print();
  }
  ```
  - **Output:**
    ```
    Doubly Linked List (forward): 1 -> 2 -> 3 -> None
    ```
  - **Note:** Uses unsafe Rust with raw pointers (`*mut Node`) for `prev` to simplify ownership. A safer implementation would use `Rc` or `Arc` with `Weak` for reference counting, but this matches undergraduate-level complexity.
  - **Roadmap Tie-In:** Supports "Common Algorithms" (e.g., bidirectional traversal) and "Caches" (e.g., LRU with efficient deletions).
