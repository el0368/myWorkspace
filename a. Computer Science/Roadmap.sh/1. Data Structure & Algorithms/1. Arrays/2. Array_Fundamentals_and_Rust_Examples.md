---

### 1. The Core Definition

- **What it is:** An array is a collection of items, all of the **same data type**, stored in a **contiguous block of memory**. Think of it as a row of numbered boxes, where each box holds the same kind of thing.
    
- **Why it matters:** This structure is what gives arrays their primary advantage: fast access to any element.
    

---

### 2. Key Properties

- **Fixed Size:** Once an array is created, its size cannot be changed. If you create an array for 10 items, it can only ever hold 10 items.
    
- **Index-Based:** Every element has a numerical index, usually starting from 0. You use this index to directly access the element.
    
- **Homogeneous Elements:** All elements must be of the same type (e.g., all integers or all strings).
    

---

### 3. Essential Operations and Their Runtimes

You should understand how to perform the basic operations and why some are faster than others. The roadmap introduces

**Asymptotic Notation** and **Common Runtimes** early, so it's good to think in these terms2222.

- **Accessing (Reading/Writing): Very Fast**
    
    - You can jump directly to any element using its index (e.g., `my_array[5]`).
        
    - **Runtime:** Constant time or **O(1)**3. It takes the same amount of time to access the 5th element as it does the 5,000th.
        
- **Searching: Slow**
    
    - To find if a value exists, you typically have to check each element one by one, from the beginning to the end. This is called a
        
        **Linear Search**4.
        
    - **Runtime:** Linear time or **O(n)**5. In the worst case, you have to look at every single element.
        
- **Inserting/Deleting: Can be very slow**
    
    - If you want to add or remove an element from the middle of the array, you have to shift all the subsequent elements over to make space or fill the gap.
        
    - **Runtime:** Linear time or **O(n)**6. The time it takes depends on how many elements you have to shift.
