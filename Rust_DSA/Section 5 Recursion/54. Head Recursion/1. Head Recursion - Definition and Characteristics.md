
### What is Head Recursion?

In a **head recursive** function, the very **first statement inside the function is the recursive call** itself. This is a defining characteristic that sets it apart from other types of recursion.

### How Does Head Recursion Process Information?

A key aspect of head recursion is that **all the processing is done at returning time**. This means:

- When a head recursive function is called, it doesn't perform any significant work or calculations immediately.
    
- Instead, it makes the recursive call first, pushing the current function's state onto the call stack.
    
- This continues until the base case is reached.
    
- Once the base case returns a value, the functions then start unwinding from the call stack. It's during this **returning phase** that the actual operations and processing take place, using the results from the subsequent recursive calls.
    

### Example in Rust (Conceptual)

While the full processing happens on return, here's a conceptual Rust example to illustrate where the recursive call would be placed in a head recursive function:

Rust

```Rust
fn head_recursive_function(n: i32) {
    // Base case: When to stop recursing
    if n == 0 {
        return; // Or perform the initial action
    }

    // This is the head recursive call - it's the first significant statement
    head_recursive_function(n - 1);

    // All processing for 'n' happens AFTER the recursive call returns
    // For example, printing values in reverse order of call
    println!("Processing n: {}", n);
}

fn main() {
    head_recursive_function(3); // Example call
}
```

In this example, when `head_recursive_function(3)` is called:

1. `head_recursive_function(3)` calls `head_recursive_function(2)`.
    
2. `head_recursive_function(2)` calls `head_recursive_function(1)`.
    
3. `head_recursive_function(1)` calls `head_recursive_function(0)`.
    
4. `head_recursive_function(0)` hits the base case and returns.
    
5. Then, `head_recursive_function(1)` resumes, prints "Processing n: 1", and returns.
    
6. Then, `head_recursive_function(2)` resumes, prints "Processing n: 2", and returns.
    
7. Finally, `head_recursive_function(3)` resumes, prints "Processing n: 3", and returns.
    

This clearly demonstrates that the "processing" (in this case, printing) occurs as the functions are returning from the call stack, not as they are being called.
